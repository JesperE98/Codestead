# عائلة Red Hat: dnf وCOPR

تشكّل Fedora وRed Hat Enterprise Linux (RHEL) ونسخ RHEL المستنسخة مثل Rocky Linux
**عائلة Red Hat**. وهي تستخدم مدير الحزم **dnf** والحزم بصيغة `.rpm`. يعمل هذا
الفصل دائمًا على توزيعة من عائلة Red Hat – وهي الآن **{{distro}}**.

## dnf باختصار

| ماذا | الأمر |
|---|---|
| تحديث قائمة الحزم | `dnf check-update` |
| ترقية كل شيء | `dnf upgrade` |
| التثبيت | `dnf install X` |
| الإزالة | `dnf remove X` |
| البحث | `dnf search X` |
| معلومات الحزمة | `dnf info X` |
| عرض المثبّت | `dnf list --installed` |

الأوامر التي تغيّر النظام تتطلب صلاحيات root، لذا تُشغَّل باستخدام `sudo`.

## بيانات وصفية تلقائية

يجلب dnf معلومات الحزم الجديدة بنفسه عندما يحتاج إليها، لذا لا توجد خطوة منفصلة
مثل `apt update` في عائلة Debian. وإذا أردت أن ترى التحديثات المتاحة، فشغّل:

```sh
dnf check-update
```

لا يحتاج `dnf check-update` إلى صلاحيات root. ويكون رمز الخروج `100` إذا وُجدت
تحديثات – وهذا مفيد في السكربتات. وفي المحاكي توجد تحديثات بانتظارك. ماذا يطبع
هذا؟

```predict
$ dnf check-update > /dev/null; echo $?
100
---
يُخفي `> /dev/null` القائمة، و`$?` هو رمز خروج آخر أمر:
`100` يعني أن هناك تحديثات.
```

## التثبيت والإزالة

```sh
sudo dnf install htop
```

لاحظ السؤال `Is this ok [y/N]`. الحرف الكبير `N` يعني أن **لا** (No) هي الإجابة
الافتراضية – فإذا ضغطت Enter فقط، أُلغي التثبيت. اكتب `y` ثم Enter، أو استخدم
`-y`.

```quiz
يسألك dnf `Is this ok [y/N]` فتضغط Enter فقط. ماذا يحدث؟
- [ ] تُثبَّت الحزمة
- [x] يُلغى التثبيت
- [ ] يسألك dnf مرة أخرى
---
الحرف الكبير هو الإجابة الافتراضية. في عائلة Debian يسأل apt `[Y/n]`، لذا فإن
Enter هناك يعني نعم.
```

يزيل `dnf remove package` الحزمة مرة أخرى.

## ترقية النظام

```sh
sudo dnf upgrade
```

## خلف الكواليس: rpm

الحزم عبارة عن ملفات `.rpm`، والأداة منخفضة المستوى اسمها `rpm`. حلّ dnf محل
`yum` الأقدم، وجاء Fedora 41 بالإصدار الجديد **dnf5** الأسرع بكثير. وعلى RHEL
وRocky وAlmaLinux يسمى الأمر أيضًا `dnf`.

## المستودعات الإضافية – مريحة، لكن على مسؤوليتك

تحتوي مستودعات التوزيعة على عشرات الآلاف من الحزم – لكن ليس على كل شيء. فقد لا
يوجد برنامج متخصص فيها على الإطلاق، أو قد يوجد بإصدار قديم فقط. ولهذا توجد
**مستودعات إضافية** يتشارك فيها المطوّرون والمستخدمون حزمهم الخاصة.

الحزم في مستودعات التوزيعة نفسها مختبَرة معًا، وموقّعة، ويراجعها مطوّرو التوزيعة.
أما المستودع الإضافي فيمكن لأي أحد أن ينشئه. تذكّر ذلك قبل أن تضيف واحدًا:

- **الحزم تُثبَّت بصلاحيات root.** يمكن للحزمة أن تفعل أي شيء على الإطلاق بالحاسوب.
  فأنت تثق بمن بناها بقدر ما تثق بالتوزيعة.
- **قد تتعارض.** قد تستبدل حزمة من مستودع إضافي مكتبات النظام نفسه، أو تحتاج إلى
  إصدارات غير التي لديك.
- **قد يتوقف تحديثها.** إذا فقد الشخص الذي يدير المستودع اهتمامه، فلن تحصل بعد ذلك
  على تحديثات أمنية للبرنامج.

قاعدة عامة جيدة: ابحث أولًا في مستودعات التوزيعة، ثم عن Flatpak (في الفصل الخاص
بالحزم العامة)، وبعد ذلك فقط في مستودع إضافي من شخص تثق به.

## COPR

**COPR** (*Cool Other Package Repo*) هي خدمة البناء الخاصة بـ Fedora. يستطيع أي
شخص لديه حساب Fedora أن يبني فيها حزم `.rpm`، ويصبح كل مشروع مستودعًا مستقلًا
اسمه `user/project`. ولا تراجع التوزيعة مستودعات COPR.

في بقية هذا الفصل تثبّت برنامجًا خياليًا، `moonphase` (وهو يعرض طور القمر في
الطرفية)، من COPR.

### المستودعات التي لديك الآن

```sh
dnf repolist
```

```try
dnf repolist
---
هذه هي مستودعات Fedora نفسها.
```

### فعّل مستودع COPR

```sh
sudo dnf copr enable lunatool/moonphase
```

يذكّرك dnf بأن المستودع ليس جزءًا من Fedora وأن الجودة قد تتفاوت. والإجابة
الافتراضية للسؤال هي **لا** (No)، لذا أجب بـ `y`. ويُنشأ ملف جديد في
`/etc/yum.repos.d/`:

```sh
ls /etc/yum.repos.d
dnf copr list
dnf repolist
```

```quiz
يستطيع أي شخص لديه حساب Fedora أن يبني حزمًا في COPR. من يراجعها؟
- [ ] مطوّرو Fedora، قبل نشرها
- [ ] Red Hat
- [x] لا أحد – عليك أن تثق بمن يدير المستودع
```

### التثبيت والتشغيل

يجلب dnf معلومات المستودع الجديد بنفسه، لذا يمكن تثبيت الحزمة فورًا:

```sh
sudo dnf install moonphase
moonphase
```

### من أين تأتي الحزمة؟

```sh
dnf info moonphase
```

يُظهر السطر `From repository` أن الحزمة جاءت من COPR. وتُحدَّث حزم COPR كالمعتاد
باستخدام `sudo dnf upgrade`.

### التعطيل أو الإزالة

```sh
sudo dnf copr disable lunatool/moonphase
dnf copr list
```

يترك `disable` الملف في مكانه لكنه يوقف المستودع، أما `remove` فيحذفه تمامًا. ويبقى
البرنامج، لكنه لا يحصل على تحديثات بعد ذلك.

```quiz
ما الفرق بين `dnf copr disable` و`dnf copr remove`؟
- [x] يوقف `disable` المستودع لكنه يترك الملف، أما `remove` فيحذفه
- [ ] يزيل `disable` الحزم أيضًا، أما `remove` فلا
- [ ] لا يوجد فرق
```

### RPM Fusion

مستودع إضافي آخر شائع لـ Fedora هو **RPM Fusion**. فيه أشياء لا تستطيع Fedora أو
لا تريد أن تضمّها، مثل بعض برامج ترميز الوسائط (codecs) والتعريفات. وهو مشروع كبير
مشترك – لا مستودع مستخدم واحد كما في COPR.

كل مستودع تضيفه مصدر آخر تثق به. فأبقِ القائمة قصيرة، وأزل ما لم تعد تستخدمه.
