# عائلة Arch: pacman والـ AUR

تشكّل Arch Linux والتوزيعات المبنية عليها، مثل Manjaro وEndeavourOS، **عائلة
Arch**. وهي تستخدم مدير الحزم **pacman** والحزم بصيغة `.pkg.tar.zst`. يعمل هذا
الفصل دائمًا على توزيعة من عائلة Arch – وهي الآن **{{distro}}**.

## pacman باختصار

| ماذا | الأمر |
|---|---|
| تحديث قائمة الحزم | `pacman -Sy` |
| ترقية كل شيء | `pacman -Syu` |
| التثبيت | `pacman -S X` |
| الإزالة | `pacman -R X` |
| البحث | `pacman -Ss X` |
| معلومات الحزمة | `pacman -Si X` |
| عرض المثبّت | `pacman -Q` |

الأوامر التي تغيّر النظام تتطلب صلاحيات root، لذا تُشغَّل باستخدام `sudo`.

يستخدم pacman خيارات قصيرة يكون فيها **الحرف الكبير** هو العملية، والأحرف
الصغيرة معدِّلات:

| الخيار | المعنى |
|---|---|
| `-S` | Sync – التثبيت من المستودعات |
| `-R` | Remove – الإزالة |
| `-Q` | Query – الاستعلام عن الحزم المثبّتة |
| `y` | تحديث قاعدة بيانات الحزم |
| `u` | ترقية كل الحزم |
| `s` | البحث (مع ‎-S و‎-Q)، أو إزالة الاعتماديات (مع ‎-R) |
| `i` | المعلومات |

```quiz
ماذا يعني الحرف الكبير `Q` في `pacman -Q`؟
- [ ] Quit – إيقاف pacman
- [x] Query – الاستعلام عن الحزم المثبّتة
- [ ] Quick – التثبيت من دون سؤال
---
يستعلم `-Q` عمّا هو مثبّت، ويثبّت `-S` من المستودعات، ويزيل `-R`.
```

البحث لا يحتاج إلى root. جرّبه:

```try
pacman -Ss htop
```

## تحديث النظام

```sh
sudo pacman -Syu
```

`-Syu` تعني: زامِن (`S`)، وحدّث قاعدة البيانات (`y`)، ورقِّ كل شيء (`u`). وArch
توزيعة *rolling release* (متجددة)، لذا ستشغّل هذا الأمر كثيرًا.

> **مهم!** لا تشغّل أبدًا `pacman -Sy` وحده ثم `pacman -S package`. فقد تحتاج
> الحزمة الجديدة عندئذ إلى مكتبات أحدث من التي لديك – وهذا ما يسمى *partial
> upgrade* (ترقية جزئية) وقد يعطّل نظامك. استخدم دائمًا `-Syu`.

```quiz
لماذا يجب ألا تشغّل `pacman -Sy` ثم `pacman -S package`؟
- [ ] لأن `-Sy` يحذف قاعدة بيانات الحزم
- [x] قد تحتاج الحزمة الجديدة إلى مكتبات أحدث من التي لديك، وهذا قد يعطّل النظام
- [ ] لأن pacman لا يستطيع تثبيت أكثر من حزمة واحدة في اليوم
---
رقِّ كل شيء دفعة واحدة دائمًا باستخدام `-Syu`.
```

## التثبيت والإزالة

```sh
sudo pacman -S htop
```

يزيل `pacman -R package` حزمة، ويزيل `pacman -Rs package` أيضًا الاعتماديات التي
لا يحتاجها أي شيء آخر.

## الـ AUR

تحتوي مستودعات التوزيعة على عشرات الآلاف من الحزم – لكن ليس على كل شيء. فقد لا
يوجد برنامج متخصص فيها على الإطلاق، أو قد يوجد بإصدار قديم فقط. وفي عائلة Arch
يكون الحل هو **AUR** (*Arch User Repository*).

يختلف الـ AUR عن المستودعات العادية: فليست فيه حزم جاهزة، بل **وصفات بناء** فقط.
تسمى الوصفة `PKGBUILD`، وهي سكربت bash صغير يقول أين توجد الشيفرة المصدرية وكيف
يُبنى البرنامج. تنزّل الوصفة، وتبني الحزمة بنفسك، وتثبّتها باستخدام pacman. الـ
AUR ضخم – ففيه تقريبًا كل ما هو موجود للينكس – لكن يمكن لأي أحد أن يرفع وصفة.

```quiz
ماذا تنزّل من الـ AUR؟
- [ ] حزمة `.pkg.tar.zst` جاهزة راجعتها Arch
- [x] وصفة بناء (`PKGBUILD`) تبني منها الحزمة بنفسك
- [ ] حزمة Flatpak
```

### على مسؤوليتك

الحزم في مستودعات التوزيعة نفسها مختبَرة معًا، وموقّعة، ويراجعها مطوّرو التوزيعة.
أما الحزم في الـ AUR فلا تراجعها Arch. تذكّر ذلك:

- **الحزم تُثبَّت بصلاحيات root.** يمكن للحزمة أن تفعل أي شيء على الإطلاق بالحاسوب.
  فأنت تثق بمن كتب الوصفة بقدر ما تثق بالتوزيعة.
- **قد تتعارض.** قد تستبدل حزمة ما مكتبات النظام نفسه، أو تحتاج إلى إصدارات غير
  التي لديك.
- **قد يتوقف تحديثها.** إذا فقد الشخص الذي يصون الوصفة اهتمامه، فلن تحصل بعد ذلك
  على تحديثات أمنية للبرنامج.

قاعدة عامة جيدة: ابحث أولًا في مستودعات التوزيعة، ثم عن Flatpak (في الفصل الخاص
بالحزم العامة)، وبعد ذلك فقط في الـ AUR.

في بقية هذا الفصل تثبّت برنامجًا خياليًا، `moonphase` (وهو يعرض طور القمر في
الطرفية)، من الـ AUR.

### التحضيرات

لتنزيل الوصفات وبناء الحزم تحتاج إلى `git` و`base-devel` (مترجم، و`make`،
و`fakeroot` وغيرها):

```sh
sudo pacman -S --needed git base-devel
```

يتخطى `--needed` ما هو مثبّت أصلًا.

### احصل على الوصفة

كل حزمة في الـ AUR مستودع git مستقل:

```sh
cd ~
git clone https://aur.archlinux.org/moonphase.git
cd moonphase
ls
```

> إذا أخطأت في كتابة اسم الحزمة، يقول git *"You appear to have cloned an empty
> repository"* ويكون المجلد فارغًا. فالـ AUR يسمح لك باستنساخ أي شيء!

### اقرأ الـ PKGBUILD – في كل مرة

```sh
less PKGBUILD
```

`PKGBUILD` سكربت يعمل على حاسوبك. تحقّق على الأقل من:

- أن `source=` ينزّل من الموقع الحقيقي للبرنامج،
- أن `build()` و`package()` لا يفعلان سوى بناء الملفات ونسخها – ولا يفعلان مثلًا
  تنزيل شيء آخر وتشغيله (`curl … | sh`)،
- أن الحزمة تبدو مُصانة (التواريخ، والتعليقات على aur.archlinux.org).

### البناء والتثبيت

```sh
makepkg -si
```

يقرأ `makepkg` الملف `PKGBUILD`، وينزّل الشيفرة المصدرية، ويبنيها، ويحزمها في ملف
`.pkg.tar.zst`. يثبّت `-s` الاعتماديات الناقصة، ويثبّت `-i` الحزمة باستخدام pacman
عندما ينتهي. **لا** تشغّل makepkg باستخدام sudo – فهو يرفض العمل بصلاحيات root،
ويستخدم sudo بنفسه عند الحاجة.

```sh
ls
moonphase
```

### الحزم «الأجنبية»

لا يعرف pacman شيئًا عن الـ AUR. والحزم التي لا تأتي من المستودعات تسمى *foreign*
(أجنبية)، وتُعرض باستخدام:

```sh
pacman -Qm
```

ويعني هذا أيضًا أن `sudo pacman -Syu` **لا** يحدّث حزم الـ AUR. فعليك أن تجلب
الوصفة الجديدة بنفسك (`git pull`) وتعيد البناء – أو تترك ذلك لأداة مساعدة للـ AUR.

```quiz
ثبّتّ `moonphase` من الـ AUR وشغّلت `sudo pacman -Syu`. هل يُحدَّث `moonphase`؟
- [ ] نعم – يحدّث pacman كل حزمة مثبّتة
- [x] لا – لا يعرف pacman شيئًا عن الـ AUR
---
اجلب الوصفة الجديدة باستخدام `git pull` وأعد البناء، أو استخدم أداة مساعدة للـ AUR.
```

### أداة الـ AUR المساعدة yay

تفعل أداة الـ AUR المساعدة (AUR helper) كل هذا عنك: تبحث، وتنزّل، وتعرض الـ
`PKGBUILD`، وتبني، وتثبّت. وأشهرها **yay** (وأخرى هي *paru*). لا يوجد yay نفسه إلا
في الـ AUR، لذا يُثبَّت يدويًا مرة واحدة. والحزمة `yay-bin` مُترجمة مسبقًا وهي
الأسرع:

```sh
cd ~
git clone https://aur.archlinux.org/yay-bin.git
cd yay-bin
makepkg -si
```

بعد ذلك يُستخدم yay بطريقة تشبه pacman كثيرًا – لكن دون sudo:

```sh
yay -Ss snowfall
yay -S snowfall
snowfall
yay -Syu
```

يرقّي `yay -Syu` (أو `yay` وحده) حزم المستودعات وحزم الـ AUR الخاصة بك معًا. لكن
الراحة لا تعني أنك تستطيع التوقف عن قراءة الوصفات!

لا يوجد مستودع لإزالته في حالة الـ AUR – فكل حزمة وصفة مستقلة. أزل ما لم تعد
تستخدمه.
