# نسخ الملفات عبر SSH

في فصل الشبكات شغّلت أوامر على الخادم `192.168.1.10` باستخدام `ssh`. هنا تعطي
الخادم اسمًا قصيرًا، وتنسخ الملفات منه وإليه باستخدام `scp`، وتُبقي مجلدات كاملة
متزامنة باستخدام `rsync`.

## أسماء قصيرة – `~/.ssh/config`

كتابة `ssh {{user}}@192.168.1.10` في كل مرة تصبح مملّة. في الملف
`~/.ssh/config` يمكنك إعطاء الخادم اسمًا قصيرًا:

```text
Host srv
    HostName 192.168.1.10
    User {{user}}
```

`Host` هو الاسم القصير، و`HostName` العنوان الحقيقي (أو الاسم)، و`User` اسم
المستخدم على الخادم. وإذا كان الخادم يستمع على منفذ غير 22، فأضف سطرًا مثل
`Port 2222`. بعد ذلك يكفي هذا:

```sh
ssh srv hostname
```

لا يوجد في المحاكي محرّر نصوص بعد، لذا اكتب الملف باستخدام `echo`. والإزاحة
موجودة فقط لتسهيل القراءة:

```sh
mkdir -p ~/.ssh
echo 'Host srv' > ~/.ssh/config
echo '    HostName 192.168.1.10' >> ~/.ssh/config
echo '    User {{user}}' >> ~/.ssh/config
chmod 600 ~/.ssh/config
```

ssh صارم مع هذا الملف. فإذا كان يحق للآخرين الكتابة فيه، يرفض ssh برسالة
*Bad owner or permissions*، وكلمة واحدة مكتوبة خطأً توقفه فورًا:

```predict
$ mkdir -p ~/.ssh
$ echo 'Hostnam 192.168.1.10' > ~/.ssh/config
$ ssh srv hostname
/home/{{user}}/.ssh/config: line 1: Bad configuration option: hostnam
/home/{{user}}/.ssh/config: terminating, 1 bad configuration options
---
يقرأ ssh الملف كله قبل أن يتصل، لذا فإن كلمة واحدة خاطئة توقف كل الاتصالات –
وتذكر رسالة الخطأ رقم السطر الذي فيه الخطأ.
```

تعمل هذه الأسماء مع `scp` و`rsync` أيضًا.

```quiz
في `~/.ssh/config`، أي سطر يحدّد المكان الذي يتصل به ssh حقًا؟
- [ ] `Host`
- [x] `HostName`
- [ ] `User`
---
`Host` هو الاسم القصير الذي تكتبه بنفسك، و`HostName` العنوان الحقيقي، و`User`
المستخدم الذي تسجّل الدخول به.
```

## النسخ – `scp`

يعمل `scp` (*secure copy*) مثل `cp`، لكن أحد الطرفين يمكن أن يكون على حاسوب
آخر. وتكتبه على الشكل `HOST:PATH`:

```sh
scp {{notes}} srv:
scp srv:{{welcomeFile}} .
scp -r {{documents}} srv:backup
```

- يأتي المصدر أولًا والهدف أخيرًا، تمامًا كما في `cp`.
- المسار بعد النقطتين يُحسب من مجلد المنزل على الخادم، و`srv:` وحدها تعني مجلد
  المنزل.
- المجلدات تحتاج إلى `-r`.
- يُحدَّد المنفذ بحرف `-P` كبير (أما مع `ssh` فهو `-p` صغير).

لكل ملف يعرض `scp` سطرًا فيه الاسم و`100%` والحجم والسرعة.

```quiz
تكتب `scp report.txt srv` – من دون نقطتين. ماذا يحدث؟
- [ ] يُنسخ الملف إلى مجلد المنزل على الخادم
- [x] تحصل على نسخة محلية اسمها `srv`
- [ ] يسألك scp أي حاسوب تقصد
---
من دون النقطتين يكون `srv` مجرد اسم ملف، فينسخ `scp` محليًا مثل `cp`. من السهل
نسيان النقطتين!
```

## إبقاء الملفات متزامنة – `rsync`

للملفات الكثيرة، أو لشيء تنسخه مرة بعد مرة (النسخ الاحتياطية!)، يكون `rsync`
أفضل. فهو لا ينسخ إلا ما هو ناقص أو ما تغيّر:

```sh
rsync -av {{documents}}/ /tmp/{{documents}}
```

```text
sending incremental file list
created directory /tmp/{{documents}}
./
{{fruits}}
{{grades}}
server.log

sent 1,342 bytes  received 102 bytes  2,888.00 bytes/sec
total size is 1,104  speedup is 0.76
```

ينسخ `-a` (*archive*) المجلدات بشكل تعاودي ويحافظ على الصلاحيات والأوقات، ويعرض
`-v` قائمة بما يُنسخ. شغّل الأمر نفسه مرة أخرى وستكون القائمة فارغة – فلم يتغيّر
شيء. يقارن rsync حجم كل ملف ووقت تعديله؛ ومن دون `-a` تحصل النسخ على أوقات
جديدة، فيُرسَل كل شيء في كل مرة.

### الشرطة المائلة في النهاية

الشرطة المائلة في نهاية المصدر مهمة:

| الأمر | النتيجة |
|---|---|
| `rsync -a {{documents}} /tmp/x` | `/tmp/x/{{documents}}/...` – المجلد نفسه |
| `rsync -a {{documents}}/ /tmp/x` | `/tmp/x/...` – ما بداخله فقط |

```predict
$ rsync -a {{documents}} /tmp/x
$ ls /tmp/x
{{documents}}
---
من دون الشرطة المائلة نُسخ المجلد نفسه إلى داخل `/tmp/x`.
```

### عبر SSH و`--delete`

عندما يكون الهدف خادمًا، يعمل rsync عبر ssh:

```sh
rsync -av {{documents}}/ srv:{{documents}}/
```

يحذف `--delete` أيضًا من الهدف الملفات التي لم تعد موجودة في المصدر، فيصبح الهدف
نسخة مطابقة تمامًا. وعندها قد يحذف مسار خاطئ أشياء كثيرة، لذا جرّب أولًا باستخدام
`-n` (*dry run*). لا يحدث شيء، بل يعرض rsync فقط ما كان سيفعله، وينتهي السطر
الأخير بـ `(DRY RUN)`:

```sh
rsync -avn --delete {{documents}}/ /tmp/{{documents}}
```

```quiz
ماذا يفعل `-n` في `rsync -avn --delete a/ b/`؟
- [ ] ينسخ الملفات الجديدة فقط
- [x] يعرض ما سيحدث من دون أن يفعل شيئًا
- [ ] يتخطّى الملفات التي كانت ستُحذف
---
`-n` تشغيل تجريبي. راجع القائمة أولًا – ثم شغّل الأمر نفسه من دون `-n`.
```

## scp أم rsync؟

| | `scp` | `rsync` |
|---|---|---|
| مناسب لـ | ملفات قليلة، مرة واحدة | النسخ الاحتياطية والنسخ المتكرر |
| يرسل | كل شيء، في كل مرة | ما تغيّر فقط |
| محليًا أيضًا | يعمل، لكن `cp` أبسط | نعم |
| مرآة باستخدام `--delete` | لا | نعم |

يأتي `scp` مع عميل ssh. أما `rsync` فيجب أن يكون مثبّتًا على الحاسوبين: فهو موجود
منذ البداية في Ubuntu وDebian وFedora، أما في Arch فتثبّت الحزمة `rsync`.

في المحاكي ينسى الخادم ملفاته عندما تغلق التطبيق.
