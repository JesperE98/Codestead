# Red Hat ファミリー: dnf と COPR

Fedora、Red Hat Enterprise Linux（RHEL）、そして Rocky Linux のような RHEL の
クローンが **Red Hat ファミリー** を構成しています。どれもパッケージマネージャー
**dnf** と、`.rpm` 形式のパッケージを使います。この章は常に Red Hat ファミリーの
ディストリビューションで動きます。いまは **{{distro}}** です。

## dnf の要点

| 操作 | コマンド |
|---|---|
| パッケージ一覧を更新 | `dnf check-update` |
| すべてをアップグレード | `dnf upgrade` |
| インストール | `dnf install X` |
| 削除 | `dnf remove X` |
| 検索 | `dnf search X` |
| パッケージ情報 | `dnf info X` |
| インストール済みの一覧 | `dnf list --installed` |

システムを変更するコマンドには root 権限が必要なので、`sudo` を付けて実行します。

## 自動のメタデータ

dnf は必要なときに新しいパッケージ情報を自分で取得するので、Debian ファミリーの
`apt update` のような別の手順はありません。どんな更新があるかを確認したい場合は、
次を実行します。

```sh
dnf check-update
```

`dnf check-update` には root 権限は要りません。更新がある場合、終了コードは
`100` になります。スクリプトで便利です。シミュレーターには更新が待っています。
次のコマンドは何を表示しますか？

```predict
$ dnf check-update > /dev/null; echo $?
100
---
`> /dev/null` は一覧を隠し、`$?` は最後のコマンドの終了コードです。
`100` は更新があるという意味です。
```

## インストールと削除

```sh
sudo dnf install htop
```

`Is this ok [y/N]` という質問に注意してください。大文字の `N` は **No** が
既定値であることを意味します。Enter だけを押すと、インストールは取り消されます。
`y` と入力して Enter を押すか、`-y` を使いましょう。

```quiz
dnf が `Is this ok [y/N]` と聞いてきて、Enter だけを押しました。どうなりますか？
- [ ] パッケージがインストールされる
- [x] インストールが取り消される
- [ ] dnf がもう一度聞いてくる
---
大文字が既定値です。Debian ファミリーの apt は `[Y/n]` と聞くので、そちらでは
Enter は yes という意味になります。
```

`dnf remove パッケージ` で、パッケージをまた削除できます。

## システムをアップグレードする

```sh
sudo dnf upgrade
```

## 内部のしくみ: rpm

パッケージは `.rpm` ファイルで、低レベルツールは `rpm` という名前です。dnf は
古い `yum` に取って代わったもので、Fedora 41 では大幅に高速になった新しい
バージョン **dnf5** が導入されました。RHEL、Rocky、AlmaLinux でもコマンド名は
`dnf` です。

## 追加リポジトリ – 便利だけれど、自己責任で

ディストリビューションのリポジトリには何万ものパッケージがありますが、すべてが
あるわけではありません。マイナーなプログラムはまったく見つからないこともあれば、
古いバージョンしかないこともあります。そのために、開発者やユーザーが自分の
パッケージを共有する **追加リポジトリ** があります。

ディストリビューション自身のリポジトリにあるパッケージは、一緒にテストされ、
署名され、ディストリビューションの開発者によってレビューされています。一方、
追加リポジトリは誰でも作れます。追加する前に、次のことを覚えておきましょう。

- **パッケージは root としてインストールされます。** パッケージはコンピューターに
  対してどんなことでもできます。それを作った人を、ディストリビューションと同じ
  くらい信頼することになるのです。
- **衝突することがあります。** 追加リポジトリのパッケージが、システム自身の
  ライブラリを置き換えたり、手元にあるものとは別のバージョンを必要としたりする
  ことがあります。
- **更新されなくなることがあります。** リポジトリを運営している人が興味を
  なくすと、そのプログラムのセキュリティ更新はもう届きません。

よい目安: まずディストリビューションのリポジトリを探し、次に Flatpak
（ユニバーサルパッケージの章）を探し、それでもなければ、信頼できる人の
追加リポジトリを探しましょう。

## COPR

**COPR**（*Cool Other Package Repo*）は Fedora のビルドサービスです。Fedora
アカウントを持っている人なら誰でも、そこで `.rpm` パッケージをビルドできます。
各プロジェクトは `ユーザー/プロジェクト` という名前の独立したリポジトリになります。
COPR リポジトリはディストリビューションによるレビューを受けていません。

この章の残りでは、`moonphase` という架空のプログラム（ターミナルに月の満ち欠けを
表示します）を COPR からインストールします。

### いま使っているリポジトリ

```sh
dnf repolist
```

```try
dnf repolist
---
これらは Fedora 自身のリポジトリです。
```

### COPR リポジトリを有効にする

```sh
sudo dnf copr enable lunatool/moonphase
```

dnf は、そのリポジトリが Fedora の一部ではなく、品質にばらつきがあるかもしれない
ことを念押しします。質問の既定値は **No** なので、`y` と答えてください。
`/etc/yum.repos.d/` に新しいファイルが作られます。

```sh
ls /etc/yum.repos.d
dnf copr list
dnf repolist
```

```quiz
Fedora アカウントを持っている人なら誰でも、COPR でパッケージをビルドできます。
それをレビューするのは誰ですか？
- [ ] 公開される前に、Fedora の開発者が
- [ ] Red Hat が
- [x] 誰もしない。リポジトリを運営している人を信頼するしかない
```

### インストールして実行する

dnf は新しいリポジトリの情報を自分で取得するので、パッケージはすぐに
インストールできます。

```sh
sudo dnf install moonphase
moonphase
```

### パッケージはどこから来たのか？

```sh
dnf info moonphase
```

`From repository` の行を見ると、パッケージが COPR から来たことがわかります。
COPR のパッケージは、いつもどおり `sudo dnf upgrade` で更新されます。

### 無効にする、または削除する

```sh
sudo dnf copr disable lunatool/moonphase
dnf copr list
```

`disable` はファイルを残したままリポジトリを無効にし、`remove` はファイルを完全に
削除します。プログラムは残りますが、もう更新は届きません。

```quiz
`dnf copr disable` と `dnf copr remove` の違いは何ですか？
- [x] `disable` はファイルを残したままリポジトリを無効にし、`remove` はファイルを削除する
- [ ] `disable` はパッケージもアンインストールするが、`remove` はしない
- [ ] 違いはない
```

### RPM Fusion

Fedora でよく使われる追加リポジトリには、ほかに **RPM Fusion** があります。
一部のメディアコーデックやドライバーなど、Fedora が含められない、あるいは含め
ようとしないものがそろっています。COPR のような個人のリポジトリではなく、大きな
共同プロジェクトです。

リポジトリを 1 つ追加するたびに、信頼する相手が 1 人増えることになります。
一覧は短く保ち、もう使っていないものは片付けましょう。
