# cron で定期的なジョブを実行する

毎晩のバックアップ、毎週の古いログの片付け、5 分ごとのデータの取得。
コンピューターは、決まった時刻に自分でコマンドを実行できます。そのための
昔ながらのツールが **cron** で、systemd には独自の **タイマー** があります。

## cron と crontab

cron というサービスは毎分目を覚まし、時刻が来たジョブを実行します。ユーザーは
それぞれ自分のジョブの一覧、つまり **crontab** を持っています。

```sh
crontab -l
```

*no crontab for {{user}}* は、まだジョブが 1 つもないという意味です。

## 5 つの時刻フィールド

crontab の各行には、5 つの時刻フィールドがあり、その後にコマンドが続きます。

```text
┌───────────── 分（0–59）
│ ┌─────────── 時（0–23）
│ │ ┌───────── 日（1–31）
│ │ │ ┌─────── 月（1–12）
│ │ │ │ ┌───── 曜日（0–7、日曜日は 0 または 7）
│ │ │ │ │
* * * * *  コマンド
```

| 書き方 | 意味 |
|---|---|
| `*` | 毎回 |
| `5` | ちょうど 5 |
| `1-5` | 1 から 5 まで |
| `1,15` | 1 と 15 |
| `*/10` | 10 ごと: 0、10、20 … |

| 行 | 実行されるとき |
|---|---|
| `* * * * * command` | 毎分 |
| `*/5 * * * * command` | 5 分ごと |
| `30 2 * * * command` | 毎晩 02:30 |
| `0 7 * * 1-5 command` | 月曜日から金曜日の 07:00 |
| `0 0 1 * * command` | 毎月 1 日の午前 0 時 |
| `@reboot command` | コンピューターの起動時に 1 回 |

`@hourly`、`@daily`、`@weekly`、`@monthly` という短い書き方もあります。

```quiz
ジョブ `15 8 * * 6 ~/backup.sh` はいつ実行されますか？
- [ ] 毎日 15:08
- [x] 毎週土曜日の 08:15
- [ ] 毎月 15 日の 08:00
---
順番は分、時、日、月、曜日です。分が 15、時が 8、日付と月は何でもよく、
曜日が 6、つまり土曜日です。
```

```quiz
`0 */2 * * * command` はどのくらいの間隔で実行されますか？
- [ ] 2 分ごと
- [x] 2 時間ごと、毎正時に
- [ ] 1 日に 2 回
---
分が 0 で、時が 2 つおきです。00:00、02:00、04:00 … となります。
```

## ジョブを登録する

`crontab -e` は crontab をテキストエディターで開き、保存したときに登録します。
シミュレーターにはまだエディターがないので、ここでは `crontab` の入力として
ジョブを渡します。`-` は「入力から読む」という意味です。

```sh
echo '* * * * * date >> ~/cron.log' | crontab -
crontab -l
```

気をつけてください。`crontab -` と `crontab FILE` は crontab 全体を
**置き換えます**。ジョブを追加するには、古いジョブと新しいジョブを
組み合わせます。

```sh
(crontab -l; echo '30 2 * * * ~/backup.sh') | crontab -
```

1 行だけ削除するには、`grep -v` でその行を取り除いて残りを登録します。
すべてを削除するなら `crontab -r` です。

```sh
crontab -l | grep -v backup.sh | crontab -
```

`crontab` は何かを登録する前に、行をチェックします。

```predict
$ echo '0 25 * * * date' | crontab -
"-":1: bad hour
errors in crontab file, can't install.
---
25 時はありません。時は 0 から 23 までです。何も登録されませんでした。
```

## 実行されるのを見る

毎分実行されるジョブを登録したら、1 分待ってから見てみましょう。

```sh
cat ~/cron.log
journalctl -u cron
```

実行のたびに、`CRON[4211]: ({{user}}) CMD (date >> ~/cron.log)` のような行が
ジャーナルに書かれます。シミュレーターでは、cron はアプリが開いている間だけ
動きます。本物のコンピューターと同じように、電源が切れている間に逃したジョブを
あとから取り戻すことはありません。

## cron の落とし穴: 別の環境

ジョブはあなたのターミナルの中では実行されません。これにはほとんど誰もが
驚きます。

- ジョブは `/bin/sh` で実行され、あなたのエイリアスや `~/.bashrc` は使われません。
- `PATH` が短い（`/usr/bin:/bin`）ので、ほかの場所にあるプログラムには完全な
  パスが必要です。
- ジョブはホームディレクトリで開始します。
- ファイルに送られなかった出力は失われます。行の最後には必ず、たとえば
  `>> ~/job.log 2>&1` を付けましょう。

まずはコマンドを手で実行してみましょう。そこでうまくいったら、crontab に
入れます。

```quiz
ジョブ `* * * * * echo hi` は毎分実行されているのに、`hi` がどこにも
見当たりません。なぜでしょうか？
- [ ] cron では `echo` が使えない
- [x] 出力の行き先がない。`>>` でファイルに送る
- [ ] ジョブは root としてしか実行されない
---
cron のジョブの出力は、どのターミナルにも表示されません。本物の cron は出力を
メールで送ろうとしますが、ほとんどのコンピューターにはメールの仕組みが
ないので、出力は失われます。
```

## システム自身のジョブ

ユーザーの crontab のほかに、`/etc/crontab` と、`/etc/cron.daily` や
`/etc/cron.weekly` のようなディレクトリがあります。その中のスクリプトは
1 日に 1 回、または 1 週間に 1 回実行されます。

```sh
cat /etc/crontab
ls /etc/cron.daily
```

`/etc/crontab` の行には、コマンドの前にもう 1 つフィールドがあります。
ジョブをどのユーザーとして実行するかです。

## systemd のタイマー

最近のディストリビューションでは、こうした仕事の多くを代わりに systemd の
**タイマー** が行っています。決まった時刻に `.service` ユニットを開始する
`.timer` ユニットです。タイマーはジャーナルにログを残し、逃した実行を
あとから取り戻すこともできますが、ジョブごとに 2 つのユニットファイルが
必要です。自分用の小さなジョブなら、cron がいちばん手軽です。コンピューター上の
タイマーを、次回と前回の実行時刻といっしょに一覧表示してみましょう。

```try
systemctl list-timers
```

## ほかのディストリビューションでは

| | Ubuntu と Debian | Fedora | Arch |
|---|---|---|---|
| パッケージ | `cron` | `cronie` | `cronie` |
| サービス | `cron` | `crond` | `cronie` |
| 最初からインストール済み | はい | はい | いいえ |

Arch では、まず `sudo pacman -S cronie` と
`sudo systemctl enable --now cronie` を実行します。
