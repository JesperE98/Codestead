# ディストリビューションとファミリー

これで基本がわかりました。基本はどのディストリビューションでも同じように
使えます。では、ディストリビューション同士の違いは何なのでしょうか？

:::debian
いまあなたが使っているのは、**Debian ファミリー** の **{{distro}}** です。
:::

:::arch
いまあなたが使っているのは、**Arch ファミリー** の **{{distro}}** です。
:::

:::redhat
いまあなたが使っているのは、**Red Hat ファミリー** の **{{distro}}** です。
:::

この章は概要です。上部のメニューでディストリビューションを切り替えて、もう一度
課題をやってみてください。違いがすぐにわかるはずです。この章のあとには、
ファミリーごとに 1 つずつ章があります。**Debian ファミリー**（apt）、
**Arch ファミリー**（pacman）、**Red Hat ファミリー**（dnf）です。それぞれの章は
常にそのファミリーのディストリビューションで動くので、3 つすべてに取り組めます。

## どこでも同じものは？

- **Linux カーネル**。ただしバージョンは異なります。
- **bash シェル** と、GNU の基本ツール（`ls`、`cp`、`grep` など）。
- **ディレクトリ構成**。`/etc`、`/home`、`/usr/bin` などです。
- **systemd**。システムを起動し、サービスを管理します。ほぼすべての主要な
  ディストリビューションで使われています。

変数 `SHELL` には、ログインに使うシェルのフルパスが入っています。bash の場合は、
スクリプトのシバン行に書くのと同じパスです。

```predict
$ echo $SHELL
/bin/bash
---
シミュレーターでは、どのディストリビューションを選んでいても、シェルは bash です。
```

## 違うものは？

| | Debian ファミリー | Arch ファミリー | Red Hat ファミリー |
|---|---|---|---|
| パッケージマネージャー | `apt` | `pacman` | `dnf` |
| パッケージ形式 | `.deb` | `.pkg.tar.zst` | `.rpm` |
| 低レベルツール | `dpkg` | （pacman） | `rpm` |
| sudo グループ | `sudo` | `wheel` | `wheel` |
| リリース | 安定版 | ローリング | 6 か月ごとに新バージョン（Fedora） |

```quiz
sudo を使えるグループが `wheel` という名前なのは、どのファミリーですか？
- [ ] Debian ファミリー
- [x] Arch ファミリー
- [x] Red Hat ファミリー
---
Debian ファミリーではこのグループを `sudo` と呼び、Arch と Red Hat では `wheel` と呼びます。
```

### リリースモデル

- **固定バージョンの安定版** – Debian はおよそ 2 年ごとに新しいバージョンを
  出し、Ubuntu LTS（*Long Term Support*）は 2 年ごとに 5 年間のサポート付きで
  リリースされます。プログラムにはセキュリティ修正が入りますが、新しい
  バージョンに置き換えられることはめったにありません。サーバーに最適です。
- **ローリング** – Arch にはバージョンというものがありません。継続的に更新し、
  常に最新のものを使います。ユーザーには少し多くのことが求められます。
- **速いサイクル** – Fedora はおよそ 6 か月ごとに新しいバージョンを出し、
  Red Hat Enterprise Linux（RHEL）の一種の実験場の役割を果たしています。
  RHEL のほうは 10 年間のサポートがあり、企業で使われています。

```quiz
バージョンというものがなく、継続的に更新される（*ローリング*）ディストリビューションはどれですか？
- [ ] Debian
- [ ] Ubuntu LTS
- [x] Arch
- [ ] Fedora
```

## どのディストリビューションを使っている？

`/etc/os-release` ファイルはすべての最近のディストリビューションにあり、
名前とバージョンを教えてくれます。

```sh
cat /etc/os-release
```

カーネルのバージョンは `uname -r` で表示できます。

```sh
uname -r
```

```try
cat /etc/os-release
---
`NAME` と `PRETTY_NAME` の行を見れば、どのディストリビューションなのかがわかります。
```

## パッケージ、リポジトリ、依存関係

Windows や macOS では、Web サイトからプログラムをダウンロードすることがよく
あります。Linux では、代わりにほとんどすべてを **パッケージマネージャー** で
インストールします。これはディストリビューションのファミリー間で最も大きな違い
です。

- **パッケージ** とは、プログラム（またはライブラリ）を、そのバージョンや必要な
  ものについての情報と一緒に 1 つのファイルにまとめたものです。
- **リポジトリ** とは、ディストリビューションがすべてのパッケージを公開している
  サーバーです。パッケージはテストされ、署名されているので、改ざんされていない
  ことがわかります。
- **依存関係** とは、必要とされる別のパッケージのことです。パッケージマネージャー
  は依存関係を自動的にインストールします。

パッケージマネージャーは何がインストールされているかも管理していて、1 つの
コマンドでコンピューター上の *すべて* を更新できます。システムを変更する
コマンドには root 権限が必要なので、`sudo` を付けて実行します。

```quiz
あるパッケージが、あなたの持っていない別のパッケージを必要としています。
パッケージマネージャーでインストールすると、どうなりますか？
- [ ] インストールが止まり、もう一方のパッケージを自分で探す必要がある
- [x] パッケージマネージャーが依存関係を自動的にインストールする
- [ ] パッケージはインストールされるが、もう一方をダウンロードするまで動かない
```

### 同じプログラム、違う名前

パッケージはたいていどこでも同じ名前ですが、いつもそうとは限りません。
いくつか例を挙げます。

| プログラム | Debian/Ubuntu | Arch | Fedora |
|---|---|---|---|
| Vim | `vim` | `vim` | `vim-enhanced` |
| Python 3 | `python3` | `python` | `python3` |
| SSH クライアント | `openssh-client` | `openssh` | `openssh-clients` |

名前がわからないときは、必ずパッケージマネージャーで検索しましょう。

## パッケージマネージャーの設定

:::debian
Debian ファミリーでは、`/etc/apt/sources.list.d/` にあるファイルで、apt が
どの *リポジトリ* からパッケージを取得するかを指定します。

```sh
ls /etc/apt/sources.list.d
```
:::

:::arch
Arch ファミリーでは、pacman は `/etc/pacman.conf` で設定され、ミラーサーバーの
一覧は `/etc/pacman.d/mirrorlist` にあります。

```sh
cat /etc/pacman.conf
```
:::

:::redhat
Red Hat ファミリーでは、dnf の設定は `/etc/dnf/dnf.conf` にあり、*リポジトリ*
は `/etc/yum.repos.d/` にあるファイルで定義されています。

```sh
ls /etc/yum.repos.d
```
:::

## どれを選べばいい？

正解はありませんが、目安を挙げておきます。

- **Linux は初めて？** Ubuntu、Linux Mint、または Fedora。
- **サーバー用？** Debian、Ubuntu LTS、または Rocky Linux のような RHEL クローン。
- **すべてがどう組み合わさっているのか学びたい？** Arch と、その優れた Wiki。
