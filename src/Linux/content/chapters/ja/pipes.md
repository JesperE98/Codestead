# リダイレクトとパイプ

この章では、コマンドラインをこれほど強力にしているもの、つまり小さな
プログラム同士を *つなげる* 方法を扱います。

## 3 つのストリーム

どのプログラムにも 3 つの標準ストリームがあります。

| 番号 | 名前 | 内容 |
|---|---|---|
| 0 | stdin | 入力。通常はキーボードから |
| 1 | stdout | 通常の出力。通常は画面へ |
| 2 | stderr | エラーメッセージ。これも画面へ |

*リダイレクト* と *パイプ* を使うと、これらのストリームを別の場所へ送れます。

## ファイルへ – `>` と `>>`

`>` は stdout を画面ではなくファイルへ送ります。ファイルが存在しなければ
作成され、存在すれば **上書き** されます！

```sh
echo "1行目" > test.txt
```

`>>` は代わりにファイルの末尾へ追記します。

```sh
echo "2行目" >> test.txt
cat test.txt
```

```predict
$ echo one > t.txt
$ echo two > t.txt
$ cat t.txt
two
---
2 回目の `>` がファイルを上書きしました。`>>` なら両方の行が入ります。
```

## ファイルから – `<`

`{{fruits}}` は 10 行あり、1 行に 1 つの果物が書かれています。`wc -l` にファイル名を
渡すと、行数の後にその名前を表示します。次は 9 行ある `{{grades}}` の例です。

```sh
wc -l {{documents}}/{{grades}}
```

```text
9 {{documents}}/{{grades}}
```

`<` を使うと、プログラムは stdin をファイルから読み込みます。

```sh
wc -l < {{documents}}/{{fruits}}
```

この場合 `wc` はファイル名を目にしません。stdin でテキストを受け取るだけなので、
数だけを表示します。

```predict
$ wc -l {{documents}}/{{fruits}}
$ wc -l < {{documents}}/{{fruits}}
10 {{documents}}/{{fruits}}
10
---
ファイル名を引数として渡すと、`wc` は名前も表示します。`<` を使うと、
テキストだけを受け取ります。
```

## エラーメッセージ – `2>`

エラーメッセージは stderr に出力されるので、`>` の影響を受けません。
エラーメッセージを扱うには、ストリームの番号を前に書きます。

```sh
ls /{{missing}} 2> errors.txt
```

```quiz
`ls /{{missing}} > errors.txt` を実行しました。エラーメッセージはどこに行きますか？
- [ ] `errors.txt` の中
- [x] 画面に表示され、`errors.txt` は空のまま
- [ ] どこにも行かず、消える
---
`>` がリダイレクトするのは stdout（ストリーム 1）だけです。エラーメッセージは
stderr（ストリーム 2）に出力され、それは引き続き画面に送られます。`2>` が必要です。
```

`/dev/null` というファイルは「ブラックホール」です。書き込んだものはすべて
消えてしまいます。エラーを黙らせたいときに便利です。`2>&1` を使うと、
stderr が stdout と同じ行き先に送られます。

## パイプ – `|`

**パイプ** は、あるコマンドの stdout を次のコマンドの stdin へ直接送ります。
これが Unix 哲学の核心です。*1 つのことをうまくこなし、プログラム同士を
協力させる* という考え方です。

```sh
grep INFO {{documents}}/server.log | wc -l
```

`grep` が行を見つけ、`wc -l` がそれを数えます。いくつでもつなげられます。

```sh
sort {{documents}}/{{fruits}} | uniq -c | sort -rn
```

1 段ずつ読んでみましょう。果物を並べ替え、それぞれがいくつあるかを数え
（`uniq -c`）、最後に数の大きい順に数値で並べ替えます（`sort -rn`）。

`/etc` にはファイルとディレクトリがいくつありますか？パイプを使って数えてみましょう。

```try
ls /etc | wc -l
```

## 入力から引数へ – `xargs`

パイプからはまったく読まず、名前を **引数** として受け取りたいコマンドも
あります。`rm`、`mkdir`、`touch`、そしてファイルの中を数えるときの `wc` です。
`xargs` はその橋渡しをします。入力の単語を読み、それをコマンドの後ろに
並べます。

```sh
find {{documents}} -type f | xargs wc -l
```

これは、すべてのファイル名を自分で `wc -l` の後ろに書くのと同じです。`-n 1` を
付けると `xargs` は単語ごとに 1 回ずつコマンドを実行し、`-I {}` を付けると行ごとに
1 回ずつ、`{}` をその行に置き換えて実行します。

```sh
ls {{documents}} | xargs -I {} echo "File: {}"
```

```predict
$ printf 'a\nb\nc\n' | xargs echo
a b c
---
`xargs` は 3 行を集めて、`echo a b c` を 1 回だけ実行しました。
```

## 画面とファイルの両方へ – `tee`

`tee` は入力をそのまま次へ渡し、*さらに* ファイルにコピーを保存します。

```sh
ls /etc | tee etc-list.txt | wc -l
```

## コマンドの連結 – `;`、`&&`、`||`

1 行に複数のコマンドを書くことができます。

| 構文 | 意味 |
|---|---|
| `a ; b` | a を実行し、次に b を実行する |
| `a && b` | a が成功したときだけ b を実行する |
| `a \|\| b` | a が失敗したときだけ b を実行する |

```sh
mkdir -p new && cd new
```

```predict
$ mkdir {{documents}} 2> /dev/null && echo created || echo failed
failed
---
`{{documents}}` はすでに存在するので、`mkdir` は失敗します（そのエラーメッセージは
`/dev/null` に消えます）。`echo created` は飛ばされ、`echo failed` が実行されます。
```
