# テキストを読む・検索する

Linux では、設定、ログ、リストなど、ほとんどすべてがテキストです。そのため、
テキストファイルを読んだり検索したりするための小さなツールがたくさんあります。
ホームディレクトリには `{{documents}}` というディレクトリがあり、練習用のファイルが
入っています。その中には果物のリスト `{{fruits}}` と、架空の Web サーバーのログ
`server.log` があります。

## ファイルを表示する – `cat` と `less`

`cat` はファイル全体を表示します。

```sh
cat {{documents}}/{{fruits}}
```

長いファイルには `less` のほうが向いています。矢印キーとスペースキーで
スクロールし、`/word`（word は探したい単語）で検索し、`q` で終了します。

果物のリストを見てみましょう。次の問題で必要になります。

```try
cat {{documents}}/{{fruits}}
```

## 先頭と末尾 – `head` と `tail`

`head` は最初の数行を、`tail` は最後の数行を表示します。標準では 10 行ですが、
`-n` で行数を指定できます。

```sh
head -n 5 {{documents}}/server.log
tail -n 3 {{documents}}/server.log
```

`tail -f` はファイルを *追いかけ*、新しい行が書き込まれるたびに表示します。
ログを見るのにぴったりです。**Ctrl+C** で止めます。

```predict
$ tail -n 1 {{documents}}/{{fruits}}
マンゴー
---
`tail -n 1` はいちばん最後の行だけを表示します。
```

## 数える – `wc`

`wc`（*word count*）は行数、単語数、バイト数を数えます。

```sh
wc {{documents}}/{{fruits}}
```

行数だけ知りたいことがよくあります。その場合は `wc -l` を使います。

## 検索する – `grep`

`grep` は、数あるコマンドの中でも特に便利なものの 1 つです。パターンを含む
すべての行を表示します。

```sh
grep INFO {{documents}}/server.log
```

よく使うオプションをいくつか紹介します。

| オプション | 意味 |
|---|---|
| `-i` | 大文字と小文字の違いを無視する |
| `-n` | 行番号を表示する |
| `-v` | 一致 *しない* 行を表示する |
| `-c` | 一致する行を数える |
| `-r` | ディレクトリ内のすべてのファイルを再帰的に検索する |
| `-E` | 拡張パターン。例: `"ERROR|WARN"` |

```sh
grep -n WARN {{documents}}/server.log
```

パターンは *正規表現* です。例を 2 つ挙げると、`^` は行頭、`$` は行末を
意味します。つまり `grep "^2026"` は 2026 で始まる行を見つけます。

```quiz
`server.log` には `WARN` を含む行が 2 行、小文字の `warn` を含む行が 1 行あります。
`grep -c WARN {{documents}}/server.log` は何を表示しますか？
- [ ] 1
- [x] 2
- [ ] 3
---
`-c` は一致する行を数えます。`-i` を付けなければ大文字と小文字は区別されます。
`grep -ic WARN` なら 3 行すべてを数えます。
```

```quiz
`server.log` の中で `INFO` を含ま **ない** 行をすべて表示するコマンドはどれですか？
- [ ] `grep -i INFO {{documents}}/server.log`
- [ ] `grep -c INFO {{documents}}/server.log`
- [x] `grep -v INFO {{documents}}/server.log`
```

## 並べ替える – `sort` と `uniq`

`sort` は行をアルファベット順に並べ替えます（数値順なら `-n`、逆順なら `-r`）。
`uniq` は *すぐ上の* 行とまったく同じ行を取り除きます。そのため、ほとんど
いつも `sort` のあとに使われます。

```sh
sort {{documents}}/{{fruits}}
```

```quiz
`uniq` がほとんどいつも `sort` のあとに使われるのはなぜですか？
- [ ] `uniq` は並べ替えたファイルでしか動かず、それ以外ではエラーになるから
- [x] `uniq` はすぐ上の行と同じ行しか取り除かないので、同じ行が隣り合っている必要があるから
- [ ] `sort` が重複を取り除き、`uniq` がそれを元に戻すから
```

## フィールドを切り出す – `cut`

`{{documents}}` には 3 つ目の練習用ファイル `{{grades}}` があります。生徒の名前、
科目、点数が入った CSV ファイルです。

```sh
cat ~/{{documents}}/{{grades}}
```

CSV は *comma-separated values*（カンマ区切りの値）の略です。列はカンマで
区切られ、1 行目は見出しです。

ファイルが区切り文字で分けられたフィールドからできている場合、`cut` で 1 つの
フィールドを取り出せます。`-d` で区切り文字（*delimiter*）を、`-f` で残す
フィールドを選びます。次は CSV ファイルから科目（フィールド 2）を取り出します。

```sh
cut -d, -f2 ~/{{documents}}/{{grades}}
```

`/etc/passwd` ではフィールドがコロンで区切られ、フィールド 1 がユーザー名なので、
`cut -d: -f1 /etc/passwd` ですべてのユーザーを一覧表示できます。

## マニュアル – `man`

オプションの意味を忘れてしまいましたか？ すべてのコマンドにはマニュアル
ページがあります。

```sh
man grep
```
