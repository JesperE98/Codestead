# プロジェクト: レポートロボット

サーバーの調子が悪かったあの日を覚えていますか？ 上司はあなたのレポートをとても
気に入りました。少し気に入りすぎたくらいです。「すばらしい。これを毎朝机の上に
置いてほしい。平日は毎日。7 時までに」。6 時に起きて `grep` コマンドを打つつもりは
ありません。幸い、その必要もありません。もうスクリプトが書けるのですから。
代わりに仕事をしてくれるロボットを作りましょう。

ロボットはログ `~/{{documents}}/server.log` を読み、短いレポートを書きます。
レベルごとの行数と、どんなエラーが起きたかです。必要なものはすべて
「スクリプトと自動化」にあります。それを自分で組み立てるのがこの課題です。

## ミッション

1. **ロボットを作る。** スクリプト `~/{{robotScript}}` を作り、シバンの行と、見出しを
   表示する行を書きます。実行可能にして、実行してみましょう。
2. **ログを求めるように教える。** ロボットはログファイルを最初の引数として受け取り
   ます。引数なしで実行されたら、使い方を説明して、0 以外の終了コードで終わります。
3. **……ファイルがなければ文句を言うように教える。** 引数のファイルが存在しなければ、
   ロボットはそう伝えて、0 以外の終了コードで終わります。存在しないファイル名で
   試してみましょう。
4. **レベルを数える。** `~/{{documents}}/server.log` に対して実行すると、ロボットは
   ログにレベルごとに何行あるかを `awk` で数えて表示します。注意: `WARN` と `warn`
   は同じレベルです！
5. **エラーを一覧にする。** 数字の下に、レポートはすべてのエラーを時刻とメッセージ
   付きで並べます。ただし日付は**付けません**。どの行でも同じだからです。`sed` で
   取り除きましょう。
6. **ロボットを雇う。** cron でスケジュールします。月曜から金曜の 06:30 に
   サーバーのログに対して実行し、出力を `~/{{robotLog}}` に追記します。今までの
   ジョブは残しておきましょう。
7. **リハーサル。** ジョブのコマンドを一度手で実行して、今日のレポートを
   `~/{{robotLog}}` に入れ、ファイルを見てみましょう。

このテキストの横にあるリストのマイルストーンは、コマンドを実行するたびに自動で
チェックされます。

## ヒント

- ロボットは少しずつ作り、変更するたびに実行しましょう。いちばん簡単なのは、
  毎回ヒアドキュメントでスクリプト全体を書き直すことです。古い版と入れ替わります。
- どの行も、まずコマンドラインで `"$1"` の代わりにログのパスを使って試しましょう。
  そこで動いたら、スクリプトに入れます。
- ロボットのすぐあとに `echo $?` を実行すると、どの終了コードで終わったかがわかります。
- `awk` の `toupper()` は `warn` を `WARN` に変え、`sort | uniq -c` は同じ行を数えます。
- ログの各行は日付と空白で始まります。`sed` の `s` コマンドでその部分を何もない
  文字列に置き換えられます。
- cron のジョブはあなたの端末の中では実行されません。`~/{{robotScript}}` のような
  完全なパスを使い、出力はファイルに送りましょう。`>>` を使えば、毎朝のレポートが
  昨日の分を上書きせずに末尾に追加されます。

## もっとやってみたい？

マイルストーンを終えたら、ロボットに新しい技を覚えさせましょう。`$(date)` で
見出しに日付を入れる。レポートの各部分をそれぞれ関数にする。`for file in "$@"` で
一度に複数のログを受け取れるようにする。あるいは、`404` の応答を受けたリクエストが
いくつあるか数える。平日の 06:30 にアプリが開いていれば、`journalctl -u cron` で
ロボットが本当に出勤したことを確かめられます。
