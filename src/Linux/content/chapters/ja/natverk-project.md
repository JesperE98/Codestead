# プロジェクト: Web サイトが落ちた！

金曜日、16 時 47 分。電話が鳴ります。上司が息を切らしています。「Web サイトが
落ちてる！ お客さんが営業時間を見られないって。同じお客さんからもう 3 回も電話が
来てるんだ！」

会社の Web サイトは、ポート 8080 で動く小さな Web サーバー `myserver` です。
しかも *あなたの* コンピューターの上で。そう、本当に。何年も前に誰かが「とりあえず」
そこに置いて、それ以来、誰も移す勇気がなかったのです。

原因はネットワーク？ Web サーバー？ それとも上司のノートパソコン？ 内側から外側へ
順に調べて、すべてを障害ログに書き留めましょう。そして次はもっと楽になるように
しておきます。必要なものはすべて「ネットワーク」の中にあります。部品を自分で
組み立てるのがこの課題です。

## ミッション

1. **ログを書き始める。** フォルダー `~/{{incidentDir}}` と、その中に障害ログ
   `{{incidentLog}}` を作り、コンピューターの IP アドレスとゲートウェイの
   アドレスを書き込みます。
2. **外への道。** 名前解決も含めて、インターネットまでネットワークが通じている
   ことを示します。インターネット上の名前に 3 パケットの ping を送った結果を
   ログに追加しましょう。
3. **誰か待ち受けている？** ポート 8080 で何かが待ち受けているか調べます。何も
   なければ Web サーバーを起動して、もう一度確認します。
4. **サイトは応答する？** トップページ `http://localhost:8080` のレスポンス
   ヘッダーをログに追加します。ステータスコードは 200 のはずです。
5. **サーバーの鍵。** 次からはパスワードなしでサーバー `server.lan` に入りたい
   ところです。鍵ペアを作り、公開鍵をサーバーに置きます。
6. **バックアップ。** フォルダー `~/{{incidentDir}}` を丸ごと、サーバー上の自分の
   ホームディレクトリにコピーします。自分のコンピューターが壊れても、ログが
   残るようにするためです。
7. **離れた場所から読む。** サーバーにあるログを `ssh` で表示します。パスワードを
   聞かれないことが条件です。

このテキストの横にあるリストのマイルストーンは、コマンドを実行するたびに自動で
チェックされます。

## ヒント

- `>` はファイルを作り（または上書きし）、`>>` は末尾に追加します。ログは `>` で
  書き始めて、あとはずっと `>>` を使いましょう。
- 内側から外側へ。アドレス、ルート、ルーター、インターネット、そして最後に名前
  です。`-c` を付けないと、`ping` は止めるまで続きます。
- `ss -tulpn` で待ち受けているポートがわかります。ほかのユーザーのプロセスでは
  *Process* の列は空になりますが、ここで大事なのはポートです。
- Ubuntu には `curl` が最初から入っていません。`sudo apt update` と
  `sudo apt install curl` を実行しましょう。`-I` はヘッダーだけを取得します。
- `~/.ssh/config` の短い名前 `srv` はどこでも使えます。`{{user}}@server.lan` や
  `{{user}}@192.168.1.10` でもかまいません。
- `rsync -av コピー元/ srv:コピー先/` のように、コピー元の後ろのスラッシュは
  「ディレクトリの中にあるもの」という意味です。
- それでも `ssh` がパスワードを聞いてくる？ それなら鍵はまだサーバーに置かれて
  いません。

## もっとやってみたい？

マイルストーンを終えたら、さらに続けてみましょう。`sudo ip link set enp0s3 down`
でネットワークカードを止め、内側から外側への確認がどこで途切れるかを見てから、
`up` で元に戻します。`curl` で Web サイトのページ `/about.html` を取得してみま
しょう。ログに 1 行追加して同じ `rsync -av` をもう一度実行すると、変更分だけが
送られます。そして上司に折り返し電話をしましょう。（うわさでは、ノートパソコンが
機内モードだったそうです。）
