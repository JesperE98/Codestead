# परीक्षा: सिस्टम प्रशासन

दिखाइए कि आपने सेवाओं, डिस्क और यूज़रों के बारे में क्या सीखा है। प्रश्न पूरे भाग से
हैं, और पास होने के लिए आपको 80 % सही चाहिए।

```quiz
`myserver` को हर बार कंप्यूटर बूट होने पर अपने-आप शुरू होना चाहिए, लेकिन उसे अभी
**नहीं** शुरू होना चाहिए। कौन-सा कमांड ठीक यही करता है?
- [ ] `sudo systemctl start myserver`
- [x] `sudo systemctl enable myserver`
- [ ] `sudo systemctl enable --now myserver`
- [ ] `sudo systemctl restart myserver`
---
`enable` बूट पर लागू होता है, `start` अभी लागू होता है, और `--now` दोनों करता है।
```

इस कंप्यूटर पर सेवा `reportd` शुरू होने में विफल रही है। यह कमांड क्या छापता है?

```predict
$ systemctl is-active reportd
failed
---
`is-active` सिर्फ़ एक शब्द छापता है – यहाँ वही स्थिति जो `systemctl --failed` दिखाता
है। एग्ज़िट स्टेटस सिर्फ़ तब 0 होता है जब जवाब `active` हो।
```

```quiz
आप `myserver` को परखते समय उसका लॉग देखना चाहते हैं, जिसमें नई पंक्तियाँ आते ही
दिखें। आप कौन-सा कमांड इस्तेमाल करते हैं?
- [ ] `journalctl -n 20`
- [x] `journalctl -u myserver -f`
- [ ] `journalctl -p err -b`
- [ ] `systemctl status myserver --all`
---
`-u` एक unit चुनता है और `-f` तब तक नई पंक्तियाँ दिखाता रहता है जब तक आप Ctrl+C न
दबाएँ।
```

```try
systemctl cat myserver
---
`ExecStart=` वह कमांड है जो सेवा शुरू करता है, और `WantedBy=` वह है जिसे `enable`
इस्तेमाल करता है।
```

```quiz
आप `sudo` के बिना `systemctl stop myserver` चलाते हैं और
*Interactive authentication required* मिलता है। क्यों?
- [ ] myserver चल नहीं रहा है
- [x] सेवा को बदलने वाली हर चीज़ के लिए root चाहिए
- [ ] आपको पहले `daemon-reload` चलाना होगा
- [ ] `stop` सिर्फ़ enable की गई सेवाओं के लिए काम करता है
```

```quiz
`/etc/fstab` में आमतौर पर `/dev/sda2` के बजाय `UUID=…` क्यों लिखा होता है?
- [ ] UUID टाइप करने में छोटे होते हैं
- [x] डिस्क जोड़ने पर डिवाइस नाम बदल सकते हैं, लेकिन UUID कभी नहीं बदलता
- [ ] `mount` डिवाइस नाम नहीं समझता
- [ ] UUID दिखाता है कि फ़ाइल सिस्टम कितना भरा है
---
UUID फ़ाइल सिस्टम के साथ ही बनता है। आप उसे `lsblk -f`, `blkid` या `findmnt` से
ढूँढते हैं।
```

```quiz
`df -h` दिखाता है कि `/` 98 % भरा है। कौन-सा कमांड यह पता लगाने में मदद करता है कि
**कौन-सी डायरेक्टरी** जगह ले रही हैं?
- [ ] `df -hT`
- [ ] `lsblk -f`
- [x] `du -h -d 1`
- [ ] `swapon --show`
---
`df` फ़ाइल सिस्टम से पूछता है कि वह कितना भरा है; `du` फ़ाइलों से होकर गुज़रता है और
उन्हें जोड़ता है।
```

इस कंप्यूटर पर आपकी होम डायरेक्टरी किसी अलग फ़ाइल सिस्टम पर नहीं है। यह क्या छापता
है?

```predict
$ df -h ~ | tail -n 1 | tr -s ' ' | cut -d' ' -f6
/
---
पाथ देने पर `df` सिर्फ़ वह फ़ाइल सिस्टम दिखाता है जिस पर वह पाथ है। छठा कॉलम
`Mounted on` है – रूट फ़ाइल सिस्टम।
```

```quiz
आपने `/etc/fstab` में एक पंक्ति जोड़ी है। रीबूट करने से **पहले** आपको क्या करना
चाहिए?
- [ ] कुछ नहीं – फ़ाइल सिर्फ़ बूट पर पढ़ी जाती है
- [x] इसे `sudo mount -a` से परखना
- [ ] `sudo systemctl daemon-reload` चलाना
- [ ] पार्टिशन को `mkfs` से फ़ॉर्मैट करना
---
`/etc/fstab` में एक ग़लती कंप्यूटर को ठीक से बूट होने से रोक सकती है। `mount -a`
फ़ाइल की हर वह चीज़ माउंट करता है जो अभी माउंट नहीं है, इसलिए आपको त्रुटियाँ अभी दिख
जाती हैं।
```

```quiz
आप एक असली कंप्यूटर पर `mkfs` से एक पार्टिशन फ़ॉर्मैट करने वाले हैं। आपको पहले क्या
जाँचना चाहिए? (जो भी लागू हों, सब चुनिए।)
- [x] `lsblk -f` से, कि आकार, `RM` कॉलम और लेबल मेल खाते हैं
- [x] कि पार्टिशन माउंट नहीं है
- [x] कि आपके पास हर ज़रूरी चीज़ का बैकअप है
- [ ] कि पार्टिशन `/etc/fstab` में सूचीबद्ध है
```

```quiz
पासवर्ड हैश `/etc/passwd` के बजाय `/etc/shadow` में क्यों होते हैं?
- [ ] `/etc/passwd` बहुत छोटी है
- [x] `/etc/passwd` हर किसी के लिए पढ़ने योग्य होनी चाहिए, लेकिन `/etc/shadow` सिर्फ़ root के लिए
- [ ] हैश वापस खोले जा सकते हैं, इसलिए उन्हें छिपाना ज़रूरी है
- [ ] `/etc/passwd` सिर्फ़ बूट पर पढ़ी जाती है
---
वरना कोई भी हैश कॉपी करके आराम से उन्हें तोड़ने की कोशिश कर सकता था। मालिकों के नाम
दिखाने के लिए `ls -l` को `/etc/passwd` चाहिए।
```

`/etc/group` के फ़ील्ड हैं समूह का नाम, `x`, GID और सदस्य। समूह `sudo` में कौन है?

```predict
$ grep ^sudo /etc/group | cut -d: -f4
{{user}}
```

```quiz
`sudo userdel kim` – बिना `-r` के – से क्या होता है?
- [x] यूज़र मिट जाता है, लेकिन होम डायरेक्टरी `/home/kim` बची रहती है
- [ ] कुछ नहीं – `userdel` को हमेशा `-r` चाहिए
- [ ] यूज़र और होम डायरेक्टरी, दोनों मिट जाते हैं
- [ ] खाता सिर्फ़ लॉक होता है
```

```quiz
किसी यूज़र का UID 33 है और शेल `/usr/sbin/nologin`। यह सबसे ज़्यादा संभावना से क्या है?
- [ ] root
- [ ] एक सामान्य यूज़र – एक व्यक्ति
- [x] एक सिस्टम यूज़र, जिसके रूप में कोई सेवा चलती है
- [ ] एक मिटाया गया यूज़र
---
UID 1–999 सिस्टम यूज़रों के लिए हैं, और `nologin` का मतलब है कि कोई भी उनके रूप में
लॉग इन नहीं कर सकता।
```

```try
getent group sudo
---
`getent` समूह को उसी तरह खोजता है जैसे सिस्टम खोजता है।
```
