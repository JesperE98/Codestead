# Red Hat परिवार: dnf और COPR

Fedora, Red Hat Enterprise Linux (RHEL) और Rocky Linux जैसे RHEL क्लोन मिलकर **Red
Hat परिवार** बनाते हैं। ये पैकेज मैनेजर **dnf** और `.rpm` फ़ॉर्मैट के पैकेज इस्तेमाल
करते हैं। यह अध्याय हमेशा Red Hat परिवार के किसी डिस्ट्रीब्यूशन पर चलता है – अभी यह
**{{distro}}** है।

## dnf संक्षेप में

| क्या | कमांड |
|---|---|
| पैकेज सूची ताज़ा करना | `dnf check-update` |
| सब कुछ अपग्रेड करना | `dnf upgrade` |
| इंस्टॉल करना | `dnf install X` |
| हटाना | `dnf remove X` |
| खोजना | `dnf search X` |
| पैकेज की जानकारी | `dnf info X` |
| इंस्टॉल किए पैकेजों की सूची | `dnf list --installed` |

सिस्टम बदलने वाले कमांड के लिए root चाहिए, इसलिए उन्हें `sudo` के साथ चलाया जाता है।

## अपने-आप आने वाला मेटाडेटा

ज़रूरत पड़ने पर dnf नई पैकेज जानकारी ख़ुद ही ले आता है, इसलिए Debian परिवार के
`apt update` जैसा कोई अलग चरण नहीं है। अगर आप देखना चाहते हैं कि कौन-से अपडेट उपलब्ध
हैं, तो चलाइए:

```sh
dnf check-update
```

`dnf check-update` को root की ज़रूरत नहीं होती। अपडेट होने पर एग्ज़िट कोड `100`
होता है – स्क्रिप्ट में बहुत काम का। सिम्युलेटर में अपडेट इंतज़ार कर रहे हैं। यह
क्या छापेगा?

```predict
$ dnf check-update > /dev/null; echo $?
100
---
`> /dev/null` सूची को छिपा देता है, और `$?` पिछले कमांड का एग्ज़िट कोड है: `100`
का मतलब है कि अपडेट उपलब्ध हैं।
```

## इंस्टॉल करना और हटाना

```sh
sudo dnf install htop
```

सवाल `Is this ok [y/N]` पर ध्यान दीजिए। बड़े `N` का मतलब है कि **No** डिफ़ॉल्ट है –
अगर आप बस Enter दबाते हैं, तो इंस्टॉलेशन रद्द हो जाता है। `y` और Enter टाइप
कीजिए, या `-y` इस्तेमाल कीजिए।

```quiz
dnf पूछता है `Is this ok [y/N]` और आप बस Enter दबाते हैं। क्या होता है?
- [ ] पैकेज इंस्टॉल हो जाता है
- [x] इंस्टॉलेशन रद्द हो जाता है
- [ ] dnf फिर से पूछता है
---
बड़ा अक्षर डिफ़ॉल्ट होता है। Debian परिवार में apt `[Y/n]` पूछता है, इसलिए वहाँ
Enter का मतलब हाँ है।
```

`dnf remove package` किसी पैकेज को फिर से हटा देता है।

## सिस्टम अपग्रेड करना

```sh
sudo dnf upgrade
```

## अंदर की बात: rpm

पैकेज `.rpm` फ़ाइलें होते हैं और निचले स्तर के टूल का नाम `rpm` है। dnf ने पुराने
`yum` की जगह ली, और Fedora 41 नया संस्करण **dnf5** लेकर आया, जो काफ़ी तेज़ है।
RHEL, Rocky और AlmaLinux पर भी कमांड का नाम `dnf` ही है।

## अतिरिक्त रिपॉज़िटरी – सुविधाजनक, लेकिन अपने जोखिम पर

डिस्ट्रीब्यूशन की रिपॉज़िटरी में दसियों हज़ार पैकेज होते हैं – लेकिन सब कुछ नहीं।
कोई ख़ास (niche) प्रोग्राम शायद वहाँ बिलकुल न हो, या सिर्फ़ किसी पुराने संस्करण में
हो। इसीलिए **अतिरिक्त रिपॉज़िटरी** होती हैं, जहाँ डेवलपर और यूज़र अपने ख़ुद के पैकेज
साझा करते हैं।

डिस्ट्रीब्यूशन की अपनी रिपॉज़िटरी के पैकेज एक साथ जाँचे जाते हैं, हस्ताक्षरित किए
जाते हैं और डिस्ट्रीब्यूशन के डेवलपर उनकी समीक्षा करते हैं। दूसरी तरफ़, अतिरिक्त
रिपॉज़िटरी कोई भी बना सकता है। कोई रिपॉज़िटरी जोड़ने से पहले यह ध्यान में रखिए:

- **पैकेज root के रूप में इंस्टॉल होते हैं।** एक पैकेज कंप्यूटर के साथ कुछ भी कर
  सकता है। आप उसे बनाने वाले पर उतना ही भरोसा करते हैं जितना डिस्ट्रीब्यूशन पर।
- **यह टकरा सकता है।** अतिरिक्त रिपॉज़िटरी का पैकेज सिस्टम की अपनी लाइब्रेरी को
  बदल सकता है या उसे आपके पास मौजूद संस्करणों के बजाय दूसरे संस्करण चाहिए हो सकते
  हैं।
- **इसके अपडेट बंद हो सकते हैं।** अगर रिपॉज़िटरी चलाने वाले व्यक्ति की दिलचस्पी
  ख़त्म हो जाए, तो आपको प्रोग्राम के लिए आगे कोई सुरक्षा अपडेट नहीं मिलते।

एक अच्छा नियम: पहले डिस्ट्रीब्यूशन की रिपॉज़िटरी में देखिए, फिर Flatpak (यूनिवर्सल
पैकेज वाले अध्याय में) के लिए, और उसके बाद ही किसी भरोसेमंद व्यक्ति की अतिरिक्त
रिपॉज़िटरी में।

## COPR

**COPR** (*Cool Other Package Repo*) Fedora की बिल्ड सेवा है। Fedora खाते वाला कोई
भी वहाँ `.rpm` पैकेज बिल्ड कर सकता है, और हर प्रोजेक्ट `user/project` नाम की अपनी
अलग रिपॉज़िटरी बन जाता है। डिस्ट्रीब्यूशन COPR रिपॉज़िटरी की समीक्षा नहीं करता।

इस अध्याय के बाक़ी हिस्से में आप एक काल्पनिक प्रोग्राम, `moonphase` (यह टर्मिनल में
चाँद की कला दिखाता है), COPR से इंस्टॉल करेंगे।

### अभी आपके पास मौजूद रिपॉज़िटरी

```sh
dnf repolist
```

```try
dnf repolist
---
ये Fedora की अपनी रिपॉज़िटरी हैं।
```

### COPR रिपॉज़िटरी चालू करना

```sh
sudo dnf copr enable lunatool/moonphase
```

dnf आपको याद दिलाता है कि यह रिपॉज़िटरी Fedora का हिस्सा नहीं है और गुणवत्ता
अलग-अलग हो सकती है। सवाल का डिफ़ॉल्ट **No** है, इसलिए `y` जवाब दीजिए।
`/etc/yum.repos.d/` में एक नई फ़ाइल बनती है:

```sh
ls /etc/yum.repos.d
dnf copr list
dnf repolist
```

```quiz
Fedora खाते वाला कोई भी COPR में पैकेज बिल्ड कर सकता है। उनकी समीक्षा कौन करता है?
- [ ] Fedora के डेवलपर, उनके प्रकाशित होने से पहले
- [ ] Red Hat
- [x] कोई नहीं – आपको रिपॉज़िटरी चलाने वाले पर भरोसा करना पड़ता है
```

### इंस्टॉल करना और चलाना

dnf नई रिपॉज़िटरी की जानकारी ख़ुद ले आता है, इसलिए पैकेज तुरंत इंस्टॉल किया जा
सकता है:

```sh
sudo dnf install moonphase
moonphase
```

### पैकेज कहाँ से आता है?

```sh
dnf info moonphase
```

`From repository` वाली पंक्ति दिखाती है कि पैकेज COPR से आया है। COPR के पैकेज
हमेशा की तरह `sudo dnf upgrade` से अपडेट होते हैं।

### बंद करना या हटाना

```sh
sudo dnf copr disable lunatool/moonphase
dnf copr list
```

`disable` फ़ाइल को वहीं रहने देता है लेकिन रिपॉज़िटरी को बंद कर देता है, `remove`
उसे पूरी तरह मिटा देता है। प्रोग्राम बना रहता है, लेकिन उसे आगे अपडेट नहीं मिलते।

```quiz
`dnf copr disable` और `dnf copr remove` में क्या फ़र्क़ है?
- [x] `disable` रिपॉज़िटरी को बंद करता है लेकिन फ़ाइल छोड़ देता है, `remove` उसे मिटा देता है
- [ ] `disable` पैकेज भी अनइंस्टॉल करता है, `remove` नहीं
- [ ] कोई फ़र्क़ नहीं है
```

### RPM Fusion

Fedora के लिए एक और आम अतिरिक्त रिपॉज़िटरी है **RPM Fusion**। इसमें वे चीज़ें हैं
जो Fedora शामिल नहीं कर सकता या नहीं करना चाहता, जैसे कुछ मीडिया कोडेक और ड्राइवर।
यह एक बड़ा, साझा प्रोजेक्ट है – COPR की तरह किसी एक यूज़र की रिपॉज़िटरी नहीं।

आपकी जोड़ी हर रिपॉज़िटरी एक और ऐसा भेजने वाला है जिस पर आप भरोसा करते हैं। सूची
छोटी रखिए और जो अब इस्तेमाल नहीं करते, उसे हटा दीजिए।
