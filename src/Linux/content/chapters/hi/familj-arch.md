# Arch परिवार: pacman और AUR

Arch Linux और उस पर बने डिस्ट्रीब्यूशन, जैसे Manjaro और EndeavourOS, मिलकर **Arch
परिवार** बनाते हैं। ये पैकेज मैनेजर **pacman** और `.pkg.tar.zst` फ़ॉर्मैट के पैकेज
इस्तेमाल करते हैं। यह अध्याय हमेशा Arch परिवार के किसी डिस्ट्रीब्यूशन पर चलता है –
अभी यह **{{distro}}** है।

## pacman संक्षेप में

| क्या | कमांड |
|---|---|
| पैकेज सूची ताज़ा करना | `pacman -Sy` |
| सब कुछ अपग्रेड करना | `pacman -Syu` |
| इंस्टॉल करना | `pacman -S X` |
| हटाना | `pacman -R X` |
| खोजना | `pacman -Ss X` |
| पैकेज की जानकारी | `pacman -Si X` |
| इंस्टॉल किए पैकेजों की सूची | `pacman -Q` |

सिस्टम बदलने वाले कमांड के लिए root चाहिए, इसलिए उन्हें `sudo` के साथ चलाया जाता है।

pacman छोटे ऑप्शन इस्तेमाल करता है, जिनमें **बड़ा अक्षर** (capital letter) ऑपरेशन
होता है और छोटे अक्षर उसमें बदलाव (modifiers) करते हैं:

| ऑप्शन | मतलब |
|---|---|
| `-S` | Sync – रिपॉज़िटरी से इंस्टॉल करना |
| `-R` | Remove – हटाना |
| `-Q` | Query – इंस्टॉल किए पैकेजों के बारे में पूछना |
| `y` | पैकेज डेटाबेस ताज़ा करना |
| `u` | सारे पैकेज अपग्रेड करना |
| `s` | खोजना (-S और -Q के साथ), या निर्भरताएँ हटाना (-R के साथ) |
| `i` | जानकारी (Info) |

```quiz
`pacman -Q` में बड़े `Q` का क्या मतलब है?
- [ ] Quit – pacman को बंद करना
- [x] Query – इंस्टॉल किए पैकेजों के बारे में पूछना
- [ ] Quick – बिना पूछे इंस्टॉल करना
---
`-Q` इंस्टॉल की गई चीज़ों के बारे में पूछता है, `-S` रिपॉज़िटरी से इंस्टॉल करता है
और `-R` हटाता है।
```

खोजने के लिए root की ज़रूरत नहीं होती। आज़माइए:

```try
pacman -Ss htop
```

## सिस्टम अपडेट करना

```sh
sudo pacman -Syu
```

`-Syu` का मतलब है: सिंक्रनाइज़ करो (`S`), डेटाबेस ताज़ा करो (`y`) और सब कुछ अपग्रेड
करो (`u`)। Arch एक *rolling release* है, इसलिए आप इसे अक्सर चलाएँगे।

> **ज़रूरी!** कभी भी सिर्फ़ `pacman -Sy` और उसके बाद `pacman -S package` मत
> चलाइए। हो सकता है नए पैकेज को आपके पास मौजूद लाइब्रेरी से नई लाइब्रेरी चाहिए
> हों – एक तथाकथित *partial upgrade*, जो आपका सिस्टम तोड़ सकता है। हमेशा `-Syu`
> इस्तेमाल कीजिए।

```quiz
आपको `pacman -Sy` और फिर `pacman -S package` क्यों नहीं चलाना चाहिए?
- [ ] क्योंकि `-Sy` पैकेज डेटाबेस मिटा देता है
- [x] नए पैकेज को आपके पास मौजूद लाइब्रेरी से नई लाइब्रेरी चाहिए हो सकती हैं, जिससे सिस्टम टूट सकता है
- [ ] क्योंकि pacman एक दिन में सिर्फ़ एक पैकेज इंस्टॉल कर सकता है
---
हमेशा `-Syu` से सब कुछ एक साथ अपग्रेड कीजिए।
```

## इंस्टॉल करना और हटाना

```sh
sudo pacman -S htop
```

`pacman -R package` एक पैकेज हटाता है, और `pacman -Rs package` उन निर्भरताओं को
भी हटा देता है जिनकी किसी और को ज़रूरत नहीं है।

## AUR

डिस्ट्रीब्यूशन की रिपॉज़िटरी में दसियों हज़ार पैकेज होते हैं – लेकिन सब कुछ नहीं।
कोई ख़ास (niche) प्रोग्राम शायद वहाँ बिलकुल न हो, या सिर्फ़ किसी पुराने संस्करण में
हो। Arch परिवार में इसका जवाब है **AUR** (*Arch User Repository*)।

AUR सामान्य रिपॉज़िटरी से अलग है: इसमें तैयार पैकेज नहीं होते, सिर्फ़ **बिल्ड
नुस्ख़े** (build recipes) होते हैं। नुस्ख़े को `PKGBUILD` कहते हैं और यह एक छोटी
bash स्क्रिप्ट है जो बताती है कि सोर्स कोड कहाँ है और प्रोग्राम कैसे बिल्ड होता है।
आप नुस्ख़ा डाउनलोड करते हैं, पैकेज ख़ुद बिल्ड करते हैं और उसे pacman से इंस्टॉल करते
हैं। AUR बहुत विशाल है – Linux के लिए मौजूद लगभग हर चीज़ वहाँ है – लेकिन नुस्ख़ा
कोई भी अपलोड कर सकता है।

```quiz
आप AUR से क्या डाउनलोड करते हैं?
- [ ] एक तैयार `.pkg.tar.zst` पैकेज, जिसकी Arch ने समीक्षा की है
- [x] एक बिल्ड नुस्ख़ा (`PKGBUILD`), जिससे आप पैकेज ख़ुद बिल्ड करते हैं
- [ ] एक Flatpak
```

### अपने जोखिम पर

डिस्ट्रीब्यूशन की अपनी रिपॉज़िटरी के पैकेज एक साथ जाँचे जाते हैं, हस्ताक्षरित किए
जाते हैं और डिस्ट्रीब्यूशन के डेवलपर उनकी समीक्षा करते हैं। AUR के पैकेजों की Arch
समीक्षा नहीं करता। यह ध्यान में रखिए:

- **पैकेज root के रूप में इंस्टॉल होते हैं।** एक पैकेज कंप्यूटर के साथ कुछ भी कर
  सकता है। आप नुस्ख़ा लिखने वाले पर उतना ही भरोसा करते हैं जितना डिस्ट्रीब्यूशन पर।
- **यह टकरा सकता है।** एक पैकेज सिस्टम की अपनी लाइब्रेरी को बदल सकता है या उसे
  आपके पास मौजूद संस्करणों के बजाय दूसरे संस्करण चाहिए हो सकते हैं।
- **इसके अपडेट बंद हो सकते हैं।** अगर नुस्ख़े की देखभाल करने वाले व्यक्ति की
  दिलचस्पी ख़त्म हो जाए, तो आपको प्रोग्राम के लिए आगे कोई सुरक्षा अपडेट नहीं मिलते।

एक अच्छा नियम: पहले डिस्ट्रीब्यूशन की रिपॉज़िटरी में देखिए, फिर Flatpak (यूनिवर्सल
पैकेज वाले अध्याय में) के लिए, और उसके बाद ही AUR में।

इस अध्याय के बाक़ी हिस्से में आप एक काल्पनिक प्रोग्राम, `moonphase` (यह टर्मिनल में
चाँद की कला दिखाता है), AUR से इंस्टॉल करेंगे।

### तैयारी

नुस्ख़े डाउनलोड करने और पैकेज बिल्ड करने के लिए आपको `git` और `base-devel` (एक
कंपाइलर, `make`, `fakeroot` और भी बहुत कुछ) चाहिए:

```sh
sudo pacman -S --needed git base-devel
```

`--needed` वह छोड़ देता है जो पहले से इंस्टॉल है।

### नुस्ख़ा लाना

हर AUR पैकेज अपनी अलग git रिपॉज़िटरी है:

```sh
cd ~
git clone https://aur.archlinux.org/moonphase.git
cd moonphase
ls
```

> अगर आप पैकेज का नाम ग़लत लिखते हैं, तो git कहता है *"You appear to have cloned an
> empty repository"* और डायरेक्टरी ख़ाली रहती है। AUR आपको कुछ भी क्लोन करने देता
> है!

### PKGBUILD पढ़िए – हर बार

```sh
less PKGBUILD
```

`PKGBUILD` एक स्क्रिप्ट है जो आपके कंप्यूटर पर चलती है। कम से कम जाँचिए:

- कि `source=` प्रोग्राम की असली वेबसाइट से डाउनलोड करता है,
- कि `build()` और `package()` सिर्फ़ फ़ाइलें बिल्ड और कॉपी करते हैं – और, उदाहरण के
  लिए, कुछ और डाउनलोड करके नहीं चलाते (`curl … | sh`),
- कि पैकेज की देखभाल होती लगती है (तारीख़ें, aur.archlinux.org पर टिप्पणियाँ)।

### बिल्ड और इंस्टॉल करना

```sh
makepkg -si
```

`makepkg` `PKGBUILD` पढ़ता है, सोर्स कोड डाउनलोड करता है, उसे बिल्ड करता है और एक
`.pkg.tar.zst` फ़ाइल बनाता है। `-s` छूटी हुई निर्भरताएँ इंस्टॉल करता है और `-i`
तैयार होने पर पैकेज को pacman से इंस्टॉल करता है। makepkg को sudo के साथ **मत**
चलाइए – यह root के रूप में चलने से मना करता है, और ज़रूरत पड़ने पर ख़ुद sudo
इस्तेमाल करता है।

```sh
ls
moonphase
```

### "विदेशी" (foreign) पैकेज

pacman को AUR के बारे में कुछ नहीं पता। जो पैकेज रिपॉज़िटरी से नहीं आते, उन्हें
*foreign* कहते हैं और उनकी सूची ऐसे मिलती है:

```sh
pacman -Qm
```

इसका यह भी मतलब है कि `sudo pacman -Syu` AUR पैकेजों को अपडेट **नहीं** करता। आपको
नया नुस्ख़ा ख़ुद लाना होगा (`git pull`) और फिर से बिल्ड करना होगा – या यह काम किसी
AUR हेल्पर पर छोड़ना होगा।

```quiz
आपने AUR से `moonphase` इंस्टॉल किया है और `sudo pacman -Syu` चलाते हैं। क्या
`moonphase` अपडेट होता है?
- [ ] हाँ – pacman हर इंस्टॉल किए गए पैकेज को अपडेट करता है
- [x] नहीं – pacman को AUR के बारे में कुछ नहीं पता
---
`git pull` से नया नुस्ख़ा लाइए और फिर से बिल्ड कीजिए, या किसी AUR हेल्पर का
इस्तेमाल कीजिए।
```

### AUR हेल्पर yay

AUR हेल्पर यह सब आपके लिए करता है: वह खोजता है, डाउनलोड करता है, `PKGBUILD`
दिखाता है, बिल्ड करता है और इंस्टॉल करता है। सबसे आम है **yay** (एक और है *paru*)।
yay ख़ुद सिर्फ़ AUR में है, इसलिए उसे एक बार हाथ से इंस्टॉल किया जाता है। पैकेज
`yay-bin` पहले से कंपाइल किया हुआ है और सबसे जल्दी होता है:

```sh
cd ~
git clone https://aur.archlinux.org/yay-bin.git
cd yay-bin
makepkg -si
```

उसके बाद yay काफ़ी हद तक pacman की तरह इस्तेमाल होता है – लेकिन sudo के बिना:

```sh
yay -Ss snowfall
yay -S snowfall
snowfall
yay -Syu
```

`yay -Syu` (या बस `yay`) रिपॉज़िटरी वाले पैकेज और आपके AUR पैकेज, दोनों को अपग्रेड
करता है। सुविधा का मतलब यह नहीं कि आप नुस्ख़े पढ़ना बंद कर दें!

AUR के लिए हटाने को कोई रिपॉज़िटरी नहीं है – हर पैकेज अपना अलग नुस्ख़ा है। जो अब
इस्तेमाल नहीं करते, उसे हटा दीजिए।
