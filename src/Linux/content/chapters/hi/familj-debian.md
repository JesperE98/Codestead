# Debian परिवार: apt और PPA

Debian, Ubuntu और उन पर बने डिस्ट्रीब्यूशन, जैसे Linux Mint, मिलकर **Debian
परिवार** बनाते हैं। ये सभी पैकेज मैनेजर **apt** और `.deb` फ़ॉर्मैट के पैकेज
इस्तेमाल करते हैं। यह अध्याय हमेशा Debian परिवार के किसी डिस्ट्रीब्यूशन पर चलता है –
अभी यह **{{distro}}** है। ऊपर के मेन्यू में आप Ubuntu और Debian के बीच बदल सकते हैं।

## apt संक्षेप में

| क्या | कमांड |
|---|---|
| पैकेज सूची ताज़ा करना | `apt update` |
| सब कुछ अपग्रेड करना | `apt upgrade` |
| इंस्टॉल करना | `apt install X` |
| हटाना | `apt remove X` |
| खोजना | `apt search X` |
| पैकेज की जानकारी | `apt show X` |
| इंस्टॉल किए पैकेजों की सूची | `apt list --installed` |

सिस्टम बदलने वाले कमांड के लिए root चाहिए, इसलिए उन्हें `sudo` के साथ चलाया जाता है।

```quiz
इनमें से कौन-से कमांड सिस्टम बदलते हैं और इसलिए उन्हें `sudo` चाहिए?
- [x] `apt install htop`
- [ ] `apt search htop`
- [x] `apt remove htop`
- [ ] `apt show htop`
---
खोजना और जानकारी दिखाना सिर्फ़ पैकेज सूचियाँ पढ़ते हैं। इंस्टॉल करना और हटाना
सिस्टम को बदलते हैं।
```

## update और upgrade अलग-अलग चीज़ें हैं

शुरू में यह लगभग सबको उलझा देता है:

- `apt update` यह **सूची** डाउनलोड करता है कि कौन-से पैकेज और संस्करण उपलब्ध
  हैं। यह कुछ भी इंस्टॉल नहीं करता।
- `apt upgrade` जो आपके पास पहले से है, उसके नए संस्करण **इंस्टॉल** करता है।

इसलिए हमेशा पहले `update` चलाइए। सिस्टम अपडेट करने का सबसे आम तरीक़ा है:

```sh
sudo apt update && sudo apt upgrade
```

जब तक आपने `apt update` नहीं चलाया है (जैसे किसी नए इंस्टॉल किए गए सर्वर पर), तब
तक पैकेज सूची ख़ाली रहती है और apt को कोई पैकेज मिलता ही नहीं।

```quiz
`sudo apt update` क्या करता है?
- [x] यह सूची डाउनलोड करता है कि कौन-से पैकेज और संस्करण उपलब्ध हैं
- [ ] आपके पास पहले से मौजूद पैकेजों के नए संस्करण इंस्टॉल करता है
- [ ] ख़ुद apt को सबसे नए संस्करण में अपडेट करता है
---
`apt update` सिर्फ़ सूची ताज़ा करता है। नए संस्करण `apt upgrade` इंस्टॉल करता है।
```

## इंस्टॉल करना और हटाना

```sh
sudo apt install htop
```

`apt remove` प्रोग्राम को हटा देता है लेकिन उसकी सेटिंग्स फ़ाइलें छोड़ देता है।
`apt purge` उन्हें भी हटा देता है। जब apt पूछता है `Do you want to continue? [Y/n]`,
तो बड़े `Y` का मतलब है कि बस Enter दबाने से जवाब हाँ माना जाएगा। `-y` ऑप्शन के
साथ apt अपने-आप हाँ कह देता है।

खोजने के लिए root की ज़रूरत नहीं होती। आज़माइए:

```try
apt search htop
```

### apt या apt-get?

`apt` आधुनिक, इस्तेमाल में आसान रूप है जिसमें प्रगति पट्टी (progress bar) और रंग
हैं। `apt-get` और `apt-cache` पुराने हैं लेकिन उनका आउटपुट ज़्यादा स्थिर रहता है,
इसलिए स्क्रिप्ट में वे अब भी इस्तेमाल होते हैं।

### अंदर की बात: dpkg और .deb

पैकेज `.deb` फ़ाइलें होते हैं, और उन्हें असल में प्रोग्राम `dpkg` खोलता (unpack
करता) है। apt उसके आसपास की हर चीज़ संभालता है: डाउनलोड, निर्भरताएँ और अपडेट।

## अतिरिक्त रिपॉज़िटरी – सुविधाजनक, लेकिन अपने जोखिम पर

डिस्ट्रीब्यूशन की रिपॉज़िटरी में दसियों हज़ार पैकेज होते हैं – लेकिन सब कुछ नहीं।
कोई ख़ास (niche) प्रोग्राम शायद वहाँ बिलकुल न हो, या सिर्फ़ किसी पुराने संस्करण में
हो। इसीलिए **अतिरिक्त रिपॉज़िटरी** होती हैं, जहाँ डेवलपर और यूज़र अपने ख़ुद के पैकेज
साझा करते हैं।

डिस्ट्रीब्यूशन की अपनी रिपॉज़िटरी के पैकेज एक साथ जाँचे जाते हैं, हस्ताक्षरित किए
जाते हैं और डिस्ट्रीब्यूशन के डेवलपर उनकी समीक्षा करते हैं। दूसरी तरफ़, अतिरिक्त
रिपॉज़िटरी कोई भी बना सकता है। कोई रिपॉज़िटरी जोड़ने से पहले यह ध्यान में रखिए:

- **पैकेज root के रूप में इंस्टॉल होते हैं।** एक पैकेज कंप्यूटर के साथ कुछ भी कर
  सकता है। आप उसे बनाने वाले पर उतना ही भरोसा करते हैं जितना डिस्ट्रीब्यूशन पर।
- **यह टकरा सकता है।** अतिरिक्त रिपॉज़िटरी का पैकेज सिस्टम की अपनी लाइब्रेरी को
  बदल सकता है या उसे आपके पास मौजूद संस्करणों के बजाय दूसरे संस्करण चाहिए हो सकते
  हैं।
- **इसके अपडेट बंद हो सकते हैं।** अगर रिपॉज़िटरी चलाने वाले व्यक्ति की दिलचस्पी
  ख़त्म हो जाए, तो आपको प्रोग्राम के लिए आगे कोई सुरक्षा अपडेट नहीं मिलते।

एक अच्छा नियम: पहले डिस्ट्रीब्यूशन की रिपॉज़िटरी में देखिए, फिर Flatpak (यूनिवर्सल
पैकेज वाले अध्याय में) के लिए, और उसके बाद ही किसी भरोसेमंद व्यक्ति की अतिरिक्त
रिपॉज़िटरी में।

## PPA

**PPA** (*Personal Package Archive*) Launchpad पर एक छोटी रिपॉज़िटरी है, जो Ubuntu
के लिए Canonical की सेवा है। डेवलपर सोर्स कोड अपलोड करता है और Launchpad अलग-अलग
Ubuntu रिलीज़ के लिए `.deb` पैकेज बिल्ड करता है। PPA को `ppa:user/name` लिखा जाता
है। डिस्ट्रीब्यूशन PPA की समीक्षा नहीं करता।

इस अध्याय के बाक़ी हिस्से में आप एक काल्पनिक प्रोग्राम, `moonphase` (यह टर्मिनल में
चाँद की कला दिखाता है), एक PPA से इंस्टॉल करेंगे।

### add-apt-repository टूल

PPA `add-apt-repository` से जोड़े जाते हैं, जो पैकेज `software-properties-common`
में है। यह Ubuntu पर पहले से इंस्टॉल होता है, लेकिन Debian पर नहीं:

```sh
sudo apt update
sudo apt install software-properties-common
```

### PPA जोड़ना

```sh
sudo add-apt-repository ppa:lunatool/moonphase
```

आपको दिखता है कि क्या जोड़ा जा रहा है और PPA का विवरण भी। आगे बढ़ने के लिए Enter
दबाइए (`-y` के साथ सवाल छूट जाता है)। दो चीज़ें होती हैं:

1. `/etc/apt/sources.list.d/` में एक फ़ाइल बनती है। उसमें लिखा होता है कि रिपॉज़िटरी
   कहाँ है और उसमें वह कुंजी (key) होती है जिससे पैकेज हस्ताक्षरित किए गए हैं।
2. `add-apt-repository` आपके लिए `apt update` चला देता है – वरना apt को नए
   पैकेजों के बारे में पता ही नहीं चलता। अगर आप कोई स्रोत हाथ से जोड़ते हैं (एक
   फ़ाइल बनाकर), तो उसके बाद आपको ख़ुद `sudo apt update` चलाना होगा।

```quiz
आप `/etc/apt/sources.list.d/` में एक फ़ाइल बनाकर हाथ से एक रिपॉज़िटरी जोड़ते हैं।
apt उससे पैकेज इंस्टॉल कर सके, इससे पहले आपको क्या करना होगा?
- [ ] कुछ नहीं – अगली बार इंस्टॉल करते समय apt फ़ाइल ख़ुद पढ़ लेता है
- [x] `sudo apt update` चलाना
- [ ] कंप्यूटर को रीस्टार्ट करना
---
`add-apt-repository` आपके लिए `apt update` चलाता है। जब आप फ़ाइल ख़ुद बनाते हैं,
तो यह काम भी आपको ख़ुद करना होता है।
```

फ़ाइल देखिए:

```sh
ls /etc/apt/sources.list.d
cat /etc/apt/sources.list.d/lunatool-ubuntu-moonphase-noble.sources
```

`Suites: noble` पर ध्यान दीजिए – पैकेज Ubuntu 24.04 के लिए बिल्ड किए गए हैं।

### इंस्टॉल करना और चलाना

अब पैकेज बिलकुल किसी भी दूसरे पैकेज की तरह इंस्टॉल होता है:

```sh
sudo apt install moonphase
moonphase
```

### पैकेज कहाँ से आता है?

`apt policy` दिखाता है कि कोई पैकेज किन रिपॉज़िटरी में है और कौन-सी जीतती है:

```sh
apt policy moonphase
```

`***` इंस्टॉल किए गए संस्करण को चिह्नित करता है। संख्या `500` रिपॉज़िटरी की
प्राथमिकता है और `100` का मतलब है "जो पहले से इंस्टॉल है"। अगर एक ही पैकेज कई
रिपॉज़िटरी में है, तो apt सबसे ऊँचा संस्करण चुनता है – इसलिए एक PPA डिस्ट्रीब्यूशन
के अपने किसी पैकेज को अपने संस्करण से बदल सकता है।

```quiz
एक ही पैकेज डिस्ट्रीब्यूशन की रिपॉज़िटरी में भी है और आपके जोड़े गए एक PPA में भी।
apt कौन-सा संस्करण चुनता है?
- [ ] हमेशा डिस्ट्रीब्यूशन की रिपॉज़िटरी वाला
- [ ] सबसे आख़िर में जोड़ी गई रिपॉज़िटरी वाला
- [x] सबसे ऊँचा संस्करण
---
इसीलिए एक PPA डिस्ट्रीब्यूशन के अपने किसी पैकेज की जगह ले सकता है।
```

### Debian पर PPA?

PPA Ubuntu के लिए बिल्ड किए जाते हैं, Debian के लिए नहीं। Debian पर वे शायद चल
जाएँ, लेकिन पैकेजों को Debian में मौजूद लाइब्रेरी संस्करणों के बजाय दूसरे संस्करण
चाहिए हो सकते हैं। Debian और Ubuntu पैकेजों के मिश्रण को मज़ाक में *FrankenDebian*
कहते हैं, और यह सिस्टम तोड़ने का एक आम तरीक़ा है। Debian पर *backports*, Flatpak
या डेवलपर की Debian के लिए अपनी रिपॉज़िटरी इस्तेमाल करना बेहतर है।

### अपडेट और PPA हटाना

PPA के पैकेज बाक़ी सब चीज़ों के साथ `sudo apt update && sudo apt upgrade` से अपडेट
होते हैं। PPA हटाने के लिए:

```sh
sudo add-apt-repository --remove ppa:lunatool/moonphase
```

प्रोग्राम बना रहता है, लेकिन उसे आगे अपडेट नहीं मिलते। उससे पूरी तरह छुटकारा पाने
के लिए `sudo apt remove moonphase` भी चलाइए।

आपकी जोड़ी हर रिपॉज़िटरी एक और ऐसा भेजने वाला है जिस पर आप भरोसा करते हैं। सूची
छोटी रखिए और जो अब इस्तेमाल नहीं करते, उसे हटा दीजिए।
