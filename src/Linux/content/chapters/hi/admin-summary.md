# सारांश: सिस्टम प्रशासन

इस भाग में आपने एक प्रशासक के रूप में कंप्यूटर की देखभाल की: बैकग्राउंड में चलने वाली
सेवाएँ, वे डिस्क जिन पर फ़ाइलें पहुँचती हैं और वे यूज़र जो कंप्यूटर साझा करते हैं।
यहाँ जो भी चीज़ कुछ **बदलती** है, उसमें से लगभग सबके लिए root चाहिए – इसलिए `sudo`
बार-बार आया।

## systemd से सेवाएँ और लॉग

**systemd** प्रोसेस नंबर 1 है और बाक़ी सब कुछ शुरू करता है। जिस भी चीज़ का वह हिसाब
रखता है, वह एक **unit** है, जिसका ब्योरा एक unit फ़ाइल देती है – पैकेजों के साथ आने
वाली फ़ाइलें `/usr/lib/systemd/system` में होती हैं, आपकी अपनी `/etc/systemd/system`
में, जिन्हें प्राथमिकता मिलती है। `systemctl` सेवाओं को नियंत्रित करता है, और
**`start` (अभी) और `enable` (बूट पर) दो अलग चीज़ें हैं**। सेवाएँ जो कुछ भी छापती हैं,
वह **journal** में पहुँचता है, जिसे आप `journalctl` से पढ़ते और छानते हैं। जब कोई
सेवा शुरू न हो: `systemctl --failed`, `systemctl status`, फिर `journalctl -xeu` – और
लॉग को शब्द-दर-शब्द पढ़िए। Ubuntu पर SSH सेवा का नाम `ssh` है; दूसरे परिवार कभी-कभी
सेवाओं के नाम अलग रखते हैं।

## डिस्क और फ़ाइल सिस्टम

एक **डिस्क** **पार्टिशन** में बँटी होती है, और हर पार्टिशन को फ़ाइलें रखने से पहले एक
**फ़ाइल सिस्टम** चाहिए। डिस्क `/dev` में फ़ाइलें हैं (`/dev/sda`, `/dev/sda1`, …)।
Linux में ड्राइव अक्षर नहीं होते: हर फ़ाइल सिस्टम `/` से शुरू होने वाले एक ही
डायरेक्टरी पेड़ में कहीं **माउंट** किया जाता है। `lsblk` डिस्क दिखाता है, `df` बताता
है कि फ़ाइल सिस्टम कितने भरे हैं और `du` बताता है कि फ़ाइलें कितनी जगह लेती हैं। USB
स्टिक निकालने से पहले उसे हमेशा **अनमाउंट** कीजिए, क्योंकि बदलाव अभी RAM में इंतज़ार
कर रहे हो सकते हैं। बूट पर क्या माउंट होता है, इसकी सूची `/etc/fstab` में होती है,
अच्छा हो कि **UUID** से, जो कभी नहीं बदलता। `fdisk` और `mkfs` सबसे ख़तरनाक कमांड में
से हैं – दो बार जाँचिए।

## यूज़र और समूह

हर यूज़र का एक **UID** होता है – root का 0 है, सिस्टम यूज़रों को छोटी संख्याएँ मिलती
हैं और लोग 1000 से शुरू होते हैं। यूज़रों की सूची `/etc/passwd` में है, समूहों की
`/etc/group` में और पासवर्ड हैश `/etc/shadow` में, जिसे सिर्फ़ root पढ़ सकता है। हर
यूज़र का एक **प्राथमिक समूह** और कितने भी **अतिरिक्त समूह** होते हैं।
`useradd -m -s /bin/bash` एक यूज़र बनाता है, `passwd` पासवर्ड सेट करता है और
`usermod -aG` किसी समूह में जोड़ता है – **`-a` भूलिए मत**। Ubuntu पर sudo के अधिकार
`sudo` समूह से आते हैं (दूसरे परिवार `wheel` इस्तेमाल करते हैं)। `su -` उस यूज़र के
पासवर्ड से यूज़र बदलता है, `sudo -u` आपके अपने पासवर्ड से किसी और के रूप में एक कमांड
चलाता है।

## कमांड

| कमांड | क्या करता है |
|---|---|
| `systemctl status NAME` | सेवा का क्या हाल है? |
| `sudo systemctl start` / `stop` / `restart` / `reload NAME` | शुरू करना, रोकना, फिर से शुरू करना, कॉन्फ़िगरेशन दोबारा पढ़ना |
| `sudo systemctl enable --now NAME` | बूट पर शुरू करना – और अभी भी |
| `systemctl is-active` / `is-enabled NAME` | एक शब्द, "हाँ" के लिए एग्ज़िट स्टेटस 0 |
| `systemctl --failed` | विफल हुई सेवाएँ |
| `systemctl cat NAME` | unit फ़ाइल दिखाना |
| `sudo systemctl daemon-reload` | बदली गई unit फ़ाइलें फिर से लोड करना |
| `journalctl -u NAME` | एक सेवा का लॉग |
| `journalctl -p err -b` | इस बूट के बाद से त्रुटियाँ और उससे बदतर |
| `journalctl -n 20`, `-f`, `--since today` | सबसे नई पंक्तियाँ, पीछा करना, आधी रात से |
| `lsblk -f` | डिस्क, पार्टिशन और फ़ाइल सिस्टम |
| `blkid`, `findmnt -n -o UUID /` | प्रकार, लेबल और UUID |
| `df -h`, `du -sh DIR` | डिस्क कितनी भरी है, फ़ाइलें कितनी जगह लेती हैं |
| `sudo mount /dev/sdb1 /mnt/usb` | फ़ाइल सिस्टम माउंट करना |
| `sudo umount /mnt/usb` | अनमाउंट करना |
| `cat /etc/fstab`, `sudo mount -a` | बूट पर क्या माउंट होता है – और बदलावों को परखना |
| `swapon --show`, `free -h` | स्वैप और मेमोरी |
| `id`, `groups` | UID, GID और समूह |
| `sudo useradd -m -s /bin/bash NAME` | यूज़र बनाना |
| `sudo passwd NAME` | पासवर्ड सेट करना |
| `sudo groupadd GROUP` | समूह बनाना |
| `sudo usermod -aG GROUP NAME` | किसी समूह में जोड़ना |
| `sudo usermod -L` / `-U NAME` | खाता लॉक / अनलॉक करना |
| `sudo userdel -r NAME` | यूज़र और उसकी होम डायरेक्टरी मिटाना |
| `su - NAME`, `sudo -u NAME COMMAND` | यूज़र बदलना, किसी दूसरे यूज़र के रूप में चलाना |
