# Копирование файлов по SSH

В главе о сети вы выполняли команды на сервере `192.168.1.10` с помощью
`ssh`. Здесь вы дадите серверу короткое имя, будете копировать файлы на него
и с него с помощью `scp` и синхронизировать целые каталоги с помощью `rsync`.

## Короткие имена – `~/.ssh/config`

Каждый раз набирать `ssh {{user}}@192.168.1.10` быстро надоедает. В файле
`~/.ssh/config` можно дать серверу короткое имя:

```text
Host srv
    HostName 192.168.1.10
    User {{user}}
```

`Host` – это короткое имя, `HostName` – настоящий адрес (или имя), а `User` –
имя пользователя на сервере. Если сервер слушает не порт 22, а другой,
добавьте строку вроде `Port 2222`. После этого достаточно написать:

```sh
ssh srv hostname
```

В симуляторе пока нет текстового редактора, поэтому запишите файл с помощью
`echo`. Отступы нужны только для того, чтобы файл было легче читать:

```sh
mkdir -p ~/.ssh
echo 'Host srv' > ~/.ssh/config
echo '    HostName 192.168.1.10' >> ~/.ssh/config
echo '    User {{user}}' >> ~/.ssh/config
chmod 600 ~/.ssh/config
```

ssh строго относится к этому файлу. Если в него могут писать другие, ssh
отказывается работать с сообщением *Bad owner or permissions*, а слово с
опечаткой сразу его останавливает:

```predict
$ mkdir -p ~/.ssh
$ echo 'Hostnam 192.168.1.10' > ~/.ssh/config
$ ssh srv hostname
/home/{{user}}/.ssh/config: line 1: Bad configuration option: hostnam
/home/{{user}}/.ssh/config: terminating, 1 bad configuration options
---
ssh читает весь файл до подключения, поэтому одно неверное слово
останавливает все подключения – а сообщение об ошибке говорит, в какой оно
строке.
```

Эти имена работают и для `scp` и `rsync`.

```quiz
Какая строка в `~/.ssh/config` говорит, куда ssh на самом деле должен подключаться?
- [ ] `Host`
- [x] `HostName`
- [ ] `User`
---
`Host` – короткое имя, которое вы набираете сами, `HostName` – настоящий
адрес, а `User` – пользователь, под которым вы входите.
```

## Копирование – `scp`

`scp` (*secure copy*) работает как `cp`, но одна из сторон может находиться
на другом компьютере. Она записывается как `HOST:PATH`:

```sh
scp {{notes}} srv:
scp srv:{{welcomeFile}} .
scp -r {{documents}} srv:backup
```

- Сначала указывается источник, а цель – последней, как и у `cp`.
- Путь после двоеточия отсчитывается от вашего домашнего каталога на сервере,
  а просто `srv:` означает домашний каталог.
- Для каталогов нужен `-r`.
- Порт задаётся заглавной `-P` (у `ssh` – строчной `-p`).

Для каждого файла `scp` выводит строку с именем, `100%`, размером и
скоростью.

```quiz
Вы набираете `scp report.txt srv` – без двоеточия. Что произойдёт?
- [ ] Файл скопируется в ваш домашний каталог на сервере
- [x] Появится локальная копия с именем `srv`
- [ ] scp спросит, какой компьютер вы имеете в виду
---
Без двоеточия `srv` – просто имя файла, и `scp` копирует локально, как `cp`.
Двоеточие легко забыть!
```

## Синхронизация – `rsync`

Для большого количества файлов или для того, что вы копируете снова и снова
(резервные копии!), лучше подходит `rsync`. Он копирует только то, чего не
хватает или что изменилось:

```sh
rsync -av {{documents}}/ /tmp/{{documents}}
```

```text
sending incremental file list
created directory /tmp/{{documents}}
./
{{fruits}}
{{grades}}
server.log

sent 1,342 bytes  received 102 bytes  2,888.00 bytes/sec
total size is 1,104  speedup is 0.76
```

`-a` (*archive*) копирует каталоги рекурсивно и сохраняет права и время, а
`-v` выводит список копируемого. Выполните ту же команду ещё раз – и список
окажется пустым: ничего не изменилось. rsync сравнивает размер и время
изменения каждого файла; без `-a` копии получают новое время, и всё
отправляется каждый раз заново.

### Косая черта в конце

Косая черта в конце источника очень важна:

| Команда | Результат |
|---|---|
| `rsync -a {{documents}} /tmp/x` | `/tmp/x/{{documents}}/...` – сам каталог |
| `rsync -a {{documents}}/ /tmp/x` | `/tmp/x/...` – только его содержимое |

```predict
$ rsync -a {{documents}} /tmp/x
$ ls /tmp/x
{{documents}}
---
Без косой черты в `/tmp/x` был скопирован сам каталог.
```

### По SSH и `--delete`

Если цель – сервер, rsync работает через ssh:

```sh
rsync -av {{documents}}/ srv:{{documents}}/
```

`--delete` вдобавок удаляет в цели файлы, которых больше нет в источнике, так
что цель становится точной копией. Тогда неверный путь может удалить очень
многое, поэтому сначала сделайте пробный запуск с `-n` (*dry run*). Ничего
не произойдёт: rsync только покажет, что он сделал бы, а последняя строка
закончится на `(DRY RUN)`:

```sh
rsync -avn --delete {{documents}}/ /tmp/{{documents}}
```

```quiz
Что делает `-n` в `rsync -avn --delete a/ b/`?
- [ ] Копирует только новые файлы
- [x] Показывает, что произошло бы, ничего не делая
- [ ] Пропускает файлы, которые были бы удалены
---
`-n` – это пробный запуск. Сначала проверьте список, а потом выполните ту же
команду без `-n`.
```

## scp или rsync?

| | `scp` | `rsync` |
|---|---|---|
| Подходит для | Нескольких файлов, один раз | Резервных копий и повторного копирования |
| Отправляет | Всё, каждый раз | Только изменённое |
| Локально | Работает, но `cp` проще | Да |
| Зеркало с `--delete` | Нет | Да |

`scp` входит в состав клиента ssh. `rsync` должен быть установлен на обоих
компьютерах: в Ubuntu, Debian и Fedora он есть с самого начала, а в Arch нужно
установить пакет `rsync`.

В симуляторе сервер забывает свои файлы, когда вы закрываете приложение.
