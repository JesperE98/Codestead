# Ссылки и информация о файлах

В Linux имя файла и его содержимое – две разные вещи. В этой главе вы
используете это, чтобы делать ярлыки с помощью **ссылок**, научитесь
исследовать файлы командами `stat` и `file` и узнаете, как с помощью `umask`
задать права, которые получают новые файлы.

## Имена и inode

Содержимое файла – вместе с владельцем, правами и временем изменений –
хранится в **inode** (индексном дескрипторе). Каталог – это просто список
имён, и каждое имя указывает на inode. `ls -i` показывает номер inode перед
каждым именем:

```sh
ls -i
```

## Символические ссылки – `ln -s`

**Символическая ссылка** (*симлинк*) – это маленький файл, в котором записан
путь к чему-то другому, то есть ярлык. Сначала указывается цель, а имя ссылки
– последним, как и у `cp`:

```sh
ln -s /var/log ~/log
ls -l ~/log
```

```text
lrwxrwxrwx 1 {{user}} {{user}} 8 Nov  3 10:15 /home/{{user}}/log -> /var/log
```

`l` в начале строки и стрелка `->` показывают, что это ссылка. Её права
всегда `rwxrwxrwx` – они не играют роли, значение имеют права цели.

Почти все команды следуют по ссылке: `ls ~/log/`, `cat`, `cd` и так далее.
`cd` запоминает путь, которым вы пришли, а `pwd -P` показывает, где вы на
самом деле:

```sh
cd ~/log
pwd
pwd -P
```

### Относительные ссылки

Относительный путь в ссылке отсчитывается от каталога, **где лежит сама
ссылка**, – а не от того, где вы находитесь, когда её создаёте:

```sh
cd ~
ln -s {{documents}}/{{fruits}} {{fruits}}
cat {{fruits}}
```

Это работает, потому что ссылка лежит в вашем домашнем каталоге, а
`{{documents}}/{{fruits}}` находится там же. Ссылка `/tmp/f` с тем же
содержимым искала бы `/tmp/{{documents}}/{{fruits}}` – и была бы битой.

`readlink` показывает, что записано в ссылке, а `realpath` – полный путь, в
котором пройдены все ссылки:

```sh
readlink {{fruits}}
realpath {{fruits}}
```

### Битые ссылки

Ссылка может указывать на то, чего не существует:

```predict
$ ln -s nowhere.txt broken
$ cat broken
cat: broken: No such file or directory
---
Ссылка существует, а файла, на который она указывает, нет. `ls -l` выделяет
битую ссылку красным, а `find ~ -type l` находит все ссылки в вашем домашнем
каталоге.
```

`rm` удаляет саму ссылку и никогда не трогает то, на что она указывает.

```quiz
У вас есть ссылка `~/log -> /var/log`, и вы выполняете `rm ~/log`. Что произойдёт?
- [ ] `/var/log` и всё его содержимое будут удалены
- [x] Удалится только ссылка – `/var/log` останется нетронутым
- [ ] `rm` откажется, потому что `~/log` – каталог
---
`rm` работает с самой ссылкой. Чтобы удалить цель, нужно было бы указать
саму цель.
```

### Где встречаются ссылки

Ссылки в системе Linux повсюду. `python3` часто является ссылкой на
конкретную версию, например `python3.12`, а когда вы позже сделаете так,
чтобы служба запускалась при загрузке, с помощью `systemctl enable`, systemd
создаст ссылку на её юнит-файл. Посмотрите на службы, которые запускаются при
загрузке:

```try
ls -l /etc/systemd/system/multi-user.target.wants
```

## Жёсткие ссылки – `ln`

Без `-s` команда `ln` создаёт **жёсткую ссылку**: ещё одно имя для того же
inode.

```sh
ln {{notes}} {{todo}}
ls -li {{notes}} {{todo}}
```

```text
1310722 -rw-r--r-- 2 {{user}} {{user}} 186 Nov  3 10:20 {{notes}}
1310722 -rw-r--r-- 2 {{user}} {{user}} 186 Nov  3 10:20 {{todo}}
```

У обоих имён одинаковый номер inode, а число после прав – **счётчик ссылок**
– теперь равно 2. Это один и тот же файл: изменение через одно имя видно
через другое. Если удалить одно из имён, содержимое продолжает жить, пока у
файла остаётся хотя бы одно имя.

```predict
$ echo hello > a.txt
$ ln a.txt b.txt
$ echo again >> b.txt
$ rm b.txt
$ cat a.txt
hello
again
---
`a.txt` и `b.txt` были одним и тем же файлом. Строка, записанная через
`b.txt`, осталась на месте и после удаления `b.txt`.
```

| | Символическая ссылка (`ln -s`) | Жёсткая ссылка (`ln`) |
|---|---|---|
| Что это | Маленький файл с путём | Ещё одно имя для того же inode |
| На каталог | Да | Нет |
| На другую файловую систему | Да | Нет – inode принадлежат одной файловой системе |
| Если оригинал удалён | Ссылка становится битой | Файл продолжает жить |
| В `ls -l` | `l` и `->` | Растёт счётчик ссылок |

```quiz
Какая ссылка может указывать на каталог?
- [x] Только символическая
- [ ] Только жёсткая
- [ ] Обе
---
Жёсткие ссылки на каталоги запрещены. Для ярлыка на каталог используйте
`ln -s`.
```

## Всё о файле – `stat`

`stat` показывает всё, что знает inode:

```sh
stat /etc/hostname
```

```text
  File: /etc/hostname
  Size: 7         	Blocks: 8          IO Block: 4096   regular file
Device: 8,3	Inode: 1310755     Links: 1
Access: (0644/-rw-r--r--)  Uid: (    0/    root)   Gid: (    0/    root)
Access: 2026-11-03 10:15:22.000000000 +0100
Modify: 2026-11-03 10:15:22.000000000 +0100
Change: 2026-11-03 10:15:22.000000000 +0100
 Birth: 2026-11-03 10:15:22.000000000 +0100
```

Вы видите размер, номер inode, количество ссылок, права – и цифрами (`0644`),
и буквами, – владельца и группу, а также когда файл читали, изменяли его
содержимое и его атрибуты. С `-c` вы сами выбираете, что показать: `%a` –
права цифрами, `%U` – владелец, `%n` – имя.

```predict
$ stat -c '%a %U' /etc/shadow
640 root
```

## Что внутри? – `file`

Linux не обращает внимания на расширения в именах файлов: файл с именем
`.jpg` может содержать что угодно. `file` вместо этого смотрит на содержимое:

```sh
file /usr/bin/ls {{documents}}/{{grades}} /etc
```

```predict
$ echo hello > {{vacationPic}}
$ file {{vacationPic}}
{{vacationPic}}: ASCII text
---
Имя заканчивается на `.jpg`, но внутри текст – а `file` судит именно по
содержимому.
```

## Права для новых файлов – `umask`

Новые файлы получают права `rw-rw-rw-` (666), а новые каталоги – `rwxrwxrwx`
(777), минус биты из **umask**. Команда `umask` показывает её:

```sh
umask
```

Обычная umask `0022` убирает право записи у группы и остальных, поэтому ваши
файлы получают `644`, а каталоги – `755`.

| umask | Новые файлы | Новые каталоги | Что значит |
|---|---|---|---|
| `022` | `644` `rw-r--r--` | `755` `rwxr-xr-x` | Обычное значение |
| `027` | `640` `rw-r-----` | `750` `rwxr-x---` | Группа может читать, остальные – ничего |
| `077` | `600` `rw-------` | `700` `rwx------` | Только вы |

```predict
$ umask 027
$ touch plan.txt
$ stat -c %a plan.txt
640
---
666 минус 027: группа теряет `w`, а остальные теряют всё.
```

`umask` влияет только на файлы, созданные после неё, и только в том shell, где
вы её выполнили. Чтобы umask сохранялась, добавьте эту строку в `~/.bashrc`.

```quiz
Ваша umask – `077`. Какие права получит новый каталог?
- [ ] `755`
- [ ] `600`
- [x] `700`
---
Каталоги начинают с 777. 777 минус 077 оставляет 700: всё для вас, ничего для
остальных.
```
