# Итоги: дистрибутивы и пакеты

## Семейства

Основы во всех дистрибутивах одинаковы: ядро Linux, bash и инструменты GNU,
структура каталогов и (почти везде) systemd. Семейства различаются в
основном тем, как устанавливаются программы.

| | Семейство Debian | Семейство Arch | Семейство Red Hat |
|---|---|---|---|
| Примеры | Debian, Ubuntu, Linux Mint | Arch, Manjaro, EndeavourOS | Fedora, RHEL, Rocky Linux |
| Пакетный менеджер | `apt` | `pacman` | `dnf` |
| Формат пакетов | `.deb` | `.pkg.tar.zst` | `.rpm` |
| Низкоуровневый инструмент | `dpkg` | (pacman) | `rpm` |
| Группа sudo | `sudo` | `wheel` | `wheel` |
| Выпуски | Стабильные версии | Rolling | Новая версия каждые 6 месяцев (Fedora) |

- `cat /etc/os-release` показывает, какой у вас дистрибутив, а `uname -r` –
  версию ядра.
- **Пакет** – это программа, упакованная в файл, **репозиторий** – сервер с
  проверенными и подписанными пакетами дистрибутива, а **зависимость** –
  другой пакет, который необходим для работы, – пакетный менеджер
  устанавливает его автоматически.
- Команды, которые меняют систему, требуют прав root, поэтому их запускают
  через `sudo`.

## Одно и то же – на трёх диалектах

| Что | apt (Debian) | pacman (Arch) | dnf (Red Hat) |
|---|---|---|---|
| Обновить список пакетов | `apt update` | `pacman -Sy` | `dnf check-update` |
| Обновить всё | `apt upgrade` | `pacman -Syu` | `dnf upgrade` |
| Установить | `apt install X` | `pacman -S X` | `dnf install X` |
| Удалить | `apt remove X` | `pacman -R X` | `dnf remove X` |
| Найти | `apt search X` | `pacman -Ss X` | `dnf search X` |
| Информация о пакете | `apt show X` | `pacman -Si X` | `dnf info X` |
| Список установленных | `apt list --installed` | `pacman -Q` | `dnf list --installed` |

Что стоит запомнить:

- **apt**: `apt update` только загружает список пакетов – новые версии
  устанавливает `apt upgrade`. Сначала выполняйте `update`. `[Y/n]` означает,
  что Enter – это ответ «да».
- **pacman**: заглавная буква – это операция (`-S`, `-R`, `-Q`), а строчные –
  модификаторы. Всегда обновляйтесь с `-Syu` – никогда не делайте `-Sy`, а
  затем `-S пакет` (частичное обновление может сломать систему).
- **dnf**: сам загружает информацию о пакетах. `dnf check-update` завершается
  с кодом `100`, если есть обновления. `[y/N]` означает, что Enter – это
  ответ **«нет»**.

Обычно пакеты везде называются одинаково, но не всегда – Vim в Fedora
называется `vim-enhanced`. Если не уверены, ищите.

## Дополнительные репозитории

| | PPA | AUR | COPR |
|---|---|---|---|
| Семейство | Ubuntu (и, например, Linux Mint) | Arch (и, например, Manjaro, EndeavourOS) | Fedora (и семейство RHEL) |
| Что вы скачиваете | Готовые пакеты `.deb` | Рецепт сборки (`PKGBUILD`) – собираете сами | Готовые пакеты `.rpm` |
| Как добавить | `add-apt-repository ppa:…` | `git clone …` и `makepkg -si` | `dnf copr enable …` |
| Как обновляется | `sudo apt update && sudo apt upgrade` | `yay -Syu` – или пересобрать самому | `sudo dnf upgrade` |
| Как удалить репозиторий | `sudo add-apt-repository --remove ppa:…` | – (удалять нечего, репозитория нет) | `sudo dnf copr remove …` |
| Проверено дистрибутивом | Нет | Нет | Нет |

- Пакеты из дополнительного репозитория устанавливаются с правами root, могут
  конфликтовать с собственными пакетами системы и могут перестать
  обновляться. Сначала ищите в репозиториях дистрибутива, затем – Flatpak, и
  только после этого – в дополнительном репозитории от того, кому вы
  доверяете.
- `apt policy` показывает, откуда взялся пакет; apt выбирает самую высокую
  версию.
- Всегда читайте `PKGBUILD` перед сборкой. Не запускайте `makepkg` через sudo.
  `pacman -Qm` выводит *foreign* («чужие») пакеты, и `pacman -Syu` их не
  обновляет – это делает AUR-помощник вроде `yay`.

## Универсальные пакеты

| | Flatpak | Snap | AppImage |
|---|---|---|---|
| Откуда | Flathub (или другие *remotes*) | Snap Store (Canonical) | Сайт разработчика |
| Песочница | Да | Да (кроме *classic*) | Нет |
| Обновления | `flatpak update` | Автоматически в фоне | Сами – скачайте новый файл |
| Установка | `flatpak install flathub ID` | `sudo snap install name` | `chmod +x file` и запуск |

- У программ Flatpak есть ID, записанный как перевёрнутое доменное имя
  (`org.gimp.GIMP`), а запускаются они через `flatpak run`. `--user`
  устанавливает в ваш домашний каталог, со своими remote.
- Snap используется по умолчанию в Ubuntu. Snap-пакетам с ограничением classic
  нужен `--classic`, и у каждого snap есть каналы, например `stable` и `edge`.
- AppImage нужен FUSE 2 (`libfuse2t64` в Ubuntu 24.04 и Debian 13, `fuse2` в
  Arch, `fuse-libs` в Fedora); у него нет ни песочницы, ни автоматических
  обновлений.

**Практическое правило:** пакеты дистрибутива – для системных программ и
программ командной строки, Flatpak – для настольных программ, Snap – в Ubuntu
или когда программа существует только как snap, а AppImage – чтобы быстро
попробовать программу.
