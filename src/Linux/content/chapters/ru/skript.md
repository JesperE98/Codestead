# Скрипты на shell

Всё, что вы до сих пор вводили в терминале, можно также сохранить в файл и
запускать снова и снова. Такой файл называется **скриптом**. Скрипты
позволяют автоматизировать скучную работу: резервные копии, переименование
сотни файлов или ежедневную утреннюю проверку логов. Вдобавок bash – это
настоящий язык программирования с переменными, условиями, циклами и
функциями.

## Первый скрипт

Скрипт – это обычный текстовый файл. На настоящих компьютерах его пишут в
текстовом редакторе, например `nano` или `vim`. Другой способ, который
работает и здесь, и на серверах, – **here document** (встроенный документ):
всё, что находится между `<< '{{heredocEnd}}'` и строкой `{{heredocEnd}}`, подаётся на вход
команде. (Вместо `{{heredocEnd}}` можно выбрать любое слово, часто берут `EOF`.)

Введите первую строку и нажмите Enter. Приглашение сменится на `> ` – shell
ждёт продолжения. Вводите строки по одной и закончите словом `{{heredocEnd}}`:

```sh
cat > {{helloScript}} << '{{heredocEnd}}'
#!/bin/bash
echo "Привет из скрипта!"
echo "Сегодня $(date)"
{{heredocEnd}}
```

Первая строка, `#!/bin/bash`, называется *shebang* и сообщает системе, какая
программа должна выполнять файл. Сделайте скрипт исполняемым и запустите
его:

```sh
chmod +x {{helloScript}}
./{{helloScript}}
```

Строки, начинающиеся с `#` (кроме строки shebang), – это **комментарии**,
которые shell пропускает. Используйте их, чтобы объяснять, что делает код!

## Переменные

Переменная создаётся так: `имя=значение`. Вокруг знака равенства **не**
должно быть пробелов – иначе shell решит, что `имя` – это команда.

```sh
city=Москва
echo "Мой город – $city"
```

Всегда заключайте переменные в **двойные
кавычки**, когда используете их. Без кавычек значение разбивается по
пробелам, что приводит к странным ошибкам, если в имени файла есть пробел.
Если нужно написать текст сразу после имени переменной, используйте фигурные
скобки: `"${city}_2026"` – без них bash искал бы переменную с именем
`city_2026`.

```quiz
В `city` записано `Москва`, а переменной `city_2026` нет. Что выведет
`echo "$city_2026"`?
- [ ] `Москва_2026`
- [ ] `Москва`
- [x] Пустую строку
---
Bash читает всё имя `city_2026`, а такой переменной не существует.
Напишите `"${city}_2026"`, чтобы получить `Москва_2026`.
```

## Подстановка команд – `$(...)`

`$(команда)` заменяется тем, что выводит команда. Так можно сохранить
результат команды в переменной:

```sh
today=$(date)
files=$(ls ~ | wc -l)
echo "Объектов в домашнем каталоге: $files"
```

## Арифметика – `$(( ))`

Bash выполняет целочисленные вычисления внутри `$(( ))`. Внутри скобок перед
переменными не нужен `$`:

```sh
a=7
echo $(( a * 6 ))
echo $(( 17 / 5 )) remainder $(( 17 % 5 ))
```

Чтобы изменить переменную, напишите `(( a++ ))` или `(( a += 10 ))`.

```predict
$ echo $(( 7 / 2 )) $(( 7 % 2 ))
3 1
---
Bash считает только в целых числах: 7 / 2 – это 3, а остаток (`%`) равен 1.
```

## Аргументы

Когда вы запускаете `./script.sh one two`, скрипт может прочитать аргументы:

| Переменная | Содержит |
|---|---|
| `$0` | Имя скрипта |
| `$1`, `$2` ... | Первый, второй ... аргумент |
| `$#` | Число аргументов |
| `"$@"` | Все аргументы, каждый по отдельности |
| `$?` | Код возврата предыдущей команды |

```quiz
Скрипт запущен так: `./script.sh red green blue`. Что содержат `$1` и `$#`?
- [ ] `$1` – это `./script.sh`, а `$#` – `4`
- [x] `$1` – это `red`, а `$#` – `3`
- [ ] `$1` – это `red`, а `$#` – `blue`
---
Имя самого скрипта хранится в `$0`, поэтому в `$#` оно не учитывается.
```

## Условия – `if`

`if` выполняет команду и смотрит на её **код возврата**: 0 означает «истина»,
всё остальное – «ложь». Чаще всего используют команду `[` (она же `test`):

```sh
if [ -f ~/.bashrc ]; then echo "Файл существует"; else echo "Файла нет"; fi
```

Пробелы внутри `[ ]` обязательны! Если записать это в несколько строк, как в
скрипте, получится так:

```text
if [ "$answer" = "да" ]; then
    echo "Отлично!"
elif [ "$answer" = "нет" ]; then
    echo "Жаль."
else
    echo "Ответьте «да» или «нет»."
fi
```

Самые распространённые проверки:

| Проверка | Истинна, если |
|---|---|
| `-f FILE` | файл существует (и это обычный файл) |
| `-d DIR` | каталог существует |
| `-z "$x"` | переменная пуста |
| `"$a" = "$b"` | строки равны (`!=` – различны) |
| `$a -eq $b` | числа равны |
| `$a -lt $b` | меньше (`-le`, `-gt`, `-ge`, `-ne`) |
| `! CONDITION` | условие *не* выполняется |

Обратите внимание: числа сравниваются с помощью `-eq`, `-lt` и т. д., а `=` и
`<` сравнивают текст. В bash есть ещё `[[ ... ]]` – чуть более умный вариант:
в нём можно писать `&&` и `||` и сравнивать с шаблонами вроде
`[[ $file == *.txt ]]`.

Для коротких условий часто хватает `&&` и `||`:

```sh
[ -d ~/{{pictures}} ] && echo "Каталог {{pictures}} существует"
```

```predict
$ x=""
$ if [ -z "$x" ]; then echo empty; else echo "not empty"; fi
empty
```

## Циклы

**Цикл for** выполняет одно и то же для каждого элемента списка:

```sh
for fruit in яблоко банан киви; do echo "Мне нравится $fruit"; done
```

Список может получаться из шаблонов или команды:

```sh
for file in ~/{{documents}}/*; do echo "Файл: $file"; done
for i in $(seq 1 3); do echo "Раунд $i"; done
```

**Цикл while** повторяется, пока условие истинно:

```sh
i=1; while [ $i -le 3 ]; do echo $i; (( i++ )); done
```

Самый распространённый способ пройти по файлу строка за строкой –
`while read`, а файл подаётся через `<` после `done`:

```sh
while read {{lineVar}}; do echo "> ${{lineVar}}"; done < ~/{{documents}}/{{fruits}}
```

`break` выходит из цикла, а `continue` сразу переходит к следующему проходу.

```predict
$ for x in 2 4 6; do echo $(( x * 10 )); done
20
40
60
```

> **Осторожно с бесконечными циклами!** Цикл, условие которого никогда не
> становится ложным, работает вечно. В настоящем терминале его останавливают
> клавишами **Ctrl+C**. Симулятор останавливает его сам после 20 000 шагов.

## Выбор с помощью `case`

Когда переменная может принимать много разных значений, `case` понятнее
длинной цепочки `elif`:

```sh
file={{vacationPic}}
case $file in *.jpg|*.png) echo "Картинка";; *.txt) echo "Текстовый файл";; *) echo "Неизвестный тип";; esac
```

Каждый вариант заканчивается на `;;`, а `*)` ловит всё остальное.

## Функции

**Функция** – это именованный фрагмент кода, который можно вызывать как
отдельную команду. Аргументы она получает так же, как скрипт, – `$1`, `$2` и
`$#`:

```sh
greet() { echo "Привет, $1, добро пожаловать!"; }
greet Kim
```

Переменные, которые должны существовать только внутри функции, создаются с
помощью `local`, а `return` завершает функцию с кодом возврата.

## Вопрос пользователю – `read`

`read` читает строку с клавиатуры в переменную:

```sh
read -p "Как вас зовут? " {{nameVar}}; echo "Привет, ${{nameVar}}!"
```

## Полный пример

Вот скрипт, в котором используется почти всё, о чём шла речь в этой главе.
Он делает резервные копии файлов, переданных ему в аргументах:

```text
#!/bin/bash
# backup.sh – копирует каждый файл в файл.bak

if [ $# -eq 0 ]; then
    echo "Использование: $0 ФАЙЛ..."
    exit 1
fi

for file in "$@"; do
    if [ -f "$file" ]; then
        cp "$file" "$file.bak"
        echo "Скопирован $file"
    else
        echo "Не удаётся найти $file" >&2
    fi
done
```

`exit 1` завершает скрипт с кодом возврата 1, чтобы тот, кто вызвал скрипт,
увидел, что что-то пошло не так.

## Советы для хороших скриптов

- Начинайте с `#!/bin/bash` и пишите комментарии.
- Заключайте переменные в кавычки: `"$file"`, а не `$file`.
- Многие начинают свои скрипты с `set -euo pipefail`, чтобы скрипт
  останавливался при первой же ошибке, а не продолжал работать вслепую.
- Программа **ShellCheck** находит типичные ошибки в скриптах bash – её можно
  установить пакетным менеджером в любом крупном дистрибутиве.
