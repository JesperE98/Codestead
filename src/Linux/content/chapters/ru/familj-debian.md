# Семейство Debian: apt и PPA

Debian, Ubuntu и построенные на них дистрибутивы, например Linux Mint,
образуют **семейство Debian**. Все они используют пакетный менеджер **apt** и
пакеты в формате `.deb`. Эта глава всегда работает на дистрибутиве из
семейства Debian – сейчас это **{{distro}}**. Переключаться между Ubuntu и
Debian можно в меню вверху.

## apt вкратце

| Что | Команда |
|---|---|
| Обновить список пакетов | `apt update` |
| Обновить всё | `apt upgrade` |
| Установить | `apt install X` |
| Удалить | `apt remove X` |
| Найти | `apt search X` |
| Информация о пакете | `apt show X` |
| Список установленных | `apt list --installed` |

Команды, которые меняют систему, требуют прав root, поэтому их запускают через
`sudo`.

```quiz
Какие из этих команд меняют систему и поэтому требуют `sudo`?
- [x] `apt install htop`
- [ ] `apt search htop`
- [x] `apt remove htop`
- [ ] `apt show htop`
---
Поиск и вывод информации только читают списки пакетов. Установка и удаление
меняют систему.
```

## update и upgrade – разные вещи

Поначалу это путает почти всех:

- `apt update` загружает **список** доступных пакетов и версий. Он ничего
  не устанавливает.
- `apt upgrade` **устанавливает** новые версии того, что у вас уже есть.

Поэтому всегда сначала выполняйте `update`. Самый распространённый способ
обновить систему:

```sh
sudo apt update && sudo apt upgrade
```

Пока вы не выполнили `apt update` (например, на только что установленном
сервере), список пакетов пуст, и apt вообще не может найти никаких пакетов.

```quiz
Что делает `sudo apt update`?
- [x] Загружает список доступных пакетов и версий
- [ ] Устанавливает новые версии пакетов, которые у вас уже есть
- [ ] Обновляет сам apt до последней версии
---
`apt update` только обновляет список. Новые версии устанавливает
`apt upgrade`.
```

## Установка и удаление

```sh
sudo apt install htop
```

`apt remove` удаляет программу, но оставляет её файлы настроек.
`apt purge` удаляет и их. Когда apt спрашивает `Do you want to continue? [Y/n]`,
заглавная `Y` означает, что простое нажатие Enter – это ответ «да». С опцией
`-y` apt отвечает «да» автоматически.

Для поиска права root не нужны. Попробуйте:

```try
apt search htop
```

### apt или apt-get?

`apt` – современный, удобный вариант с индикатором прогресса и цветами.
`apt-get` и `apt-cache` старше, но их вывод стабильнее, поэтому их до сих пор
используют в скриптах.

### Под капотом: dpkg и .deb

Пакеты – это файлы `.deb`, а распаковывает их на самом деле программа
`dpkg`. apt берёт на себя всё остальное: загрузку, зависимости и обновления.

## Дополнительные репозитории – удобно, но на ваш страх и риск

В репозиториях дистрибутива десятки тысяч пакетов – но не всё. Какой-нибудь
нишевой программы там может вообще не быть или она есть только в старой
версии. Поэтому существуют **дополнительные репозитории**, где разработчики и
пользователи делятся своими пакетами.

Пакеты в собственных репозиториях дистрибутива протестированы вместе,
подписаны и проверены разработчиками дистрибутива. А вот дополнительный
репозиторий может создать кто угодно. Помните об этом, прежде чем добавлять
его:

- **Пакеты устанавливаются с правами root.** Пакет может сделать с
  компьютером что угодно. Тому, кто его собрал, вы доверяете так же, как
  самому дистрибутиву.
- **Возможны конфликты.** Пакет из дополнительного репозитория может заменить
  собственные библиотеки системы или потребовать других версий, чем те, что
  у вас есть.
- **Обновления могут прекратиться.** Если тот, кто ведёт репозиторий, потеряет
  интерес, вы больше не получите обновлений безопасности для программы.

Хорошее практическое правило: сначала ищите в репозиториях дистрибутива,
затем – Flatpak (в главе об универсальных пакетах), и только после этого – в
дополнительном репозитории от того, кому вы доверяете.

## PPA

**PPA** (*Personal Package Archive*, «личный архив пакетов») – это небольшой
репозиторий на Launchpad, сервисе Canonical для Ubuntu. Разработчик загружает
исходный код, а Launchpad собирает пакеты `.deb` для разных выпусков Ubuntu.
PPA записывается как `ppa:пользователь/имя`. Дистрибутив PPA не проверяет.

В оставшейся части главы вы установите из PPA выдуманную программу
`moonphase` (она показывает фазу Луны в терминале).

### Утилита add-apt-repository

PPA добавляются с помощью `add-apt-repository`, которая находится в пакете
`software-properties-common`. В Ubuntu он установлен заранее, а в Debian –
нет:

```sh
sudo apt update
sudo apt install software-properties-common
```

### Добавляем PPA

```sh
sudo add-apt-repository ppa:lunatool/moonphase
```

Вы увидите, что добавляется, и описание PPA. Нажмите Enter, чтобы продолжить
(с `-y` вопрос пропускается). Происходят две вещи:

1. В `/etc/apt/sources.list.d/` создаётся файл. В нём указано, где находится
   репозиторий, и содержится ключ, которым подписаны пакеты.
2. `add-apt-repository` сам выполняет за вас `apt update` – иначе apt не
   узнал бы о новых пакетах. Если вы добавляете источник вручную (создавая
   файл), потом нужно самостоятельно выполнить `sudo apt update`.

```quiz
Вы добавляете репозиторий вручную, создав файл в `/etc/apt/sources.list.d/`.
Что нужно сделать, прежде чем apt сможет устанавливать из него пакеты?
- [ ] Ничего – apt сам прочитает файл при следующей установке
- [x] Выполнить `sudo apt update`
- [ ] Перезагрузить компьютер
---
`add-apt-repository` выполняет `apt update` за вас. Если вы создаёте файл
сами, это нужно сделать самостоятельно.
```

Посмотрите на файл:

```sh
ls /etc/apt/sources.list.d
cat /etc/apt/sources.list.d/lunatool-ubuntu-moonphase-noble.sources
```

Обратите внимание на `Suites: noble` – пакеты собраны для Ubuntu 24.04.

### Установка и запуск

Теперь пакет устанавливается так же, как любой другой:

```sh
sudo apt install moonphase
moonphase
```

### Откуда взялся пакет?

`apt policy` показывает, в каких репозиториях есть пакет и какой из них
побеждает:

```sh
apt policy moonphase
```

`***` отмечает установленную версию. Число `500` – это приоритет
репозитория, а `100` означает «то, что уже установлено». Если один и тот же
пакет есть в нескольких репозиториях, apt выбирает самую высокую версию –
так что PPA может заменить один из собственных пакетов дистрибутива своей
версией.

```quiz
Один и тот же пакет есть и в репозитории дистрибутива, и в добавленном вами
PPA. Какую версию выберет apt?
- [ ] Всегда ту, что из репозитория дистрибутива
- [ ] Ту, что из репозитория, добавленного последним
- [x] Самую высокую версию
---
Поэтому PPA и может заменить один из собственных пакетов дистрибутива.
```

### PPA в Debian?

PPA собираются для Ubuntu, а не для Debian. В Debian они могут работать, но
пакетам могут понадобиться другие версии библиотек, чем есть в Debian. Смесь
пакетов Debian и Ubuntu в шутку называют *FrankenDebian*, и это
распространённый способ сломать систему. В Debian лучше использовать
*backports*, Flatpak или собственный репозиторий разработчика для Debian.

### Обновления и удаление PPA

Пакеты из PPA обновляются вместе со всем остальным командой
`sudo apt update && sudo apt upgrade`. Чтобы удалить PPA:

```sh
sudo add-apt-repository --remove ppa:lunatool/moonphase
```

Программа останется, но больше не будет получать обновлений. Чтобы полностью
от неё избавиться, выполните также `sudo apt remove moonphase`.

Каждый добавленный репозиторий – это ещё один источник, которому вы
доверяете. Держите их список коротким и убирайте то, чем больше не
пользуетесь.
