# 项目：报告机器人

还记得服务器闹毛病的那一天吗？老板非常喜欢你的报告——喜欢得有点过头了。“太棒了。我希望每天早上桌上都有一份这样的报告。每个工作日。七点之前。”
你可不打算六点起床去敲 `grep` 命令。幸好也不用：你现在会写脚本了。是时候造一个替你干活的机器人了。

机器人读取日志 `~/{{documents}}/server.log`，写一份简短的报告：每个级别各有多少行，以及发生了哪些错误。它需要的一切都在“脚本和自动化”里——挑战在于你自己把它们拼起来。

## 任务

1. **造出机器人。** 创建脚本 `~/{{robotScript}}`，包含一行 shebang 和一行打印标题的命令。让它可执行，然后运行它。
2. **教它索要日志。** 机器人把日志文件作为第一个参数。如果不带参数运行，它应该说明用法，并以不为 0 的退出码结束。
3. **……并在文件不存在时抱怨。** 如果参数里的文件不存在，机器人要说出来，并以不为 0 的退出码结束。用一个不存在的文件名试一试。
4. **统计级别。** 对 `~/{{documents}}/server.log` 运行时，机器人打印日志中每个级别各有多少行，用 `awk` 来统计。注意：`WARN` 和 `warn` 是同一个级别！
5. **列出错误。** 在数字下面，报告列出每个错误的时间和消息——但**不要**日期，反正每一行的日期都一样。用 `sed` 把它去掉。
6. **雇用机器人。** 用 cron 安排它：周一到周五 06:30 对服务器日志运行，输出追加到 `~/{{robotLog}}`。保留你原来的任务。
7. **彩排。** 手动运行一次任务里的命令，让今天的报告写进 `~/{{robotLog}}`，再看一看这个文件。

这段文字旁边列表里的里程碑会在你运行命令时自动检查。

## 小提示

- 一块一块地搭建机器人，每次修改后都运行一下。最简单的办法是每次都用 here document 把整个脚本重新写一遍——它会替换旧版本。
- 先在命令行上试每一行，用日志的路径代替 `"$1"`。在那里能用了，再把它放进脚本。
- 紧接着机器人运行 `echo $?`，可以看到它是以哪个退出码结束的。
- `awk` 的 `toupper()` 能把 `warn` 变成 `WARN`，而 `sort | uniq -c` 会统计相同的行。
- 日志的每一行都以日期和一个空格开头——`sed` 的 `s` 命令可以把这部分替换成空。
- cron 中的任务不在你的终端里运行：使用像 `~/{{robotScript}}` 这样的完整路径，并把输出发送到文件。用 `>>`，每天早上的报告都会追加到末尾，而不会覆盖昨天的。

## 还想多做一点？

完成里程碑之后，机器人还可以学新本领。用 `$(date)` 把日期写进标题。把报告的每一部分写成单独的函数。用 `for file in "$@"` 让机器人一次处理多个日志，或者统计有多少请求得到了 `404` 的回应。如果某个工作日 06:30 应用还开着，`journalctl -u cron` 会显示机器人真的上班去了。
