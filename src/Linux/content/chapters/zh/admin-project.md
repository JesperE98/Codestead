# 项目：周一来了位新同事

周五下午三点半。上司从门口探进头来：
"对了——{{newUser}} 周一加入支持团队。你能把一切都准备好吗？账户、团队文件夹、
第一周的阅读材料。还有，这次一定要让内网能用——上一位新人整个第一个上午都盯着
*Couldn't connect to server* 发呆。"

你需要的一切都在《系统管理》里——用户和组、磁盘、服务——再加上前面几部分的一点
帮助。这里没有新知识；挑战在于自己把这些零件拼起来，让周一早上顺顺利利。

## 任务

1. **一个账户。** 创建用户 `{{newUser}}`，带主目录，以 `/bin/bash` 为 shell，并给
   账户设置密码。
2. **团队。** 创建组 `{{teamGroup}}`，把 `{{newUser}}` 和你自己都加进去。
   `{{newUser}}` 没有 sudo 权限——暂时还没有，那要等试用期结束。
3. **共享文件夹。** 创建 `/srv/{{teamGroup}}`，让它属于组 `{{teamGroup}}`。组可以
   读、写和进入这个文件夹；其他人什么都不能做。
4. **试用账户。** 切换成 `{{newUser}}`，在共享文件夹中创建一个文件，证明权限没问题，
   然后回到你自己的账户。
5. **欢迎礼包。** 第一周的阅读材料 `{{report}}` 在 U 盘（`/dev/sdb1`）上。在
   `{{newUser}}` 的主目录里放一份副本——归 `{{newUser}}` 所有，而不是 root——完成
   后卸载 U 盘。
6. **内网。** 团队的内网是服务 `myserver`。确保它现在正在运行，**并且**每次开机时
   都会自动启动。
7. **彩排。** 重启计算机，并在 journal 中证明内网在这次启动时自动启动了。

这段文字旁边列表里的里程碑会在你运行命令时自动检查。

## 小提示

- 这里几乎所有操作都会修改系统，所以大多数命令都需要 `sudo`。
- `usermod -aG`——别忘了 `-a`，否则用户会被踢出其他所有组。`id {{newUser}}` 显示
  一个账户属于哪些组。
- `ls -ld` 显示目录的所有者、组和权限。用八进制计算权限：*rwx* 是 7，什么都没有
  是 0。
- 用 `sudo` 复制的文件归 root 所有。改为*以*新人的身份复制——用 `su -` 或
  `sudo -u`——文件从一开始就归对的人所有。
- 那里已经有一份归 root 所有的副本？`{{newUser}}` 可以删掉它（它就在自己的主目录
  里），然后重新复制。
- `umount` 提示 *target is busy*？是你自己的 shell 还在那个目录里：先 `cd ~`。
- `start` 和 `enable` 是两回事。`systemctl is-active` 和 `systemctl is-enabled`
  会告诉你当前的状态。
- 重启之后，`journalctl -b` 只显示本次启动的内容。

## 还想多做一点？

完成里程碑后，你可以继续。新人的文件放得下吗？`df -h` 和 `du -sh` 知道答案。用
`usermod -L` 把账户锁到周一早上，用 `passwd -S` 检查，再用 `usermod -U` 解锁。
再从系统的角度看看你的成果：`/etc/passwd` 和 `/etc/group` 中 `{{newUser}}` 的那几
行，以及 `systemctl status myserver`。
