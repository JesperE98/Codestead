# 项目：网站挂了！

周五，16:47。你的电话响了。是上司，上气不接下气："网站挂了！客户看不到我们的
营业时间，同一个客户已经打了三次电话了！"

公司的网站就是 8080 端口上那个小小的 Web 服务器 `myserver`——在*你的*计算机上。
是的，真的。几年前有人"临时"把它放在那里，从此再也没人敢搬动它。

是网络的问题？Web 服务器的问题？还是上司笔记本的问题？由内向外查清楚，把一切都
记进故障日志——并且让下一次轻松一些。你需要的一切都在《网络》里；挑战在于自己
把这些零件拼起来。

## 任务

1. **开始写日志。** 创建文件夹 `~/{{incidentDir}}` 和其中的故障日志
   `{{incidentLog}}`，写入计算机的 IP 地址和网关的地址。
2. **出去的路。** 证明网络一路通到互联网，包括名字解析：在日志中加入一次向互联网
   上某个名字发送三个数据包的 ping。
3. **有人在监听吗？** 查明是否有程序在 8080 端口上监听。如果没有，就启动 Web
   服务器，然后再检查一次。
4. **网站有响应吗？** 把首页 `http://localhost:8080` 的响应头加到日志里。状态码
   应该是 200。
5. **服务器的钥匙。** 下次你想不用密码就登录服务器 `server.lan`。创建一个密钥对，
   并把公钥放到服务器上。
6. **备份。** 把整个文件夹 `~/{{incidentDir}}` 复制到服务器上你的主目录，这样即使
   你自己的计算机罢工，日志也还在。
7. **远程查看。** 用 `ssh` 显示服务器上的那份日志——不能有任何人问你要密码。

这段文字旁边列表里的里程碑会在你运行命令时自动检查。

## 小提示

- `>` 创建（或覆盖）文件，`>>` 追加到文件末尾：用 `>` 开始写日志，之后一直用
  `>>`。
- 由内向外排查：地址、路由、路由器、互联网，最后是名字。不加 `-c` 的话，`ping`
  会一直运行，直到你停止它。
- `ss -tulpn` 显示正在监听的端口。对于其他用户的进程，*Process* 一列是空的——这里
  看端口就够了。
- 在 Ubuntu 上 `curl` 不是预装的：`sudo apt update`，再 `sudo apt install curl`。
  `-I` 只获取响应头。
- `~/.ssh/config` 里的短名字 `srv` 到处都能用——`{{user}}@server.lan` 和
  `{{user}}@192.168.1.10` 也一样。
- `rsync -av 源/ srv:目标/`——源后面的斜杠表示"目录里面的内容"。
- `ssh` 还是要密码？那说明密钥还没放到服务器上。

## 还想多做一点？

完成里程碑后，你可以继续。用 `sudo ip link set enp0s3 down` 关掉网卡，看看由内
向外的排查在哪一步断掉，再用 `up` 打开它。用 `curl` 获取网站的页面
`/about.html`。在日志里加一行，再运行一次同样的 `rsync -av`——只有改动的部分会被
传输。然后给上司回个电话。（据说那台笔记本当时开着飞行模式。）
