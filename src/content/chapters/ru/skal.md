# Другие shell: zsh и fish

До сих пор вы вводили все команды в **bash**. Но bash – лишь один из
нескольких shell, и многие предпочитают что-то другое. В этой главе вы
установите две популярные альтернативы, **zsh** и **fish**, попробуете их и
увидите, чем они отличаются от bash. Вы также узнаете, почему скрипты
по-прежнему почти всегда пишут для bash.

## Что такое shell, ещё раз?

**Shell** – это программа, которая читает то, что вы вводите, интерпретирует
это и запускает другие программы. Именно shell понимает `|`, `>`,
`$ПЕРЕМЕННЫЕ`, шаблоны вроде `*.txt` и циклы. Терминал – всего лишь окно, в
котором работает shell.

Программы вроде `ls`, `grep` и `cat` – это отдельные программы в `/usr/bin`:
они работают одинаково, каким бы shell вы ни пользовались. Различается между
shell **язык вокруг них**: как задаются переменные, как пишутся циклы и
условия, как выглядит приглашение и какие удобства доступны.

## Родословная: sh, bash, zsh и fish

| Shell | С какого года | Особенности |
|---|---|---|
| `sh` | 1979 | Bourne shell. Сегодняшний `sh` следует стандарту **POSIX** и является наименьшим общим знаменателем. |
| `bash` | 1989 | *Bourne Again SHell*. Используется по умолчанию почти во всех дистрибутивах Linux. |
| `zsh` | 1990 | В основном совместим с bash, но умеет больше. Используется по умолчанию в macOS. |
| `fish` | 2005 | *Friendly interactive shell*. Прост в использовании, но со **своим собственным синтаксисом**. |

**POSIX** – это стандарт, описывающий, как должен вести себя shell `sh`.
Скрипт, использующий только возможности POSIX, работает в любом
`sh`-совместимом shell: bash, zsh, `dash` (который является `/bin/sh` в
Debian и Ubuntu) и `ash` (в небольших системах вроде Alpine). fish намеренно
**не** совместим с POSIX – именно это делает его проще, но и непохожим на
остальные.

## Какие shell установлены?

В файле `/etc/shells` перечислены shell, которые можно использовать как
login shell:

```sh
cat /etc/shells
```

Какой shell вы получаете при входе в систему, указано в последнем поле
вашей строки в `/etc/passwd`, а также в переменной `$SHELL`:

```sh
grep elev /etc/passwd
echo $SHELL
```

## zsh – bash с дополнениями

### Установка zsh

Пакет zsh называется одинаково во всех семействах:

:::debian
```sh
sudo apt update
sudo apt install zsh
```
:::

:::arch
```sh
sudo pacman -S zsh
```
:::

:::redhat
```sh
sudo dnf install zsh
```
:::

Посмотрите на `/etc/shells` ещё раз – пакет добавил `/usr/bin/zsh` (и
`/bin/zsh`):

```sh
cat /etc/shells
```

### Запуск zsh

Shell – такая же программа, как любая другая, поэтому zsh запускают, введя
его имя:

```sh
zsh
```

В первый раз вас встретит **zsh-newuser-install**, потому что у вас ещё нет
конфигурационного файла для zsh. Это меню, которое помогает начать:

| Клавиша | Что делает |
|---|---|
| `q` | Выйти, ничего не делая (в следующий раз вас спросят снова) |
| `0` | Создать почти пустой `~/.zshrc` |
| `1` | Главное меню со всеми настройками (в симуляторе недоступно) |
| `2` | Создать `~/.zshrc` с рекомендуемыми настройками |

Ответьте `2`. Приглашение изменится на `elev@{{hostname}} ~ %` – в zsh `%`
является обычным знаком для обычного пользователя (root получает `#`, как и
в bash).

Какой shell у вас сейчас запущен? Переменная `$0` содержит имя shell:

```sh
echo $0
ps
```

`ps` показывает, что zsh работает **внутри** bash: bash запустил zsh как
новый процесс. Обратите также внимание, что `$SHELL` по-прежнему
`/bin/bash` – эта переменная говорит о вашем *login shell*, а не о том, какой
shell запущен у вас прямо сейчас.

```sh
echo $SHELL
```

### Почти всё работает как в bash

zsh понимает почти весь синтаксис bash. Pipe, перенаправления, переменные,
`if`, `for` и функции работают так, как вы привыкли:

```sh
for f in ~/dokument/*.txt; do wc -l $f; done
```

### Возможность 1: `**` ищет во всех подкаталогах

В zsh `**/` означает «все каталоги на всех уровнях». Эта команда выводит все
файлы `.txt` в вашем домашнем каталоге и во всём, что ниже:

```sh
ls ~/**/*.txt
```

В bash `**` работает как обычная `*` – если только вы сначала не включите
это с помощью `shopt -s globstar`.

### Возможность 2: autocd

С опцией `autocd` (она входит в рекомендуемые настройки) достаточно ввести
имя каталога, чтобы перейти в него, – без `cd`:

```sh
dokument
..
```

Опции включают и выключают командами `setopt` и `unsetopt`:

```sh
setopt
unsetopt autocd
setopt autocd
```

### Отличие, за которым нужно следить: переменные не разбиваются

В bash переменная без кавычек разбивается по пробелам. В zsh – нет:

```sh
filer="a.txt b.txt"
for f in $filer; do echo "[$f]"; done
```

bash выводит `[a.txt]` и `[b.txt]`, а zsh – `[a.txt b.txt]`. Поведение zsh
обычно именно то, что нужно, но это значит, что скрипт для bash не всегда
делает в zsh то же самое. (С `setopt shwordsplit` zsh ведёт себя как bash.)

### ~/.zshrc и приглашение

bash при запуске читает `~/.bashrc`, а zsh – `~/.zshrc`. Посмотрите на файл,
который создал zsh-newuser-install:

```sh
cat ~/.zshrc
```

Приглашение задаётся переменной `PROMPT` и использует коды с `%`:

| Код | Означает |
|---|---|
| `%n` | Имя пользователя |
| `%m` | Имя компьютера |
| `%~` | Весь каталог (с `~` для домашнего каталога) |
| `%1~` | Только последняя часть каталога |
| `%#` | `%` для обычных пользователей, `#` для root |
| `%F{green}` … `%f` | Цвет (red, green, blue, yellow …) |

Попробуйте:

```sh
PROMPT='%F{green}%n%f:%~ %# '
```

Изменение действует только до выхода из zsh. Если хотите, чтобы оно было
всегда, добавьте эту строку в `~/.zshrc`.

### Oh My Zsh

Многие пользователи zsh устанавливают **Oh My Zsh** – набор тем и плагинов:
например, информация о Git в приглашении, улучшенное автодополнение по Tab и
подсказки во время ввода. Он устанавливается скриптом с сайта проекта и
настраивается в `~/.zshrc`. В симуляторе его нет, но теперь вы знаете, о чём
говорят, когда его упоминают.

### Назад в bash

zsh – это процесс, работающий внутри bash. Выйдите из него с помощью `exit`,
и вы снова окажетесь в bash, где переменных, алиасов и смены каталога из zsh
уже нет:

```sh
exit
echo $0
```

## fish – дружелюбный интерактивный shell

fish стремится быть удобным сразу, без всякой настройки: цвета,
автодополнение по Tab и **автоподсказки** – fish предлагает окончание
команды серым текстом на основе вашей истории, а принять подсказку можно
клавишей «стрелка вправо». (Симулятор подсказок не показывает, но синтаксис
работает.)

### Установка и запуск fish

:::debian
```sh
sudo apt update
sudo apt install fish
```
:::

:::arch
```sh
sudo pacman -S fish
```
:::

:::redhat
```sh
sudo dnf install fish
```
:::

```sh
fish
```

fish поприветствует вас, а приглашение станет `elev@{{hostname}} ~>`.
Спуститесь на несколько каталогов вниз и посмотрите, как fish сокращает путь
в приглашении:

```sh
mkdir -p ~/dokument/projekt
cd ~/dokument/projekt
cd ~
```

В каталоге `~/dokument/projekt` приглашение показывает `~/d/projekt>` –
каждый каталог, кроме последнего, сокращается до одной буквы.

### У fish свой синтаксис

Именно здесь fish сильнее всего отличается от bash и zsh:

| Что | bash и zsh | fish |
|---|---|---|
| Задать переменную | `frukt=äpple` | `set frukt äpple` |
| Переменная окружения | `export EDITOR=nano` | `set -x EDITOR nano` |
| Удалить переменную | `unset frukt` | `set -e frukt` |
| Подстановка команды | `$(pwd)` | `(pwd)` |
| Код завершения последней команды | `$?` | `$status` |
| Аргументы скрипта | `$@`, `$1` | `$argv`, `$argv[1]` |
| Условие | `if …; then …; fi` | `if …; …; end` |
| Цикл | `for …; do …; done` | `for …; …; end` |
| Функция | `hej() { …; }` | `function hej; …; end` |
| Арифметика | `$((17 * 23))` | `math 17 x 23` |

### Переменные через set

Попробуйте задать переменную так, как это делается в bash (`frukt` по-шведски «фрукт»,
`äpple` – «яблоко»):

```sh
frukt=äpple
```

fish откажется и подскажет, как это записать:

```text
fish: Unsupported use of '='. In fish, please use 'set frukt äpple'.
```

Вот как это делается в fish:

```sh
set frukt äpple
echo $frukt
set -x EDITOR nano
set -e frukt
```

`-x` (*export*) делает переменную переменной окружения, которую видят
запускаемые вами программы, а `-e` (*erase*) удаляет её.

В fish каждая переменная – это **список**. Элементы нумеруются с 1:

```sh
set frukter äpple päron banan
echo $frukter[2]
count $frukter
```

### Подстановка команд и $status

В fish подстановка команды записывается обычными круглыми скобками:

```sh
echo "Я нахожусь в" (pwd)
```

Внутри кавычек скобки – обычный текст, поэтому `(pwd)` стоит снаружи. Код
завершения последней команды называется `$status`:

```sh
false
echo $status
```

### and, or и not

У fish есть собственные команды для объединения условий:

```sh
test -f ~/.bashrc; and echo exists
test -f ~/missing.txt; or echo missing
```

Новые версии fish (3.0 и новее) понимают также `&&` и `||`, а начиная с 3.4
работает и `$(...)`. Но `X=1`, `$?` и `$((...))` по-прежнему не работают –
они выдают ошибки, которые подсказывают, как это делается в fish.

### Блоки заканчиваются на end

В fish каждый блок – `if`, `for`, `while`, `switch` и `function` –
заканчивается словом `end`. Никаких `then`, `do`, `done` или `fi`:

```sh
for i in 1 2 3; echo $i; end
if test -f ~/.bashrc; echo exists; else; echo missing; end
```

Блок можно записать и на нескольких строках. Shell ждёт `end`, прежде чем
выполнить цикл:

```sh
for f in ~/dokument/*.txt
echo (basename $f)
end
```

Функции получают свои аргументы в списке `$argv`:

```sh
function hello; echo "Привет, $argv!"; end
hello Kim
```

### Арифметика с math

В fish нет `$((...))`. Вместо этого есть команда `math`, которая умеет
работать и с дробными числами:

```sh
math 17 x 23
math 10 / 4
```

Для умножения пишите `x` (или `"17 * 23"` в кавычках) – одиночная `*` в fish
является шаблоном, как и в bash.

### Настройки fish

При запуске fish читает `~/.config/fish/config.fish`. Если хотите избавиться
от приветствия, очистите переменную `fish_greeting`. С `-U` переменная
становится **универсальной**: она сохраняется в
`~/.config/fish/fish_variables` и действует во всех fish, даже после
перезапуска.

```sh
cat ~/.config/fish/config.fish
set -U fish_greeting ""
```

Выйдите из fish с помощью `exit`:

```sh
exit
```

## Почему скрипты по-прежнему пишут для bash

Каким shell пользоваться в терминале – дело вкуса. Но **скрипты** почти
всегда пишут для bash (или для POSIX `sh`):

- bash установлен практически в каждой системе Linux, а zsh и fish – нет.
- Синтаксис fish не работает в bash, и наоборот.
- Строка `#!` в начале скрипта определяет, какой shell его выполняет, –
  **независимо** от того, в каком shell вы сейчас находитесь.

Попробуйте написать скрипт для bash и запустить его из fish:

```sh
cat > ~/hej.sh << 'SLUT'
#!/bin/bash
name=Kim
echo "Привет, $name, меня запускает bash"
SLUT
chmod +x ~/hej.sh
fish
~/hej.sh
exit
```

Скрипт работает в fish, хотя `name=Kim` там запрещено, – потому что его
выполняет bash. Вот почему `#!/bin/bash` (или `#!/usr/bin/env bash`) так
важен. Скрипт, который должен работать везде, даже там, где нет bash, пишут
с `#!/bin/sh` и только с синтаксисом POSIX.

## Смена shell по умолчанию с помощью chsh

Вводить `zsh` каждый раз при открытии терминала быстро надоедает. С помощью
`chsh` (*change shell*) вы меняете свой **login shell** – тот, что указан в
`/etc/passwd`:

```sh
chsh -s /usr/bin/zsh
grep elev /etc/passwd
```

- Shell нужно указывать полным путём, и он должен быть перечислен в
  `/etc/shells`.
- `chsh` спрашивает ваш пароль (симулятор это пропускает).
- Изменение вступает в силу при **следующем входе в систему**. В уже
  открытом терминале остаётся старый shell, а `$SHELL` изменится только
  после повторного входа.
- root может менять shell другим: `sudo chsh -s /usr/bin/fish kim`.

:::arch
В Arch `chsh -l` выводит список всех допустимых shell.
:::

:::redhat
В Fedora `chsh -l` выводит список всех допустимых shell.
:::

Чтобы вернуться к bash, сделайте то же самое:

```sh
chsh -s /bin/bash
```

Распространённый совет для fish – оставить bash в качестве login shell, а
fish пусть запускает программа-терминал: тогда всё, что ожидает при входе
POSIX-совместимый shell, продолжит работать.

## Какой shell выбрать?

- **bash** – стандарт везде. То, что вы здесь выучите, работает на любом
  сервере, на который вам когда-либо придётся войти. Пишите скрипты для
  bash.
- **zsh** – для тех, кто хочет больше удобства, но сохранить синтаксис bash.
  Oh My Zsh даёт темы и плагины.
- **fish** – лучший опыт «из коробки», но с другим синтаксисом. Команды,
  скопированные из интернета, работают не всегда.
- **sh/dash** – для скриптов, которые должны работать везде, и для небольших
  систем.

## Итоги

| Команда | Что делает |
|---|---|
| `cat /etc/shells` | Выводит список shell, которые можно использовать |
| `echo $0` / `ps` | Показывает, какой shell запущен прямо сейчас |
| `echo $SHELL` | Показывает ваш login shell |
| `zsh` / `fish` / `exit` | Запускает другой shell / возвращает назад |
| `ls ~/**/*.txt` | Ищет во всех подкаталогах (zsh, fish) |
| `setopt autocd` | Включает опцию zsh |
| `set frukt äpple` | Задаёт переменную в fish |
| `set -x NAME value` | Задаёт переменную окружения в fish |
| `chsh -s /usr/bin/zsh` | Меняет ваш login shell |

Конфигурационные файлы: `~/.bashrc` (bash), `~/.zshrc` (zsh) и
`~/.config/fish/config.fish` (fish).
