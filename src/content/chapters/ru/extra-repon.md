# AUR, PPA и COPR

В репозиториях дистрибутива десятки тысяч пакетов – но не всё. Какой-нибудь
нишевой программы там может вообще не быть или она есть только в старой
версии. Поэтому существуют **дополнительные репозитории**, где разработчики и
пользователи делятся своими пакетами. У каждого семейства – свой: **PPA** в
Ubuntu, **AUR** в Arch и **COPR** в Fedora.

В этой главе вы установите одну и ту же выдуманную программу `moonphase` (она
показывает фазу Луны в терминале) из дополнительного репозитория в
{{distro}}. Переключите дистрибутив в меню, если хотите сравнить, как это
устроено в других семействах.

## Удобно – но на ваш страх и риск

Пакеты в собственных репозиториях дистрибутива протестированы вместе,
подписаны и проверены разработчиками дистрибутива. А вот дополнительный
репозиторий может создать кто угодно. Помните об этом, прежде чем добавлять
его:

- **Пакеты устанавливаются с правами root.** Пакет может сделать с
  компьютером что угодно. Тому, кто его собрал, вы доверяете так же, как
  самому дистрибутиву.
- **Возможны конфликты.** Пакет из дополнительного репозитория может заменить
  собственные библиотеки системы или потребовать других версий, чем те, что
  у вас есть.
- **Обновления могут прекратиться.** Если тот, кто ведёт репозиторий, потеряет
  интерес, вы больше не получите обновлений безопасности для программы.

Хорошее практическое правило: сначала ищите в репозиториях дистрибутива,
затем – Flatpak (следующая глава), и только после этого – в дополнительном
репозитории от того, кому вы доверяете.

## Три семейства – три решения

| | PPA | AUR | COPR |
|---|---|---|---|
| Семейство | Ubuntu (и, например, Linux Mint) | Arch (и, например, Manjaro, EndeavourOS) | Fedora (и семейство RHEL) |
| Сайт | launchpad.net | aur.archlinux.org | copr.fedorainfracloud.org |
| Что вы скачиваете | Готовые пакеты `.deb` | Рецепт сборки (`PKGBUILD`) – собираете сами | Готовые пакеты `.rpm` |
| Как добавить | `add-apt-repository ppa:…` | `git clone …` и `makepkg -si` | `dnf copr enable …` |
| Проверено дистрибутивом | Нет | Нет | Нет |

## PPA в {{distro}}

**PPA** (*Personal Package Archive*, «личный архив пакетов») – это небольшой
репозиторий на Launchpad, сервисе Canonical для Ubuntu. Разработчик загружает
исходный код, а Launchpad собирает пакеты `.deb` для разных выпусков Ubuntu.
PPA записывается как `ppa:пользователь/имя`.

### Утилита add-apt-repository

PPA добавляются с помощью `add-apt-repository`, которая находится в пакете
`software-properties-common`. В Ubuntu он установлен заранее, а в Debian –
нет:

```sh
sudo apt update
sudo apt install software-properties-common
```

### Добавляем PPA

```sh
sudo add-apt-repository ppa:lunatool/moonphase
```

Вы увидите, что добавляется, и описание PPA. Нажмите Enter, чтобы продолжить
(с `-y` вопрос пропускается). Происходят две вещи:

1. В `/etc/apt/sources.list.d/` создаётся файл. В нём указано, где находится
   репозиторий, и содержится ключ, которым подписаны пакеты.
2. `add-apt-repository` сам выполняет за вас `apt update` – иначе apt не
   узнал бы о новых пакетах. Если вы добавляете источник вручную (создавая
   файл), потом нужно самостоятельно выполнить `sudo apt update`.

Посмотрите на файл:

```sh
ls /etc/apt/sources.list.d
cat /etc/apt/sources.list.d/lunatool-ubuntu-moonphase-noble.sources
```

Обратите внимание на `Suites: noble` – пакеты собраны для Ubuntu 24.04.

### Установка и запуск

Теперь пакет устанавливается так же, как любой другой:

```sh
sudo apt install moonphase
moonphase
```

### Откуда взялся пакет?

`apt policy` показывает, в каких репозиториях есть пакет и какой из них
побеждает:

```sh
apt policy moonphase
```

`***` отмечает установленную версию. Число `500` – это приоритет
репозитория, а `100` означает «то, что уже установлено». Если один и тот же
пакет есть в нескольких репозиториях, apt выбирает самую высокую версию –
так что PPA может заменить один из собственных пакетов дистрибутива своей
версией.

### PPA в Debian?

PPA собираются для Ubuntu, а не для Debian. В Debian они могут работать, но
пакетам могут понадобиться другие версии библиотек, чем есть в Debian. Смесь
пакетов Debian и Ubuntu в шутку называют *FrankenDebian*, и это
распространённый способ сломать систему. В Debian лучше использовать
*backports*, Flatpak или собственный репозиторий разработчика для Debian.

### Удаление PPA

```sh
sudo add-apt-repository --remove ppa:lunatool/moonphase
```

Программа останется, но больше не будет получать обновлений. Чтобы полностью
от неё избавиться, выполните также `sudo apt remove moonphase`.

## AUR в {{distro}}

**AUR** (*Arch User Repository*, «пользовательский репозиторий Arch») устроен
иначе, чем остальные: в нём нет готовых пакетов, только **рецепты сборки**.
Рецепт называется `PKGBUILD` – это небольшой скрипт на bash, в котором
указано, где лежит исходный код и как собирается программа. Вы скачиваете
рецепт, сами собираете пакет и устанавливаете его через pacman. AUR огромен –
там есть почти всё, что существует для Linux, – но загрузить рецепт может
кто угодно.

### Подготовка

Чтобы скачивать рецепты и собирать пакеты, нужны `git` и `base-devel`
(компилятор, `make`, `fakeroot` и многое другое):

```sh
sudo pacman -S --needed git base-devel
```

`--needed` пропускает то, что уже установлено.

### Получаем рецепт

Каждый пакет AUR – это отдельный git-репозиторий:

```sh
cd ~
git clone https://aur.archlinux.org/moonphase.git
cd moonphase
ls
```

> Если вы ошибётесь в имени пакета, git скажет *"You appear to have cloned an
> empty repository"*, и каталог будет пустым. AUR позволяет клонировать что
> угодно!

### Читайте PKGBUILD – каждый раз

```sh
less PKGBUILD
```

`PKGBUILD` – это скрипт, который выполняется на вашем компьютере. Проверьте
как минимум:

- что `source=` скачивает с настоящего сайта программы,
- что `build()` и `package()` только собирают и копируют файлы – и не делают,
  например, загрузку и запуск чего-то ещё (`curl … | sh`),
- что пакет выглядит поддерживаемым (даты, комментарии на aur.archlinux.org).

### Сборка и установка

```sh
makepkg -si
```

`makepkg` читает `PKGBUILD`, скачивает исходный код, собирает его и
упаковывает в файл `.pkg.tar.zst`. `-s` устанавливает недостающие
зависимости, а `-i` по окончании устанавливает пакет через pacman. **Не**
запускайте makepkg через sudo – он откажется работать от root и сам
воспользуется sudo, когда это нужно.

```sh
ls
moonphase
```

### «Чужие» пакеты

pacman ничего не знает об AUR. Пакеты, которые пришли не из репозиториев,
называются *foreign* («чужие»), и их список выводится так:

```sh
pacman -Qm
```

Это также значит, что `sudo pacman -Syu` **не** обновляет пакеты из AUR.
Новый рецепт нужно получить самому (`git pull`) и пересобрать пакет – или
поручить это AUR-помощнику.

### AUR-помощник yay

AUR-помощник делает всё это за вас: ищет, скачивает, показывает `PKGBUILD`,
собирает и устанавливает. Самый распространённый – **yay** (другой –
*paru*). Сам yay есть только в AUR, поэтому один раз его устанавливают
вручную. Пакет `yay-bin` уже скомпилирован, и с ним быстрее всего:

```sh
cd ~
git clone https://aur.archlinux.org/yay-bin.git
cd yay-bin
makepkg -si
```

После этого yay используется почти как pacman – но без sudo:

```sh
yay -Ss snowfall
yay -S snowfall
snowfall
yay -Syu
```

`yay -Syu` (или просто `yay`) обновляет и пакеты из репозиториев, и ваши
пакеты из AUR. Но удобство не означает, что можно перестать читать рецепты!

## COPR в {{distro}}

**COPR** (*Cool Other Package Repo*) – это сервис сборки Fedora. Любой, у
кого есть аккаунт Fedora, может собирать там пакеты `.rpm`, и каждый проект
становится отдельным репозиторием с именем `пользователь/проект`.

### Репозитории, которые у вас есть сейчас

```sh
dnf repolist
```

### Включаем репозиторий COPR

```sh
sudo dnf copr enable lunatool/moonphase
```

dnf напомнит, что репозиторий не входит в Fedora и что качество может быть
разным. По умолчанию на вопрос отвечается **нет**, поэтому ответьте `y`. В
`/etc/yum.repos.d/` создаётся новый файл:

```sh
ls /etc/yum.repos.d
dnf copr list
dnf repolist
```

### Установка и запуск

dnf сам загружает информацию о новом репозитории, так что пакет можно
установить сразу:

```sh
sudo dnf install moonphase
moonphase
```

### Откуда взялся пакет?

```sh
dnf info moonphase
```

Строка `From repository` показывает, что пакет пришёл из COPR. Пакеты из COPR
обновляются как обычно – командой `sudo dnf upgrade`.

### Отключение или удаление

```sh
sudo dnf copr disable lunatool/moonphase
dnf copr list
```

`disable` оставляет файл на месте, но выключает репозиторий, а `remove`
удаляет его полностью. Программа останется, но больше не будет получать
обновлений.

### RPM Fusion

Ещё один распространённый дополнительный репозиторий для Fedora – **RPM
Fusion**. В нём есть то, что Fedora не может или не хочет включать, например
некоторые медиакодеки и драйверы. Это большой совместный проект, а не
репозиторий одного пользователя, как в COPR.
:::

## Обновления и обслуживание

| | Как обновляется | Как удалить репозиторий |
|---|---|---|
| PPA | `sudo apt update && sudo apt upgrade` | `sudo add-apt-repository --remove ppa:…` |
| AUR | `yay -Syu` – или пересобрать самому | – (удалять нечего, репозитория нет) |
| COPR | `sudo dnf upgrade` | `sudo dnf copr remove …` |

Дополнительные репозитории – мощный инструмент, но каждый добавленный
репозиторий – это ещё один источник, которому вы доверяете. Держите их список
коротким и убирайте то, чем больше не пользуетесь.
