# 重定向和管道

本章讲的是让命令行如此强大的东西：把一个个小程序*连接*起来。

## 三个流

每个程序都有三个标准流：

| 编号 | 名称 | 作用 |
|---|---|---|
| 0 | stdin | 输入，通常来自键盘 |
| 1 | stdout | 正常输出，通常输出到屏幕 |
| 2 | stderr | 错误信息，同样输出到屏幕 |

借助*重定向*和*管道*（pipe），你可以把这些流发送到别的地方。

## 写入文件——`>` 和 `>>`

`>` 把 stdout 发送到文件而不是屏幕。如果文件不存在，就会创建它——如果文件已经存在，就会被**覆盖**！

```sh
echo "first line" > test.txt
```

而 `>>` 则是追加到文件末尾：

```sh
echo "second line" >> test.txt
cat test.txt
```

## 从文件读取——`<`

`<` 让程序从文件中读取它的 stdin：

```sh
wc -l < dokument/frukter.txt
```

## 错误信息——`2>`

错误信息会发送到 stderr，不受 `>` 影响。要处理它们，需要在前面写上流的编号：

```sh
ls /finnsinte 2> fel.txt
```

（*Finns inte* 是瑞典语的“不存在”，*fel* 的意思是“错误”。）

文件 `/dev/null` 是一个“黑洞”——写进去的任何东西都会消失。用它来屏蔽错误信息非常方便。使用 `2>&1`，stderr 就会被发送到和 stdout 相同的地方。

## 管道——`|`

**管道**（pipe）把一个命令的 stdout 直接送进下一个命令的 stdin。这正是 Unix 哲学的核心：*只做一件事，并把它做好；让程序彼此协作*。

```sh
grep INFO dokument/server.log | wc -l
```

`grep` 找出这些行，`wc -l` 统计它们的数量。你想串联多少个命令都可以：

```sh
sort dokument/frukter.txt | uniq -c | sort -rn
```

一步一步地读：先对水果排序，再统计每种水果有多少个（`uniq -c`），最后按数字排序，最大的排在最前面（`sort -rn`）。

## 同时输出到屏幕和文件——`tee`

`tee` 会把输入继续往下传，*同时*在文件中保存一份副本：

```sh
ls /etc | tee etc-lista.txt | wc -l
```

## 命令链——`;`、`&&` 和 `||`

多个命令可以写在同一行：

| 语法 | 含义 |
|---|---|
| `a ; b` | 先运行 a，再运行 b |
| `a && b` | 只有 a 成功时才运行 b |
| `a \|\| b` | 只有 a 失败时才运行 b |

```sh
mkdir -p ny && cd ny
```
