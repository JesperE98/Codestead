# ユーザーとグループ

Linux は最初から、大勢の人が同じコンピューターを同時に共有できるように
作られています。どのファイルにも所有者がいて、どのプログラムも特定のユーザーと
して動きます。だからこそ、アカウントの作成、変更、削除は、管理者の最も重要な
仕事の 1 つなのです。この章では、ユーザー `kim` を作成し、そのアカウントに
パスワードと sudo 権限を与え、それらがすべてどこに保存されているかを学びます。

## ユーザーと UID

自分が誰なのかを調べる方法は、もう知っていますね。

```sh
whoami
id
```

`id` を見ると、あなたには名前だけでなく番号もあることがわかります:
`uid=1000`。これが **UID**（*user ID*）で、カーネルが管理しているのは名前では
なくこの番号です。名前は、私たち人間が番号を覚えなくて済むようにあるだけです。
重要な番号をいくつか挙げます。

| UID | 誰か |
|---|---|
| `0` | **root**、つまり管理者。UID 0 を持つ者は何でもできる。 |
| `1`～`999` | サービスやプログラムのための **システムユーザー** |
| `1000` 以上 | **一般ユーザー** – 人間。最初のユーザーが 1000 になる。 |

## ユーザーの一覧 – `/etc/passwd`

すべてのユーザーは、テキストファイル `/etc/passwd` に 1 ユーザー 1 行で
書かれています。

```sh
cat /etc/passwd
```

各行には、コロンで区切られた 7 つのフィールドがあります。自分の行を
見てみましょう。

```sh
grep elev /etc/passwd
```

```text
elev:x:1000:1000:Elev,,,:/home/elev:/bin/bash
 1   2  3    4      5        6          7
```

| フィールド | 意味 |
|---|---|
| 1 | ユーザー名 |
| 2 | `x` – パスワードは `/etc/shadow` にある（後述） |
| 3 | UID |
| 4 | GID – ユーザーの **プライマリグループ** の番号 |
| 5 | コメント。ふつうはフルネーム |
| 6 | ホームディレクトリ |
| 7 | ユーザーがログインしたときに起動するシェル |

`getent` コマンドも同じ検索をします。違いは、ファイルに書かれていないユーザーも
見つけられることです。たとえば学校や会社で、アカウントが中央のサーバーで
管理されている場合です。

```sh
getent passwd elev
```

### システムユーザー

`/etc/passwd` の行のほとんどは人間ではありません。Web サーバーやログの仕組み
などのサービスは、できるだけ少ない権限を持つ専用のユーザーとして動きます。
もし乗っ取られても、攻撃者はあなたのファイルに手が届きません。システム
ユーザーのシェルは `nologin` なので、誰もそのユーザーとしてログインできません。

:::debian
Debian と Ubuntu では、Web サーバーのユーザーは `www-data` という名前です。

```sh
grep www-data /etc/passwd
```
:::

:::arch
Arch では、Web サーバーのユーザーは `http` という名前です。

```sh
grep http /etc/passwd
```
:::

:::redhat
Fedora には、たとえばシステムのメッセージバスを動かす `dbus` があります。

```sh
grep dbus /etc/passwd
```
:::

テキスト処理の章で学んだ `awk` を使えば、UID が 1000 以上のユーザー、
つまり一般ユーザーを全員一覧表示できます。

```sh
awk -F: '$3 >= 1000 {print $1}' /etc/passwd
```

`nobody`（UID 65534）も表示されます。これは「何も」所有していない特別な
ユーザーで、プログラムの権限をできるだけ少なくしたいときに使われます。

## グループと GID

**グループ** は、複数のユーザーに同じ権限を与えるための仕組みです。
たとえば共有のプロジェクトディレクトリへの権限です。グループは
`/etc/group` に書かれています。

```sh
cat /etc/group
```

```text
sudo:x:27:elev
 1   2  3   4
```

フィールドは、グループ名、`x`、グループの番号（**GID**）、そしてカンマ区切りの
メンバーの一覧です。

どのユーザーにも **プライマリグループが 1 つ**（`/etc/passwd` の GID
フィールド）あり、さらにいくつでも **補助グループ** のメンバーになれます。
あなたが作った新しいファイルには、あなたのプライマリグループが付きます。
ほとんどのディストリビューションでは、どのユーザーにも同じ名前の個人用
プライマリグループが作られます。`elev` はグループ `elev` に属しています。

```sh
groups
id
```

## パスワード – `/etc/shadow`

`/etc/passwd` のフィールド 2 にある `x` に注目してください。昔は、ここに
（暗号化された）パスワードがそのまま書かれていました。問題は、`/etc/passwd` は
誰でも読める **必要がある** ことです。`ls -l` が所有者の名前を取ってくるのは
このファイルからなのです。そのため、誰でも暗号化されたパスワードをコピーして、
時間をかけて解読を試みることができてしまいました。だからパスワードは、
root しか読めない `/etc/shadow` に移されたのです。

```sh
ls -l /etc/passwd /etc/shadow
sudo cat /etc/shadow
```

```text
kim:$y$j9T$Tm9...$Kx2...:20756:0:99999:7:::
```

フィールド 2 はパスワードそのものではなく **ハッシュ** です。元に戻すことの
できない「指紋」のようなものです。ログインするとき、入力したもののハッシュが
計算され、保存されているハッシュと比べられます。`$y$` は *yescrypt* 方式が
使われていることを意味します。代わりに `!` や `*` が書かれていれば、
パスワードがないか、アカウントが **ロック** されていることを意味します。
残りのフィールドは、パスワードを最後に変更した日や、有効期限に関するものです。
`chage` を使うと、それらをわかりやすく表示できます。

```sh
chage -l elev
```

## ユーザーを作成する – `useradd`

ユーザーを作成するには root 権限が必要です。最もよく使われるコマンドは、
どのディストリビューションにもあります。

```sh
sudo useradd -m -s /bin/bash kim
```

| オプション | 意味 |
|---|---|
| `-m` | ホームディレクトリ `/home/kim` を作成する |
| `-s /bin/bash` | ユーザーのシェル |
| `-c "Kim Svensson"` | コメント（フルネーム） |
| `-G group1,group2` | 最初から補助グループに入れる |

`useradd` は 1000 から順に、次の空いている UID を探します。`kim` は 1001 に
なります。範囲は `/etc/login.defs` に書かれています。グループ `kim` も作成され、
`/etc/skel`（*skeleton*、骨組み）にあるファイルが新しいホームディレクトリに
コピーされます。ここに何かを置いておけば、新しいユーザー全員がそれを受け取ります。

```sh
ls -a /etc/skel
```

ここでディストリビューションの違いが出てきます。

:::debian
Debian と Ubuntu の `useradd` はけちです。`-m` がないとホームディレクトリは
**作られず**、`-s` がないとシェルは `/bin/sh` になります。そのため、Debian
ファミリーには、もっと親切なスクリプト `adduser` があります。ホームディレクトリを
作り、bash を選び、パスワードと名前を尋ねてくれます。

```sh
sudo adduser lisa
```

質問に答えてください。ほとんどは Enter を押すだけでかまいません。`adduser` は
既存のユーザーをグループに追加することもできます: `sudo adduser lisa sudo`。
:::

:::arch
Arch では、`-m` がないとホームディレクトリは作られません。また、`adduser`
コマンドはそもそも存在しません。試してみましょう。

```sh
adduser lisa
```

Arch Wiki では、すべてを一度に行うことを勧めています:
`useradd -m -G wheel -s /bin/bash name`。
:::

:::redhat
Fedora では、`-m` がなくてもホームディレクトリが作られ（`/etc/login.defs` の
`CREATE_HOME` 設定）、シェルは bash になります。とはいえ `-m` を付けても害は
ないので、付ける習慣をつけましょう。そうすれば、同じコマンドがどこでも使えます。
:::

`useradd`、`passwd`、そしてこの章のほかのコマンドは、いつもインストール
されています。パッケージ名は Debian では `passwd`、Arch では `shadow`、
Fedora では `shadow-utils` です。同じものの名前が違う、また 1 つの例ですね。

## パスワードを設定する – `passwd`

新しいアカウントにはパスワードがない（`/etc/shadow` に `!`）ので、誰も
ログインできません。`passwd` でパスワードを設定しましょう。

```sh
sudo passwd kim
```

パスワードは 2 回入力します。**入力した文字は表示されません**。星印も何も
出ません。これはわざとです。肩越しにのぞいている人に、パスワードの長さすら
わからないようにするためです。入力して Enter を押してください。

名前を付けずに `passwd` を実行すると、自分のパスワードを変更します。ほかの
ユーザーのパスワードを変更できるのは root だけです。sudo なしで試してみましょう。

```sh
passwd root
```

## グループ – `groupadd`、`usermod -aG`、`gpasswd`

グループを作成して、メンバーを追加します。

```sh
sudo groupadd utvecklare
sudo usermod -aG utvecklare kim
groups kim
```

`-aG` は *append to Groups*（グループに追加）という意味です。**`-a` を
忘れないでください！** `-G` だけだと、補助グループの一覧が入力したものそのものに
置き換えられ、ユーザーはほかのすべてのグループ、たとえば sudo のグループからも
外されてしまいます。自分を締め出してしまう、よくあるパターンです。

`gpasswd` も同じことができ、メンバーを外すこともできます。

```sh
sudo gpasswd -a kim utvecklare
sudo gpasswd -d kim utvecklare
```

本物のコンピューターでは、新しいグループのメンバーシップが有効になるのは、
ユーザーが次にログインしたときです。シミュレーターはもっと親切で、
すぐに反映されます。

グループは共有ディレクトリに使われます。`chgrp` と `chmod` で、グループを
所有者にして書き込み権限を与えましょう。

```sh
sudo mkdir /srv/projekt
sudo chgrp utvecklare /srv/projekt
sudo chmod 775 /srv/projekt
ls -ld /srv/projekt
```

## sudo 権限を与える – `sudo` または `wheel`

誰が `sudo` を使えるかは、`/etc/sudoers` で決められています。

```sh
sudo cat /etc/sudoers
```

`%{{adminGroup}} ALL=(ALL:ALL) ALL` という行は、グループ **{{adminGroup}}** の
全員が、どんなコマンドでも root として実行できることを意味します。つまり、
誰かに sudo 権限を与えるには、正しいグループに追加するだけでよいのです。
そして、そのグループの名前はファミリーごとに違います。

:::debian
Debian と Ubuntu では、グループの名前は `sudo` です。

```sh
sudo usermod -aG sudo kim
```
:::

:::arch
Arch では、グループの名前は `wheel` です。「偉い人たち」（*big wheel*）を
意味する、Unix の古い呼び名です。

```sh
sudo usermod -aG wheel kim
```
:::

:::redhat
Fedora では、グループの名前は `wheel` です。「偉い人たち」（*big wheel*）を
意味する、Unix の古い呼び名です。

```sh
sudo usermod -aG wheel kim
```
:::

`/etc/sudoers` を、ふつうのエディターで直接編集してはいけません。タイプミス
1 つで、誰も sudo を使えなくなることがあります。保存する前にファイルを
チェックしてくれる `visudo` を使いましょう。たいていは、グループだけで
十分です。

## ユーザーを切り替える – `su` と `sudo -u`

別の人になる方法は 2 つあります。

| コマンド | 誰のパスワード？ | 何が起きるか |
|---|---|---|
| `su - kim` | **kim の** | `exit` と入力するまで、kim としてログインしている |
| `sudo -u kim command` | **自分の**（sudo 権限が必要） | 1 つのコマンドを kim として実行する |
| `sudo -iu kim` | 自分の | kim としてのログインシェル |

```sh
sudo -u kim whoami
```

`su` では本当に切り替わります。ダッシュ（`-`）を付けるとログインになり、
kim のホームディレクトリで kim の設定のまま作業することになります。
プロンプトには自分が誰なのかが表示され、`exit` で元に戻れます。

```sh
su - kim
```

名前を付けない `su` は root を意味します。Ubuntu では root にパスワードが
ないので、`su -` は使えません。代わりに `sudo -i` を使ってください。

## アカウントのロックと削除

しばらく使わないアカウントは **ロック** できます。`usermod -L` は
`/etc/shadow` のハッシュの前に `!` を付けるので、どんなパスワードも
一致しなくなります。`-U` でロックを解除します。

```sh
sudo usermod -L kim
sudo passwd -S kim
sudo usermod -U kim
```

`passwd -S` は状態を表示します: `P`（パスワードあり）、`L`（ロック中）、
`NP`（パスワードなし）。`chage -E` を使うと、アカウントを特定の日に失効
させられます。夏のアルバイトや代理の人に便利です。

誰かを削除する前に、誰がログインしているか、最後にいつログインしたかを
確認しておくとよいでしょう。

```sh
who
last
```

そのあと `userdel` でユーザーを削除します。`-r` を付けるとホームディレクトリも
削除されます。`-r` がないと、ファイルは残ったままになります。

```sh
sudo useradd -m vikarie
sudo userdel -r vikarie
```

:::debian
Debian ファミリーには、`adduser` の対になる `deluser` もあります:
`sudo deluser --remove-home vikarie`。`sudo deluser kim sudo` は、kim を
グループ sudo から外します。
:::

`userdel` は、ログイン中のユーザーを削除するのを拒否します。
`sudo userdel elev` を試してみましょう。

## まとめ

| コマンド | 機能 |
|---|---|
| `id`, `groups` | UID、GID、グループを表示する |
| `useradd -m -s /bin/bash name` | ユーザーを作成する |
| `passwd name` | パスワードを設定する |
| `usermod -aG group name` | グループに追加する |
| `groupadd group` | グループを作成する |
| `usermod -L` / `-U` | ロックする / ロックを解除する |
| `userdel -r name` | ユーザーとホームディレクトリを削除する |
| `su - name`, `sudo -u name` | ユーザーを切り替える |
| `/etc/passwd`, `/etc/group`, `/etc/shadow` | すべてが保存されている場所 |
