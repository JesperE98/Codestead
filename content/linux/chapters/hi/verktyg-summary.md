# सारांश: और टूल

इस भाग में आप दो ऐसे टूल से मिले जिन्हें आप टर्मिनल में ज़िंदगी भर इस्तेमाल करेंगे:
git, जो आपकी फ़ाइलों का इतिहास रखता है, और bash के अलावा दूसरे शेल। परीक्षा से पहले
आपको यह याद रखना चाहिए।

## टर्मिनल में Git

**Git** एक संस्करण नियंत्रण प्रणाली (version control system) है: यह पूरे प्रोजेक्ट के
स्नैपशॉट सहेजता है, याद रखता है कि किसने क्या और क्यों बदला, और आपको समय में पीछे
जाने देता है। Ubuntu पर आप इसे `sudo apt install git` से इंस्टॉल करते हैं; दूसरे
डिस्ट्रीब्यूशन अपना पैकेज मैनेजर इस्तेमाल करते हैं।

- अपने पहले कमिट से पहले आप `git config --global user.name` और `user.email` से git
  को बताते हैं कि आप कौन हैं। `--global` का मतलब है आपके सारे प्रोजेक्ट; सेटिंग्स
  `~/.gitconfig` में पहुँचती हैं।
- `git init` एक डायरेक्टरी को **रिपॉज़िटरी** बना देता है। पूरा इतिहास छिपी डायरेक्टरी
  `.git` में रहता है।
- एक बदलाव तीन जगहों से गुज़रता है: **working tree** (वे फ़ाइलें जो आप देखते हैं),
  **index** (जो अगले कमिट में जाता है) और **इतिहास** (कमिट)। `git add` बदलावों को
  index में ले जाता है, `git commit` index को एक नए कमिट के रूप में सहेजता है।
- `git commit -a` हर उस बदली हुई फ़ाइल को जोड़ता है जिस पर git पहले से नज़र रखता है –
  लेकिन नई फ़ाइलों को कभी नहीं।
- `git diff` वे बदलाव दिखाता है जो अभी index में नहीं हैं; `git diff --staged`
  दिखाता है कि index में क्या है।
- एक **ब्रांच** एक लेबल है जो किसी कमिट की ओर इशारा करता है और नए कमिट के साथ आगे
  बढ़ता है। जब आप ब्रांच बदलते हैं, तो git working tree को फिर से लिख देता है।
- `git merge` किसी ब्रांच को उस ब्रांच में ले आता है जिस पर आप हैं। अगर दोनों ब्रांच
  ने एक ही पंक्तियाँ बदली हैं, तो आपको एक **टकराव** (conflict) मिलता है: फ़ाइल ठीक
  कीजिए, उसे `git add` कीजिए और `git commit` से पूरा कीजिए।
- `.gitignore` उन फ़ाइलों की सूची है जिन पर git को नज़र नहीं रखनी चाहिए। यह सिर्फ़ उन
  फ़ाइलों पर लागू होती है जिन पर git पहले से नज़र नहीं रखता।
- एक **remote** रिपॉज़िटरी की कहीं और रखी कॉपी है, जिसे आमतौर पर `origin` कहते हैं।
  `git pull` लाता है और मिलाता है, `git push` आपके कमिट भेजता है।

| कमांड | क्या करता है |
|---|---|
| `git config --global user.name "…"` | git को अपना नाम बताना (और `user.email`) |
| `git init` | डायरेक्टरी को रिपॉज़िटरी बनाना |
| `git status` | दिखाना कि हर बदलाव कहाँ है |
| `git add FILE` / `git add .` | बदलावों को index में रखना |
| `git commit -m "…"` | index को नए कमिट के रूप में सहेजना |
| `git commit -am "…"` | एक ही चरण में नज़र रखी गई हर फ़ाइल जोड़ना और कमिट करना |
| `git diff` / `git diff --staged` | वे बदलाव दिखाना जो कमिट नहीं हुए |
| `git log --oneline --graph --all` | इतिहास दिखाना |
| `git restore FILE` | किसी फ़ाइल के बदलाव फेंक देना |
| `git restore --staged FILE` | किसी फ़ाइल को index से बाहर निकालना |
| `git switch -c BRANCH` / `git switch BRANCH` | ब्रांच बनाना / ब्रांच बदलना |
| `git merge BRANCH` | किसी ब्रांच को उसमें मिलाना जिस पर आप हैं |
| `git branch -d BRANCH` | मिलाई जा चुकी ब्रांच मिटाना |
| `git rm --cached FILE` | किसी फ़ाइल पर नज़र रखना बंद करना लेकिन उसे डिस्क पर रखना |
| `git clone`, `git pull`, `git push` | एक remote के ज़रिए मिलकर काम करना |

## दूसरे शेल: zsh और fish

**शेल** आपका टाइप किया हुआ पढ़ता है और दूसरे प्रोग्राम शुरू करता है। `ls` और `grep`
जैसे प्रोग्राम हर शेल में एक जैसे काम करते हैं – जो अलग है, वह उनके आसपास की भाषा है:
वेरिएबल, लूप, शर्तें और प्रॉम्प्ट।

- `/etc/shells` उन शेलों की सूची है जो लॉगिन शेल हो सकते हैं। आपका लॉगिन शेल
  `/etc/passwd` में आपकी पंक्ति का आख़िरी फ़ील्ड है और `$SHELL` में भी होता है। `$0`
  में वह शेल होता है जो आप अभी चला रहे हैं।
- **zsh** लगभग सारा bash सिंटैक्स समझता है और सुविधाएँ जोड़ता है: `**/` सभी
  उप-डायरेक्टरी में खोजता है, और `autocd` के साथ आप सिर्फ़ किसी डायरेक्टरी का नाम
  टाइप करके उसमें चले जाते हैं। ऑप्शन `setopt` और `unsetopt` से चालू और बंद किए जाते
  हैं। bash के उलट, zsh बिना उद्धरण चिह्नों वाले वेरिएबल को स्पेस पर नहीं बाँटता।
- **fish** शुरू से ही इस्तेमाल में आसान है लेकिन उसका **अपना सिंटैक्स** है: `=` की
  जगह `set`, `$?` की जगह `$status`, `$((...))` की जगह `math`, और हर ब्लॉक `end` पर
  ख़त्म होता है। हर वेरिएबल एक सूची है, जिसकी गिनती 1 से होती है।
- शुरू किया गया शेल bash के **अंदर** चलता है; `exit` आपको वापस ले जाता है। `-c` के
  साथ कोई शेल एक कमांड चलाकर बाहर निकल जाता है।
- स्क्रिप्ट अब भी bash (या POSIX `sh`) के लिए लिखी जाती हैं: `#!` पंक्ति तय करती है कि
  कौन-सा शेल स्क्रिप्ट चलाए, चाहे आप किसी भी शेल में बैठे हों।
- `chsh -s` आपका लॉगिन शेल बदलता है। बदलाव अगले लॉगिन पर लागू होता है।

| कमांड | क्या करता है |
|---|---|
| `cat /etc/shells` | इस्तेमाल किए जा सकने वाले शेलों की सूची |
| `echo $0` / `ps` | देखना कि आप अभी कौन-सा शेल चला रहे हैं |
| `echo $SHELL` | अपना लॉगिन शेल देखना |
| `zsh` / `fish` / `exit` | कोई दूसरा शेल शुरू करना / वापस जाना |
| `zsh -c '…'` / `fish -c '…'` | किसी दूसरे शेल में एक कमांड चलाना |
| `setopt autocd` / `unsetopt autocd` | zsh का कोई ऑप्शन चालू / बंद करना |
| `set frukt äpple` / `set -e frukt` | fish में वेरिएबल सेट करना / हटाना |
| `set -x NAME value` | fish में एनवायरनमेंट वेरिएबल सेट करना |
| `math 17 x 23` | fish में गणित |
| `chsh -s /usr/bin/zsh` | अपना लॉगिन शेल बदलना |

कॉन्फ़िगरेशन फ़ाइलें: `~/.bashrc` (bash), `~/.zshrc` (zsh) और
`~/.config/fish/config.fish` (fish)।
