# Семейство Red Hat: dnf и COPR

Fedora, Red Hat Enterprise Linux (RHEL) и клоны RHEL, например Rocky Linux,
образуют **семейство Red Hat**. Они используют пакетный менеджер **dnf** и
пакеты в формате `.rpm`. Эта глава всегда работает на дистрибутиве из
семейства Red Hat – сейчас это **{{distro}}**.

## dnf вкратце

| Что | Команда |
|---|---|
| Обновить список пакетов | `dnf check-update` |
| Обновить всё | `dnf upgrade` |
| Установить | `dnf install X` |
| Удалить | `dnf remove X` |
| Найти | `dnf search X` |
| Информация о пакете | `dnf info X` |
| Список установленных | `dnf list --installed` |

Команды, которые меняют систему, требуют прав root, поэтому их запускают через
`sudo`.

## Автоматические метаданные

dnf сам загружает новую информацию о пакетах, когда она нужна, поэтому
отдельного шага вроде `apt update` в семействе Debian здесь нет. Если хотите
увидеть, какие обновления доступны, выполните:

```sh
dnf check-update
```

Для `dnf check-update` права root не нужны. Код возврата равен `100`, если
есть обновления, – удобно в скриптах. В симуляторе обновления ждут
установки. Что выведет эта команда?

```predict
$ dnf check-update > /dev/null; echo $?
100
---
`> /dev/null` скрывает список, а `$?` – код возврата последней команды:
`100` означает, что обновления есть.
```

## Установка и удаление

```sh
sudo dnf install htop
```

Обратите внимание на вопрос `Is this ok [y/N]`. Заглавная `N` означает, что
по умолчанию ответ – **нет**: если просто нажать Enter, установка
отменится. Введите `y` и нажмите Enter или используйте `-y`.

```quiz
dnf спрашивает `Is this ok [y/N]`, а вы просто нажимаете Enter. Что произойдёт?
- [ ] Пакет установится
- [x] Установка отменится
- [ ] dnf спросит ещё раз
---
Заглавная буква – это ответ по умолчанию. В семействе Debian apt спрашивает
`[Y/n]`, поэтому там Enter означает «да».
```

`dnf remove пакет` снова удаляет пакет.

## Обновление системы

```sh
sudo dnf upgrade
```

## Под капотом: rpm

Пакеты – это файлы `.rpm`, а низкоуровневый инструмент называется `rpm`. dnf
пришёл на смену более старому `yum`, а в Fedora 41 появилась новая версия
**dnf5**, которая заметно быстрее. В RHEL, Rocky и AlmaLinux команда тоже
называется `dnf`.

## Дополнительные репозитории – удобно, но на ваш страх и риск

В репозиториях дистрибутива десятки тысяч пакетов – но не всё. Какой-нибудь
нишевой программы там может вообще не быть или она есть только в старой
версии. Поэтому существуют **дополнительные репозитории**, где разработчики и
пользователи делятся своими пакетами.

Пакеты в собственных репозиториях дистрибутива протестированы вместе,
подписаны и проверены разработчиками дистрибутива. А вот дополнительный
репозиторий может создать кто угодно. Помните об этом, прежде чем добавлять
его:

- **Пакеты устанавливаются с правами root.** Пакет может сделать с
  компьютером что угодно. Тому, кто его собрал, вы доверяете так же, как
  самому дистрибутиву.
- **Возможны конфликты.** Пакет из дополнительного репозитория может заменить
  собственные библиотеки системы или потребовать других версий, чем те, что
  у вас есть.
- **Обновления могут прекратиться.** Если тот, кто ведёт репозиторий, потеряет
  интерес, вы больше не получите обновлений безопасности для программы.

Хорошее практическое правило: сначала ищите в репозиториях дистрибутива,
затем – Flatpak (в главе об универсальных пакетах), и только после этого – в
дополнительном репозитории от того, кому вы доверяете.

## COPR

**COPR** (*Cool Other Package Repo*) – это сервис сборки Fedora. Любой, у
кого есть аккаунт Fedora, может собирать там пакеты `.rpm`, и каждый проект
становится отдельным репозиторием с именем `пользователь/проект`. Дистрибутив
репозитории COPR не проверяет.

В оставшейся части главы вы установите из COPR выдуманную программу
`moonphase` (она показывает фазу Луны в терминале).

### Репозитории, которые у вас есть сейчас

```sh
dnf repolist
```

```try
dnf repolist
---
Это собственные репозитории Fedora.
```

### Включаем репозиторий COPR

```sh
sudo dnf copr enable lunatool/moonphase
```

dnf напомнит, что репозиторий не входит в Fedora и что качество может быть
разным. По умолчанию на вопрос отвечается **нет**, поэтому ответьте `y`. В
`/etc/yum.repos.d/` создаётся новый файл:

```sh
ls /etc/yum.repos.d
dnf copr list
dnf repolist
```

```quiz
Любой, у кого есть аккаунт Fedora, может собирать пакеты в COPR. Кто их проверяет?
- [ ] Разработчики Fedora, перед публикацией
- [ ] Red Hat
- [x] Никто – вам приходится доверять тому, кто ведёт репозиторий
```

### Установка и запуск

dnf сам загружает информацию о новом репозитории, так что пакет можно
установить сразу:

```sh
sudo dnf install moonphase
moonphase
```

### Откуда взялся пакет?

```sh
dnf info moonphase
```

Строка `From repository` показывает, что пакет пришёл из COPR. Пакеты из COPR
обновляются как обычно – командой `sudo dnf upgrade`.

### Отключение или удаление

```sh
sudo dnf copr disable lunatool/moonphase
dnf copr list
```

`disable` оставляет файл на месте, но выключает репозиторий, а `remove`
удаляет его полностью. Программа останется, но больше не будет получать
обновлений.

```quiz
Чем отличаются `dnf copr disable` и `dnf copr remove`?
- [x] `disable` выключает репозиторий, но оставляет файл, а `remove` удаляет его
- [ ] `disable` заодно удаляет пакеты, а `remove` – нет
- [ ] Ничем
```

### RPM Fusion

Ещё один распространённый дополнительный репозиторий для Fedora – **RPM
Fusion**. В нём есть то, что Fedora не может или не хочет включать, например
некоторые медиакодеки и драйверы. Это большой совместный проект, а не
репозиторий одного пользователя, как в COPR.

Каждый добавленный репозиторий – это ещё один источник, которому вы
доверяете. Держите их список коротким и убирайте то, чем больше не
пользуетесь.
