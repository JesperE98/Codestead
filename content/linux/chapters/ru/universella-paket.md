# Flatpak, Snap и AppImage

Обычный пакет собирается для одного конкретного дистрибутива и выпуска. Для
того, кто делает настольную программу, это проблема: одну и ту же программу
приходится заново упаковывать для Debian, Ubuntu, Fedora, Arch и всех их
выпусков. **Универсальные форматы пакетов** решают эту задачу, укладывая
внутрь пакета большую часть того, что нужно программе, – так что один и тот
же пакет работает в любом дистрибутиве.

Три главных формата – **Flatpak**, **Snap** и **AppImage**. Они не заменяют
пакетный менеджер дистрибутива, а дополняют его, в основном для настольных
программ.

> В симуляторе есть только терминал. Когда вы запускаете графическую
> программу, вместо окна появляется строка о том, что она открылась бы в
> окне.

## Четыре способа установить программу

| | Пакет дистрибутива | Flatpak | Snap | AppImage |
|---|---|---|---|---|
| Откуда | Репозитории дистрибутива | Flathub (или другие *remotes*) | Snap Store (Canonical) | Сайт разработчика |
| Где работает | В одном дистрибутиве и выпуске | Везде | Везде, где есть `snapd` | Везде (нужен FUSE) |
| Песочница | Нет | Да | Да (кроме *classic*) | Нет |
| Размер | Маленький – делит библиотеки с системой | Большой в первый раз (среды выполнения), потом общие | Большой – каждый snap и его база | Большой – всё в одном файле |
| Обновления | Вместе с системой (`apt upgrade` …) | `flatpak update` | Автоматически в фоне | Сами – скачайте новый файл |
| Подходит для | Системных программ, утилит командной строки, серверов | Настольных программ | Ubuntu, рабочих столов и серверов | Отдельных программ, проб новых версий |

**Песочница** (*sandbox*) означает, что программа может добраться только до
того, что ей разрешено, например до сети или до папки загрузок, а не до всего
вашего домашнего каталога.

## Flatpak

Flatpak – это формат, на котором для настольных программ сошлось большинство
дистрибутивов. Программы скачиваются из **удалённого источника** (*remote*) –
почти всегда это **Flathub** – и используют общие **среды выполнения**
(*runtimes*, например `org.gnome.Platform`), чтобы каждой программе не
приходилось тащить всё с собой.

:::debian
### Установка Flatpak

В {{distro}} Flatpak не установлен заранее:

```sh
sudo apt update
sudo apt install flatpak
```
:::

:::arch
### Установка Flatpak

Flatpak есть в репозиториях Arch:

```sh
sudo pacman -S flatpak
```
:::

:::redhat
### Flatpak в {{distro}}

В Fedora Workstation Flatpak уже есть, и собственный источник Fedora `fedora`
уже добавлен:

```sh
flatpak --version
flatpak remotes
```
:::

### Добавляем Flathub

```sh
flatpak remote-add --if-not-exists flathub https://dl.flathub.org/repo/flathub.flatpakrepo
flatpak remotes
```

`--if-not-exists` делает так, что команда не завершится ошибкой, если Flathub
уже добавлен, – это полезно в скриптах и инструкциях по установке.

### Поиск, установка и запуск

У каждой программы есть **ID**, записанный как перевёрнутое доменное имя,
например `org.gimp.GIMP`:

```sh
flatpak search gimp
flatpak install flathub org.gimp.GIMP
```

Flatpak показывает, какие **разрешения** хочет программа и какие среды
выполнения устанавливаются вместе с ней. Обратите внимание на размер: первая
программа подтягивает среду выполнения в несколько сотен мегабайт, зато
следующая программа, использующая ту же среду, будет маленькой.

```sh
flatpak list
flatpak run org.gimp.GIMP
flatpak info --show-permissions org.gimp.GIMP
```

### Для всей системы или только для вас

Без опций Flatpak устанавливает программы для **всей системы** (в
`/var/lib/flatpak`). На рабочем столе Flatpak спрашивает пароль в окне, так
что sudo не нужен. С `--user` программа попадает в ваш домашний каталог
(`~/.local/share/flatpak`), и другие пользователи её не видят. У
пользовательской установки **свои источники**, поэтому Flathub нужно
добавить ещё раз, тоже с `--user`:

```sh
flatpak remote-add --user --if-not-exists flathub https://dl.flathub.org/repo/flathub.flatpakrepo
flatpak install --user flathub org.videolan.VLC
flatpak list --user
```

### Обновление и удаление

```sh
flatpak update
flatpak uninstall --user org.videolan.VLC
flatpak uninstall --unused
```

`--unused` удаляет среды выполнения, которые больше не использует ни одна
установленная программа.

## Snap

Snap – формат компании **Canonical** и стандарт в Ubuntu: там, например,
Firefox установлен как snap. Snap-пакеты берутся из **Snap Store**, которым
управляет Canonical, а работает с ними служба `snapd`. Они обновляются
автоматически в фоне.

:::debian
### Snap в Ubuntu и Debian

В Ubuntu Snap уже есть. В Debian сначала установите `snapd`:

```sh
sudo apt update
sudo apt install snapd
```
:::

:::arch
### Snap в Arch

Snap нет в репозиториях Arch – только в AUR. Соберите его, как в предыдущей
главе:

```sh
sudo pacman -S --needed git base-devel
cd ~
git clone https://aur.archlinux.org/snapd.git
cd snapd
makepkg -si
```

В настоящей системе нужно ещё запустить службу командой
`sudo systemctl enable --now snapd.socket`. Это признак того, что Snap в Arch
чувствует себя не как дома: большинство там пользуется Flatpak.
:::

:::redhat
### Snap в Fedora

Fedora делает ставку на Flatpak, но Snap есть в репозиториях:

```sh
sudo dnf install snapd
```
:::

### Работа со snap

```sh
snap list
snap find vlc
sudo snap install hello-world
hello-world
snap info hello-world
```

Установленные snap-пакеты появляются как программы в `/snap/bin`. Для
установки и удаления нужны права root.

### Strict или classic

Большинство snap-пакетов работают **строго** (*strict*) в песочнице.
Программы, которым нужен доступ ко всей системе, например редакторы кода,
публикуются с **classic confinement** («классическим ограничением»). Тогда вы
должны сами это одобрить с помощью `--classic`:

```sh
sudo snap install code
sudo snap install code --classic
```

### Каналы и обновления

У каждого snap есть **каналы**: `stable`, `candidate`, `beta` и `edge`
(самая свежая, непротестированная версия). `snap info` показывает их, а
`--channel=beta` выбирает другой канал. Обновления происходят автоматически,
но их можно запустить принудительно, а snap-пакеты – удалить:

```sh
sudo snap refresh
sudo snap remove hello-world
```

У Snap есть и критики: Snap Store целиком в руках одной Canonical,
автоматические обновления нельзя отключить полностью, а программы могут
медленно запускаться в первый раз.

## AppImage

**AppImage** – это целая программа в **одном-единственном файле**. Вы
скачиваете его с сайта программы, делаете исполняемым и запускаете – без
установки и без root. Чтобы избавиться от программы, просто удалите файл.

В вашем домашнем каталоге, в `~/Nedladdningar` (по-шведски «Загрузки»), уже
лежит скачанный AppImage:

```sh
cd ~/Nedladdningar
ls -l
```

Скачанные файлы изначально никогда не бывают исполняемыми. Сделайте файл
исполняемым и запустите его (*Kalkylator* по-шведски – «калькулятор»):

```sh
chmod +x Kalkylator.AppImage
./Kalkylator.AppImage
```

### FUSE

AppImage монтирует сам себя как файловую систему с помощью **FUSE**, и ему
нужна старая, вторая версия библиотеки (`libfuse.so.2`). Без неё вы получите
ошибку *"AppImages require FUSE to run"*.

:::debian
В Ubuntu 24.04 и Debian 13 пакет называется `libfuse2t64` (суффикс *t64*
появился при переходе на 64-битное время; в старых выпусках он назывался
`libfuse2`):

```sh
sudo apt update
sudo apt install libfuse2t64
./Kalkylator.AppImage
```

> **Не** устанавливайте в Ubuntu пакет `fuse` – он заменяет `fuse3`, который
> нужен рабочему столу.
:::

:::arch
В Arch пакет называется `fuse2`:

```sh
sudo pacman -S fuse2
./Kalkylator.AppImage
```
:::

:::redhat
В Fedora пакет называется `fuse-libs`:

```sh
sudo dnf install fuse-libs
./Kalkylator.AppImage
```
:::

### Заглянем внутрь

AppImage можно также распаковать. Это работает даже без FUSE:

```sh
./Kalkylator.AppImage --appimage-extract
ls squashfs-root
./squashfs-root/AppRun
```

`--appimage-extract-and-run` распаковывает программу во временный каталог и
сразу её запускает.

### Помните

- У AppImage **нет песочницы** – программа работает от вашего имени и может
  добраться до всего, до чего можете вы. Скачивайте только с официального
  сайта программы.
- **Автоматических обновлений нет.** Когда выходит новая версия, вы
  скачиваете новый файл (некоторые программы умеют обновляться сами).
- Программа сама по себе не появляется в меню приложений. Это могут исправить
  инструменты вроде *Gear Lever* или *AppImageLauncher*.

## Что же выбрать?

1. **Пакеты дистрибутива** – для системных программ и программ командной
   строки: они самые маленькие, самые быстрые и обновляются вместе с
   остальной системой.
2. **Flatpak** – для настольных программ, когда нужна более новая версия или
   программа, которой нет в репозиториях.
3. **Snap** – если у вас Ubuntu или программа существует только как snap.
4. **AppImage** – чтобы быстро попробовать программу или когда разработчик
   предлагает только этот формат.
