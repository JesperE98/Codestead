# Семейство Arch: pacman и AUR

Arch Linux и построенные на нём дистрибутивы, например Manjaro и EndeavourOS,
образуют **семейство Arch**. Они используют пакетный менеджер **pacman** и
пакеты в формате `.pkg.tar.zst`. Эта глава всегда работает на дистрибутиве из
семейства Arch – сейчас это **{{distro}}**.

## pacman вкратце

| Что | Команда |
|---|---|
| Обновить список пакетов | `pacman -Sy` |
| Обновить всё | `pacman -Syu` |
| Установить | `pacman -S X` |
| Удалить | `pacman -R X` |
| Найти | `pacman -Ss X` |
| Информация о пакете | `pacman -Si X` |
| Список установленных | `pacman -Q` |

Команды, которые меняют систему, требуют прав root, поэтому их запускают через
`sudo`.

pacman использует короткие опции, где **заглавная буква** – это операция, а
строчные – модификаторы:

| Опция | Означает |
|---|---|
| `-S` | Sync – установить из репозиториев |
| `-R` | Remove – удалить |
| `-Q` | Query – запросить сведения об установленных пакетах |
| `y` | Обновить базу данных пакетов |
| `u` | Обновить все пакеты |
| `s` | Поиск (с -S и -Q) или удаление зависимостей (с -R) |
| `i` | Информация |

```quiz
Что означает заглавная `Q` в `pacman -Q`?
- [ ] Quit – завершить pacman
- [x] Query – запросить сведения об установленных пакетах
- [ ] Quick – установить без вопросов
---
`-Q` спрашивает об установленном, `-S` устанавливает из репозиториев, а `-R`
удаляет.
```

Для поиска права root не нужны. Попробуйте:

```try
pacman -Ss htop
```

## Обновление системы

```sh
sudo pacman -Syu
```

`-Syu` означает: синхронизировать (`S`), обновить базу данных (`y`) и
обновить всё (`u`). Arch – это *rolling release*, так что запускать это
придётся часто.

> **Важно!** Никогда не выполняйте просто `pacman -Sy`, а затем
> `pacman -S пакет`. Новому пакету могут понадобиться более новые библиотеки,
> чем те, что у вас есть, – это так называемое *частичное обновление*
> (partial upgrade), которое может сломать систему. Всегда используйте `-Syu`.

```quiz
Почему нельзя выполнять `pacman -Sy`, а затем `pacman -S пакет`?
- [ ] Потому что `-Sy` удаляет базу данных пакетов
- [x] Новому пакету могут понадобиться более новые библиотеки, чем у вас есть, и это может сломать систему
- [ ] Потому что pacman может устанавливать только один пакет в день
---
Всегда обновляйте всё сразу с помощью `-Syu`.
```

## Установка и удаление

```sh
sudo pacman -S htop
```

`pacman -R пакет` удаляет пакет, а `pacman -Rs пакет` удаляет ещё и
зависимости, которые больше ничему не нужны.

## AUR

В репозиториях дистрибутива десятки тысяч пакетов – но не всё. Какой-нибудь
нишевой программы там может вообще не быть или она есть только в старой
версии. В семействе Arch ответ на это – **AUR** (*Arch User Repository*,
«пользовательский репозиторий Arch»).

AUR устроен иначе, чем обычные репозитории: в нём нет готовых пакетов, только
**рецепты сборки**. Рецепт называется `PKGBUILD` – это небольшой скрипт на
bash, в котором указано, где лежит исходный код и как собирается программа.
Вы скачиваете рецепт, сами собираете пакет и устанавливаете его через pacman.
AUR огромен – там есть почти всё, что существует для Linux, – но загрузить
рецепт может кто угодно.

```quiz
Что вы скачиваете из AUR?
- [ ] Готовый пакет `.pkg.tar.zst`, проверенный Arch
- [x] Рецепт сборки (`PKGBUILD`), по которому вы сами собираете пакет
- [ ] Flatpak
```

### На ваш страх и риск

Пакеты в собственных репозиториях дистрибутива протестированы вместе,
подписаны и проверены разработчиками дистрибутива. Пакеты в AUR командой Arch
не проверяются. Помните об этом:

- **Пакеты устанавливаются с правами root.** Пакет может сделать с
  компьютером что угодно. Тому, кто написал рецепт, вы доверяете так же, как
  самому дистрибутиву.
- **Возможны конфликты.** Пакет может заменить собственные библиотеки системы
  или потребовать других версий, чем те, что у вас есть.
- **Обновления могут прекратиться.** Если тот, кто поддерживает рецепт,
  потеряет интерес, вы больше не получите обновлений безопасности для
  программы.

Хорошее практическое правило: сначала ищите в репозиториях дистрибутива,
затем – Flatpak (в главе об универсальных пакетах), и только после этого – в
AUR.

В оставшейся части главы вы установите из AUR выдуманную программу
`moonphase` (она показывает фазу Луны в терминале).

### Подготовка

Чтобы скачивать рецепты и собирать пакеты, нужны `git` и `base-devel`
(компилятор, `make`, `fakeroot` и многое другое):

```sh
sudo pacman -S --needed git base-devel
```

`--needed` пропускает то, что уже установлено.

### Получаем рецепт

Каждый пакет AUR – это отдельный git-репозиторий:

```sh
cd ~
git clone https://aur.archlinux.org/moonphase.git
cd moonphase
ls
```

> Если вы ошибётесь в имени пакета, git скажет *"You appear to have cloned an
> empty repository"*, и каталог будет пустым. AUR позволяет клонировать что
> угодно!

### Читайте PKGBUILD – каждый раз

```sh
less PKGBUILD
```

`PKGBUILD` – это скрипт, который выполняется на вашем компьютере. Проверьте
как минимум:

- что `source=` скачивает с настоящего сайта программы,
- что `build()` и `package()` только собирают и копируют файлы – и не делают,
  например, загрузку и запуск чего-то ещё (`curl … | sh`),
- что пакет выглядит поддерживаемым (даты, комментарии на aur.archlinux.org).

### Сборка и установка

```sh
makepkg -si
```

`makepkg` читает `PKGBUILD`, скачивает исходный код, собирает его и
упаковывает в файл `.pkg.tar.zst`. `-s` устанавливает недостающие
зависимости, а `-i` по окончании устанавливает пакет через pacman. **Не**
запускайте makepkg через sudo – он откажется работать от root и сам
воспользуется sudo, когда это нужно.

```sh
ls
moonphase
```

### «Чужие» пакеты

pacman ничего не знает об AUR. Пакеты, которые пришли не из репозиториев,
называются *foreign* («чужие»), и их список выводится так:

```sh
pacman -Qm
```

Это также значит, что `sudo pacman -Syu` **не** обновляет пакеты из AUR.
Новый рецепт нужно получить самому (`git pull`) и пересобрать пакет – или
поручить это AUR-помощнику.

```quiz
Вы установили `moonphase` из AUR и выполнили `sudo pacman -Syu`. Обновится ли
`moonphase`?
- [ ] Да – pacman обновляет все установленные пакеты
- [x] Нет – pacman ничего не знает об AUR
---
Получите новый рецепт с помощью `git pull` и пересоберите пакет – или
воспользуйтесь AUR-помощником.
```

### AUR-помощник yay

AUR-помощник делает всё это за вас: ищет, скачивает, показывает `PKGBUILD`,
собирает и устанавливает. Самый распространённый – **yay** (другой –
*paru*). Сам yay есть только в AUR, поэтому один раз его устанавливают
вручную. Пакет `yay-bin` уже скомпилирован, и с ним быстрее всего:

```sh
cd ~
git clone https://aur.archlinux.org/yay-bin.git
cd yay-bin
makepkg -si
```

После этого yay используется почти как pacman – но без sudo:

```sh
yay -Ss snowfall
yay -S snowfall
snowfall
yay -Syu
```

`yay -Syu` (или просто `yay`) обновляет и пакеты из репозиториев, и ваши
пакеты из AUR. Но удобство не означает, что можно перестать читать рецепты!

У AUR нет репозитория, который нужно удалять, – каждый пакет является
отдельным рецептом. Убирайте то, чем больше не пользуетесь.
