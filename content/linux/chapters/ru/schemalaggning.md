# Задания по расписанию с cron

Резервная копия каждую ночь, чистка старых журналов каждую неделю, загрузка
данных каждые пять минут – компьютер может сам выполнять команды в заданное
время. Классический инструмент для этого – **cron**, а у systemd есть свои
**таймеры**.

## cron и crontab

Служба cron просыпается каждую минуту и выполняет задания, время которых
пришло. У каждого пользователя есть свой список заданий – **crontab**:

```sh
crontab -l
```

*no crontab for {{user}}* означает, что заданий у вас пока нет.

## Пять полей времени

Каждая строка crontab содержит пять полей времени, а затем команду:

```text
┌───────────── минута (0–59)
│ ┌─────────── час (0–23)
│ │ ┌───────── день месяца (1–31)
│ │ │ ┌─────── месяц (1–12)
│ │ │ │ ┌───── день недели (0–7, воскресенье – 0 или 7)
│ │ │ │ │
* * * * *  команда
```

| Вы пишете | Что значит |
|---|---|
| `*` | Каждый |
| `5` | Ровно 5 |
| `1-5` | С 1 по 5 |
| `1,15` | 1 и 15 |
| `*/10` | Каждый десятый: 0, 10, 20 … |

| Строка | Когда выполняется |
|---|---|
| `* * * * * command` | Каждую минуту |
| `*/5 * * * * command` | Каждые пять минут |
| `30 2 * * * command` | В 02:30 каждую ночь |
| `0 7 * * 1-5 command` | В 07:00 с понедельника по пятницу |
| `0 0 1 * * command` | В полночь первого числа каждого месяца |
| `@reboot command` | Один раз, при запуске компьютера |

Есть и другие сокращения: `@hourly`, `@daily`, `@weekly` и `@monthly`.

```quiz
Когда выполняется задание `15 8 * * 6 ~/backup.sh`?
- [ ] В 15:08 каждый день
- [x] В 08:15 каждую субботу
- [ ] 15-го числа каждого месяца в 08:00
---
Порядок такой: минута, час, день месяца, месяц и день недели. Минута 15, час
8, любое число, любой месяц, день 6 – суббота.
```

```quiz
Как часто выполняется `0 */2 * * * command`?
- [ ] Каждые две минуты
- [x] Раз в два часа, ровно в начале часа
- [ ] Два раза в день
---
Минута 0 и каждый второй час: 00:00, 02:00, 04:00 …
```

## Установка заданий

`crontab -e` открывает ваш crontab в текстовом редакторе и устанавливает его,
когда вы сохраняете файл. В симуляторе пока нет редактора, поэтому здесь вы
передаёте задания `crontab` через ввод – `-` означает «читать из ввода»:

```sh
echo '* * * * * date >> ~/cron.log' | crontab -
crontab -l
```

Осторожно: `crontab -` и `crontab FILE` **заменяют** весь crontab. Чтобы
добавить задание, объедините старые задания с новым:

```sh
(crontab -l; echo '30 2 * * * ~/backup.sh') | crontab -
```

Чтобы удалить одну строку, отфильтруйте её с помощью `grep -v` и установите
остальное – или удалите всё командой `crontab -r`:

```sh
crontab -l | grep -v backup.sh | crontab -
```

`crontab` проверяет строки, прежде чем что-либо устанавливать:

```predict
$ echo '0 25 * * * date' | crontab -
"-":1: bad hour
errors in crontab file, can't install.
---
Часа 25 не существует – часы идут от 0 до 23. Ничего не было установлено.
```

## Как задание выполняется

Установив задание, которое выполняется каждую минуту, подождите минуту и
посмотрите:

```sh
cat ~/cron.log
journalctl -u cron
```

Каждый запуск записывается в journal, например
`CRON[4211]: ({{user}}) CMD (date >> ~/cron.log)`. В симуляторе cron работает,
только пока приложение открыто, – как и настоящий компьютер, он не наверстывает
задания, пропущенные, пока он был выключен.

## Ловушка cron: другое окружение

Задания выполняются не в вашем терминале, и это удивляет почти всех:

- Они выполняются с `/bin/sh`, без ваших псевдонимов и без `~/.bashrc`.
- `PATH` короткий (`/usr/bin:/bin`), поэтому для программ, лежащих в других
  местах, нужен полный путь.
- Они запускаются в вашем домашнем каталоге.
- Вывод, который не отправлен в файл, теряется. Всегда заканчивайте строку,
  например, на `>> ~/job.log 2>&1`.

Сначала выполните команду вручную. Когда она там заработает, поместите её в
crontab.

```quiz
Задание `* * * * * echo hi` выполняется каждую минуту, но `hi` вы нигде не
видите. Почему?
- [ ] cron не разрешает `echo`
- [x] Выводу некуда деваться – отправьте его в файл с помощью `>>`
- [ ] Задания выполняются только от имени root
---
Вывод заданий cron не показывается ни в одном терминале. Настоящий cron
пытается отправить его по почте, а на большинстве компьютеров почта не
настроена – поэтому он теряется.
```

## Собственные задания системы

Помимо crontab пользователей есть `/etc/crontab` и каталоги вроде
`/etc/cron.daily` и `/etc/cron.weekly`. Скрипты в них выполняются раз в день
или раз в неделю:

```sh
cat /etc/crontab
ls /etc/cron.daily
```

В строках `/etc/crontab` перед командой есть ещё одно поле: пользователь, от
имени которого выполняется задание.

## Таймеры systemd

В современных дистрибутивах многое из этого вместо cron делают **таймеры**
systemd: юнит `.timer`, который запускает юнит `.service` в заданное время.
Они пишут в journal и умеют наверстывать пропущенные запуски, но каждому
заданию нужны два юнит-файла. Для ваших собственных небольших заданий cron –
самый быстрый путь. Выведите список таймеров на компьютере со следующим и
предыдущим запуском:

```try
systemctl list-timers
```

## В других дистрибутивах

| | Ubuntu и Debian | Fedora | Arch |
|---|---|---|---|
| Пакет | `cron` | `cronie` | `cronie` |
| Служба | `cron` | `crond` | `cronie` |
| Установлен с самого начала | Да | Да | Нет |

В Arch начните с `sudo pacman -S cronie` и
`sudo systemctl enable --now cronie`.
