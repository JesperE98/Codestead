# Пользователи, права доступа и sudo

Linux устроен так, чтобы несколько пользователей могли работать на одном
компьютере. Поэтому у каждого файла есть владелец и правила, кому что можно.

## Пользователи и группы

Вы вошли как пользователь `{{user}}`. Каждый пользователь состоит в одной или
нескольких **группах**:

```sh
id
```

Самый важный пользователь – **root**, администратор, которому можно всё.
Входить в систему как root приходится редко. Вместо этого используют `sudo`
(см. ниже).

## Как читать права

Выполните `ls -l` и посмотрите на первый столбец:

```text
drwxr-xr-x 2 {{user}} {{user}} 4096 Oct 29 13:55 {{documents}}
-rw-r--r-- 1 {{user}} {{user}}  332 Oct 29 13:55 {{notes}}
```

Первый символ – тип: `-` для файла, `d` для каталога. Затем идут три группы
по три символа:

```text
-     rw-       r--      r--
тип   владелец  группа   остальные
```

| Символ | Для файла | Для каталога |
|---|---|---|
| `r` (read) | Читать содержимое | Просматривать содержимое |
| `w` (write) | Изменять содержимое | Создавать и удалять в нём файлы |
| `x` (execute) | Запускать файл как программу | Входить в каталог с помощью `cd` |

Дальше идут владелец (`{{user}}`) и группа (`{{user}}`).

```quiz
У каталога права `drwxr-x---`. Что могут делать члены его группы?
- [ ] Вообще ничего
- [x] Просматривать содержимое и входить в него с помощью `cd`, но не создавать и не удалять в нём файлы
- [ ] Всё, что может владелец
---
У группы набор `r-x`: `r` позволяет просматривать содержимое, а `x` – входить в
каталог. Без `w` создавать и удалять в нём файлы нельзя.
```

## Изменение прав – `chmod`

Права можно задавать **числами**. Каждая группа получает цифру, равную сумме
r = 4, w = 2 и x = 1:

| Число | Права | Типично для |
|---|---|---|
| `755` | `rwxr-xr-x` | Программ и каталогов |
| `644` | `rw-r--r--` | Обычных файлов |
| `600` | `rw-------` | Секретных файлов |

```sh
chmod 644 {{notes}}
```

Или **символами**: `u` (владелец), `g` (группа), `o` (остальные), `a` (все),
затем `+`, `-` или `=` и сами права:

```sh
chmod u+x script.sh
chmod go-w file.txt
```

```predict
$ touch plan.txt
$ chmod 600 plan.txt
$ chmod g+r plan.txt
$ ls -l plan.txt | awk '{print $1}'
-rw-r-----
```

## Скрипты

**Скрипт** – это текстовый файл с командами. Первая строка, `#!/bin/bash`,
называется *shebang* и сообщает системе, какая программа должна выполнять
файл:

```sh
echo '#!/bin/bash' > date.sh
echo 'echo "Сегодня:"; date' >> date.sh
cat date.sh
```

Чтобы запускать скрипт как программу, он должен быть исполняемым:

```sh
chmod +x date.sh
./date.sh
```

`./` нужен потому, что текущий каталог не входит в `PATH`.

```quiz
Вы написали скрипт `test.sh` и запускаете `./test.sh`, но получаете
`Permission denied`. Чего не хватает?
- [ ] `sudo` в начале
- [x] Права на выполнение – сначала выполните `chmod +x test.sh`
- [ ] `./` лишний – нужно писать `test.sh`
---
Чтобы запустить файл как программу, у него должно быть право `x`. `./` здесь
верен: без него shell ищет только в каталогах из `PATH`.
```

## root и sudo

Некоторые файлы, например `/etc/shadow`, где хранятся пароли, может читать
только root. С помощью `sudo` (*superuser do*) вы выполняете одну команду от
имени root:

```sh
sudo whoami
```

В первый раз `sudo` спрашивает **ваш собственный** пароль. Пользоваться sudo
могут только пользователи из группы администраторов. В Ubuntu эта группа
называется **sudo** – её видно среди ваших групп, если выполнить `id`. В
некоторых других дистрибутивах группа называется `wheel`; подробнее о
различиях между дистрибутивами вы прочитаете в части о дистрибутивах.

Если нужно выполнить много команд от имени root, можно запустить root-shell
командой `sudo -i`. Приглашение тогда сменится на `#`. Вернуться можно
командой `exit`.

> **Помните!** С sudo нет никакой страховки. Выполняйте только те команды,
> которые понимаете.

```quiz
`sudo` спрашивает пароль. Чей пароль нужно ввести?
- [ ] Пароль root
- [x] Свой собственный пароль
- [ ] Никакой – просто нажмите Enter
---
`sudo` спрашивает **ваш собственный** пароль и пропускает вас, только если вы
состоите в группе администраторов.
```

### Частая ловушка

```text
sudo echo "text" > /etc/file     # НЕ работает
```

Файл для `>` открывает *ваш* shell, а не sudo. Используйте вместо этого
`tee`, который запускается через sudo:

```sh
echo "127.0.0.1 test.local" | sudo tee -a /etc/hosts
```

```quiz
Почему `sudo echo "text" > /etc/file` не работает?
- [ ] `echo` нельзя запускать через sudo
- [x] Файл для `>` открывает ваш собственный shell, а он работает не от имени root
- [ ] Файлы в `/etc` вообще нельзя изменять
---
sudo действует только на команду (`echo`). Перенаправление выполняет ваш shell,
который работает от вашего имени. Файл записывает программа `tee`, поэтому
sudo нужен именно `tee`.
```
