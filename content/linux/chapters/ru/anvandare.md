# Пользователи и группы

Linux с самого начала создавался так, чтобы много людей могли одновременно
пользоваться одним компьютером. У каждого файла есть владелец, и каждая
программа работает от имени определённого пользователя, – поэтому создание,
изменение и удаление учётных записей – одна из важнейших задач
администратора. В этой главе вы создадите пользователя `kim`, зададите для
этой учётной записи пароль и права sudo и узнаете, где всё это хранится.

## Пользователи и UID

Вы уже знаете, как узнать, кто вы:

```sh
whoami
id
```

`id` показывает, что у вас есть не только имя, но и номер: `uid=1000`. Это
**UID** (*user ID*), и ядро отслеживает именно номер, а не имя. Имя нужно
лишь для того, чтобы нам, людям, не приходилось запоминать числа. Несколько
важных номеров:

| UID | Кто |
|---|---|
| `0` | **root**, администратор. Тот, у кого UID 0, может всё. |
| `1`–`999` | **Системные пользователи** для служб и программ |
| `1000` и выше | **Обычные пользователи** – люди. Первый получает 1000. |

## Список пользователей – `/etc/passwd`

Все пользователи перечислены в текстовом файле `/etc/passwd`, по одной строке
на пользователя:

```sh
cat /etc/passwd
```

В каждой строке семь полей, разделённых двоеточиями. Посмотрите на свою
строку:

```sh
grep elev /etc/passwd
```

```text
elev:x:1000:1000:Elev,,,:/home/elev:/bin/bash
 1   2  3    4      5        6          7
```

| Поле | Значение |
|---|---|
| 1 | Имя пользователя |
| 2 | `x` – пароль хранится в `/etc/shadow` (см. ниже) |
| 3 | UID |
| 4 | GID – номер **основной группы** пользователя |
| 5 | Комментарий, обычно полное имя |
| 6 | Домашний каталог |
| 7 | Shell, который запускается при входе пользователя |

Команда `getent` выполняет тот же поиск. Разница в том, что она находит и
пользователей, которых нет в файле, – например, в школе или компании, где
учётные записи хранятся на центральном сервере:

```sh
getent passwd elev
```

### Системные пользователи

Большинство строк в `/etc/passwd` – не люди. Службы вроде веб-сервера и
системы журналирования работают от имени собственных пользователей с
минимально возможными правами – если их взломают, злоумышленник не доберётся
до ваших файлов. У них shell `nologin`, так что войти под ними никто не
может. В Ubuntu пользователь веб-сервера называется `www-data` (имена
системных пользователей в разных дистрибутивах различаются):

```sh
grep www-data /etc/passwd
```

С помощью `awk` из главы об обработке текста можно вывести всех, у кого UID
1000 или больше, – обычных пользователей:

```sh
awk -F: '$3 >= 1000 {print $1}' /etc/passwd
```

В списке окажется и `nobody` (UID 65534). Это особый пользователь, которому
не принадлежит «ничего»; его используют, когда у программы должно быть как
можно меньше прав.

```predict
$ awk -F: '$3 == 0 {print $1}' /etc/passwd
root
---
Поле 3 – это UID, и UID 0 есть только у root. Права root даёт именно число, а
не имя.
```

## Группы и GID

**Группа** – это способ дать нескольким пользователям одинаковые права,
например на общий каталог проекта. Группы перечислены в `/etc/group`:

```sh
cat /etc/group
```

```text
sudo:x:27:elev
 1   2  3   4
```

Поля – это имя группы, `x`, номер группы (**GID**) и список участников через
запятую.

У каждого пользователя есть **одна основная группа** (поле GID в
`/etc/passwd`), и он может также состоять в любом количестве
**дополнительных групп**. Новые файлы, которые вы создаёте, получают вашу
основную группу. В большинстве дистрибутивов каждый пользователь получает
личную основную группу с тем же именем – `elev` состоит в группе `elev`.

```sh
groups
id
```

```quiz
Вы (`elev`) состоите в группах `elev` и `sudo`, а ваша основная группа – `elev`.
Какую группу получит новый файл, который вы создадите?
- [x] `elev`
- [ ] `sudo`
- [ ] Обе
- [ ] `root`
---
Новые файлы получают вашу **основную** группу – поле GID в `/etc/passwd`.
Дополнительные группы вроде `sudo` дают вам дополнительные права, но на ваши
файлы не попадают.
```

## Пароли – `/etc/shadow`

Обратите внимание на `x` в поле 2 файла `/etc/passwd`. В старые времена
(зашифрованный) пароль хранился прямо там. Проблема в том, что `/etc/passwd`
**должен** быть доступен для чтения всем – именно оттуда `ls -l` берёт имена
владельцев. Значит, кто угодно мог скопировать зашифрованные пароли и
спокойно попытаться их взломать. Поэтому их перенесли в `/etc/shadow`,
который может читать только root:

```sh
ls -l /etc/passwd /etc/shadow
sudo cat /etc/shadow
```

```text
kim:$y$j9T$Tm9...$Kx2...:20756:0:99999:7:::
```

Поле 2 – это не сам пароль, а **хеш**: «отпечаток», который нельзя обратить.
Когда вы входите в систему, вычисляется хеш того, что вы ввели, и
сравнивается с сохранённым. `$y$` означает, что используется метод
*yescrypt*. `!` или `*` вместо хеша означает, что пароля нет или что учётная
запись **заблокирована**. Остальные поля говорят о том, когда пароль меняли в
последний раз и когда истекает его срок. `chage` показывает их понятным
текстом:

```sh
chage -l elev
```

```try
chage -l elev
---
`Password expires: never` – пароль elev никогда не нужно менять.
```

## Создание пользователя – `useradd`

Для создания пользователей нужны права root. Самая распространённая команда
есть в каждом дистрибутиве:

```sh
sudo useradd -m -s /bin/bash kim
```

| Опция | Значение |
|---|---|
| `-m` | Создать домашний каталог `/home/kim` |
| `-s /bin/bash` | Shell пользователя |
| `-c "Kim Svensson"` | Комментарий (полное имя) |
| `-G group1,group2` | Сразу задать дополнительные группы |

`useradd` находит следующий свободный UID начиная с 1000 – `kim` получит
1001. Границы заданы в `/etc/login.defs`. Также создаётся группа `kim`, а
файлы из `/etc/skel` (*skeleton*, «скелет») копируются в новый домашний
каталог. Положите туда что-нибудь – и это получит каждый новый пользователь:

```sh
ls -a /etc/skel
```

В Ubuntu `useradd` скуп: без `-m` домашний каталог **не** создаётся, а без
`-s` shell будет `/bin/sh`. В других дистрибутивах другие значения по
умолчанию, так что приучитесь писать `-m` и `-s` – тогда одна и та же команда
будет работать везде.

Поэтому в Ubuntu есть ещё и более дружелюбный скрипт `adduser`, характерный
для семейства Debian. Он создаёт домашний каталог, выбирает bash и
спрашивает пароль и имя:

```sh
sudo adduser lisa
```

Ответьте на вопросы – на большинство можно просто нажать Enter. `adduser`
умеет также добавлять существующего пользователя в группу:
`sudo adduser lisa sudo`.

`useradd`, `passwd` и остальные команды из этой главы установлены всегда. В
Ubuntu они входят в пакет `passwd`; в других семействах пакет называется
иначе.

## Установка пароля – `passwd`

У новой учётной записи нет пароля (`!` в `/etc/shadow`), так что войти в неё
никто не может. Задайте пароль с помощью `passwd`:

```sh
sudo passwd kim
```

Пароль вводится дважды. **То, что вы вводите, не отображается** – ни
звёздочек, ничего. Так задумано: человек, заглядывающий вам через плечо, не
должен видеть даже длину пароля. Введите его и нажмите Enter.

`passwd` без имени меняет ваш собственный пароль. Менять пароли других
пользователей может только root – попробуйте без sudo:

```sh
passwd root
```

## Группы – `groupadd`, `usermod -aG` и `gpasswd`

Создайте группу и добавьте в неё участника:

```sh
sudo groupadd utvecklare
sudo usermod -aG utvecklare kim
groups kim
```

`-aG` означает *append to Groups* (добавить к группам). **Не забывайте
`-a`!** С одним только `-G` список дополнительных групп заменяется ровно
тем, что вы ввели, – и пользователь удаляется из всех остальных групп,
например из группы sudo. Распространённый способ лишить себя доступа.

```quiz
`kim` состоит в дополнительных группах `sudo` и `utvecklare`. Администратор
выполняет `sudo usermod -G backup kim`. В каких дополнительных группах kim
окажется после этого?
- [ ] `sudo`, `utvecklare` и `backup`
- [x] Только `backup`
- [ ] `sudo` и `utvecklare` – без `-a` команда завершится ошибкой
- [ ] Ни в одной
---
Без `-a` список заменяется ровно тем, что вы ввели. С
`sudo usermod -aG backup kim` kim остался бы и в других группах.
```

`gpasswd` делает то же самое и умеет ещё удалять участников:

```sh
sudo gpasswd -a kim utvecklare
sudo gpasswd -d kim utvecklare
```

На настоящем компьютере новое членство в группе вступает в силу только при
следующем входе пользователя в систему. Симулятор добрее – здесь оно
действует сразу.

Группы используют для общих каталогов. Сделайте группу владельцем и дайте ей
право на запись с помощью `chgrp` и `chmod`:

```sh
sudo mkdir /srv/projekt
sudo chgrp utvecklare /srv/projekt
sudo chmod 775 /srv/projekt
ls -ld /srv/projekt
```

## Выдача прав sudo – группа `sudo`

Кому разрешено пользоваться `sudo`, определяется в `/etc/sudoers`:

```sh
sudo cat /etc/sudoers
```

Строка `%sudo ALL=(ALL:ALL) ALL` означает, что все члены группы **sudo**
могут выполнять любые команды от имени root. Поэтому, чтобы дать кому-то
права sudo, достаточно добавить его в нужную группу – в Ubuntu это группа
`sudo`:

```sh
sudo usermod -aG sudo kim
```

В разных семействах эта группа называется по-разному: в Arch и Fedora она
называется `wheel` – старое название из Unix для «тех, кто главный»
(*big wheel*, «большая шишка»).

Никогда не редактируйте `/etc/sudoers` напрямую обычным редактором – из-за
опечатки может оказаться, что sudo больше никто не может пользоваться.
Используйте `visudo`, который проверяет файл перед сохранением. Обычно
хватает групп.

## Смена пользователя – `su` и `sudo -u`

Стать кем-то другим можно двумя способами:

| Команда | Чей пароль? | Что происходит |
|---|---|---|
| `su - kim` | **kim** | Вы работаете как kim, пока не введёте `exit` |
| `sudo -u kim команда` | **ваш собственный** (нужны права sudo) | Одна команда выполняется от имени kim |
| `sudo -iu kim` | ваш собственный | Login shell от имени kim |

```sh
sudo -u kim whoami
```

С `su` вы действительно переключаетесь. Дефис (`-`) делает это входом в
систему: вы оказываетесь в домашнем каталоге kim с настройками kim.
Приглашение показывает, кто вы, а `exit` возвращает вас обратно:

```sh
su - kim
```

`su` без имени означает root. В Ubuntu у root нет пароля, поэтому `su -` там
не работает – используйте `sudo -i`.

```quiz
Вы хотите выполнить одну команду от имени `kim`, но не знаете пароль kim. Права
sudo у вас есть. Что сработает?
- [ ] `su - kim`
- [x] `sudo -u kim command`
- [ ] `su kim command`
- [ ] Ничего – нужен пароль kim
---
`su` спрашивает пароль того пользователя, которым вы становитесь. `sudo`
спрашивает **ваш собственный** пароль и проверяет в `/etc/sudoers`, что вам
это разрешено.
```

## Блокировка и удаление учётных записей

Учётную запись, которой какое-то время не должны пользоваться, можно
**заблокировать**. `usermod -L` ставит `!` перед хешем в `/etc/shadow`, так
что ни один пароль больше не подходит. `-U` снимает блокировку:

```sh
sudo usermod -L kim
sudo passwd -S kim
sudo usermod -U kim
```

`passwd -S` показывает состояние: `P` (пароль есть), `L` (заблокирована) или
`NP` (пароля нет). С помощью `chage -E` можно задать дату, когда истечёт срок
действия учётной записи, – удобно для летних работников и временных
сотрудников.

Перед удалением кого-либо полезно посмотреть, кто сейчас в системе и когда
кто-то входил в последний раз:

```sh
who
last
```

Затем `userdel` удаляет пользователя. С `-r` удаляется и домашний каталог –
без `-r` файлы остаются:

```sh
sudo useradd -m vikarie
sudo userdel -r vikarie
```

В Ubuntu есть также `deluser`, парный к `adduser`:
`sudo deluser --remove-home vikarie`. `sudo deluser kim sudo` удаляет kim из
группы sudo.

`userdel` отказывается удалять пользователя, который сейчас в системе, –
попробуйте `sudo userdel elev`.

## Итоги

| Команда | Что делает |
|---|---|
| `id`, `groups` | Показывает UID, GID и группы |
| `useradd -m -s /bin/bash имя` | Создаёт пользователя |
| `passwd имя` | Задаёт пароль |
| `usermod -aG группа имя` | Добавляет в группу |
| `groupadd группа` | Создаёт группу |
| `usermod -L` / `-U` | Блокирует / разблокирует |
| `userdel -r имя` | Удаляет пользователя и домашний каталог |
| `su - имя`, `sudo -u имя` | Сменяет пользователя |
| `/etc/passwd`, `/etc/group`, `/etc/shadow` | Где всё это хранится |
