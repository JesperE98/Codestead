# Управление пакетами

В Windows и macOS программы часто скачивают с веб-сайтов. В Linux же почти
всё устанавливается с помощью **пакетного менеджера**. Это самое большое
различие между семействами дистрибутивов – и эта глава выглядит по-разному в
зависимости от выбранного дистрибутива. Сейчас это **{{pm}}** в {{distro}}.

## Пакеты, репозитории и зависимости

- **Пакет** – это программа (или библиотека), упакованная в файл вместе со
  сведениями о её версии и о том, что ей нужно для работы.
- **Репозиторий** – это сервер, на котором дистрибутив публикует все свои
  пакеты. Они проверены и подписаны, так что вы знаете, что их никто не
  подменил.
- **Зависимость** – это другой пакет, который необходим для работы.
  Пакетный менеджер устанавливает зависимости автоматически.

Кроме того, пакетный менеджер следит за тем, что установлено, и может
обновить *всё* на компьютере одной командой.

## Одно и то же – на трёх диалектах

| Что | apt (Debian) | pacman (Arch) | dnf (Red Hat) |
|---|---|---|---|
| Обновить список пакетов | `apt update` | `pacman -Sy` | `dnf check-update` |
| Обновить всё | `apt upgrade` | `pacman -Syu` | `dnf upgrade` |
| Установить | `apt install X` | `pacman -S X` | `dnf install X` |
| Удалить | `apt remove X` | `pacman -R X` | `dnf remove X` |
| Найти | `apt search X` | `pacman -Ss X` | `dnf search X` |
| Информация о пакете | `apt show X` | `pacman -Si X` | `dnf info X` |
| Список установленных | `apt list --installed` | `pacman -Q` | `dnf list --installed` |

Команды, которые меняют систему, требуют прав root, поэтому их запускают через
`sudo`.

## apt в {{distro}}

### update и upgrade – разные вещи

Поначалу это путает почти всех:

- `apt update` загружает **список** доступных пакетов и версий. Он ничего
  не устанавливает.
- `apt upgrade` **устанавливает** новые версии того, что у вас уже есть.

Поэтому всегда сначала выполняйте `update`. Самый распространённый способ
обновить систему:

```sh
sudo apt update && sudo apt upgrade
```

Пока вы не выполнили `apt update` (например, на только что установленном
сервере), список пакетов пуст, и apt вообще не может найти никаких пакетов.

### Установка и удаление

```sh
sudo apt install htop
```

`apt remove` удаляет программу, но оставляет её файлы настроек.
`apt purge` удаляет и их. Когда apt спрашивает `Do you want to continue? [Y/n]`,
заглавная `Y` означает, что простое нажатие Enter – это ответ «да». С опцией
`-y` apt отвечает «да» автоматически.

### apt или apt-get?

`apt` – современный, удобный вариант с индикатором прогресса и цветами.
`apt-get` и `apt-cache` старше, но их вывод стабильнее, поэтому их до сих пор
используют в скриптах.

### Под капотом: dpkg и .deb

Пакеты – это файлы `.deb`, а распаковывает их на самом деле программа
`dpkg`. apt берёт на себя всё остальное: загрузку, зависимости и обновления.
:::

## pacman в {{distro}}

pacman использует короткие опции, где **заглавная буква** – это операция, а
строчные – модификаторы:

| Опция | Означает |
|---|---|
| `-S` | Sync – установить из репозиториев |
| `-R` | Remove – удалить |
| `-Q` | Query – запросить сведения об установленных пакетах |
| `y` | Обновить базу данных пакетов |
| `u` | Обновить все пакеты |
| `s` | Поиск (с -S и -Q) или удаление зависимостей (с -R) |
| `i` | Информация |

### Обновление системы

```sh
sudo pacman -Syu
```

`-Syu` означает: синхронизировать (`S`), обновить базу данных (`y`) и
обновить всё (`u`). Arch – это *rolling release*, так что запускать это
придётся часто.

> **Важно!** Никогда не выполняйте просто `pacman -Sy`, а затем
> `pacman -S пакет`. Новому пакету могут понадобиться более новые библиотеки,
> чем те, что у вас есть, – это так называемое *частичное обновление*
> (partial upgrade), которое может сломать систему. Всегда используйте `-Syu`.

### Установка и удаление

```sh
sudo pacman -S htop
```

`pacman -R пакет` удаляет пакет, а `pacman -Rs пакет` удаляет ещё и
зависимости, которые больше ничему не нужны.

### AUR

Помимо официальных репозиториев есть **AUR** (*Arch User Repository*), где
пользователи делятся рецептами сборки тысяч программ. Для установки оттуда
часто используют помощник вроде `yay` или `paru`. Пакеты в AUR не
проверяются командой Arch – всегда сначала читайте рецепт сборки (PKGBUILD).
:::

## dnf в {{distro}}

### Автоматические метаданные

dnf сам загружает новую информацию о пакетах, когда она нужна, поэтому
отдельного шага вроде `apt update` нет. Если хотите увидеть, какие обновления
доступны, выполните:

```sh
dnf check-update
```

Код возврата равен `100`, если есть обновления, – удобно в скриптах.

### Установка и удаление

```sh
sudo dnf install htop
```

Обратите внимание на вопрос `Is this ok [y/N]`. Заглавная `N` означает, что
по умолчанию ответ – **нет**: если просто нажать Enter, установка
отменится. Введите `y` и нажмите Enter или используйте `-y`.

### Обновление системы

```sh
sudo dnf upgrade
```

### Под капотом: rpm

Пакеты – это файлы `.rpm`, а низкоуровневый инструмент называется `rpm`. dnf
пришёл на смену более старому `yum`, а в Fedora 41 появилась новая версия
**dnf5**, которая заметно быстрее. В RHEL, Rocky и AlmaLinux команда тоже
называется `dnf`.
:::

## Одна программа – разные имена

Обычно пакеты везде называются одинаково – но не всегда. Несколько
примеров:

| Программа | Debian/Ubuntu | Arch | Fedora |
|---|---|---|---|
| Vim | `vim` | `vim` | `vim-enhanced` |
| Python 3 | `python3` | `python` | `python3` |
| SSH-клиент | `openssh-client` | `openssh` | `openssh-clients` |

Если не уверены в имени, всегда ищите через пакетный менеджер.

## Универсальные форматы пакетов

Есть также форматы, которые работают в любом дистрибутиве: **Flatpak**
(распространён для настольных приложений, через Flathub), **Snap** (от
Canonical, по умолчанию в Ubuntu) и **AppImage** (один исполняемый файл). У
них свои команды, и они дополняют пакетный менеджер дистрибутива.
