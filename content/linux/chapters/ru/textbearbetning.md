# Обработка текста: sed, tr и awk

С помощью `grep` можно *находить* строки. Но часто нужно больше: заменить
слово, удалить определённые строки, вытащить столбец или сложить числа.
Тогда в ход идут три классических инструмента:

| Инструмент | Работает с | Типичная задача |
|---|---|---|
| `tr` | отдельными **символами** | перевести в верхний регистр, превратить `:` в переводы строк |
| `sed` | **строками** | заменить слово, удалить строки |
| `awk` | **столбцами** (полями) | выбрать столбцы, сложить, посчитать |

Все три – *фильтры*: они читают текст, что-то с ним делают и пишут результат
в stdout. Поэтому они идеально подходят для конвейеров. А исходный файл
**не** меняется (за одним исключением – `sed -i`, до него мы ещё дойдём).

В `dokument` есть третий учебный файл – CSV-файл с баллами учеников
(*namn* = имя, *ämne* = предмет, *poäng* = баллы):

```sh
cat ~/dokument/betyg.csv
```

CSV расшифровывается как *comma-separated values* (значения, разделённые
запятыми): столбцы разделены запятыми, а первая строка – заголовок.

## Замена символов – `tr`

`tr` (*translate*) заменяет каждый символ из первого набора символом,
стоящим на той же позиции во втором. `a-z` означает все буквы от a до z:

```sh
echo "hello from café" | tr a-z A-Z
```

```text
HELLO FROM CAFé
```

Заметили é? `tr` работает с отдельными *байтами*, а такие буквы, как é, –
или шведские å, ä и ö, и уж тем более кириллица, – не входят в `a-z`. Это
полезно знать: GNU `awk` (о нём ниже) справляется с этим лучше.

`tr` читает **только** из stdin, никогда из файлов. Если нужно обработать
файл, подайте его через `<` или конвейер:

```sh
tr a-z A-Z < ~/dokument/frukter.txt
```

Классический приём – превратить двоеточия в переводы строк (`\n`), чтобы
каждый каталог из `PATH` оказался на отдельной строке:

```sh
echo $PATH | tr ':' '\n'
```

С `-d` (*delete*) символы удаляются, а с `-s` (*squeeze*) несколько
одинаковых символов подряд сжимаются в один:

```sh
echo "070-123 45 67" | tr -d ' -'
echo "слишком     много      пробелов" | tr -s ' '
```

```predict
$ echo "hello world" | tr -d o
hell wrld
---
`-d` удаляет каждую `o`, где бы она ни стояла.
```

Вместо диапазонов можно писать *классы*, например `[:upper:]` (прописные
буквы), `[:lower:]` (строчные), `[:digit:]` (цифры) и `[:space:]` (пробельные
символы):

```sh
echo "Комната 101, этаж 3" | tr -d '[:digit:]'
```

## Потоковый редактор – `sed`

`sed` (*stream editor*) читает текст построчно и выполняет над каждой
строкой маленький *скрипт*. Самая частая команда – `s`, *substitute*
(заменить).

### Замена текста – `s`

```sh
sed 's/ERROR/FEL/' ~/dokument/server.log
```

Скрипт `s/ERROR/FEL/` означает: заменить `ERROR` на `FEL` (по-шведски
«ошибка»). Он имеет вид

```text
s/ШАБЛОН/ЗАМЕНА/ФЛАГИ
```

Без флагов заменяется только **первое** совпадение в каждой строке. С флагом
`g` (*global*) – все:

```sh
echo "cat cat cat" | sed 's/cat/dog/'
echo "cat cat cat" | sed 's/cat/dog/g'
```

```predict
$ echo banana | sed 's/a/o/'
bonana
---
Без `g` заменяется только первая `a` в строке.
```

Флаг `i` делает поиск нечувствительным к регистру, как `grep -i`:

```sh
sed 's/warn/WARNING/i' ~/dokument/server.log
```

Шаблон – это *регулярное выражение*, так же как в `grep`. Здесь мы удаляем
дату в начале каждой строки (`^` = начало строки, `[0-9-]*` = цифры и
дефисы):

```sh
sed 's/^[0-9-]* //' ~/dokument/server.log
```

В замене `&` означает «то, что совпало»:

```sh
echo "Linux – это весело" | sed 's/Linux/**&**/'
```

**Другой разделитель.** Если в самом тексте есть косые черты, получается
каша: `s/\/usr\/local/\/opt/`. Но разделитель задаёт символ сразу после `s`,
так что можно с тем же успехом взять `|` или `#`:

```sh
echo /usr/local/bin | sed 's|/usr/local|/opt|'
```

**Группы.** С `-E` (расширенные регулярные выражения) можно захватывать части
совпадения круглыми скобками и использовать их в замене как `\1`, `\2` …
Здесь мы переворачиваем дату:

```sh
sed -E 's|^([0-9]+)-([0-9]+)-([0-9]+)|\3/\2/\1|' ~/dokument/server.log
```

### Выбор строк – адреса

Перед командой можно написать *адрес*, который выбирает, к каким строкам она
применяется. Команда `d` (*delete*) удаляет строки, а `p` (*print*) выводит
их:

```sh
sed '/INFO/d' ~/dokument/server.log
sed '1d' ~/dokument/betyg.csv
```

Первая удаляет все строки, содержащие `INFO`, вторая удаляет строку 1 –
заголовок.

Обычно `sed` выводит *каждую* строку. С `-n` он перестаёт это делать, и
тогда выводится только то, что просит `p`. Вот как показать строки с 5 по 8:

```sh
sed -n '5,8p' ~/dokument/server.log
```

| Адрес | Означает |
|---|---|
| `5` | строка 5 |
| `$` | последняя строка |
| `/ERROR/` | строки, совпадающие с шаблоном |
| `2,4` | строки со 2 по 4 |
| `/WARN/,/ERROR/` | от строки с WARN до следующей строки с ERROR |
| `/INFO/!` | все строки, **кроме** совпадающих |

Адреса работают с любой командой, в том числе с `s`. Здесь помечаются только
строки с ошибками:

```sh
sed '/ERROR/s/^/>>> /' ~/dokument/server.log
```

Команда `q` (*quit*) останавливает работу после заданной строки, поэтому
`sed 3q` делает то же самое, что `head -n 3`. Несколько команд разделяют
через `;` или несколькими `-e`:

```sh
sed -e '/INFO/d' -e 's/ERROR/FEL/' ~/dokument/server.log
```

### Правка файла на месте – `sed -i`

Всё, что мы делали до сих пор, только *выводилось*. Сам файл не изменился –
можете проверить с помощью `cat`. С `-i` (*in-place*) `sed` записывает
результат обратно в файл. Попробуйте на копии:

```sh
cp ~/dokument/frukter.txt ~/frukter-kopia.txt
sed -i 's/kiwi/kiwifruit/' ~/frukter-kopia.txt
cat ~/frukter-kopia.txt
```

Отменить `sed -i` нельзя. Хороший подход – сначала выполнить команду **без**
`-i` и посмотреть на результат, а потом добавить `-i`, когда всё выглядит
правильно. Если написать `-i.bak`, оригинал к тому же сохранится как
`file.bak`.

```quiz
Вы выполняете `sed 's/kiwi/KIWI/' ~/dokument/frukter.txt`. Что происходит с файлом?
- [ ] Каждое `kiwi` в файле становится `KIWI`
- [ ] Только первое `kiwi` в файле становится `KIWI`
- [x] Ничего – результат только выводится, файл не меняется
---
Без `-i` `sed` пишет только в stdout. Файл остаётся прежним.
```

Конфигурационные файлы в `/etc` принадлежат root, поэтому там нужен
`sudo sed -i ...`. Это распространённый способ изменить настройку из скрипта,
не открывая текстовый редактор.

## Вырезание полей – `cut`

Если файл состоит из полей с разделителем между ними, `cut` может выбрать одно
поле. `-d` задаёт разделитель (*delimiter*), а `-f` – какое поле оставить. Вот
предметы – поле 2 – из CSV-файла:

```sh
cut -d, -f2 ~/dokument/betyg.csv
```

В `/etc/passwd` поля разделены двоеточиями, а поле 1 – имя пользователя,
поэтому `cut -d: -f1 /etc/passwd` выводит всех пользователей. Как и другие
фильтры, `cut` хорошо вписывается в конвейер – например, перед `tr`.

## Столбцы – `awk`

`awk` – на самом деле целый маленький язык программирования, но чаще всего
его используют для одного: работы со **столбцами**. awk разбивает каждую
строку на *поля*:

| Поле | Означает |
|---|---|
| `$1`, `$2` … | первое, второе … поле |
| `$0` | вся строка |
| `NF` | число полей в строке (*number of fields*) |
| `$NF` | последнее поле |
| `NR` | номер строки (*number of record*) |

По умолчанию поля разделяются пробелами (любым их количеством). В
`server.log` поле 3 – это уровень записи в журнале:

```sh
awk '{print $3}' ~/dokument/server.log
```

Программа пишется внутри `{ }` и выполняется для каждой строки. Всегда
заключайте программу awk в **одинарные** кавычки – иначе shell решит, что
`$3` – это переменная shell, и подставит её ещё до запуска awk.

awk отлично вписывается в конвейер. Сколько строк каждого уровня?

```sh
awk '{print $3}' ~/dokument/server.log | sort | uniq -c
```

### Другие разделители – `-F`

С помощью `-F` выбирается разделитель полей. В `/etc/passwd` это двоеточие;
поле 1 – имя пользователя, а поле 7 – его shell:

```sh
awk -F: '{print $1, $7}' /etc/passwd
```

Запятая в `print` превращается в пробел в выводе. Без запятой поля склеиваются,
и тогда можно вставлять свой текст:

```sh
awk -F: '{print $1 " использует " $7}' /etc/passwd
```

Сравните с `cut -d: -f1` из предыдущего раздела. Разница в том, что awk может
менять порядок полей, вставлять текст и справляется с несколькими пробелами
подряд.

```predict
$ echo "Alva,matte,87" | awk -F, '{print $3, $1}'
87 Alva
---
`-F,` разбивает строку по запятым. awk выводит сначала поле 3, затем поле 1, с
пробелом между ними из-за запятой в `print`.
```

### Шаблоны – выбор строк

Перед `{ }` можно написать *шаблон*. Тогда программа выполняется только для
подходящих строк. Шаблоном может быть регулярное выражение, как в `grep`:

```sh
awk '/ERROR/ {print $2}' ~/dokument/server.log
```

… или условие. Текст пишется в двойных кавычках:

```sh
awk -F, '$2 == "matte" {print $1, $3}' ~/dokument/betyg.csv
```

(*Matte* по-шведски – «математика».) Сравнения записываются как `==`, `!=`,
`<`, `<=`, `>` и `>=`, а условия объединяются с помощью `&&` (и), `||` (или)
и `!` (не). Вот все ученики, набравшие не меньше 90 баллов (без `{ }`
выводится вся строка):

```sh
awk -F, '$3 >= 90' ~/dokument/betyg.csv
```

Строка заголовка тоже попала в вывод? В ней поле 3 – это слово `poäng`, а
если значение не число, awk сравнивает его как *текст* – и `"poäng"` идёт в
алфавитном порядке после `"90"`. Заголовок пропускается с помощью `NR > 1`:

```sh
awk -F, 'NR > 1 && $3 >= 90' ~/dokument/betyg.csv
```

Попробуйте собственный шаблон – имена всех, кто изучает *svenska* (шведский
язык):

```try
awk -F, '$2 == "svenska" {print $1}' ~/dokument/betyg.csv
```

### Подсчёт – переменные и `END`

В awk есть переменные, которые не нужно объявлять, – они начинаются с 0.
Блок `END { }` выполняется один раз, **после** последней строки. Вместе они
дают простой способ сложить столбец:

```sh
awk -F, 'NR > 1 {summa += $3} END {print summa}' ~/dokument/betyg.csv
```

`summa += $3` означает «прибавить поле 3 к summa» (*summa* по-шведски –
«сумма»). Если одновременно считать строки (`antal++` увеличивает *antal* –
количество – на 1), можно вычислить среднее:

```sh
awk -F, 'NR > 1 {summa += $3; antal++} END {print "Среднее:", summa / antal}' ~/dokument/betyg.csv
```

Есть ещё `BEGIN { }`, который выполняется **до** первой строки, – удобно для
заголовков. А с помощью `printf` вы точно задаёте вид вывода: `%-8s` – текст,
выровненный по левому краю в поле из 8 символов, а `%5d` – целое число в поле
из 5 символов.

```sh
awk -F, 'BEGIN {print "Ученик   Баллы"} NR > 1 {printf "%-8s %5d\n", $1, $3}' ~/dokument/betyg.csv
```

В awk есть и функции, например `length()`, `toupper()` и `tolower()`:

```sh
awk '{print toupper($0)}' ~/dokument/frukter.txt
```

Присмотритесь к `äpple` и `päron`. В Ubuntu, на которой работает здешний
терминал, `awk` по умолчанию – это **mawk**, маленький и быстрый вариант. Для
простых программ вроде этих разницы вы не заметите – но mawk не переводит å, ä
и ö в верхний регистр с помощью `toupper()`. **GNU awk** (пакет `gawk`), в
отличие от `tr`, это умеет. Дистрибутивы различаются тем, какой awk они
используют и как в них устанавливаются программы, – об этом в главе о
дистрибутивах.

Симулятор знает только часть языка awk – то, что описано здесь, и ещё
немного (`if`, циклы и массивы). Смотрите `man awk`.

## Какой инструмент выбрать?

| Если нужно … | Используйте |
|---|---|
| найти строки, которые что-то содержат | `grep` |
| заменить или удалить отдельные символы | `tr` |
| заменить слова или шаблоны, удалить строки | `sed` |
| выбрать столбцы, сравнить числа, сложить | `awk` |

Настоящая сила – в их сочетании. Какие уровни встречаются среди строк,
которые *не* INFO, если не обращать внимания на регистр?

```sh
grep -v INFO ~/dokument/server.log | awk '{print $3}' | tr A-Z a-z | sort | uniq -c
```
