# まとめ: ネットワーク

このパートでは、ターミナルから小さな家庭内ネットワークを探検しました。自分の
アドレス、インターネットへの出口、名前と DNS、ポート、Web、そして SSH 経由の
ほかのコンピューターです。

## ネットワーク

ネットワーク上のどのコンピューターにも **IP アドレス** があり、`192.168.`、
`10.`、`172.16.`～`172.31.` で始まるアドレスは **プライベート** です。`ip a` は
コンピューターのインターフェースとアドレスを表示します。`lo` はループバック
カードで、`127.0.0.1`（**localhost**）は常にそのコンピューター自身を意味します。
**ネットマスク**（`/24`）は、どのアドレスがローカルネットワーク上にあるかを
示します。それ以外はすべて、デフォルトルートを通って **ゲートウェイ** に送られ
ます。ゲートウェイは `ip route` で確認できます。`ping` は、あるコンピューターに
届くかどうかをテストします。

**DNS** は名前をアドレスに変換します。DNS に問い合わせる前に、コンピューターは
`/etc/hosts` を調べます。`getent hosts` はシステムが名前をどう解決するかを表示し、
`dig` は DNS に直接問い合わせます。Ubuntu では `/etc/resolv.conf` は
systemd-resolved である `127.0.0.53` を指していて、`dig`、`host`、`nslookup` は
`dnsutils` パッケージに含まれています。

**ポート** はコンピューター上のプログラムを指し示すもので、`ss -tulpn` は
どのポートが待ち受けているかを表示します。`curl` は URL を取得して表示し、
`wget` はファイルにダウンロードします。Ubuntu では `wget` は最初から入っていて、
`curl` は apt でインストールします。**SSH** を使うと、ほかのコンピューターで
暗号化された状態でコマンドを実行できます。初回はサーバーのホスト鍵を確認し、
鍵ペアを使えばパスワードはもう要りません。

「インターネットがつながらない」ときは、内側から外側へ順に調べましょう。
アドレス、ルート、ルーター、インターネット上のアドレス、そして最後に名前です。
アドレスでは通じるのに名前では通じないなら、原因は DNS です。

## コマンド

| コマンド | 何をするか |
|---|---|
| `ip a`、`ip -br a`、`hostname -I` | IP アドレスを表示する |
| `ip route` | ルーティングテーブルとゲートウェイを表示する |
| `ping -c 3 HOST` | コンピューターに届くかどうかをテストする |
| `sudo ip link set CARD down` / `up` | ネットワークカードを無効 / 有効にする |
| `cat /etc/resolv.conf` | どの DNS サーバーに問い合わせるか |
| `dig +short NAME`、`dig @SERVER NAME` | DNS で名前を調べる |
| `host NAME`、`nslookup NAME` | 名前を調べる（`host` ではアドレスから名前も） |
| `getent hosts NAME` | システムと同じ方法で調べる（`/etc/hosts` も使う） |
| `sudo tee -a /etc/hosts` | パイプから来たものを root として `/etc/hosts` に追記する |
| `ss -tulpn` | 待ち受けているポートを表示する |
| `curl URL` | 取得して表示する |
| `curl -I URL`、`curl -L URL` | ヘッダーだけ、リダイレクトをたどる |
| `curl -o FILE URL`、`wget URL`、`wget -O FILE URL` | ファイルにダウンロードする |
| `ssh USER@HOST COMMAND` | ほかのコンピューターでコマンドを実行する |
| `ssh-keygen`、`ssh-copy-id USER@HOST` | 鍵ペアを作り、公開鍵をサーバーに置く |
