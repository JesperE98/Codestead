# パッケージ管理

Windows や macOS では、Web サイトからプログラムをダウンロードすることがよく
あります。Linux では、代わりにほとんどすべてを **パッケージマネージャー** で
インストールします。これはディストリビューションのファミリー間で最も大きな違い
です。そのため、この章の内容は選んだディストリビューションによって変わります。
いまは {{distro}} の **{{pm}}** です。

## パッケージ、リポジトリ、依存関係

- **パッケージ** とは、プログラム（またはライブラリ）を、そのバージョンや必要な
  ものについての情報と一緒に 1 つのファイルにまとめたものです。
- **リポジトリ** とは、ディストリビューションがすべてのパッケージを公開している
  サーバーです。パッケージはテストされ、署名されているので、改ざんされていない
  ことがわかります。
- **依存関係** とは、必要とされる別のパッケージのことです。パッケージマネージャー
  は依存関係を自動的にインストールします。

パッケージマネージャーは何がインストールされているかも管理していて、1 つの
コマンドでコンピューター上の *すべて* を更新できます。

## 同じことを 3 つの方言で

| 操作 | apt（Debian） | pacman（Arch） | dnf（Red Hat） |
|---|---|---|---|
| パッケージ一覧を更新 | `apt update` | `pacman -Sy` | `dnf check-update` |
| すべてをアップグレード | `apt upgrade` | `pacman -Syu` | `dnf upgrade` |
| インストール | `apt install X` | `pacman -S X` | `dnf install X` |
| 削除 | `apt remove X` | `pacman -R X` | `dnf remove X` |
| 検索 | `apt search X` | `pacman -Ss X` | `dnf search X` |
| パッケージ情報 | `apt show X` | `pacman -Si X` | `dnf info X` |
| インストール済みの一覧 | `apt list --installed` | `pacman -Q` | `dnf list --installed` |

システムを変更するコマンドには root 権限が必要なので、`sudo` を付けて実行します。

:::debian
## {{distro}} の apt

### update と upgrade は別物

最初はほとんど誰もがここで混乱します。

- `apt update` は、どのパッケージのどのバージョンが利用できるかという **一覧**
  をダウンロードします。何もインストールしません。
- `apt upgrade` は、すでに持っているものの新しいバージョンを **インストール**
  します。

ですから、必ず先に `update` を実行しましょう。システムを更新する最も一般的な
方法は次のとおりです。

```sh
sudo apt update && sudo apt upgrade
```

（たとえばインストールしたばかりのサーバーで）`apt update` を実行する前は、
パッケージ一覧が空なので、apt はパッケージを 1 つも見つけられません。

### インストールと削除

```sh
sudo apt install htop
```

`apt remove` はプログラムを削除しますが、設定ファイルは残します。
`apt purge` は設定ファイルも削除します。apt が `Do you want to continue? [Y/n]`
と聞いてきたとき、大文字の `Y` は Enter を押すだけで yes と答えたことになる
という意味です。`-y` オプションを付けると、apt は自動的に yes と答えます。

### apt と apt-get のどちら？

`apt` は、進行状況バーや色が付いた、現代的で使いやすい形式です。`apt-get` と
`apt-cache` は古いものですが、出力が安定しているので、今でもスクリプトで
使われています。

### 内部のしくみ: dpkg と .deb

パッケージは `.deb` ファイルで、実際にそれを展開しているのは `dpkg` という
プログラムです。apt は、ダウンロード、依存関係、更新など、その周りのことを
すべて引き受けています。
:::

:::arch
## {{distro}} の pacman

pacman では短いオプションを使います。**大文字** が操作を、小文字がその動作を
調整するものを表します。

| オプション | 意味 |
|---|---|
| `-S` | Sync – リポジトリからインストールする |
| `-R` | Remove – 削除する |
| `-Q` | Query – インストール済みのパッケージについて問い合わせる |
| `y` | パッケージデータベースを更新する |
| `u` | すべてのパッケージをアップグレードする |
| `s` | 検索する（-S と -Q と一緒に）、または依存関係を削除する（-R と一緒に） |
| `i` | 情報 |

### システムを更新する

```sh
sudo pacman -Syu
```

`-Syu` は、同期（`S`）し、データベースを更新（`y`）し、すべてをアップグレード
（`u`）するという意味です。Arch は *ローリングリリース* なので、これを頻繁に
実行することになります。

> **重要！** `pacman -Sy` だけを実行してから `pacman -S package` を実行しては
> いけません。新しいパッケージが、手元にあるものより新しいライブラリを必要と
> するかもしれません。これはいわゆる *部分アップグレード* で、システムを
> 壊すおそれがあります。必ず `-Syu` を使いましょう。

### インストールと削除

```sh
sudo pacman -S htop
```

`pacman -R package` はパッケージを削除し、`pacman -Rs package` はほかに何も
必要としていない依存関係も一緒に削除します。

### AUR

公式リポジトリのほかに、**AUR**（*Arch User Repository*）があります。ここでは
ユーザーが何千ものプログラムのビルドレシピを共有しています。AUR からの
インストールには、`yay` や `paru` などのヘルパーがよく使われます。AUR の
パッケージは Arch によるレビューを受けていないので、必ず先にビルドレシピ
（PKGBUILD）を読みましょう。
:::

:::redhat
## {{distro}} の dnf

### 自動のメタデータ

dnf は必要なときに新しいパッケージ情報を自分で取得するので、`apt update` の
ような別の手順はありません。どんな更新があるかを確認したい場合は、次を
実行します。

```sh
dnf check-update
```

更新がある場合、終了コードは `100` になります。スクリプトで便利です。

### インストールと削除

```sh
sudo dnf install htop
```

`Is this ok [y/N]` という質問に注意してください。大文字の `N` は **No** が
既定値であることを意味します。Enter だけを押すと、インストールは取り消されます。
`y` と入力して Enter を押すか、`-y` を使いましょう。

### システムをアップグレードする

```sh
sudo dnf upgrade
```

### 内部のしくみ: rpm

パッケージは `.rpm` ファイルで、低レベルツールは `rpm` という名前です。dnf は
古い `yum` に取って代わったもので、Fedora 41 では大幅に高速になった新しい
バージョン **dnf5** が導入されました。RHEL、Rocky、AlmaLinux でもコマンド名は
`dnf` です。
:::

## 同じプログラム、違う名前

パッケージはたいていどこでも同じ名前ですが、いつもそうとは限りません。
いくつか例を挙げます。

| プログラム | Debian/Ubuntu | Arch | Fedora |
|---|---|---|---|
| Vim | `vim` | `vim` | `vim-enhanced` |
| Python 3 | `python3` | `python` | `python3` |
| SSH クライアント | `openssh-client` | `openssh` | `openssh-clients` |

名前がわからないときは、必ずパッケージマネージャーで検索しましょう。

## ディストリビューションを問わないパッケージ形式

どのディストリビューションでも使える形式もあります。**Flatpak**（Flathub
経由でデスクトップアプリによく使われます）、**Snap**（Canonical 製で、Ubuntu
の標準）、**AppImage**（1 つの実行可能ファイル）です。これらには独自の
コマンドがあり、ディストリビューションのパッケージマネージャーを補う役割を
果たします。
