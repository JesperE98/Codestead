# リンクとファイルの情報

Linux では、ファイルの名前と中身は別々のものです。この章ではそれを利用して
**リンク** でショートカットを作り、`stat` と `file` でファイルを調べる方法を
学び、新しいファイルにどのパーミッションを付けるかを `umask` で決めます。

## 名前と inode

ファイルの中身は、所有者、パーミッション、時刻といっしょに **inode** に
保存されています。ディレクトリは名前の一覧にすぎず、それぞれの名前が 1 つの
inode を指しています。`ls -i` は、それぞれの名前の前に inode 番号を表示します。

```sh
ls -i
```

## シンボリックリンク – `ln -s`

**シンボリックリンク**（*symlink*）は、別の何かへのパスが入った小さなファイル、
つまりショートカットです。`cp` と同じように、リンク先が先で、リンクの名前が
最後です。

```sh
ln -s /var/log ~/log
ls -l ~/log
```

```text
lrwxrwxrwx 1 {{user}} {{user}} 8 Nov  3 10:15 /home/{{user}}/log -> /var/log
```

行の先頭の `l` と矢印 `->` が、リンクであることを示しています。リンクの
パーミッションは常に `rwxrwxrwx` です。これは意味を持たず、効いてくるのは
リンク先のパーミッションです。

ほとんどのコマンドはリンクをたどります。`ls ~/log/`、`cat`、`cd` などです。
`cd` はどの道を通って来たかを覚えていて、`pwd -P` は本当はどこにいるのかを
表示します。

```sh
cd ~/log
pwd
pwd -P
```

### 相対リンク

リンクの中の相対パスは、作ったときにあなたがいた場所からではなく、
**リンクが置かれているディレクトリ** から数えられます。

```sh
cd ~
ln -s {{documents}}/{{fruits}} {{fruits}}
cat {{fruits}}
```

リンクはホームディレクトリにあり、そこに `{{documents}}/{{fruits}}` があるので、
これはうまくいきます。同じ中身のリンク `/tmp/f` は
`/tmp/{{documents}}/{{fruits}}` を探すことになり、壊れたリンクになります。

`readlink` はリンクの中身を表示し、`realpath` はすべてのリンクをたどった
完全なパスを表示します。

```sh
readlink {{fruits}}
realpath {{fruits}}
```

### 壊れたリンク

リンクは、存在しないものを指すこともあります。

```predict
$ ln -s nowhere.txt broken
$ cat broken
cat: broken: No such file or directory
---
リンクは存在しますが、リンクが指すファイルは存在しません。`ls -l` は壊れた
リンクを赤で表示し、`find ~ -type l` はホームディレクトリにあるすべての
リンクを見つけます。
```

`rm` はリンクそのものを削除し、リンク先を削除することは決してありません。

```quiz
リンク `~/log -> /var/log` があり、`rm ~/log` を実行しました。何が起きますか？
- [ ] `/var/log` とその中身がすべて削除される
- [x] リンクだけが削除される。`/var/log` はそのまま残る
- [ ] `~/log` はディレクトリなので、`rm` は実行を拒否する
---
`rm` はリンクそのものに対して働きます。リンク先を削除するには、リンク先を
指定する必要があります。
```

### リンクに出会う場所

Linux システムのいたるところにリンクがあります。`python3` は多くの場合
`python3.12` のような特定のバージョンへのリンクですし、あとで
`systemctl enable` を使ってサービスを起動時に開始するようにすると、systemd は
そのユニットファイルへのリンクを作ります。起動時に開始されるサービスを
見てみましょう。

```try
ls -l /etc/systemd/system/multi-user.target.wants
```

## ハードリンク – `ln`

`-s` を付けないと、`ln` は **ハードリンク** を作ります。同じ inode に
もう 1 つ名前を付けるものです。

```sh
ln {{notes}} {{todo}}
ls -li {{notes}} {{todo}}
```

```text
1310722 -rw-r--r-- 2 {{user}} {{user}} 186 Nov  3 10:20 {{notes}}
1310722 -rw-r--r-- 2 {{user}} {{user}} 186 Nov  3 10:20 {{todo}}
```

どちらの名前も inode 番号が同じで、パーミッションの後ろの数字、つまり
**リンク数** が 2 になっています。これは同じファイルなので、一方の名前で
変更すると、もう一方の名前からもその変更が見えます。どちらかの名前を削除しても、
ファイルに名前が 1 つでも残っている限り、中身は残り続けます。

```predict
$ echo hello > a.txt
$ ln a.txt b.txt
$ echo again >> b.txt
$ rm b.txt
$ cat a.txt
hello
again
---
`a.txt` と `b.txt` は同じファイルでした。`b.txt` を通して書き込んだ行は、
`b.txt` を削除したあとも残っています。
```

| | シンボリックリンク（`ln -s`） | ハードリンク（`ln`） |
|---|---|---|
| 正体 | パスが入った小さなファイル | 同じ inode のもう 1 つの名前 |
| ディレクトリへのリンク | できる | できない |
| 別のファイルシステムへのリンク | できる | できない。inode は 1 つのファイルシステムに属する |
| 元のファイルを削除すると | リンクが壊れる | ファイルは残り続ける |
| `ls -l` での見え方 | `l` と `->` | リンク数が増える |

```quiz
ディレクトリを指すことができるのは、どの種類のリンクですか？
- [x] シンボリックリンクだけ
- [ ] ハードリンクだけ
- [ ] どちらも
---
ディレクトリへのハードリンクは許されていません。ディレクトリへの
ショートカットには `ln -s` を使います。
```

## ファイルのすべて – `stat`

`stat` は inode が知っていることをすべて表示します。

```sh
stat /etc/hostname
```

```text
  File: /etc/hostname
  Size: 7         	Blocks: 8          IO Block: 4096   regular file
Device: 8,3	Inode: 1310755     Links: 1
Access: (0644/-rw-r--r--)  Uid: (    0/    root)   Gid: (    0/    root)
Access: 2026-11-03 10:15:22.000000000 +0100
Modify: 2026-11-03 10:15:22.000000000 +0100
Change: 2026-11-03 10:15:22.000000000 +0100
 Birth: 2026-11-03 10:15:22.000000000 +0100
```

サイズ、inode 番号、リンクの数、数字（`0644`）と文字の両方で表したパーミッション、
所有者とグループ、そしてファイルがいつ読まれ、いつ変更され、いつ情報が
変わったかがわかります。`-c` を使うと、表示するものを正確に選べます。
`%a` は数字で表したパーミッション、`%U` は所有者、`%n` は名前です。

```predict
$ stat -c '%a %U' /etc/shadow
640 root
```

## 中身は何？ – `file`

Linux はファイル名の拡張子を気にしません。`.jpg` という名前のファイルの中身が
何であってもかまいません。`file` は代わりに中身を調べます。

```sh
file /usr/bin/ls {{documents}}/{{grades}} /etc
```

```predict
$ echo hello > {{vacationPic}}
$ file {{vacationPic}}
{{vacationPic}}: ASCII text
---
名前は `.jpg` で終わっていますが、中身はテキストです。`file` が判断の
よりどころにするのは中身のほうです。
```

## 新しいファイルのパーミッション – `umask`

新しいファイルはパーミッション `rw-rw-rw-`（666）、新しいディレクトリは
`rwxrwxrwx`（777）から、**umask** のビットを引いたものになります。`umask` で
umask を表示できます。

```sh
umask
```

ふつうの umask `0022` はグループとその他から書き込みパーミッションを取り除きます。
そのため、あなたのファイルは `644`、ディレクトリは `755` になります。

| umask | 新しいファイル | 新しいディレクトリ | 意味 |
|---|---|---|---|
| `022` | `644` `rw-r--r--` | `755` `rwxr-xr-x` | ふつうの設定 |
| `027` | `640` `rw-r-----` | `750` `rwxr-x---` | グループは読める、その他は何もできない |
| `077` | `600` `rw-------` | `700` `rwx------` | 自分だけ |

```predict
$ umask 027
$ touch plan.txt
$ stat -c %a plan.txt
640
---
666 から 027 を引きます。グループは `w` を失い、その他はすべてを失います。
```

`umask` が影響するのは、そのあとに作られるファイルだけで、しかも実行した
シェルの中だけです。umask を保ち続けるには、その行を `~/.bashrc` に書きます。

```quiz
umask が `077` です。新しいディレクトリにはどのパーミッションが付きますか？
- [ ] `755`
- [ ] `600`
- [x] `700`
---
ディレクトリは 777 から始まります。777 から 077 を引くと 700 になります。
あなたにはすべて、ほかの人には何もありません。
```
