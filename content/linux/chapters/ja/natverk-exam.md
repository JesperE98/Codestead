システムが見つけるのは、`/etc/hosts` にある `localhost` の行です。次の
コマンドは何を表示しますか？

```predict
$ getent hosts localhost
127.0.0.1 localhost
```

`/etc/resolv.conf` によると、Ubuntu はどの DNS サーバーに問い合わせますか？

```predict
$ grep nameserver /etc/resolv.conf
nameserver 127.0.0.53
---
`127.0.0.53` は systemd-resolved です。これは自分のコンピューター上にある
ローカルの仲介役で、そこからさらにルーターに問い合わせます。
```

システムが名前を調べる順番は `/etc/nsswitch.conf` で設定されています。次の
コマンドは何を表示しますか？

```predict

hosts: files dns
---
```

```quiz
`/etc/hosts` に `server.lan` を追加しました。`ping server.lan` は通じますが、
`dig +short server.lan` は何も表示しません。なぜですか？
- [ ] `/etc/hosts` の行が間違っているから
- [x] `dig` は DNS に直接問い合わせ、`/etc/hosts` を無視するから
- [ ] `dig` には `sudo` が必要だから
- [ ] `ping` は名前を使わないから
---
*システム* が名前をどう解決するかを見るには、`getent hosts server.lan` を使います。
```

```quiz
ssh で `server.lan` に接続したところ、サーバーのホスト鍵が変わったと ssh が
大きく警告しました。どういう意味である可能性がありますか？
- [ ] パスワードの有効期限が切れた
- [x] 誰かがサーバーになりすましているかもしれない
- [ ] サーバーに新しいユーザーができた
- [ ] 鍵ペアが壊れている
---
ホスト鍵は、最初に接続したときに `~/.ssh/known_hosts` に保存されています。
```

```quiz
パスワードの代わりに鍵ペアでサーバーにログインしたいです。サーバーに置くのは
どの鍵ですか？
- [x] 公開鍵 `id_ed25519.pub`
- [ ] 秘密鍵 `id_ed25519`
- [ ] 両方
- [ ] どちらでもない。サーバーが自分で作る
---
`ssh-copy-id` は、サーバー上の `~/.ssh/authorized_keys` に公開鍵を追加します。
秘密鍵は決して誰にも見せてはいけません！
```
