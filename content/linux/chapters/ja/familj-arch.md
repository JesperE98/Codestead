# Arch ファミリー: pacman と AUR

Arch Linux、そして Manjaro や EndeavourOS のようにそれをもとにした
ディストリビューションが **Arch ファミリー** を構成しています。どれもパッケージ
マネージャー **pacman** と、`.pkg.tar.zst` 形式のパッケージを使います。この章は
常に Arch ファミリーのディストリビューションで動きます。いまは **{{distro}}** です。

## pacman の要点

| 操作 | コマンド |
|---|---|
| パッケージ一覧を更新 | `pacman -Sy` |
| すべてをアップグレード | `pacman -Syu` |
| インストール | `pacman -S X` |
| 削除 | `pacman -R X` |
| 検索 | `pacman -Ss X` |
| パッケージ情報 | `pacman -Si X` |
| インストール済みの一覧 | `pacman -Q` |

システムを変更するコマンドには root 権限が必要なので、`sudo` を付けて実行します。

pacman では短いオプションを使います。**大文字** が操作を、小文字がその動作を
調整するものを表します。

| オプション | 意味 |
|---|---|
| `-S` | Sync – リポジトリからインストールする |
| `-R` | Remove – 削除する |
| `-Q` | Query – インストール済みのパッケージについて問い合わせる |
| `y` | パッケージデータベースを更新する |
| `u` | すべてのパッケージをアップグレードする |
| `s` | 検索する（-S と -Q と一緒に）、または依存関係を削除する（-R と一緒に） |
| `i` | 情報 |

```quiz
`pacman -Q` の大文字の `Q` はどういう意味ですか？
- [ ] Quit – pacman を終了する
- [x] Query – インストール済みのパッケージについて問い合わせる
- [ ] Quick – 確認せずにインストールする
---
`-Q` はインストール済みのものについて問い合わせ、`-S` はリポジトリから
インストールし、`-R` は削除します。
```

検索には root 権限は要りません。試してみましょう。

```try
pacman -Ss htop
```

## システムを更新する

```sh
sudo pacman -Syu
```

`-Syu` は、同期（`S`）し、データベースを更新（`y`）し、すべてをアップグレード
（`u`）するという意味です。Arch は *ローリングリリース* なので、これを頻繁に
実行することになります。

> **重要！** `pacman -Sy` だけを実行してから `pacman -S package` を実行しては
> いけません。新しいパッケージが、手元にあるものより新しいライブラリを必要と
> するかもしれません。これはいわゆる *部分アップグレード* で、システムを
> 壊すおそれがあります。必ず `-Syu` を使いましょう。

```quiz
`pacman -Sy` を実行してから `pacman -S package` を実行してはいけないのはなぜですか？
- [ ] `-Sy` がパッケージデータベースを削除するから
- [x] 新しいパッケージが手元にあるものより新しいライブラリを必要とするかもしれず、システムを壊すおそれがあるから
- [ ] pacman は 1 日に 1 つのパッケージしかインストールできないから
---
必ず `-Syu` で、すべてを一度にアップグレードしましょう。
```

## インストールと削除

```sh
sudo pacman -S htop
```

`pacman -R package` はパッケージを削除し、`pacman -Rs package` はほかに何も
必要としていない依存関係も一緒に削除します。

## AUR

ディストリビューションのリポジトリには何万ものパッケージがありますが、すべてが
あるわけではありません。マイナーなプログラムはまったく見つからないこともあれば、
古いバージョンしかないこともあります。Arch ファミリーでは、その答えが **AUR**
（*Arch User Repository*）です。

AUR はふつうのリポジトリとは違います。ビルド済みのパッケージはなく、あるのは
**ビルドレシピ** だけです。レシピは `PKGBUILD` と呼ばれる小さな bash
スクリプトで、ソースコードの場所と、プログラムのビルド方法が書かれています。
レシピをダウンロードし、自分でパッケージをビルドして、pacman でインストール
します。AUR は巨大で、Linux 向けに存在するほとんどすべてのものがそろっています。
ただし、レシピは誰でもアップロードできます。

```quiz
AUR からダウンロードするものは何ですか？
- [ ] Arch がレビューした、ビルド済みの `.pkg.tar.zst` パッケージ
- [x] 自分でパッケージをビルドするためのビルドレシピ（`PKGBUILD`）
- [ ] Flatpak
```

### 自己責任で

ディストリビューション自身のリポジトリにあるパッケージは、一緒にテストされ、
署名され、ディストリビューションの開発者によってレビューされています。AUR の
パッケージは Arch によるレビューを受けていません。次のことを覚えておきましょう。

- **パッケージは root としてインストールされます。** パッケージはコンピューターに
  対してどんなことでもできます。レシピを書いた人を、ディストリビューションと同じ
  くらい信頼することになるのです。
- **衝突することがあります。** パッケージが、システム自身のライブラリを
  置き換えたり、手元にあるものとは別のバージョンを必要としたりすることがあります。
- **更新されなくなることがあります。** レシピをメンテナンスしている人が興味を
  なくすと、そのプログラムのセキュリティ更新はもう届きません。

よい目安: まずディストリビューションのリポジトリを探し、次に Flatpak
（ユニバーサルパッケージの章）を探し、それでもなければ AUR を探しましょう。

この章の残りでは、`moonphase` という架空のプログラム（ターミナルに月の満ち欠けを
表示します）を AUR からインストールします。

### 準備

レシピをダウンロードしてパッケージをビルドするには、`git` と `base-devel`
（コンパイラー、`make`、`fakeroot` など）が必要です。

```sh
sudo pacman -S --needed git base-devel
```

`--needed` は、すでにインストールされているものを飛ばします。

### レシピを取得する

AUR のパッケージは、それぞれが独立した git リポジトリです。

```sh
cd ~
git clone https://aur.archlinux.org/moonphase.git
cd moonphase
ls
```

> パッケージ名を打ち間違えると、git は *"You appear to have cloned an empty
> repository"* と表示し、ディレクトリは空になります。AUR は何でもクローン
> させてくれるのです！

### PKGBUILD を読む（毎回！）

```sh
less PKGBUILD
```

`PKGBUILD` はあなたのコンピューター上で実行されるスクリプトです。少なくとも
次の点を確認しましょう。

- `source=` がプログラムの本物の Web サイトからダウンロードしていること。
- `build()` と `package()` がビルドとファイルのコピーだけをしていて、たとえば
  別のものをダウンロードして実行したり（`curl … | sh`）していないこと。
- パッケージがメンテナンスされているように見えること（日付や
  aur.archlinux.org のコメント）。

### ビルドしてインストールする

```sh
makepkg -si
```

`makepkg` は `PKGBUILD` を読み、ソースコードをダウンロードしてビルドし、
`.pkg.tar.zst` ファイルにまとめます。`-s` は足りない依存関係をインストールし、
`-i` は完成したパッケージを pacman でインストールします。makepkg を sudo で
実行しては **いけません**。makepkg は root として実行されるのを拒否し、必要な
ときには自分で sudo を使います。

```sh
ls
moonphase
```

### 「外部」パッケージ

pacman は AUR のことを何も知りません。リポジトリから来たのではないパッケージは
*foreign*（外部）パッケージと呼ばれ、次のコマンドで一覧表示できます。

```sh
pacman -Qm
```

これは、`sudo pacman -Syu` が AUR のパッケージを更新 **しない** ということでも
あります。新しいレシピを自分で取得し（`git pull`）、ビルドし直す必要があります。
あるいは、AUR ヘルパーに任せることもできます。

```quiz
`moonphase` を AUR からインストールし、`sudo pacman -Syu` を実行しました。
`moonphase` は更新されますか？
- [ ] はい。pacman はインストール済みのすべてのパッケージを更新する
- [x] いいえ。pacman は AUR のことを何も知らない
---
`git pull` で新しいレシピを取得してビルドし直すか、AUR ヘルパーを使いましょう。
```

### AUR ヘルパー yay

AUR ヘルパーは、検索、ダウンロード、`PKGBUILD` の表示、ビルド、インストールを
すべて代わりにやってくれます。最もよく使われているのは **yay** です（ほかに
*paru* もあります）。yay 自体は AUR にしかないので、最初の 1 回だけは手で
インストールします。`yay-bin` パッケージはビルド済みで、いちばん手早く済みます。

```sh
cd ~
git clone https://aur.archlinux.org/yay-bin.git
cd yay-bin
makepkg -si
```

そのあとは、yay を pacman とほとんど同じように使えます。ただし sudo は付けません。

```sh
yay -Ss snowfall
yay -S snowfall
snowfall
yay -Syu
```

`yay -Syu`（または単に `yay`）は、リポジトリのパッケージと AUR のパッケージの
両方をアップグレードします。便利になったからといって、レシピを読むのをやめて
よいわけではありません！

AUR には削除するリポジトリがありません。パッケージはそれぞれが独立した
レシピです。もう使っていないものは片付けましょう。
