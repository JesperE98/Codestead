# まとめ: その他のツール

このパートでは、これから先ずっとターミナルで使うことになる 2 つの道具に
出会いました。ファイルの履歴を管理する git と、bash 以外のシェルです。
テストの前に覚えておきたいことをまとめます。

## ターミナルで使う Git

**Git** はバージョン管理システムです。プロジェクト全体のスナップショットを
保存し、誰が何をなぜ変更したかを記録し、過去に戻れるようにしてくれます。
Ubuntu では `sudo apt install git` でインストールします。ほかの
ディストリビューションでは、それぞれのパッケージマネージャーを使います。

- 最初のコミットの前に、`git config --global user.name` と `user.email` で
  自分が誰なのかを git に伝えます。`--global` はすべてのプロジェクトという
  意味で、設定は `~/.gitconfig` に保存されます。
- `git init` はディレクトリを **リポジトリ** にします。履歴はすべて隠し
  ディレクトリ `.git` に入っています。
- 変更は 3 つの場所を通ります。**作業ツリー**（目に見えるファイル）、
  **インデックス**（次のコミットに入るもの）、そして **履歴**（コミット）です。
  `git add` は変更をインデックスに移し、`git commit` はインデックスを新しい
  コミットとして保存します。
- `git commit -a` は、git がすでに追跡している変更済みのファイルをすべて
  追加します。ただし、新しいファイルは決して追加しません。
- `git diff` はまだインデックスにない変更を表示し、`git diff --staged` は
  インデックスにあるものを表示します。
- **ブランチ** は、あるコミットを指し、新しいコミットとともに動いていく
  ラベルです。ブランチを切り替えると、git は作業ツリーを書き換えます。
- `git merge` は、あるブランチを今いるブランチに取り込みます。両方の
  ブランチが同じ行を変更していると **コンフリクト** になります。ファイルを
  直し、`git add` して、`git commit` で仕上げます。
- `.gitignore` には、git に追跡させたくないファイルを書きます。これは git が
  まだ追跡していないファイルにだけ効きます。
- **リモート** とは、どこか別の場所にあるリポジトリのコピーで、たいてい
  `origin` という名前です。`git pull` は取得してマージし、`git push` は自分の
  コミットを送ります。

| コマンド | 何をするか |
|---|---|
| `git config --global user.name "…"` | 自分の名前（と `user.email`）を git に伝える |
| `git init` | ディレクトリをリポジトリにする |
| `git status` | それぞれの変更がどこにあるかを表示する |
| `git add FILE` / `git add .` | 変更をインデックスに入れる |
| `git commit -m "…"` | インデックスを新しいコミットとして保存する |
| `git commit -am "…"` | 追跡中のファイルをすべて追加して、一度にコミットする |
| `git diff` / `git diff --staged` | コミットされていない変更を表示する |
| `git log --oneline --graph --all` | 履歴を表示する |
| `git restore FILE` | ファイルの変更を捨てる |
| `git restore --staged FILE` | ファイルをインデックスから外す |
| `git switch -c BRANCH` / `git switch BRANCH` | ブランチを作る / ブランチを切り替える |
| `git merge BRANCH` | ブランチを今いるブランチにマージする |
| `git branch -d BRANCH` | マージ済みのブランチを削除する |
| `git rm --cached FILE` | ファイルの追跡をやめるが、ディスクには残す |
| `git clone`、`git pull`、`git push` | リモートを通じて共同作業する |

## ほかのシェル: zsh と fish

**シェル** は、あなたが入力したものを読んで、ほかのプログラムを起動します。
`ls` や `grep` のようなプログラムはどのシェルでも同じように動きます。違うのは
そのまわりの言語、つまり変数、ループ、条件分岐、プロンプトです。

- `/etc/shells` には、ログインシェルにしてよいシェルが書かれています。
  ログインシェルは `/etc/passwd` の自分の行の最後のフィールドで、`$SHELL` にも
  入っています。`$0` には今実行しているシェルが入っています。
- **zsh** は bash の構文をほとんどすべて理解し、便利な機能を加えています。
  `**/` はすべてのサブディレクトリを検索し、`autocd` を使うとディレクトリ名を
  入力するだけでそこへ移動できます。オプションは `setopt` と `unsetopt` で
  オン・オフします。bash と違って、zsh は引用符で囲まれていない変数を
  スペースで分割しません。
- **fish** は最初から使いやすいですが、**独自の構文** を持っています。`=` の
  代わりに `set`、`$?` の代わりに `$status`、`$((...))` の代わりに `math` を
  使い、どのブロックも `end` で終わります。どの変数もリストで、1 から番号が
  付きます。
- 起動したシェルは bash の **中で** 動きます。`exit` で戻ります。`-c` を
  付けると、シェルはコマンドを 1 つ実行して終了します。
- スクリプトはこれまでどおり bash（または POSIX `sh`）向けに書きます。
  どのシェルを使っていても、スクリプトをどのシェルで実行するかは `#!` の行が
  決めます。
- `chsh -s` はログインシェルを変更します。変更は次回のログインから有効に
  なります。

| コマンド | 何をするか |
|---|---|
| `cat /etc/shells` | 使ってよいシェルを一覧表示する |
| `echo $0` / `ps` | 今どのシェルを実行しているかを確認する |
| `echo $SHELL` | ログインシェルを確認する |
| `zsh` / `fish` / `exit` | 別のシェルを起動する / 戻る |
| `zsh -c '…'` / `fish -c '…'` | 別のシェルでコマンドを 1 つ実行する |
| `setopt autocd` / `unsetopt autocd` | zsh のオプションをオン / オフにする |
| `set frukt äpple` / `set -e frukt` | fish で変数を設定する / 削除する |
| `set -x NAME value` | fish で環境変数を設定する |
| `math 17 x 23` | fish での計算 |
| `chsh -s /usr/bin/zsh` | ログインシェルを変更する |

設定ファイルは、`~/.bashrc`（bash）、`~/.zshrc`（zsh）、
`~/.config/fish/config.fish`（fish）です。
