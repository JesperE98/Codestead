# プロセスとジョブ

実行中のプログラムはすべて **プロセス** です。いま、このシミュレーション上の
コンピューターでは十数個のプロセスが動いています。システムのサービス、
あなたのシェル、そしてもう 1 つ、このあとすぐに目にすることになる何かです。
この章では、何が動いているかを確認する方法、おかしな動きをするプログラムを
止める方法、そしてバックグラウンドで処理を実行する方法を学びます。

## プロセスとは？

プロセスとは、実行中のプログラムと、それに必要なすべてのもの（メモリ、
開いているファイル、実行しているユーザー）をまとめたものです。どのプロセスにも
**PID**（*process ID*）という識別番号と、それを起動した親プロセスの番号
**PPID** があります。すべてはプロセス番号 1 の `init`（ほぼすべての
ディストリビューションでは `systemd`）から始まり、それがほかのすべてを起動します。

## 自分のプロセス – `ps`

オプションなしの `ps`（*process status*）は、自分のターミナルで動いている
プロセスを表示します。

```sh
ps
```

あなたのシェルである `bash` と、`ps` 自身が表示されます。`ps` は実行している
あいだだけ存在するプロセスです。

## すべてのプロセス – `ps aux`

コンピューター上で動いているものをすべて見るには、`ps aux` を使うのが一般的です。

```sh
ps aux
```

| 列 | 意味 |
|---|---|
| `USER` | プロセスを実行しているユーザー |
| `PID` | プロセスの ID 番号 |
| `%CPU` / `%MEM` | プロセッサとメモリの使用率 |
| `STAT` | 状態: `R` 実行中、`S` スリープ中、`s` セッションリーダー |
| `COMMAND` | プロセスを起動したコマンド |

一覧が長くなるので、`grep` や `sort` と組み合わせることがよくあります。

```sh
ps aux | grep sshd
ps aux --sort=-%cpu | head -5
```

`ps -ef` という形式でも同じプロセスが表示されますが、こちらは親の PID が
独立した列に表示されます。名前がわかっているプロセスの PID だけを知りたい
場合は、`pgrep` があります。

```sh
pgrep -l sshd
```

## リアルタイム表示 – `top` と `htop`

`top` は、プロセッサ時間を多く使っている順にプロセスを並べて表示し、毎秒更新
します。コンピューターを遅くしている原因を探すのにぴったりです。上部には
負荷（*load average*）、プロセス数、メモリが表示されます。

```sh
top
```

本物のターミナルでは、`q` で `top` を終了します。色付きでマウス操作もできる
`htop` を好む人も多いですが、たいていは先にインストールする必要があります。

## プロセスを止める – `kill`

名前は物騒ですが、`kill` が実際にしているのはプロセスに **シグナル** を送る
ことです。標準のシグナル `SIGTERM`（15）は、プロセスに行儀よく終了するよう
お願いします。言うことを聞かない場合は `SIGKILL`（9）を送れば、すぐに強制終了
させられます。ただし、その場合プロセスには保存や後片付けをする機会がありません。

```text
kill 1234        # プロセス 1234 に終了を頼む（SIGTERM）
kill -9 1234     # 強制終了する（SIGKILL）– 最後の手段
```

PID ではなく名前がわかっている場合は、`pkill`（パターンに一致）や
`killall`（名前が完全一致）を使えます。

```text
pkill firefox
killall firefox
```

シグナルを送れるのは **自分の** プロセスだけです。root やほかのユーザーの
プロセスには `sudo` が必要です。

> **見つけて止めよう！** このコンピューターでは、あるプロセスがプロセッサを
> ほぼ 100 % 使っています。`top` か `ps aux --sort=-%cpu` を使って、その名前と
> PID を突き止め、止めてみましょう。

## フォアグラウンドとバックグラウンド

コマンドを実行すると、シェルはそれが終わるまで待ちます。これを
**フォアグラウンド** で実行すると言います。行末に `&` を付けると、代わりに
**バックグラウンド** で実行され、すぐにプロンプトが戻ってきます。

```sh
sleep 300 &
```

シェルは角かっこで囲んだジョブ番号とプロセスの PID を返します。たとえば
`[1] 4200` のようになります。ターミナルから起動したプログラムは **ジョブ**
と呼ばれます。

```sh
jobs
```

| コマンド | 動作 |
|---|---|
| `jobs` | このターミナルのジョブを一覧表示する |
| `fg %1` | ジョブ 1 をフォアグラウンドに戻す |
| `bg %1` | 停止しているジョブをバックグラウンドで再開する |
| `kill %1` | ジョブ 1 を終了する |
| `Ctrl+C` | フォアグラウンドのプログラムを中断する |
| `Ctrl+Z` | フォアグラウンドのプログラムを一時停止する（`fg` か `bg` で再開） |

`$!` 変数には、直前のバックグラウンドジョブの PID が入っています。ジョブが
終わると、シェルは `[1]+  Done   sleep 300` のような行で知らせてくれます。

## コンピューターの調子はどう？

2 つの小さなコマンドで、手早く全体を把握できます。

```sh
uptime
free -h
```

`uptime` は、コンピューターが起動してからの時間と、直近 1 分・5 分・15 分の
負荷を表示します。`free -h` はメモリの使用量を表示します。*available* の列に
注目してください。Linux は空いているメモリをファイルのキャッシュとして
使うので、メモリが十分にあっても *free* の値は少なく見えることがよくあります。

## どこでも同じ

プロセスはどのディストリビューションでも同じように動きます。ツールは
**procps** パッケージ（Arch と Fedora では `procps-ng`）に、`killall` は
**psmisc** に含まれています。違うのは、最初からどのサービスが動いているかです。
{{distro}} とほかのディストリビューションで `ps aux` を比べてみましょう！
