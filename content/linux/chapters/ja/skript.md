# シェルスクリプト

これまでターミナルに入力してきたものは、すべてファイルに保存して何度でも
実行できます。そのようなファイルを **スクリプト** と呼びます。スクリプトを
使えば、バックアップ、100 個のファイルの名前の変更、毎朝のログの確認など、
退屈な作業を自動化できます。さらに bash は、変数、条件分岐、ループ、関数を
備えた本格的なプログラミング言語でもあります。

## はじめてのスクリプト

スクリプトはただのテキストファイルです。本物のコンピューターでは、`nano` や
`vim` などのテキストエディターで書くのが普通です。ここでもサーバーでも使える
別の方法として、**ヒアドキュメント** があります。`<< 'SLUT'` と `SLUT` だけの
行のあいだに書いたものが、すべてコマンドに渡されます。（*slut* はスウェーデン語で
「終わり」という意味にすぎません。好きな単語を選べます。`EOF` がよく使われます。）

1 行目を入力して Enter を押してください。プロンプトが `> ` に変わります。
シェルが残りを待っているのです。1 行ずつ入力し、最後に `SLUT` で終えます。

```sh
cat > hej.sh << 'SLUT'
#!/bin/bash
echo "スクリプトからこんにちは！"
echo "今日は $(date) です"
SLUT
```

1 行目の `#!/bin/bash` は *シバン*（shebang）と呼ばれ、どのプログラムで
ファイルを実行するかをシステムに伝えます。スクリプトを実行可能にして、
実行してみましょう。

```sh
chmod +x hej.sh
./hej.sh
```

`#` で始まる行（シバンの行を除く）は **コメント** で、シェルはそれを読み
飛ばします。コードが何をしているのかを説明するのに使いましょう！

## 変数

変数は `name=value` で作成します。イコール記号の前後にスペースを入れては
**いけません**。入れると、シェルは `name` をコマンドだと思ってしまいます。

```sh
stad=Göteborg
echo "私は $stad に住んでいます"
```

（*stad* は「都市」という意味です。）変数を使うときは、必ず **ダブルクォート**
で囲みましょう。囲まないと値がスペースで分割されてしまい、ファイル名に
スペースが含まれているときにおかしなエラーが起きます。変数名のすぐ後ろに
テキストを書きたい場合は、波かっこを使います: `"${stad}_2026"`。波かっこが
ないと、bash は `stad_2026` という名前の変数を探してしまいます。

```quiz
`stad` には `Göteborg` が入っていて、`stad_2026` という変数はありません。
`echo "$stad_2026"` は何を表示しますか？
- [ ] `Göteborg_2026`
- [ ] `Göteborg`
- [x] 空の行
---
bash は `stad_2026` 全体を名前として読みますが、その変数は存在しません。
`Göteborg_2026` を得るには `"${stad}_2026"` と書きます。
```

## コマンド置換 – `$(...)`

`$(command)` は、そのコマンドが出力したものに置き換えられます。こうして
コマンドの結果を変数に保存できます。

```sh
idag=$(date)
filer=$(ls ~ | wc -l)
echo "ホームディレクトリには $filer 個の項目があります"
```

## 算術演算 – `$(( ))`

bash は `$(( ))` の中で整数の計算をします。かっこの中では、変数の前に `$` を
付ける必要はありません。

```sh
a=7
echo $(( a * 6 ))
echo $(( 17 / 5 )) remainder $(( 17 % 5 ))
```

変数の値を変えるには、`(( a++ ))` や `(( a += 10 ))` と書きます。

```predict
$ echo $(( 7 / 2 )) $(( 7 % 2 ))
3 1
---
bash は整数でしか計算しません。7 / 2 は 3 で、余り（`%`）は 1 です。
```

## 引数

`./skript.sh one two` を実行すると、スクリプトは引数を読み取れます。

| 変数 | 中身 |
|---|---|
| `$0` | スクリプトの名前 |
| `$1`, `$2` ... | 1 番目、2 番目 ... の引数 |
| `$#` | 引数の数 |
| `"$@"` | すべての引数（1 つずつ別々に） |
| `$?` | 直前のコマンドの終了コード |

```quiz
スクリプトを `./skript.sh red green blue` で実行しました。`$1` と `$#` には
何が入っていますか？
- [ ] `$1` は `./skript.sh`、`$#` は `4`
- [x] `$1` は `red`、`$#` は `3`
- [ ] `$1` は `red`、`$#` は `blue`
---
スクリプト自身の名前は `$0` に入るので、`$#` には数えられません。
```

## 条件分岐 – `if`

`if` はコマンドを実行し、その **終了コード** を見ます。0 なら真、それ以外は
偽です。たいていは `[` コマンド（`test` とも呼ばれます）を使います。

```sh
if [ -f ~/.bashrc ]; then echo "ファイルがあります"; else echo "ファイルがありません"; fi
```

`[ ]` の内側のスペースは必須です！ スクリプトのように複数行で書くと、
次のようになります。

```text
if [ "$answer" = "yes" ]; then
    echo "Great!"
elif [ "$answer" = "no" ]; then
    echo "Too bad."
else
    echo "Please answer yes or no."
fi
```

よく使うテスト:

| テスト | 真になる条件 |
|---|---|
| `-f FILE` | ファイルが存在する（かつ通常のファイルである） |
| `-d DIR` | ディレクトリが存在する |
| `-z "$x"` | 変数が空である |
| `"$a" = "$b"` | 文字列が等しい（`!=` は異なる） |
| `$a -eq $b` | 数値が等しい |
| `$a -lt $b` | より小さい（`-le`、`-gt`、`-ge`、`-ne`） |
| `! CONDITION` | 条件が真 *ではない* |

数値は `-eq` や `-lt` などで比較し、`=` や `<` はテキストを比較することに注意
してください。bash には少し賢い `[[ ... ]]` もあります。その中では `&&` や
`||` を書けますし、`[[ $file == *.txt ]]` のようにパターンとの一致も調べられます。

短い条件なら、`&&` と `||` で十分なことがよくあります。

```sh
[ -d ~/bilder ] && echo "bilder ディレクトリがあります"
```

```predict
$ x=""
$ if [ -z "$x" ]; then echo empty; else echo "not empty"; fi
empty
```

## ループ

**for ループ** は、リストの各項目に対して同じことを行います。

```sh
for frukt in äpple banan kiwi; do echo "$frukt が好きです"; done
```

リストはワイルドカードやコマンドから作ることもできます。

```sh
for fil in ~/dokument/*; do echo "ファイル: $fil"; done
for i in $(seq 1 3); do echo "$i 回目"; done
```

**while ループ** は、条件が真であるあいだ続きます。

```sh
i=1; while [ $i -le 3 ]; do echo $i; (( i++ )); done
```

ファイルを 1 行ずつ処理する最も一般的な方法は `while read` で、`done` の後ろの
`<` でファイルを渡します。

```sh
while read rad; do echo "> $rad"; done < ~/dokument/frukter.txt
```

`break` でループを抜け、`continue` ですぐに次の回へ進みます。

```predict
$ for x in 2 4 6; do echo $(( x * 10 )); done
20
40
60
```

> **無限ループに注意！** 条件がいつまでも偽にならないループは、永遠に
> 続きます。本物のターミナルでは **Ctrl+C** で止めます。シミュレーターは
> 20,000 ステップで自動的に止めます。

## `case` で選ぶ

変数がさまざまな値を取りうる場合は、`elif` を長くつなげるより `case` のほうが
わかりやすくなります。

```sh
fil=semester.jpg
case $fil in *.jpg|*.png) echo "画像";; *.txt) echo "テキストファイル";; *) echo "不明な種類";; esac
```

各選択肢は `;;` で終わり、`*)` はそれ以外のすべてを受け止めます。

## 関数

**関数** とは名前を付けたコードのまとまりで、独立したコマンドのように
呼び出せます。引数はスクリプトと同じように `$1`、`$2`、`$#` で受け取ります。

```sh
halsa() { echo "こんにちは、$1 さん。ようこそ！"; }
halsa Kim
```

関数の中だけで使う変数は `local` で作成し、`return` で終了コードを返して
関数を終えます。

## ユーザーに尋ねる – `read`

`read` はキーボードから 1 行読み込んで変数に入れます。

```sh
read -p "お名前は？ " namn; echo "こんにちは、$namn さん！"
```

## 完全な例

この章で扱ったことのほとんどを使ったスクリプトです。引数として渡された
ファイルのバックアップを取ります。

```text
#!/bin/bash
# backup.sh – 各ファイルを file.bak にコピーする

if [ $# -eq 0 ]; then
    echo "Usage: $0 FILE..."
    exit 1
fi

for file in "$@"; do
    if [ -f "$file" ]; then
        cp "$file" "$file.bak"
        echo "Copied $file"
    else
        echo "Cannot find $file" >&2
    fi
done
```

`exit 1` は終了コード 1 でスクリプトを終了させます。こうすると、スクリプトを
呼び出した側は何か問題があったことがわかります。

## よいスクリプトを書くためのヒント

- `#!/bin/bash` で始め、コメントを書きましょう。
- 変数は引用符で囲みましょう。`$file` ではなく `"$file"` です。
- 多くの人はスクリプトの最初に `set -euo pipefail` と書きます。こうすると、
  スクリプトはやみくもに処理を続けるのではなく、最初のエラーで止まります。
- **ShellCheck** というプログラムは、bash スクリプトによくある間違いを見つけて
  くれます。主要なディストリビューションならどれでも、パッケージマネージャーで
  インストールできます。
