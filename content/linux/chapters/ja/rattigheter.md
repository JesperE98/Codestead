# ユーザー、パーミッション、sudo

Linux は、複数のユーザーが同じコンピューターを共有できるように作られています。
そのため、すべてのファイルには所有者と、誰が何をしてよいかを決めるルールが
あります。

## ユーザーとグループ

あなたはユーザー `{{user}}` としてログインしています。どのユーザーも 1 つ以上の
**グループ** に属しています。

```sh
id
```

最も重要なユーザーは **root** です。root は何でもできる管理者です。root として
ログインすることはめったにありません。代わりに `sudo` を使います（後述）。

## パーミッションを読む

`ls -l` を実行して、最初の列を見てみましょう。

```text
drwxr-xr-x 2 {{user}} {{user}} 4096 Oct 29 13:55 {{documents}}
-rw-r--r-- 1 {{user}} {{user}}  227 Oct 29 13:55 {{notes}}
```

最初の文字は種類を表します。`-` はファイル、`d` はディレクトリです。その後に
3 文字ずつのまとまりが 3 つ続きます。

```text
-     rw-     r--     r--
種類  所有者  グループ その他
```

| 文字 | ファイルの場合 | ディレクトリの場合 |
|---|---|---|
| `r`（read） | 内容を読む | 内容を一覧表示する |
| `w`（write） | 内容を変更する | 中にファイルを作成・削除する |
| `x`（execute） | ファイルをプログラムとして実行する | `cd` でディレクトリに入る |

その後に所有者（`{{user}}`）とグループ（`{{user}}`）が続きます。

```quiz
あるディレクトリのパーミッションが `drwxr-x---` です。グループのメンバーは何ができますか？
- [ ] 何もできない
- [x] 内容を一覧表示し、`cd` で入れるが、中にファイルを作成・削除することはできない
- [ ] 所有者ができることはすべてできる
---
グループのまとまりは `r-x` です。`r` で内容を一覧表示でき、`x` でディレクトリに
入れます。`w` がないので、中にファイルを作成・削除することはできません。
```

## パーミッションを変更する – `chmod`

パーミッションは **数字** で指定できます。各まとまりは、r = 4、w = 2、x = 1
の合計である 1 桁の数字で表します。

| 数字 | パーミッション | よく使う対象 |
|---|---|---|
| `755` | `rwxr-xr-x` | プログラムとディレクトリ |
| `644` | `rw-r--r--` | 通常のファイル |
| `600` | `rw-------` | 秘密のファイル |

```sh
chmod 644 {{notes}}
```

**記号** でも指定できます。`u`（所有者）、`g`（グループ）、`o`（その他）、
`a`（全員）の後に、`+`、`-`、`=` のいずれかとパーミッションを続けます。

```sh
chmod u+x script.sh
chmod go-w file.txt
```

```predict
$ touch plan.txt
$ chmod 600 plan.txt
$ chmod g+r plan.txt
$ ls -l plan.txt | awk '{print $1}'
-rw-r-----
```

## スクリプト

**スクリプト** は、コマンドを書いたテキストファイルです。1 行目の
`#!/bin/bash` は *シバン*（shebang）と呼ばれ、どのプログラムでファイルを
実行するかをシステムに伝えます。

```sh
echo '#!/bin/bash' > today.sh
echo 'echo "今日の日付:"; date' >> today.sh
cat today.sh
```

スクリプトをプログラムとして実行するには、実行可能にする必要があります。

```sh
chmod +x today.sh
./today.sh
```

今いるディレクトリは `PATH` に含まれていないので、`./` が必要です。

```quiz
スクリプト `test.sh` を書いて `./test.sh` を実行しましたが、
`Permission denied` と表示されました。何が足りないのでしょうか？
- [ ] 前に付ける `sudo`
- [x] 実行パーミッション。先に `chmod +x test.sh` を実行する
- [ ] `./`。`test.sh` と書くべき
---
ファイルをプログラムとして実行するには `x` パーミッションが必要です。`./` は
正しい書き方です。これがないと、シェルは `PATH` にあるディレクトリしか探しません。
```

## root と sudo

パスワードが保存されている `/etc/shadow` のように、root しか読めないファイルも
あります。`sudo`（*superuser do*）を使うと、1 つのコマンドを root として
実行できます。

```sh
sudo whoami
```

初回は、`sudo` が **あなた自身の** パスワードを尋ねます。sudo を使えるのは、
管理者グループに属するユーザーだけです。Ubuntu では、そのグループは **sudo** という
名前です。`id` を実行すると、自分のグループの中に見つかります。ほかの
ディストリビューションには、このグループを `wheel` と呼ぶものもあります。
ディストリビューションごとの違いについては、ディストリビューションのパートで
詳しく読めます。

root としてたくさんのコマンドを実行する必要がある場合は、`sudo -i` で root
シェルを起動できます。プロンプトが `#` に変わります。`exit` で元に戻ります。

> **覚えておきましょう！** sudo には安全網がありません。理解している
> コマンドだけを実行しましょう。

```quiz
`sudo` がパスワードを尋ねてきました。誰のパスワードを入力しますか？
- [ ] root のパスワード
- [x] あなた自身のパスワード
- [ ] パスワードは不要。Enter を押すだけ
---
`sudo` は **あなた自身の** パスワードを尋ね、あなたが管理者グループに属している
場合にだけ通してくれます。
```

### よくある落とし穴

```text
sudo echo "text" > /etc/file     # これはうまくいかない
```

`>` のためにファイルを開くのは sudo ではなく、*あなたの* シェルです。
代わりに、sudo 付きで実行される `tee` を使いましょう。

```sh
echo "127.0.0.1 test.local" | sudo tee -a /etc/hosts
```

```quiz
`sudo echo "text" > /etc/file` がうまくいかないのはなぜですか？
- [ ] `echo` は sudo で実行できないから
- [x] `>` のためにファイルを開くのはあなた自身のシェルで、それは root として動いていないから
- [ ] `/etc` のファイルは決して変更できないから
---
sudo が適用されるのはコマンド（`echo`）だけです。リダイレクトはあなたとして動く
シェルが処理します。ファイルに書き込むプログラムは `tee` なので、sudo が必要なのは
`tee` のほうです。
```
