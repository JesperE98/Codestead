# Debian ファミリー: apt と PPA

Debian、Ubuntu、そして Linux Mint のようにそれらをもとにしたディストリビューションが
**Debian ファミリー** を構成しています。どれもパッケージマネージャー **apt** と、
`.deb` 形式のパッケージを使います。この章は常に Debian ファミリーの
ディストリビューションで動きます。いまは **{{distro}}** です。上部のメニューで
Ubuntu と Debian を切り替えられます。

## apt の要点

| 操作 | コマンド |
|---|---|
| パッケージ一覧を更新 | `apt update` |
| すべてをアップグレード | `apt upgrade` |
| インストール | `apt install X` |
| 削除 | `apt remove X` |
| 検索 | `apt search X` |
| パッケージ情報 | `apt show X` |
| インストール済みの一覧 | `apt list --installed` |

システムを変更するコマンドには root 権限が必要なので、`sudo` を付けて実行します。

```quiz
次のうち、システムを変更するので `sudo` が必要なコマンドはどれですか？
- [x] `apt install htop`
- [ ] `apt search htop`
- [x] `apt remove htop`
- [ ] `apt show htop`
---
検索と情報の表示は、パッケージ一覧を読むだけです。インストールと削除は
システムを変更します。
```

## update と upgrade は別物

最初はほとんど誰もがここで混乱します。

- `apt update` は、どのパッケージのどのバージョンが利用できるかという **一覧**
  をダウンロードします。何もインストールしません。
- `apt upgrade` は、すでに持っているものの新しいバージョンを **インストール**
  します。

ですから、必ず先に `update` を実行しましょう。システムを更新する最も一般的な
方法は次のとおりです。

```sh
sudo apt update && sudo apt upgrade
```

（たとえばインストールしたばかりのサーバーで）`apt update` を実行する前は、
パッケージ一覧が空なので、apt はパッケージを 1 つも見つけられません。

```quiz
`sudo apt update` は何をしますか？
- [x] どのパッケージのどのバージョンが利用できるかという一覧をダウンロードする
- [ ] すでに持っているパッケージの新しいバージョンをインストールする
- [ ] apt 自身を最新バージョンに更新する
---
`apt update` は一覧を更新するだけです。新しいバージョンをインストールするのは
`apt upgrade` です。
```

## インストールと削除

```sh
sudo apt install htop
```

`apt remove` はプログラムを削除しますが、設定ファイルは残します。
`apt purge` は設定ファイルも削除します。apt が `Do you want to continue? [Y/n]`
と聞いてきたとき、大文字の `Y` は Enter を押すだけで yes と答えたことになる
という意味です。`-y` オプションを付けると、apt は自動的に yes と答えます。

検索には root 権限は要りません。試してみましょう。

```try
apt search htop
```

### apt と apt-get のどちら？

`apt` は、進行状況バーや色が付いた、現代的で使いやすい形式です。`apt-get` と
`apt-cache` は古いものですが、出力が安定しているので、今でもスクリプトで
使われています。

### 内部のしくみ: dpkg と .deb

パッケージは `.deb` ファイルで、実際にそれを展開しているのは `dpkg` という
プログラムです。apt は、ダウンロード、依存関係、更新など、その周りのことを
すべて引き受けています。

## 追加リポジトリ – 便利だけれど、自己責任で

ディストリビューションのリポジトリには何万ものパッケージがありますが、すべてが
あるわけではありません。マイナーなプログラムはまったく見つからないこともあれば、
古いバージョンしかないこともあります。そのために、開発者やユーザーが自分の
パッケージを共有する **追加リポジトリ** があります。

ディストリビューション自身のリポジトリにあるパッケージは、一緒にテストされ、
署名され、ディストリビューションの開発者によってレビューされています。一方、
追加リポジトリは誰でも作れます。追加する前に、次のことを覚えておきましょう。

- **パッケージは root としてインストールされます。** パッケージはコンピューターに
  対してどんなことでもできます。それを作った人を、ディストリビューションと同じ
  くらい信頼することになるのです。
- **衝突することがあります。** 追加リポジトリのパッケージが、システム自身の
  ライブラリを置き換えたり、手元にあるものとは別のバージョンを必要としたりする
  ことがあります。
- **更新されなくなることがあります。** リポジトリを運営している人が興味を
  なくすと、そのプログラムのセキュリティ更新はもう届きません。

よい目安: まずディストリビューションのリポジトリを探し、次に Flatpak
（ユニバーサルパッケージの章）を探し、それでもなければ、信頼できる人の
追加リポジトリを探しましょう。

## PPA

**PPA**（*Personal Package Archive*）は、Canonical の Ubuntu 向けサービスである
Launchpad 上の小さなリポジトリです。開発者がソースコードをアップロードすると、
Launchpad がさまざまな Ubuntu リリース向けに `.deb` パッケージをビルドします。
PPA は `ppa:ユーザー/名前` と書きます。PPA はディストリビューションによる
レビューを受けていません。

この章の残りでは、`moonphase` という架空のプログラム（ターミナルに月の満ち欠けを
表示します）を PPA からインストールします。

### add-apt-repository ツール

PPA は `add-apt-repository` で追加します。このコマンドは
`software-properties-common` パッケージに含まれています。Ubuntu には最初から
入っていますが、Debian には入っていません。

```sh
sudo apt update
sudo apt install software-properties-common
```

### PPA を追加する

```sh
sudo add-apt-repository ppa:lunatool/moonphase
```

何が追加されるのかと、PPA の説明が表示されます。Enter を押すと続行します
（`-y` を付けると質問を省略できます）。このとき 2 つのことが起こります。

1. `/etc/apt/sources.list.d/` にファイルが作られます。そこにはリポジトリの
   場所と、パッケージの署名に使われている鍵が書かれています。
2. `add-apt-repository` が代わりに `apt update` を実行します。そうしないと、
   apt は新しいパッケージのことを知りません。ソースを手で（ファイルを作って）
   追加した場合は、そのあと自分で `sudo apt update` を実行する必要があります。

```quiz
`/etc/apt/sources.list.d/` にファイルを作って、リポジトリを手で追加しました。
apt がそこからパッケージをインストールできるようにするには、何が必要ですか？
- [ ] 何もしなくてよい。次にインストールするとき、apt が自分でファイルを読む
- [x] `sudo apt update` を実行する
- [ ] コンピューターを再起動する
---
`add-apt-repository` は代わりに `apt update` を実行してくれます。ファイルを
自分で作った場合は、自分で実行する必要があります。
```

ファイルを見てみましょう。

```sh
ls /etc/apt/sources.list.d
cat /etc/apt/sources.list.d/lunatool-ubuntu-moonphase-noble.sources
```

`Suites: noble` に注目してください。パッケージは Ubuntu 24.04 向けにビルドされて
います。

### インストールして実行する

これで、パッケージは他のパッケージとまったく同じようにインストールできます。

```sh
sudo apt install moonphase
moonphase
```

### パッケージはどこから来たのか？

`apt policy` は、パッケージがどのリポジトリにあり、どれが優先されるのかを表示
します。

```sh
apt policy moonphase
```

`***` はインストールされているバージョンを示します。数字の `500` はリポジトリの
優先度で、`100` は「すでにインストールされているもの」を意味します。同じ
パッケージが複数のリポジトリにある場合、apt は最も新しいバージョンを選びます。
そのため、PPA はディストリビューション自身のパッケージを独自のバージョンで
置き換えることがあります。

```quiz
同じパッケージが、ディストリビューションのリポジトリと、追加した PPA の両方に
あります。apt はどのバージョンを選びますか？
- [ ] 常にディストリビューションのリポジトリにあるもの
- [ ] 最後に追加されたリポジトリにあるもの
- [x] 最も新しいバージョン
---
だから PPA は、ディストリビューション自身のパッケージを置き換えることがあるのです。
```

### Debian で PPA？

PPA は Debian ではなく Ubuntu 向けにビルドされています。Debian でも動くことは
ありますが、パッケージが Debian にあるものとは別のライブラリのバージョンを
必要とすることがあります。Debian と Ubuntu のパッケージが混ざったものは、冗談で
*FrankenDebian* と呼ばれ、システムを壊すよくある原因です。Debian では、
*backports*、Flatpak、または開発者自身が用意した Debian 向けリポジトリを使う
ほうがよいでしょう。

### 更新と PPA の削除

PPA のパッケージは、ほかのすべてと一緒に `sudo apt update && sudo apt upgrade`
で更新されます。PPA を削除するには次のようにします。

```sh
sudo add-apt-repository --remove ppa:lunatool/moonphase
```

プログラムは残りますが、もう更新は届きません。完全に取り除くには、
`sudo apt remove moonphase` も実行します。

リポジトリを 1 つ追加するたびに、信頼する相手が 1 人増えることになります。
一覧は短く保ち、もう使っていないものは片付けましょう。
