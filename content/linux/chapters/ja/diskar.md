# ディスクとファイルシステム

保存したファイルは、実際にはどこに置かれるのでしょうか？ Windows では、
答えは `C:`、`D:`、`E:` のようなドライブ文字です。Linux にはドライブ文字が
まったくなく、`/` から始まる **1 つ** のディレクトリツリーがあるだけです。
この章では内部の仕組みをのぞいてみます。コンピューターにどんなディスクがあるか、
それがどう分割されているか、空き容量はどれくらいか、そして USB メモリを
差し込み、何も失わずに取り外す方法です。

## ディスク、パーティション、ファイルシステム

よく混同されますが、意味の違う 3 つの言葉があります。

- **ディスク** は記憶装置そのものです。SSD、ハードディスク、SD カード、
  USB メモリなどです。
- **パーティション** はディスクの一部分です。1 つのディスクを複数の
  パーティションに分けて、別々の用途に使えます。各パーティションがどこから
  始まりどこで終わるかは、ディスクの **パーティションテーブル** に記録されています。
  新しいコンピューターでは **GPT** 形式、古いコンピューターやほとんどの
  USB メモリでは古い **MBR**（ツールでは `dos` と呼ばれます）です。
- **ファイルシステム** は、パーティションの *内側* の決まりごとです。ファイル名、
  ディレクトリ、権限、そしてファイルの中身そのものをどう保存するかを決めます。
  新しいパーティションは空っぽで、ファイルシステムを作るまでは使えません。
  それが **フォーマット** の意味です。

ディスクは空っぽの倉庫、パーティションは倉庫をいくつかの部屋に仕切る壁、
ファイルシステムは各部屋の棚とラベルだと考えてみてください。棚がなければ、
何も見つけられません。

```quiz
ディスクに新しいパーティションを作ったところです。まだファイルを保存できないのは
なぜですか？
- [ ] まずパーティションテーブルに追加する必要があるから
- [x] まだファイルシステムがないから。先にフォーマットする必要がある
- [ ] ファイルを入れられるのはディスクだけで、パーティションには入れられないから
- [ ] まずドライブ文字を割り当てる必要があるから
---
新しいパーティションは空っぽで、ファイルシステムを作るまでは使えません。
それがフォーマットの意味です。
```

## ディスクは `/dev` にあるファイル

Linux ではほとんどすべてがファイルで、ディスクも例外ではありません。
どのディスクやパーティションにも、`/dev` に **デバイスファイル** があります。

```sh
ls -l /dev/sd*
```

| デバイスファイル | 正体 |
|---|---|
| `/dev/sda` | 1 台目のディスク（SATA、USB、または仮想ディスク） |
| `/dev/sda1`, `/dev/sda2` | `sda` のパーティション 1 と 2 |
| `/dev/sdb` | 2 台目のディスク – このコンピューターでは USB メモリ |
| `/dev/nvme0n1`, `/dev/nvme0n1p1` | NVMe SSD とその最初のパーティション |
| `/dev/vda` | 仮想マシンのディスク |
| `/dev/mmcblk0p1` | SD カードの最初のパーティション（たとえば Raspberry Pi） |

文字はディスクが見つかった順に割り当てられます。コンピューターに NVMe SSD が
あれば、USB メモリが `sda` になることも十分ありえます。ですから **決して推測せず**、
必ず確認してください。デバイスファイルの所有者は root とグループ `disk` なので、
一般ユーザーはディスクを直接読むことはできません。

## どんなディスクがある？ – `lsblk`

`lsblk`（*list block devices*）は、ディスクをツリーとして描き、各ディスクの下に
パーティションを表示します。

```sh
lsblk
```

| 列 | 意味 |
|---|---|
| `NAME` | `/dev` での名前 |
| `RM` | 1 = 取り外し可能。たとえば USB メモリ |
| `SIZE` | サイズ |
| `TYPE` | `disk` または `part`（パーティション） |
| `MOUNTPOINTS` | ファイルシステムがディレクトリツリーのどこに現れるか。スワップは `[SWAP]` |

このコンピューターでは、`sda1` は `/boot/efi` にある **EFI パーティション**
（コンピューターのファームウェアがここから起動します）、`sda2` は
**ルートファイルシステム** `/`、`sda3` は **スワップ** です。ほかの
ディストリビューションや、ほかのインストールでは、ディスクの分け方が違うことも
あるので、思い込まずに必ず確認しましょう。

`-f` を付けると、`lsblk` はファイルシステムも表示します。種類、ラベル、UUID、
そして空き容量です。

```sh
lsblk -f
```

`sdb1` に注目してください。`USBMINNE`（スウェーデン語で「USB メモリ」）という
ラベルの付いた `vfat` ファイルシステムで、どこにもマウントされていません。
これがこれから差し込む USB メモリです。

## さまざまなファイルシステム

ファイルシステムにはたくさんの種類があり、それぞれ得意なことが違います。

| ファイルシステム | 用途 |
|---|---|
| `ext4` | Linux の昔ながらの標準。安定していて高速 – Debian と Ubuntu が使っている |
| `btrfs` | スナップショット、圧縮、サブボリューム。Fedora と openSUSE の既定 |
| `xfs` | 大きなファイルやサーバーに強い。Red Hat Enterprise Linux の既定 |
| `vfat`（FAT32） | どこでも使える: Windows、macOS、カメラ、カーステレオ。Linux の権限はなく、1 ファイルあたり最大 4 GiB。EFI パーティションは FAT でなければならない |
| `exfat` | FAT に似ているが、4 GiB の制限がない。新しい USB メモリや SD カードでよく使われる |
| `ntfs` | Windows のファイルシステム。Linux から読み書きできる |
| `swap` | ファイルのためのファイルシステムではない – ディスク上の追加の「メモリ」 |
| `tmpfs` | RAM の中にだけ存在し、再起動すると消えるファイルシステム |

## すべては 1 つのツリー – マウント

ファイルシステムを **マウント** するとは、それをディレクトリツリーの特定の
ディレクトリ、つまり **マウントポイント** に取り付けることです。ルート
ファイルシステムは `/` にマウントされ、それ以外はすべてその下のどこかに
ぶら下げられます。だから Linux はドライブ文字なしでやっていけるのです。
別のディスクは、別のディレクトリにすぎません。

`findmnt` はすべてのマウントをツリーとして表示します。

```sh
findmnt
```

そして引数なしの `mount` は、同じものを 1 つのファイルシステムにつき 1 行で
一覧表示します。

```sh
mount
```

ディスクではないものも見えます。`/proc` の `proc` と `/sys` の `sysfs` は、
カーネルの情報をファイルの姿で見せているもので、`tmpfs` は RAM 上の
ファイルシステムです。よく使われるマウントポイントは次のとおりです。

| ディレクトリ | 用途 |
|---|---|
| `/` | ルートファイルシステム |
| `/boot`, `/boot/efi` | カーネルと EFI パーティション |
| `/mnt` | 手作業で行う一時的なマウント |
| `/media/elev/…` または `/run/media/elev/…` | デスクトップ環境が USB メモリを自動的にマウントする場所 |

## 空き容量はどれくらい？ – `df`

`df`（*disk free*）は、マウントされている各ファイルシステムがどれくらい
いっぱいかを表示します。`-h` を付けると、人間が読みやすいサイズで表示されます。

```sh
df -h
```

| 列 | 意味 |
|---|---|
| `Filesystem` | ファイルシステムの場所。たとえばパーティションや `tmpfs` |
| `Size`, `Used`, `Avail` | サイズ、使用量、空き容量 |
| `Use%` | 使用率 |
| `Mounted on` | マウントポイント |

`-T` を付けるとファイルシステムの種類が加わり、パスを指定するとそのパスが
あるファイルシステムだけが表示されます。

```sh
df -hT
df -h ~
```

`Used` と `Avail` を足しても `Size` にぴったりならないことに気づきましたか？
ext4 は 5 % を root 用に予約しています。そのため、一般ユーザーがディスクを
いっぱいにしても、システムは動き続けられるのです。

```try
df -hT
---
`Type` 列を見ると、`/` は `ext4`、`/boot/efi` は `vfat` だとわかります。
```

## `df` と `du` のどちら？

名前はほとんど同じですが、答える質問の違う 2 つのコマンドです。

| 質問 | コマンド |
|---|---|
| **ディスク** はどれくらいいっぱい？ | `df -h` – ファイルシステムに問い合わせる |
| この **ファイル** はどれくらい場所を取っている？ | `du -sh directory` – ファイルをたどって合計する |

ディスクがいっぱいになったら両方を使います。まず `df -h` で *どの*
ファイルシステムがいっぱいかを調べ、次に `du` で *何が* 場所を取っているかを
見つけます。

```sh
du -h -d 1 ~
```

## USB メモリをマウントする

それでは USB メモリを差し込んでみましょう。まず、どのデバイスでしょうか？
`lsblk -f` には、取り外し可能なディスク `sdb` と、`USBMINNE` というラベルの
付いたパーティション `sdb1` が表示されていました。マウントするのは
ディスク全体ではなく **パーティション** です。

次にマウントポイントが必要です。ふつうの空のディレクトリです。作成するのにも
マウントするのにも root 権限が必要です。

```sh
sudo mkdir -p /mnt/usb
sudo mount /dev/sdb1 /mnt/usb
```

`mount` は FAT ファイルシステムを自動的に認識します。明示したい場合は
`-t vfat` を付けることもできます。これで USB メモリのファイルが
ディレクトリに現れます。

```sh
ls -l /mnt/usb
df -h /mnt/usb
```

ここからは、USB メモリはほかのディレクトリと同じように使えます。
ファイルをホームディレクトリにコピーしてみましょう。

```sh
cp /mnt/usb/att-gora.txt ~
```

> **なぜすべての所有者が root なの？** FAT には Linux の権限がありません。
> そのため FAT の USB メモリをマウントすると、*すべての* ファイルが同じ所有者と
> 権限になります。所有者はマウントした人、つまり root です。USB メモリに
> 書き込むには、`sudo` を使うか、自分が所有者になるようにマウントする必要が
> あります: `sudo mount -o uid=1000,gid=1000 /dev/sdb1 /mnt/usb`（1000 は
> あなたのユーザー ID です – `id` で確認できます）。

デバイス名の代わりにラベルでマウントすることもできます:
`sudo mount LABEL=USBMINNE /mnt/usb`。デスクトップ環境のあるコンピューターでは、
USB メモリを差し込むとファイルマネージャーがこれをすべて自動的に行います。

```quiz
`sudo mount /dev/sdb1 /mnt/usb` のあと、FAT の USB メモリ上のファイルはすべて
root が所有者になっています。なぜですか？
- [ ] ファイルは別のコンピューターで root が作ったものだから
- [x] FAT には Linux の権限がないので、すべてのファイルの所有者がマウントした人、つまり root になるから
- [ ] `/mnt` の中のものは、いつも root が所有者だから
- [ ] USB メモリは root しか使えないから
---
`-o uid=1000,gid=1000` を付ければ、マウントするときに所有者を自分で選べます。
```

## アンマウント – USB メモリを抜く前に！

Linux は、いつもすぐにディスクへ書き込むとは限りません。変更はいったん RAM
（*キャッシュ*）にためられ、少しあとで書き込まれます。そのほうがずっと速いからです。
マウントされたままの USB メモリを抜くと、「保存した」はずのファイルがなかったり
壊れていたりすることがあります。だから先に **アンマウント** するのです。
コマンドは n のない `umount` と書きます。

```text
sudo umount /mnt/usb
```

`umount` は書き込み待ちのものをすべて書き込んでから、ファイルシステムを
切り離します。プロンプトが戻ってきたら、USB メモリを抜いても安全です。
（`sync` も書き込み待ちのものをすべて書き込みますが、アンマウントはしません。）

ファイルシステムを何かが使っていると、`umount` は拒否します。

```text
$ cd /mnt/usb
$ sudo umount /mnt/usb
umount: /mnt/usb: target is busy.
```

ここでは、あなた自身のシェルがそのディレクトリにいるのが原因です。`cd ~` で
離れてから、もう一度試してください。アンマウントすると `/mnt/usb` はまた
空のディレクトリに戻りますが、ファイルや加えた変更は USB メモリに残っていて、
次にマウントしたときにまた見えます。

```quiz
USB メモリを抜く前にアンマウントするべきなのはなぜですか？
- [ ] そうしないと USB メモリ上のファイルが削除されるから
- [x] 変更がまだ RAM で待っているかもしれないから。`umount` はファイルシステムを切り離す前にそれを書き込む
- [ ] そうしないと次回 USB メモリに新しいデバイス名が付くから
- [ ] 同じコンピューターでアンマウントするまで、USB メモリを再びマウントできないから
---
Linux は変更を RAM（*キャッシュ*）にためて、少しあとで書き込みます。マウント
されたまま抜かれた USB メモリでは、「保存した」はずのファイルが失われることがあります。
```

## `/etc/fstab` – 起動時に何をマウントするか

ルートファイルシステム、`/boot`、スワップは、コンピューターが起動するたびに
自動的にマウントされます。何をマウントするかは、`/etc/fstab`
（*file system table*）というファイルに書かれています。

```sh
cat /etc/fstab
```

各行には 6 つの列があります。

| 列 | 例 | 意味 |
|---|---|---|
| デバイス | `UUID=3f1c…` | どのファイルシステムか |
| マウントポイント | `/` | ツリーのどこか（スワップは `none`） |
| 種類 | `ext4` | ファイルシステムの種類 |
| オプション | `defaults`, `errors=remount-ro` | マウントオプション。カンマ区切り |
| dump | `0` | 古いバックアップ用のフラグ。ほぼ常に 0 |
| pass | `1` | 起動時に `fsck` がチェックする順番（1 = ルート、2 = その他、0 = チェックしない） |

オプション `errors=remount-ro` は、エラーが見つかったらルートファイルシステムを
読み取り専用にする、という意味です。被害を広げるよりはそのほうがましです。
`# / was on /dev/sda2 during installation` のようなコメントは、
インストーラーが書いたものです。

なぜ単に `/dev/sda2` ではなく `UUID=…` なのでしょうか？ デバイス名は変わることが
あるからです。新しいディスクを差し込むと、古いディスクに新しい文字が
割り当てられるかもしれません。UUID はファイルシステムと一緒に作られ、決して
変わりません。`lsblk -f`、`blkid`、`findmnt` で調べられます。

```sh
sudo blkid
findmnt -n -o UUID /
```

`findmnt` では、`-o` で表示する列を選び、`-n` で見出しを省きます。値そのものだけが
ほしいときに便利です。

```predict
$ findmnt -n -o FSTYPE /boot/efi
vfat
---
`/boot/efi` は EFI パーティションで、EFI パーティションは FAT でなければなりません。
```

USB メモリをいつでも `/mnt/usb` にマウントできるようにしたいなら、次のような
行を追加できます。

```text
LABEL=USBMINNE  /mnt/usb  vfat  noauto,user,uid=1000,gid=1000  0  0
```

`noauto` は起動時にはマウントしない（USB メモリが差し込まれていないかもしれない
ので）という意味で、`user` は一般ユーザーもマウントしてよいという意味です。
そうすれば `sudo` なしで `mount /mnt/usb` だけで済みます。

> **警告:** `/etc/fstab` の間違いは、コンピューターが正常に起動しなくなる
> 原因になります。変更は、再起動する *前に* 必ず `sudo mount -a` でテスト
> してください。このコマンドは、ファイルに書かれているもののうち、まだマウント
> されていないものをすべてマウントします。いつも接続されているとは限らない
> 外付けディスクには、オプション `nofail` を付けましょう。

## スワップ

**スワップ** は、RAM が足りなくなったときに使われる領域です。いま使われていない
メモリの一部をそこへ移して、プログラムが収まるようにします。スワップは RAM より
ずっと遅いので、スワップを多用するコンピューターは動きが鈍くなります。それでも、
プログラムがクラッシュするよりはましです。

```sh
swapon --show
free -h
```

ここではスワップは専用のパーティション `sda3` です。多くのインストール
（たとえば新しめの Ubuntu）では、代わりにルートファイルシステム上の
*スワップファイル* を使います。

## パーティション分割とフォーマット – 細心の注意を払って

`fdisk -l` は、すべてのディスクのパーティションテーブルを、各パーティションの
開始位置と終了位置、種類とともに表示します。root 権限が必要です。

```sh
sudo fdisk -l
```

`fdisk`（`-l` なし）、`parted`、またはグラフィカルな `gparted` を使うと
パーティションテーブルを変更でき、`mkfs` を使うと新しいファイルシステムを
作れます。つまりフォーマットです。

```text
sudo umount /mnt/usb
sudo mkfs.vfat -n USBMINNE /dev/sdb1    # FAT32 – どこでも使える
sudo mkfs.ext4 -L BACKUP /dev/sdb1      # ext4 – Linux の権限があるが、Linux 専用
```

> **警告！** `fdisk` と `mkfs` は、最も危険なコマンドの部類に入ります。
> 1 文字打ち間違えるだけで（`sdb` のつもりが `sda`）、システムディスク全体が
> 消えてしまいます。実際のコンピューターで何かをフォーマットする前には、
> `lsblk -f` でサイズ、`RM` 列、ラベルが合っていることを確認し、
> パーティションがマウントされていないことを確かめ、大事なものはすべて
> バックアップを取っておきましょう。

シミュレーターでは、USB メモリに対して `mkfs.ext4` や `mkfs.vfat` を試せます。
ただし、USB メモリ上のファイルは消えてしまうので、先に課題を済ませてください。
システム自身のパーティションはマウントされているので保護されています。
本物のシステムと同じです。
