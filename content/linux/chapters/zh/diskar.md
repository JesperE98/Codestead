# 磁盘和文件系统

你保存的文件到底存到哪里去了？在 Windows 中，答案是一个字母——`C:`、`D:`、`E:`。Linux 根本没有盘符，只有**一棵**从 `/` 开始的目录树。在本章中，我们来看看它的内部机制：计算机有哪些磁盘、它们是如何划分的、还剩多少空间——以及如何插入 U 盘，再安全地把它拔出来而不丢失任何数据。

## 磁盘、分区和文件系统

这三个词经常被混用，但它们的含义各不相同：

- **磁盘**（disk）是存储设备本身：SSD、机械硬盘、SD 卡或 U 盘。
- **分区**（partition）是磁盘的一部分。一块磁盘可以划分成多个分区，各自用于不同的用途。每个分区从哪里开始、到哪里结束，都记录在磁盘的**分区表**中——新计算机上使用的是 **GPT** 类型，旧计算机和大多数 U 盘使用的是老式的 **MBR**（工具里称之为 `dos`）。
- **文件系统**（file system）是分区*内部*的组织方式：文件名、目录、权限以及文件内容本身是如何存储的。一个新分区是空的，在你在上面创建文件系统之前是无法使用的——这就是**格式化**的含义。

可以把磁盘想象成一座空仓库，分区是把它隔成一个个房间的墙壁，而文件系统则是每个房间里的货架和标签。没有货架，你什么也找不到。

```quiz
你刚在一块磁盘上创建了一个新分区。为什么现在还不能在上面保存文件？
- [ ] 必须先把它加入分区表
- [x] 它还没有文件系统——必须先格式化
- [ ] 分区不能存放文件，只有磁盘才能
- [ ] 必须先给它分配一个盘符
---
新分区是空的，在你在上面创建文件系统之前都无法使用。这就是格式化的含义。
```

## 磁盘就是 `/dev` 中的文件

在 Linux 中，几乎一切都是文件——磁盘也不例外。每块磁盘和每个分区在 `/dev` 中都有一个**设备文件**：

```sh
ls -l /dev/sd*
```

| 设备文件 | 是什么 |
|---|---|
| `/dev/sda` | 第一块磁盘（SATA、USB 或虚拟磁盘） |
| `/dev/sda1`, `/dev/sda2` | `sda` 上的第 1 和第 2 个分区 |
| `/dev/sdb` | 第二块磁盘——这台计算机上的 U 盘 |
| `/dev/nvme0n1`, `/dev/nvme0n1p1` | 一块 NVMe SSD 及其第一个分区 |
| `/dev/vda` | 虚拟机中的一块磁盘 |
| `/dev/mmcblk0p1` | SD 卡上的第一个分区（例如在树莓派中） |

这些字母是按照磁盘被发现的顺序分配的。如果计算机有一块 NVMe SSD，那么 U 盘很可能会成为 `sda`——所以**永远不要猜**，一定要先检查。设备文件属于 root 和 `disk` 组，所以作为普通用户，你无法直接读取磁盘。

## 有哪些磁盘？——`lsblk`

`lsblk`（*list block devices*，列出块设备）会把磁盘画成一棵树，每块磁盘下面列出它的分区：

```sh
lsblk
```

| 列 | 含义 |
|---|---|
| `NAME` | 在 `/dev` 中的名字 |
| `RM` | 1 = 可移动设备，例如 U 盘 |
| `SIZE` | 大小 |
| `TYPE` | `disk`（磁盘）或 `part`（分区） |
| `MOUNTPOINTS` | 文件系统出现在目录树中的位置，swap 显示为 `[SWAP]` |

在这台计算机上，`sda1` 是位于 `/boot/efi` 的 **EFI 分区**（计算机固件从这里启动），`sda2` 是**根文件系统** `/`，`sda3` 是 **swap**（交换分区）。其他发行版——以及其他的安装——可能会以不同的方式划分磁盘，所以一定要先查看，而不要想当然。

加上 `-f`，`lsblk` 还会显示文件系统的信息——类型、卷标、UUID 以及剩余空间：

```sh
lsblk -f
```

注意 `sdb1`：一个卷标为 `USBMINNE` 的 `vfat` 文件系统，它没有挂载在任何地方。这就是我们接下来要插入的 U 盘。

## 不同的文件系统

文件系统有很多种，各有所长：

| 文件系统 | 用途 |
|---|---|
| `ext4` | 经典的 Linux 标准。稳定又快速——Debian 和 Ubuntu 使用它 |
| `btrfs` | 快照、压缩和子卷。Fedora 和 openSUSE 的默认选择 |
| `xfs` | 擅长处理大文件和服务器场景。Red Hat Enterprise Linux 的默认选择 |
| `vfat` (FAT32) | 到处都能用：Windows、macOS、相机、车载音响。没有 Linux 权限，单个文件最大 4 GiB。EFI 分区必须是 FAT |
| `exfat` | 和 FAT 类似，但没有 4 GiB 的限制。在新的 U 盘和 SD 卡上很常见 |
| `ntfs` | Windows 的文件系统。Linux 可以读写它 |
| `swap` | 不是存放文件的文件系统——而是磁盘上的额外“内存” |
| `tmpfs` | 只存在于内存中的文件系统，重启后就会消失 |

## 一切都在一棵树上——挂载

**挂载**（mount）一个文件系统，就是把它连接到目录树中的某个目录上，这个目录叫做**挂载点**（mount point）。根文件系统挂载在 `/` 上，其他所有东西都挂在它下面的某个位置。这就是 Linux 不需要盘符的原因：另一块磁盘不过是另一个目录而已。

`findmnt` 以树的形式显示所有挂载：

```sh
findmnt
```

不带参数的 `mount` 会列出同样的内容，每个文件系统一行：

```sh
mount
```

你还会看到一些并不是磁盘的东西：`/proc` 上的 `proc` 和 `/sys` 上的 `sysfs` 是内核把信息“伪装”成了文件，而 `tmpfs` 是内存中的文件系统。常见的挂载点：

| 目录 | 用途 |
|---|---|
| `/` | 根文件系统 |
| `/boot`, `/boot/efi` | 内核和 EFI 分区 |
| `/mnt` | 你手动进行的临时挂载 |
| `/media/{{user}}/…` 或 `/run/media/{{user}}/…` | 桌面环境自动挂载 U 盘的位置 |

## 还剩多少空间？——`df`

`df`（*disk free*，磁盘剩余空间）显示每个已挂载的文件系统用了多少。加上 `-h` 可以得到人类易读的大小：

```sh
df -h
```

| 列 | 含义 |
|---|---|
| `Filesystem` | 文件系统所在的位置，例如某个分区或 `tmpfs` |
| `Size`, `Used`, `Avail` | 总大小、已用、可用 |
| `Use%` | 使用率 |
| `Mounted on` | 挂载点 |

`-T` 会额外显示文件系统类型；如果你给出一个路径，就只显示该路径所在的文件系统：

```sh
df -hT
df -h ~
```

注意到 `Used` 和 `Avail` 加起来并不完全等于 `Size` 了吗？ext4 会为 root 保留 5% 的空间，这样即使普通用户把磁盘写满了，系统也能继续工作。

```try
df -hT
---
`Type` 列显示 `/` 是 `ext4`，而 `/boot/efi` 是 `vfat`。
```

## `df` 还是 `du`？

这两个命令名字几乎一样，但回答的是不同的问题：

| 问题 | 命令 |
|---|---|
| **磁盘**有多满？ | `df -h`——询问文件系统 |
| 这些**文件**占了多少空间？ | `du -sh directory`——逐个遍历文件并累加 |

磁盘快满时，两个命令都要用：先用 `df -h` 看看是*哪个*文件系统满了，再用 `du` 找出是*什么*占用了空间：

```sh
du -h -d 1 ~
```

## 挂载 U 盘

现在来插入 U 盘。首先：它是哪个设备？`lsblk -f` 显示了一块可移动磁盘 `sdb`，上面有一个卷标为 `USBMINNE` 的分区 `sdb1`。你要挂载的是**分区**，而不是整块磁盘。

然后你需要一个挂载点——一个普通的空目录。创建目录和挂载都需要 root 权限：

```sh
sudo mkdir -p /mnt/usb
sudo mount /dev/sdb1 /mnt/usb
```

`mount` 会自己识别出 FAT 文件系统；如果你想明确指定，可以加上 `-t vfat`。现在 U 盘里的文件出现在这个目录中了：

```sh
ls -l /mnt/usb
df -h /mnt/usb
```

从现在起，U 盘用起来就和其他目录一样。把一个文件复制到你的主目录：

```sh
cp /mnt/usb/{{todo}} ~
```

> **为什么所有东西都属于 root？** FAT 没有 Linux 权限。因此，FAT 格式的 U 盘被挂载后，*所有*文件都会拥有相同的所有者和权限——所有者就是挂载它的人，也就是 root。要往 U 盘里写入，你要么需要 `sudo`，要么在挂载时让自己成为所有者：`sudo mount -o uid=1000,gid=1000 /dev/sdb1 /mnt/usb`（1000 是你的用户 ID——参见 `id`）。

你也可以用卷标代替设备名来挂载：`sudo mount LABEL=USBMINNE /mnt/usb`。在有桌面环境的计算机上，插入 U 盘时文件管理器会自动完成这一切。

```quiz
执行 `sudo mount /dev/sdb1 /mnt/usb` 之后，FAT U 盘上的每个文件都归 root 所有。为什么？
- [ ] 这些文件是 root 在另一台计算机上创建的
- [x] FAT 没有 Linux 权限，所以所有文件都归挂载它的人所有——也就是 root
- [ ] `/mnt` 中的所有东西总是归 root 所有
- [ ] U 盘只能由 root 使用
---
挂载时使用 `-o uid=1000,gid=1000`，你就可以自己选择所有者。
```

## 卸载——在拔出 U 盘之前！

Linux 并不总是立即把数据写入磁盘。更改会先收集在内存中（*cache*，缓存），稍后再写入，因为这样要快得多。如果你拔出一个仍处于挂载状态的 U 盘，你“保存”的文件可能会丢失或损坏。所以你要先**卸载**（unmount）——命令拼作 `umount`，没有 n：

```text
sudo umount /mnt/usb
```

`umount` 会写入所有等待中的数据，然后断开文件系统。等提示符重新出现时，就可以安全地拔出 U 盘了。（`sync` 也会写入所有等待中的数据，但不会卸载。）

如果有东西正在使用这个文件系统，`umount` 会拒绝执行：

```text
$ cd /mnt/usb
$ sudo umount /mnt/usb
umount: /mnt/usb: target is busy.
```

这里是你自己的 shell 正停留在这个目录中。用 `cd ~` 离开，然后再试一次。卸载后，`/mnt/usb` 又变回一个空目录——但文件以及你所做的更改仍然保存在 U 盘上，下次挂载时就能看到。

```quiz
为什么在拔出 U 盘之前应该先卸载它？
- [ ] 否则 U 盘上的文件会被删除
- [x] 更改可能还在内存中等待写入——`umount` 会在断开文件系统之前把它们写进去
- [ ] 否则 U 盘下次会得到一个新的设备名
- [ ] 在同一台计算机上卸载之前，U 盘无法再次挂载
---
Linux 会把更改收集在内存（*缓存*，cache）中，稍后再写入。仍处于挂载状态时就被拔出的 U 盘，可能会丢失你“已保存”的文件。
```

## `/etc/fstab`——开机时挂载什么

根文件系统、`/boot` 和 swap 在每次计算机启动时都会自动挂载。需要挂载哪些内容，列在 `/etc/fstab`（*file system table*，文件系统表）文件中：

```sh
cat /etc/fstab
```

每一行有六列：

| 列 | 示例 | 含义 |
|---|---|---|
| 设备 | `UUID=3f1c…` | 哪个文件系统 |
| 挂载点 | `/` | 挂在树中的什么位置（swap 用 `none`） |
| 类型 | `ext4` | 文件系统类型 |
| 选项 | `defaults`, `errors=remount-ro` | 挂载选项，用逗号分隔 |
| dump | `0` | 旧的备份标志，几乎总是 0 |
| pass | `1` | 开机时 `fsck` 检查它们的顺序（1 = 根，2 = 其他，0 = 从不检查） |

选项 `errors=remount-ro` 表示一旦检测到错误，根文件系统就会被重新挂载为只读——总比造成更大的破坏要好。像 `# / was on /dev/sda2 during installation` 这样的注释是安装程序写的。

为什么用 `UUID=…`，而不直接用 `/dev/sda2`？因为设备名可能会变——插入一块新磁盘，旧磁盘就可能分到一个新字母。UUID 是和文件系统一起创建的，永远不会改变。你可以用 `lsblk -f`、`blkid` 或 `findmnt` 找到它：

```sh
sudo blkid
findmnt -n -o UUID /
```

在 `findmnt` 中，`-o` 选择要显示的列，`-n` 则省略标题行——当你只想要值本身时很方便。

```predict
$ findmnt -n -o FSTYPE /boot/efi
vfat
---
`/boot/efi` 是 EFI 分区，而 EFI 分区必须是 FAT 格式。
```

如果你希望 U 盘总是可以挂载到 `/mnt/usb`，可以添加这样一行：

```text
LABEL=USBMINNE  /mnt/usb  vfat  noauto,user,uid=1000,gid=1000  0  0
```

`noauto` 表示开机时不挂载它（U 盘可能没有插着），`user` 表示普通用户也可以挂载它——这样只需 `mount /mnt/usb` 就够了，不用 `sudo`。

> **警告：** `/etc/fstab` 中的一个错误就可能导致计算机无法正常启动。在重启*之前*，一定要用 `sudo mount -a` 测试你的修改，它会挂载文件中所有尚未挂载的内容。对于不总是连接着的外部磁盘，要加上 `nofail` 选项。

## Swap

**Swap**（交换空间）是在内存不够用时使用的空间：内存中暂时不用的部分会被移到那里，好让程序都能装得下。swap 比内存慢得多，所以频繁使用 swap 的计算机会变得迟缓——但总比程序崩溃要好。

```sh
swapon --show
free -h
```

这里的 swap 是一个单独的分区 `sda3`。很多安装（例如较新的 Ubuntu）则改为在根文件系统上使用一个 *swap 文件*。

## 分区和格式化——务必万分小心

`fdisk -l` 显示所有磁盘的分区表，包括每个分区从哪里开始、到哪里结束以及它的类型。它需要 root 权限：

```sh
sudo fdisk -l
```

用 `fdisk`（不带 `-l`）、`parted` 或图形界面的 `gparted`，可以修改分区表；用 `mkfs` 可以创建新的文件系统——也就是格式化：

```text
sudo umount /mnt/usb
sudo mkfs.vfat -n USBMINNE /dev/sdb1    # FAT32——到处都能用
sudo mkfs.ext4 -L BACKUP /dev/sdb1      # ext4——有 Linux 权限，但只能在 Linux 上用
```

> **警告！** `fdisk` 和 `mkfs` 是最危险的命令之一。打错一个字母——把 `sdb` 写成 `sda`——整块系统盘就没了。在真实的计算机上格式化任何东西之前：先用 `lsblk -f` 检查大小、`RM` 列和卷标是否都对得上，确认该分区没有被挂载，并且把所有重要的东西都备份好。

在模拟器中，你可以在 U 盘上试试 `mkfs.ext4` 和 `mkfs.vfat`——但要先完成练习，因为 U 盘上的文件会消失。系统自己的分区是受保护的，因为它们已被挂载，这和真实系统上一样。

## 小结

| 命令 | 作用 |
|---|---|
| `lsblk`, `lsblk -f` | 显示磁盘、分区和文件系统 |
| `blkid` | 显示类型、卷标和 UUID |
| `df -h` | 文件系统有多满？ |
| `du -sh directory` | 这些文件占了多少空间？ |
| `findmnt`, `mount` | 挂载了什么，挂在哪里？ |
| `sudo mount /dev/sdb1 /mnt/usb` | 挂载一个文件系统 |
| `sudo umount /mnt/usb` | 卸载——在拔出 U 盘之前 |
| `cat /etc/fstab` | 开机时挂载什么？ |
| `swapon --show` | 显示 swap |
| `sudo fdisk -l` | 显示分区表 |
