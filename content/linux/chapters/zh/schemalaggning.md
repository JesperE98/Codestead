# 用 cron 运行定时任务

每天夜里做一次备份，每周清理一次旧日志，每五分钟获取一次数据——计算机可以在设定的时间自己运行命令。完成这件事的经典工具是 **cron**，而 systemd 也有自己的**定时器**（timer）。

## cron 和 crontab

cron 服务每分钟醒来一次，运行那些到了时间的任务。每个用户都有自己的任务列表，叫做 **crontab**：

```sh
crontab -l
```

*no crontab for {{user}}* 表示你还没有任何任务。

## 五个时间字段

crontab 中的每一行都有五个时间字段，后面跟着命令：

```text
┌───────────── 分钟 (0–59)
│ ┌─────────── 小时 (0–23)
│ │ ┌───────── 日期 (1–31)
│ │ │ ┌─────── 月份 (1–12)
│ │ │ │ ┌───── 星期几 (0–7，星期日是 0 或 7)
│ │ │ │ │
* * * * *  命令
```

| 你写的 | 含义 |
|---|---|
| `*` | 每一个 |
| `5` | 正好是 5 |
| `1-5` | 1 到 5 |
| `1,15` | 1 和 15 |
| `*/10` | 每隔十：0、10、20 … |

| 这一行 | 运行时间 |
|---|---|
| `* * * * * command` | 每分钟 |
| `*/5 * * * * command` | 每五分钟 |
| `30 2 * * * command` | 每天夜里 02:30 |
| `0 7 * * 1-5 command` | 星期一到星期五的 07:00 |
| `0 0 1 * * command` | 每月一日的午夜 |
| `@reboot command` | 计算机启动时运行一次 |

`@hourly`、`@daily`、`@weekly` 和 `@monthly` 也是快捷写法。

```quiz
任务 `15 8 * * 6 ~/backup.sh` 在什么时候运行？
- [ ] 每天 15:08
- [x] 每个星期六的 08:15
- [ ] 每月 15 日的 08:00
---
顺序是分钟、小时、日期、月份和星期几：第 15 分钟、8 点、任意日期、任意月份、星期 6——也就是星期六。
```

```quiz
`0 */2 * * * command` 多久运行一次？
- [ ] 每两分钟
- [x] 每两小时一次，在整点
- [ ] 每天两次
---
第 0 分钟，每隔一小时：00:00、02:00、04:00 …
```

## 安装任务

`crontab -e` 会在文本编辑器中打开你的 crontab，并在你保存时安装它。模拟器目前还没有编辑器，所以在这里你通过输入把任务交给 `crontab`——`-` 表示“从输入读取”：

```sh
echo '* * * * * date >> ~/cron.log' | crontab -
crontab -l
```

注意：`crontab -` 和 `crontab FILE` 会**替换**整个 crontab。要添加一个任务，就把旧任务和新任务合在一起：

```sh
(crontab -l; echo '30 2 * * * ~/backup.sh') | crontab -
```

要删除某一行，就用 `grep -v` 把它过滤掉，再安装剩下的部分——或者用 `crontab -r` 删除全部：

```sh
crontab -l | grep -v backup.sh | crontab -
```

`crontab` 在安装任何东西之前都会检查这些行：

```predict
$ echo '0 25 * * * date' | crontab -
"-":1: bad hour
errors in crontab file, can't install.
---
没有 25 点——小时的范围是 0 到 23。什么都没有安装。
```

## 看着它运行

安装了每分钟运行一次的任务之后，等一分钟再看看：

```sh
cat ~/cron.log
journalctl -u cron
```

每次运行都会记录到 journal 中，例如 `CRON[4211]: ({{user}}) CMD (date >> ~/cron.log)`。在模拟器中，cron 只在应用打开时运行——和真正的计算机一样，它不会补上关机期间错过的任务。

## cron 的陷阱：不同的环境

任务并不是在你的终端里运行的，这一点几乎让每个人都感到意外：

- 它们用 `/bin/sh` 运行，没有你的别名，也不会读取你的 `~/.bashrc`。
- `PATH` 很短（`/usr/bin:/bin`），所以其他位置的程序需要写完整路径。
- 它们从你的主目录开始运行。
- 没有发送到文件的输出会丢失。一定要在行末加上类似 `>> ~/job.log 2>&1` 的内容。

先手动运行一下命令。在那里能正常工作之后，再把它放进 crontab。

```quiz
任务 `* * * * * echo hi` 每分钟都会运行，但你在任何地方都看不到 `hi`。为什么？
- [ ] cron 不允许使用 `echo`
- [x] 输出无处可去——用 `>>` 把它发送到文件
- [ ] 任务只能以 root 身份运行
---
cron 任务的输出不会显示在任何终端中。真正的 cron 会尝试通过邮件发送它，而大多数计算机都没有配置邮件——所以输出就丢失了。
```

## 系统自己的任务

除了用户的 crontab 之外，还有 `/etc/crontab`，以及 `/etc/cron.daily` 和 `/etc/cron.weekly` 之类的目录。其中的脚本每天或每周运行一次：

```sh
cat /etc/crontab
ls /etc/cron.daily
```

`/etc/crontab` 中的行在命令前面多一个字段：运行该任务的用户。

## systemd 定时器

在现代发行版中，很多这类工作改由 systemd 的**定时器**来完成：一个 `.timer` 单元在设定的时间启动一个 `.service` 单元。定时器会把日志写入 journal，还能补上错过的运行，但每个任务都需要两个单元文件。对于你自己的小任务，cron 是最快捷的方式。列出计算机上的定时器，以及下一次和上一次运行的时间：

```try
systemctl list-timers
```

## 在其他发行版上

| | Ubuntu 和 Debian | Fedora | Arch |
|---|---|---|---|
| 软件包 | `cron` | `cronie` | `cronie` |
| 服务 | `cron` | `crond` | `cronie` |
| 一开始就已安装 | 是 | 是 | 否 |

在 Arch 上，先运行 `sudo pacman -S cronie` 和 `sudo systemctl enable --now cronie`。
