# 进程和作业

每个正在运行的程序都是一个**进程**（process）。此刻，这台模拟计算机上正运行着十几个进程：系统服务、你的 shell——还有另外一个你很快就会看到的东西。在本章中，你将学习如何查看正在运行的内容、停止行为异常的程序，以及在后台运行程序。

## 什么是进程？

进程就是一个正在运行的程序，加上它所需要的一切：内存、打开的文件，以及它以哪个用户身份运行。每个进程都有一个 **PID**（*process ID*，进程 ID）——用来标识它的编号——以及一个启动它的父进程，即 **PPID**。一切都从 1 号进程 `init` 开始（在几乎所有发行版上，它就是 `systemd`），由它启动其余所有进程。

## 我的进程——`ps`

不带选项的 `ps`（*process status*，进程状态）会显示你自己终端中的进程：

```sh
ps
```

你会看到你的 shell `bash`，以及 `ps` 本身——它只在运行期间存在。

## 所有进程——`ps aux`

要查看计算机上运行的所有内容，通常使用 `ps aux`：

```sh
ps aux
```

| 列 | 含义 |
|---|---|
| `USER` | 进程以哪个用户身份运行 |
| `PID` | 进程的 ID 号 |
| `%CPU` / `%MEM` | 它占用了多少处理器和内存 |
| `STAT` | 状态：`R` 运行中，`S` 休眠中，`s` 会话首进程 |
| `COMMAND` | 启动该进程的命令 |

这个列表会很长，所以经常和 `grep` 或 `sort` 一起使用：

```sh
ps aux | grep sshd
ps aux --sort=-%cpu | head -5
```

变体 `ps -ef` 显示的是相同的进程，但会把父进程的 PID 单独放在一列。如果你只想知道某个已知名称的进程的 PID，可以用 `pgrep`：

```sh
pgrep -l sshd
```

## 实时视图——`top` 和 `htop`

`top` 按进程占用的处理器时间排序显示进程，并且每秒刷新一次——非常适合找出拖慢计算机的“元凶”。在顶部，你会看到系统负载（*load average*，平均负载）、进程数和内存情况。

```sh
top
```

在真实的终端中，按 `q` 退出 `top`。很多人更喜欢 `htop`，它有彩色显示，还能用鼠标操作，但通常需要先安装。

## 停止进程——`kill`

这个名字听起来很吓人，但 `kill` 实际上是向进程发送一个**信号**（signal）。默认信号 `SIGTERM`（15）会请求进程体面地自行关闭。如果它不理睬，你可以发送 `SIGKILL`（9），强制它立即停止——不过这样它就没有机会保存数据或做清理工作了。

```text
kill 1234        # 请求进程 1234 退出（SIGTERM）
kill -9 1234     # 强制停止（SIGKILL）——最后的手段
```

如果你知道进程名而不知道 PID，可以使用 `pkill`（按模式匹配）或 `killall`（按确切名称）：

```text
pkill firefox
killall firefox
```

你只能向**自己的**进程发送信号。对于属于 root 或其他用户的进程，你需要使用 `sudo`。

> **找到它，停掉它！** 这台计算机上有某个进程占用了将近 100% 的处理器。用 `top` 或 `ps aux --sort=-%cpu` 找出它叫什么、PID 是多少——然后停止它。

## 前台和后台

当你运行一个命令时，shell 会一直等到它结束；这时它在**前台**运行。如果你在命令末尾加上 `&`，它就会在**后台**运行，你会立即重新得到提示符：

```sh
sleep 300 &
```

shell 会用方括号中的作业编号和进程的 PID 来回应，例如 `[1] 4200`。从终端启动的程序叫做**作业**（job）：

```sh
jobs
```

| 命令 | 作用 |
|---|---|
| `jobs` | 列出此终端中的作业 |
| `fg %1` | 把作业 1 调到前台 |
| `bg %1` | 让已暂停的作业在后台继续运行 |
| `kill %1` | 结束作业 1 |
| `Ctrl+C` | 中断前台程序 |
| `Ctrl+Z` | 暂停前台程序（用 `fg` 或 `bg` 恢复） |

变量 `$!` 保存着最近一个后台作业的 PID。当作业结束时，shell 会用类似 `[1]+  Done   sleep 300` 的一行来通知你。

## 计算机状态如何？

有两个小命令可以让你快速了解概况：

```sh
uptime
free -h
```

`uptime` 显示计算机已经运行了多长时间，以及过去 1、5 和 15 分钟的负载。`free -h` 显示内存的使用量。注意 *available*（可用）这一列：Linux 会把空闲内存用作文件缓存，所以即使内存很充足，*free*（空闲）这一列的数字也常常看起来很低。

## 到处都一样

进程在所有发行版上的工作方式都相同。这些工具来自 **procps** 软件包（在 Arch 和 Fedora 上叫做 `procps-ng`），而 `killall` 来自 **psmisc**。不同之处在于一开始运行着哪些服务——试着把 {{distro}} 上的 `ps aux` 和另一个发行版比较一下吧！
