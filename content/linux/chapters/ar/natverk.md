# الشبكات

كل ما يفعله حاسوب Linux تقريبًا يتضمّن التواصل مع حواسيب أخرى: جلب
التحديثات، وعرض صفحات الويب، وتسجيل الدخول إلى الخوادم. وعندما يحدث خطأ ما،
فإن الطرفية تملك أفضل الأدوات لمعرفة السبب. في هذا الفصل ستتعلّم كيف تجد عنوانك
الخاص، وتختبر الاتصالات، وتبحث عن الأسماء، وترى الخدمات التي تعمل، وتجلب
الأشياء من الويب، وتسجّل الدخول إلى حاسوب آخر عبر SSH.

يقع الحاسوب المحاكى في شبكة منزلية صغيرة:

| الحاسوب | العنوان | ما هو |
|---|---|---|
| حاسوبك (`ubuntu`) | `192.168.1.42` | حيث أنت الآن |
| الموجّه (router، البوابة) | `192.168.1.1` | الاتصال إلى الإنترنت |
| الخادم | `192.168.1.10` | حاسوب Linux آخر يمكنك تسجيل الدخول إليه |

وخلف الموجّه توجد "إنترنت" فيها، من بين مواقع أخرى، `example.com`
و`linux.org` و`archlinux.org`.

## عناوين IP

لكل حاسوب على الشبكة **عنوان IP**. عنوان IPv4 مكوّن من أربعة أرقام بين 0 و255،
مثل `192.168.1.42`. العناوين التي تبدأ بـ `192.168.` أو `10.` أو
`172.16.`–`172.31.` هي عناوين **خاصة** (private) – تُستخدم فقط داخل الشبكات
المحلية ولا تظهر أبدًا على الإنترنت.

الأمر الذي يعرض عناوين الحاسوب هو `ip` (من الحزمة *iproute2*). ويمكن اختصار
`ip addr` إلى `ip a`:

```sh
ip a
```

سترى **واجهتين** (interfaces، أي بطاقتي شبكة):

- `lo` – *loopback*، بطاقة وهمية يستخدمها الحاسوب ليتحدّث مع نفسه.
- `enp0s3` – بطاقة الشبكة الحقيقية. كانت البطاقات تُسمّى سابقًا `eth0`،
  وغالبًا ما تحمل البطاقات اللاسلكية أسماء مثل `wlan0` أو `wlp2s0`.

السطر `inet 192.168.1.42/24` هو عنوان IPv4 الخاص بك. و`link/ether` هو **عنوان
MAC** للبطاقة، وهو مدمج في العتاد، و`state UP` تعني أن البطاقة تعمل. وللحصول
على نظرة عامة أقصر هناك `-br` (*brief*)، أما `hostname -I` فيعرض العناوين فقط:

```sh
ip -br a
hostname -I
```

```try
ip -br a
---
سطر لكل واجهة: الاسم، والحالة (`UP`)، والعناوين.
```

ستظل ترى الأمر الأقدم `ifconfig` (من الحزمة *net-tools*) في كثير من الأدلة،
لكنه لا يُثبَّت افتراضيًا في التوزيعات الحديثة. والأمر `ip` يفعل كل ما كان
يفعله وأكثر.

## localhost – الحاسوب نفسه

العنوان `127.0.0.1` اسمه **localhost** ويعني دائمًا "هذا الحاسوب". كثيرًا ما
تتواصل البرامج الموجودة على الحاسوب نفسه عبر localhost – مثل خادم ويب تطوّره
والمتصفح الذي تختبره به. ولا تغادر حركة البيانات المتّجهة إلى localhost الحاسوبَ
أبدًا.

## قناع الشبكة والبوابة

الجزء `/24` بعد العنوان هو **قناع الشبكة** (netmask). وهو يقول إن أول 24 بتًّا
(الأرقام الثلاثة الأولى، `192.168.1`) هي عنوان الشبكة. كل الحواسيب التي يبدأ
عنوانها بـ `192.168.1.` موجودة في الشبكة المحلية نفسها ويمكن الوصول إليها
مباشرة. وكل ما عدا ذلك يُرسَل إلى **البوابة** (gateway) – أي الموجّه – التي
تمرّره إلى الإنترنت. يمكنك رؤية ذلك في جدول التوجيه:

```sh
ip route
```

```text
default via 192.168.1.1 dev enp0s3 proto dhcp src 192.168.1.42 metric 100
192.168.1.0/24 dev enp0s3 proto kernel scope link src 192.168.1.42 metric 100
```

السطر الأول، **default**، هو المسار الافتراضي: "كل ما لم يُذكر في مكان آخر
يذهب إلى 192.168.1.1". ويقول السطر الثاني إن الشبكة `192.168.1.0/24` كلها يمكن
الوصول إليها مباشرة عبر `enp0s3`. وتعني `proto dhcp` أن الحاسوب حصل على
إعداداته تلقائيًا من الموجّه عبر **DHCP**.

```quiz
عنوان حاسوبك `192.168.1.42/24`. أيّ العناوين يستطيع الوصول إليها مباشرة، من دون
المرور بالبوابة؟
- [x] `192.168.1.10`
- [x] `192.168.1.1`
- [ ] `192.168.2.10`
- [ ] `1.1.1.1`
---
مع `/24` تكون الأرقام الثلاثة الأولى عنوان الشبكة. فكل ما يبدأ بـ `192.168.1.`
موجود في الشبكة المحلية نفسها – وكل ما عدا ذلك يذهب عبر المسار الافتراضي إلى
البوابة.
```

```predict
$ ip route | grep default | awk '{print $3}'
192.168.1.1
---
الكلمة الثالثة في سطر `default` هي عنوان البوابة.
```

## ping – هل يمكن الوصول إليه؟

يرسل `ping` حزمًا صغيرة للاختبار ويقيس المدة التي تستغرقها الردود. باستخدام
`-c` (*count*) تختار عدد الحزم – وإلا فسيستمر ping حتى تضغط **Ctrl+C**:

```sh
ping -c 3 192.168.1.1
```

```text
64 bytes from 192.168.1.1: icmp_seq=1 ttl=64 time=0.756 ms
...
3 packets transmitted, 3 received, 0% packet loss, time 2004ms
```

- `time=` هو زمن الرد. داخل الشبكة المنزلية أقل من ميلي ثانية، وإلى الإنترنت
  غالبًا 10–50 ms.
- `0% packet loss` – لم تختفِ أي حزمة. أما الحزم المفقودة فتدل على شبكة سيئة
  (أو اتصال wifi سيئ).
- `Destination Host Unreachable` تعني أنه لا يوجد حاسوب في الشبكة المحلية
  يحمل ذلك العنوان.

جرّب أيضًا إرسال ping إلى الحاسوب نفسه وإلى حاسوب على الإنترنت:

```sh
ping -c 2 localhost
ping -c 3 example.com
```

انتبه! كثير من الخوادم والجدران النارية لا تردّ على ping عن قصد. لذا فإن
غياب الرد لا يعني دائمًا أن الحاسوب متوقف.

## الأسماء وDNS

البشر يتذكّرون الأسماء، والحواسيب تستخدم العناوين. **DNS** (*Domain Name
System*) هو دليل هاتف الإنترنت الذي يترجم `example.com` إلى عنوان IP. أما خادم
DNS الذي يسأله الحاسوب فمكتوب في `/etc/resolv.conf`:

```sh
cat /etc/resolv.conf
```

على Ubuntu ستجد `127.0.0.53` – وهو **systemd-resolved**، وسيط محلي على حاسوبك
يسأل الموجّه بدوره. وتذكر بعض التوزيعات الأخرى الموجّه، `192.168.1.1`، مباشرة.

لتسأل DNS بنفسك تستخدم `dig` أو `host` أو `nslookup`. هذه الأدوات غير مثبّتة
من البداية. على Ubuntu تأتي في الحزمة `dnsutils` (وتسمّي العائلات الأخرى الحزمة
باسم آخر):

```sh
sudo apt update
sudo apt install dnsutils
```

يعرض `dig` الجواب الكامل من خادم DNS. والجزء المهم موجود تحت `ANSWER SECTION`.
ومع `+short` تحصل على العنوان فقط:

```sh
dig example.com
dig +short example.com
```

يفعل `host` و`nslookup` الشيء نفسه بمخرجات أقصر. ويوجد `nslookup` أيضًا على
Windows وmacOS. ويستطيع `host` كذلك إجراء **بحث عكسي** (reverse lookup) – من
العنوان إلى الاسم:

```sh
host example.com
nslookup archlinux.org
host 1.1.1.1
```

يمكنك سؤال خادم DNS محدّد باستخدام `@`، مثل `1.1.1.1` من Cloudflare أو
`8.8.8.8` من Google:

```sh
dig @8.8.8.8 +short debian.org
```

## /etc/hosts – قائمة الأسماء الخاصة بالحاسوب

قبل أن يسأل الحاسوب DNS، ينظر في الملف `/etc/hosts`. ومن بين ما يقوله هذا
الملف أن `localhost` هو `127.0.0.1`:

```sh
cat /etc/hosts
```

للخادم في الشبكة المنزلية العنوان `192.168.1.10`، لكن الاسم `server.lan` غير
موجود في أي DNS:

```sh
ping -c 1 server.lan
```

الحل هو إضافة سطر إلى `/etc/hosts`. الملف مملوك لـ root، لذا تحتاج إلى `sudo`.
لكن انتبه – هذا **لا** ينجح:

```text
sudo echo '192.168.1.10 server.lan' >> /etc/hosts
bash: /etc/hosts: Permission denied
```

لا يسري `sudo` إلا على `echo`. فالـ shell الخاص بك (الذي يعمل باسمك، لا باسم
root) هو الذي يفتح الملف من أجل `>>`. والحيلة هي `tee -a`، الذي يُلحق ما
يتلقّاه من الـ pipe بنهاية ملف – ويمكن تشغيل `tee` باستخدام sudo:

```sh
echo '192.168.1.10 server.lan' | sudo tee -a /etc/hosts
ping -c 3 server.lan
```

الآن يعمل الاسم مع كل برنامج على الحاسوب. لكن `dig` يسأل DNS مباشرة ويتجاهل
`/etc/hosts`، لذا لا يجد شيئًا حتى الآن. ولترى ما يترجمه *النظام*، استخدم
`getent`:

```sh
dig +short server.lan
getent hosts server.lan
```

الترتيب (أولًا الملف، ثم DNS) يحدّده السطر `hosts:` في `/etc/nsswitch.conf`.

```quiz
لماذا يعطي `sudo echo '192.168.1.10 server.lan' >> /etc/hosts` الخطأ
*Permission denied*؟
- [ ] لأن `echo` لا يمكن تشغيله مع sudo
- [x] لأن الـ shell الخاص بك، لا root، هو من يفتح الملف لـ `>>` – وsudo لا يسري إلا على `echo`
- [ ] لأن `/etc/hosts` لا يمكن تغييره، ولا حتى بواسطة root
- [ ] لأن `>>` لا يعمل إلا على الملفات في مجلد المنزل
---
لهذا تستخدم `echo ... | sudo tee -a /etc/hosts`: فيكون `tee`، الذي يعمل بصلاحيات
root، هو من يفتح الملف.
```

## المنافذ والخدمات

عنوان IP يشير إلى حاسوب. أما **المنفذ** (port، وهو رقم بين 1 و65535) فيشير إلى
برنامج على ذلك الحاسوب – مثل عنوان الشارع ورقم الشقة. ويُقال عن البرنامج الذي
ينتظر الاتصالات إنه **يستمع** (listen) على منفذ. ومن المنافذ المعروفة:

| المنفذ | الخدمة |
|---|---|
| 22 | SSH – تسجيل الدخول إلى حواسيب أخرى |
| 53 | DNS |
| 80 | HTTP – الويب |
| 443 | HTTPS – الويب المشفّر |
| 8080 | غالبًا خوادم الويب أثناء التطوير |

لا يحق إلا لـ root فتح المنافذ الأقل من 1024. ويعرض `ss` (*socket statistics*)
المنافذ التي تستمع:

```sh
ss -tulpn
```

عادةً ما تُحفظ الخيارات كأنشودة: **t**cp، **u**dp، **l**istening،
**p**rocess، **n**umeric. تعني `0.0.0.0:22` أن `sshd` يستمع على المنفذ 22 على
كل عناوين الحاسوب، و`[::]:22` هي الشيء نفسه لـ IPv6. ويكون العمود *Process*
فارغًا للعمليات التي يملكها مستخدمون آخرون – ومع `sudo` تراها كلها:

```sh
sudo ss -tulpn
```

إذا كان خادم التدريب `minserver` من فصل العمليات يعمل، فستراه هنا على
المنفذ 8080. والأمر الأقدم `netstat -tulpn` (من *net-tools*) يفعل الشيء نفسه.

## الجلب من الويب: curl وwget

يجلب `curl` ما يوجد في عنوان ما (**URL**) ويطبعه في الطرفية. جرّبه مع
minserver على حاسوبك:

على Ubuntu لا يكون `curl` مثبّتًا مسبقًا (لكن `wget` مثبّت):

```sh
sudo apt install curl
```

```sh
curl http://localhost:8080
```

هل حصلت على `Couldn't connect to server`؟ إذن لا شيء يستمع على المنفذ – ربما
أوقفت minserver في فصل العمليات. شغّله من جديد:

```sh
minserver
```

مع `-I` يعرض curl **ترويسات** (headers) الرد فقط، وأول سطر فيها هو **رمز
الحالة** (status code):

```sh
curl -I https://example.com
```

| الرمز | المعنى |
|---|---|
| 200 | OK |
| 301، 302 | انتقلت الصفحة – انظر `Location:` |
| 403 | ممنوع |
| 404 | غير موجود |
| 500 | خطأ في الخادم |

كثير من المواقع تعيد التوجيه من `http://` إلى `https://`. عندها تحصل فقط على
رد قصير "301 Moved Permanently". ومع `-L` يتبع curl التوجيه:

```sh
curl -I http://linux.org
curl -L http://linux.org
```

بما أن curl يكتب في الطرفية، فهو يعمل بشكل رائع في pipe. ويُطفئ `-s`
(*silent*) مؤشر التقدّم:

```sh
curl -s https://example.com | grep title
```

للحفظ في ملف، استخدم `-o FILE` (أو `-O`، الذي يأخذ اسم الملف من العنوان):

```sh
cd ~
curl -o exempel.html https://example.com
```

صُنع `wget` لتنزيل الملفات. فهو يحفظ دائمًا في ملف، ويعرض التقدّم، ويتبع
عمليات إعادة التوجيه من تلقاء نفسه:

```sh
wget https://example.com/cheatsheet.txt
cat cheatsheet.txt
```

لتختار اسم الملف بنفسك، استخدم `-O` الكبيرة: `wget -O file.html URL`.

## SSH – تسجيل الدخول إلى حاسوب آخر

**SSH** (*Secure Shell*) هو الطريقة المعتادة للتحكّم في حاسوب Linux عن بُعد، وكل
ما يُرسَل يكون مشفّرًا. يشغّل الخادم الخدمة `sshd` على المنفذ 22، وتتصل أنت
باستخدام العميل `ssh`:

```sh
ssh elev@server.lan hostname
```

تعني `elev@server.lan` "المستخدم elev على الحاسوب server.lan". والأمر الذي
يأتي بعد المضيف (`hostname`) يعمل على الخادم ويُعرض الجواب هنا – وهو يقول
`server`، لا `ubuntu`.

في المرة الأولى التي تتصل فيها بحاسوب، يسألك ssh هل تثق به:

```text
The authenticity of host 'server.lan (192.168.1.10)' can't be established.
ED25519 key fingerprint is SHA256:q7Jx3MmP0yZk8VbW1sTn4dLr9HcE2uFgA6oYiKjN5Rw.
Are you sure you want to continue connecting (yes/no/[fingerprint])?
```

اكتب `yes` (الكلمة كاملة). عندها يُحفظ **مفتاح المضيف** (host key) الخاص
بالخادم في `~/.ssh/known_hosts`. وإذا تغيّر المفتاح لاحقًا، يحذّرك ssh بصوت عالٍ
– فقد يعني ذلك أن أحدًا ما ينتحل صفة الخادم.

يمكن أن يكون الأمر عدة أوامر داخل علامات اقتباس:

```sh
ssh elev@server.lan 'whoami; uptime; ls'
ssh elev@server.lan cat välkommen.txt
```

من دون أمر، يسجّل ssh الدخول وتحصل على shell على الحاسوب الآخر، وتخرج منه
باستخدام `exit`. هذا غير مدعوم في المحاكي – فهناك تكتب الأمر دائمًا مباشرة بعد
المضيف.

### المفاتيح بدلًا من كلمات المرور

بدلًا من كلمة المرور يمكنك تسجيل الدخول باستخدام **زوج مفاتيح** (key pair).
يبقى المفتاح الخاص معك، ويوضع المفتاح العام على الخادم:

```sh
ssh-keygen
ssh-copy-id elev@server.lan
```

اضغط Enter عند أسئلة `ssh-keygen` لتستخدم الملف الافتراضي `~/.ssh/id_ed25519`
من دون عبارة مرور (passphrase). يضيف `ssh-copy-id` المفتاح العام
(`id_ed25519.pub`) إلى `~/.ssh/authorized_keys` على الخادم. وبعد ذلك لن يطلب
ssh كلمة مرور بعد الآن. لا تُرِ المفتاح الخاص لأي أحد أبدًا!

باستخدام `scp` و`rsync` يمكنك نسخ الملفات عبر SSH، وفي الملف `~/.ssh/config`
يمكنك إعطاء الخوادم أسماء قصيرة – لكن ذلك سينتظر فصلًا لاحقًا.

## عندما لا تعمل الشبكة

لعبارة "الإنترنت لا يعمل" أسباب كثيرة محتملة. امشِ على الخطوات بالترتيب، من
الداخل إلى الخارج – فأول خطوة تفشل تُظهر مكان المشكلة:

| الخطوة | الأمر | إذا فشلت |
|---|---|---|
| 1. هل لديّ عنوان؟ | `ip a` | البطاقة متوقفة (`state DOWN`) أو لم تحصل على عنوان |
| 2. هل هناك طريق إلى الخارج؟ | `ip route` | لا يوجد سطر `default` – لا توجد بوابة |
| 3. هل أصل إلى الموجّه؟ | `ping -c 3 192.168.1.1` | مشكلة في الشبكة المحلية (الكابل، wifi) |
| 4. هل أصل إلى الإنترنت؟ | `ping -c 3 1.1.1.1` | مشكلة عند الموجّه أو مزوّد الخدمة |
| 5. هل يعمل DNS؟ | `ping -c 3 example.com` | البحث عن الأسماء يفشل – افحص `/etc/resolv.conf` |

ترسل الخطوة 4 ping إلى عنوان مباشرة، من دون أي اسم. فإذا نجحت الخطوة 4 ولم
تنجح الخطوة 5، فالعطل في DNS في كل الحالات تقريبًا – وهي من أكثر المشكلات
شيوعًا.

```quiz
`ping -c 3 1.1.1.1` يعمل، لكن `ping -c 3 example.com` يجيب بـ
*Name or service not known*. أين تكمن المشكلة على الأرجح؟
- [ ] بطاقة الشبكة متوقفة
- [ ] لا يوجد مسار افتراضي
- [x] في DNS – البحث عن الأسماء لا يعمل
- [ ] example.com لا يجيب على ping
---
إذا كنت تستطيع الوصول إلى عنوان على الإنترنت، فالبطاقة والمسار والموجّه تعمل.
ويبقى تحويل الاسم – افحص `/etc/resolv.conf`.
```

جرّب ذلك بنفسك! أطفئ بطاقة الشبكة، وامشِ على الخطوات، ثم شغّلها من جديد:

```sh
sudo ip link set enp0s3 down
ip a
ip route
ping -c 3 192.168.1.1
ping -c 3 example.com
sudo ip link set enp0s3 up
```

## الحزم

توجد أدوات الشبكة في حزم مختلفة. وعلى Ubuntu تُسمّى:

| الأداة | الحزمة على Ubuntu |
|---|---|
| `ip`، `ss` | `iproute2` |
| `ping` | `iputils-ping` |
| `dig`، `host`، `nslookup` | `dnsutils` |
| `traceroute` | `traceroute` |
| `ssh`، `ssh-keygen` | `openssh-client` |

وكالعادة، تسمّي العائلات الأخرى بعض الحزم بأسماء أخرى – والجزء الخاص بالتوزيعات
والحزم يتناول مثل هذه الاختلافات.

يعرض `traceroute` كل موجّه تمرّ به الحزم في طريقها. ثبّته وجرّب
`traceroute example.com`!

## ملخّص

| الأمر | ماذا يفعل |
|---|---|
| `ip a` | يعرض عناوين IP |
| `ip route` | يعرض جدول التوجيه والبوابة |
| `ping -c 3 HOST` | يختبر هل يمكن الوصول إلى حاسوب |
| `dig +short NAME` | يبحث عن اسم في DNS |
| `getent hosts NAME` | يبحث كما يفعل النظام (مع `/etc/hosts`) |
| `ss -tulpn` | يعرض المنافذ التي تستمع |
| `curl URL` | يجلب ويعرض |
| `curl -o FILE URL`، `wget URL` | ينزّل إلى ملف |
| `ssh USER@HOST COMMAND` | يشغّل أمرًا على حاسوب آخر |
