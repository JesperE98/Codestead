# المستخدمون والصلاحيات وsudo

صُمّم لينكس بحيث يمكن لعدة مستخدمين أن يتشاركوا الحاسوب نفسه. لهذا لكل ملف مالك
وقواعد تحدد من يحق له أن يفعل ماذا.

## المستخدمون والمجموعات

أنت مسجّل الدخول بالمستخدم `elev`. ينتمي كل مستخدم إلى **مجموعة** (group) واحدة
أو أكثر:

```sh
id
```

أهم مستخدم هو **root** – المدير الذي يحق له فعل أي شيء. نادرًا ما تسجّل الدخول
بوصفك root، بل تستخدم بدلًا من ذلك `sudo` (انظر أدناه).

## قراءة الصلاحيات

شغّل `ls -l` وانظر إلى العمود الأول:

```text
-rw-r--r-- 1 elev elev  174 Oct 29 13:55 anteckningar.txt
drwxr-xr-x 2 elev elev 4096 Oct 29 13:55 dokument
```

المحرف الأول هو النوع: `-` للملف و`d` للمجلد. ثم تأتي ثلاث مجموعات، كل منها من
ثلاثة محارف: للمالك (owner)، وللمجموعة (group)، وللآخرين (others):

```text
-     rw-     r--     r--
type  owner   group   others
```

| المحرف | للملف | للمجلد |
|---|---|---|
| `r` (read) | قراءة المحتوى | عرض المحتوى |
| `w` (write) | تعديل المحتوى | إنشاء الملفات وحذفها فيه |
| `x` (execute) | تشغيل الملف كبرنامج | الدخول إلى المجلد بـ `cd` |

بعد ذلك يأتي المالك (`elev`) والمجموعة (`elev`).

```quiz
لمجلد ما الصلاحيات `drwxr-x---`. ماذا يحق لأعضاء مجموعته أن يفعلوا؟
- [ ] لا شيء إطلاقًا
- [x] عرض المحتوى والدخول إليه بـ `cd`، لكن من دون إنشاء ملفات فيه أو حذفها
- [ ] كل ما يحق للمالك فعله
---
مجموعة صلاحيات المجموعة هي `r-x`: تتيح لك `r` عرض المحتوى وتتيح لك `x` الدخول
إلى المجلد. ومن دون `w` لا تستطيع إنشاء ملفات فيه أو حذفها.
```

## تغيير الصلاحيات – `chmod`

يمكن إعطاء الصلاحيات على شكل **أرقام**. كل مجموعة تأخذ رقمًا هو مجموع r = 4
وw = 2 وx = 1:

| الرقم | الصلاحيات | معتاد لـ |
|---|---|---|
| `755` | `rwxr-xr-x` | البرامج والمجلدات |
| `644` | `rw-r--r--` | الملفات العادية |
| `600` | `rw-------` | الملفات السرية |

```sh
chmod 644 anteckningar.txt
```

أو باستخدام **الرموز**: `u` (المالك)، `g` (المجموعة)، `o` (الآخرون)، `a` (الجميع)،
يتبعها `+` أو `-` أو `=` ثم الصلاحيات:

```sh
chmod u+x skript.sh
chmod go-w fil.txt
```

```predict
$ touch plan.txt
$ chmod 600 plan.txt
$ chmod g+r plan.txt
$ ls -l plan.txt | awk '{print $1}'
-rw-r-----
```

## السكربتات

**السكربت** (script) ملف نصي يحتوي على أوامر. السطر الأول، `#!/bin/bash`، يسمى
*shebang* ويخبر النظام بالبرنامج الذي يجب أن يشغّل الملف:

```sh
echo '#!/bin/bash' > datum.sh
echo 'echo "Today is:"; date' >> datum.sh
cat datum.sh
```

لتشغيل السكربت كبرنامج، يجب أن يكون قابلًا للتنفيذ:

```sh
chmod +x datum.sh
./datum.sh
```

نحتاج إلى `./` لأن المجلد الذي أنت فيه ليس جزءًا من `PATH`.

```quiz
كتبت السكربت `test.sh` وشغّلت `./test.sh`، لكنك حصلت على `Permission denied`.
ما الذي ينقص؟
- [ ] `sudo` في البداية
- [x] صلاحية التنفيذ – شغّل `chmod +x test.sh` أولًا
- [ ] الـ `./` – يجب أن يكون `test.sh`
---
لتشغيل ملف كبرنامج يحتاج إلى الصلاحية `x`. والـ `./` صحيحة: فمن دونها لا يبحث
الـ shell إلا في المجلدات الموجودة في `PATH`.
```

## root وsudo

بعض الملفات، مثل `/etc/shadow` حيث تُخزَّن كلمات المرور، لا يقرؤها إلا root.
وباستخدام `sudo` (*superuser do*) تشغّل أمرًا واحدًا بصلاحيات root:

```sh
sudo whoami
```

في المرة الأولى يطلب `sudo` كلمة المرور **الخاصة بك**. ولا يحق استخدام sudo إلا
للمستخدمين في مجموعة المديرين. على Ubuntu تسمى هذه المجموعة **sudo** – ويمكنك
رؤيتها بين مجموعاتك عندما تشغّل `id`. وتسمّي بعض التوزيعات الأخرى المجموعة
`wheel` بدلًا من ذلك؛ وستقرأ المزيد عن الاختلافات بين التوزيعات في الجزء الخاص
بالتوزيعات.

إذا احتجت إلى تشغيل أوامر كثيرة بصلاحيات root، يمكنك بدء shell خاص بـ root
باستخدام `sudo -i`. عندها يتغير المحث إلى `#`. وارجع باستخدام `exit`.

> **تذكّر!** مع sudo لا توجد شبكة أمان. لا تشغّل إلا الأوامر التي تفهمها.

```quiz
يطلب `sudo` كلمة مرور. كلمة مرور من يجب أن تكتب؟
- [ ] كلمة مرور root
- [x] كلمة مرورك أنت
- [ ] لا كلمة مرور – اضغط Enter فقط
---
يطلب `sudo` كلمة المرور **الخاصة بك**، ولا يسمح لك بالمرور إلا إذا كنت في
مجموعة المديرين.
```

### فخ شائع

```text
sudo echo "text" > /etc/file     # لا يعمل
```

الـ shell *الخاص بك* – وليس sudo – هو الذي يفتح الملف من أجل `>`. استخدم `tee`
بدلًا من ذلك، فهو يعمل بصلاحيات sudo:

```sh
echo "127.0.0.1 test.local" | sudo tee -a /etc/hosts
```

```quiz
لماذا لا يعمل `sudo echo "text" > /etc/file`؟
- [ ] لأن `echo` لا يمكن تشغيله مع sudo
- [x] لأن الـ shell الخاص بك هو من يفتح الملف من أجل `>`، وهو لا يعمل بصلاحيات root
- [ ] لأن الملفات في `/etc` لا يمكن تغييرها أبدًا
---
لا يسري sudo إلا على الأمر (`echo`). أما إعادة التوجيه فيتولاها الـ shell الخاص
بك، الذي يعمل باسمك. و`tee` هو البرنامج الذي يكتب الملف، لذا فإن `tee` هو الذي
يحتاج إلى sudo.
```
