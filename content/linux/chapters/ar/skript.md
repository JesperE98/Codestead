# سكربتات الـ shell

كل ما كتبته في الطرفية حتى الآن يمكن أيضًا حفظه في ملف وتشغيله مرارًا وتكرارًا.
ملف كهذا يسمى **سكربت** (script). تتيح لك السكربتات أتمتة الأعمال المملة: النسخ
الاحتياطي، أو إعادة تسمية مئة ملف، أو فحص السجلات كل صباح. وفوق ذلك، bash لغة
برمجة حقيقية، فيها متغيرات وشروط وحلقات ودوال.

## أول سكربت

السكربت ملف نصي عادي. على الحواسيب الحقيقية تكتبه في محرر نصوص مثل `nano` أو
`vim`. وهناك طريقة أخرى تعمل هنا وعلى الخوادم أيضًا، وهي **here document**: كل ما
بين `<< 'SLUT'` والسطر `SLUT` يُمرَّر إلى الأمر. (*Slut* تعني ببساطة "النهاية"
بالسويدية – يمكنك اختيار أي كلمة تريدها، و`EOF` اختيار شائع.)

اكتب السطر الأول واضغط Enter. يتغير المحث إلى `> ` – فالـ shell ينتظر البقية.
اكتب الأسطر واحدًا تلو الآخر، واختم بـ `SLUT`:

```sh
cat > hej.sh << 'SLUT'
#!/bin/bash
echo "Hello from a script!"
echo "Today is $(date)"
SLUT
```

السطر الأول، `#!/bin/bash`، يسمى *shebang* ويخبر النظام بالبرنامج الذي يجب أن
يشغّل الملف. اجعل السكربت قابلًا للتنفيذ وشغّله:

```sh
chmod +x hej.sh
./hej.sh
```

الأسطر التي تبدأ بـ `#` (باستثناء سطر الـ shebang) هي **تعليقات** يتخطاها الـ
shell. استخدمها لتشرح ما تفعله الشيفرة!

## المتغيرات

تنشئ متغيرًا بـ `name=value`. ويجب **ألا** توجد أي مسافات حول علامة المساواة –
وإلا ظن الـ shell أن `name` أمر.

```sh
stad=Göteborg
echo "I live in $stad"
```

(*Stad* تعني "مدينة".) ضع المتغيرات دائمًا داخل **علامات اقتباس مزدوجة** عندما
تستخدمها. فمن دون علامات الاقتباس تُقسَّم القيمة عند المسافات، ما يسبب أخطاء غريبة
عندما يحتوي اسم ملف على مسافة. وإذا أردت كتابة نص مباشرة بعد اسم المتغير، فاستخدم
الأقواس المعقوصة: `"${stad}_2026"` – فمن دونها سيبحث bash عن متغير اسمه
`stad_2026`.

## استبدال الأوامر – `$(...)`

يُستبدل `$(command)` بما يطبعه الأمر. وهكذا تحفظ نتيجة أمر في متغير:

```sh
idag=$(date)
filer=$(ls ~ | wc -l)
echo "There are $filer items in your home directory"
```

## الحساب – `$(( ))`

ينفّذ bash العمليات الحسابية على الأعداد الصحيحة داخل `$(( ))`. وداخل الأقواس
لا تحتاج إلى `$` قبل المتغيرات:

```sh
a=7
echo $(( a * 6 ))
echo $(( 17 / 5 )) remainder $(( 17 % 5 ))
```

لتغيير قيمة متغير، اكتب `(( a++ ))` أو `(( a += 10 ))`.

## الوسائط

عندما تشغّل `./skript.sh one two`، يستطيع السكربت قراءة الوسائط:

| المتغير | يحتوي على |
|---|---|
| `$0` | اسم السكربت |
| `$1`، `$2` ... | الوسيط الأول، الثاني ... |
| `$#` | عدد الوسائط |
| `"$@"` | كل الوسائط، كل منها على حدة |
| `$?` | رمز خروج الأمر السابق |

## الشروط – `if`

يشغّل `if` أمرًا وينظر إلى **رمز خروجه**: 0 يعني صحيح، وأي قيمة أخرى تعني خطأ. في
أغلب الأحيان تستخدم الأمر `[` (المعروف أيضًا باسم `test`):

```sh
if [ -f ~/.bashrc ]; then echo "The file exists"; else echo "The file is missing"; fi
```

المسافات داخل `[ ]` إلزامية! وعند كتابته على عدة أسطر، كما في السكربت، يبدو هكذا:

```text
if [ "$answer" = "yes" ]; then
    echo "Great!"
elif [ "$answer" = "no" ]; then
    echo "Too bad."
else
    echo "Please answer yes or no."
fi
```

أكثر الاختبارات شيوعًا:

| الاختبار | يكون صحيحًا إذا |
|---|---|
| `-f FILE` | كان الملف موجودًا (وكان ملفًا عاديًا) |
| `-d DIR` | كان المجلد موجودًا |
| `-z "$x"` | كان المتغير فارغًا |
| `"$a" = "$b"` | كانت السلسلتان النصيتان متساويتين (`!=` مختلفتين) |
| `$a -eq $b` | كان العددان متساويين |
| `$a -lt $b` | كان الأول أصغر (`-le`، `-gt`، `-ge`، `-ne`) |
| `! CONDITION` | كان الشرط *غير* صحيح |

لاحظ أن الأعداد تُقارن بـ `-eq` و`-lt` وما شابه، بينما `=` و`<` تقارنان النصوص.
ولدى bash أيضًا `[[ ... ]]`، وهو أذكى قليلًا: يمكنك فيه كتابة `&&` و`||` والمطابقة
مع أنماط مثل `[[ $file == *.txt ]]`.

للشروط القصيرة، غالبًا ما يكفي `&&` و`||`:

```sh
[ -d ~/bilder ] && echo "The pictures directory exists"
```

## الحلقات

**حلقة for** تفعل الشيء نفسه لكل عنصر في قائمة:

```sh
for frukt in äpple banan kiwi; do echo "I like $frukt"; done
```

يمكن أن تأتي القائمة من أحرف البدل أو من أمر:

```sh
for fil in ~/dokument/*; do echo "File: $fil"; done
for i in $(seq 1 3); do echo "Round $i"; done
```

**حلقة while** تستمر ما دام الشرط صحيحًا:

```sh
i=1; while [ $i -le 3 ]; do echo $i; (( i++ )); done
```

الطريقة الأكثر شيوعًا للمرور على ملف سطرًا سطرًا هي `while read`، مع تمرير الملف
باستخدام `<` بعد `done`:

```sh
while read rad; do echo "> $rad"; done < ~/dokument/frukter.txt
```

يخرج `break` من الحلقة، وينتقل `continue` مباشرة إلى الدورة التالية.

> **احذر الحلقات اللانهائية!** الحلقة التي لا يصبح شرطها خاطئًا أبدًا تستمر إلى
> الأبد. في طرفية حقيقية توقفها بـ **Ctrl+C**. أما المحاكي فيوقفها بنفسه بعد
> 20,000 خطوة.

## الاختيار بـ `case`

عندما يمكن أن يأخذ متغير قيمًا مختلفة كثيرة، يكون `case` أوضح من سلسلة طويلة من
`elif`:

```sh
fil=semester.jpg
case $fil in *.jpg|*.png) echo "An image";; *.txt) echo "A text file";; *) echo "Unknown type";; esac
```

كل بديل ينتهي بـ `;;`، و`*)` يلتقط كل ما عدا ذلك.

## الدوال

**الدالة** (function) قطعة شيفرة لها اسم، يمكنك استدعاؤها كأنها أمر مستقل. وهي
تستقبل الوسائط بالطريقة نفسها التي يستقبلها بها السكربت – `$1` و`$2` و`$#`:

```sh
halsa() { echo "Hello $1, welcome!"; }
halsa Kim
```

المتغيرات التي يجب أن توجد داخل الدالة فقط تُنشأ بـ `local`، وينهي `return` الدالة
برمز خروج.

## سؤال المستخدم – `read`

يقرأ `read` سطرًا من لوحة المفاتيح إلى متغير:

```sh
read -p "What's your name? " namn; echo "Hello $namn!"
```

## مثال كامل

إليك سكربتًا يستخدم معظم ما تناوله هذا الفصل. فهو ينسخ احتياطيًا الملفات التي
تعطيه إياها كوسائط:

```text
#!/bin/bash
# backup.sh – ينسخ كل ملف إلى file.bak

if [ $# -eq 0 ]; then
    echo "Usage: $0 FILE..."
    exit 1
fi

for file in "$@"; do
    if [ -f "$file" ]; then
        cp "$file" "$file.bak"
        echo "Copied $file"
    else
        echo "Cannot find $file" >&2
    fi
done
```

ينهي `exit 1` السكربت برمز الخروج 1، حتى يرى من استدعى السكربت أن شيئًا ما قد
حدث بشكل خاطئ.

## نصائح لسكربتات جيدة

- ابدأ بـ `#!/bin/bash` واكتب تعليقات.
- ضع المتغيرات بين علامات اقتباس: `"$file"`، وليس `$file`.
- يبدأ كثيرون سكربتاتهم بـ `set -euo pipefail`، حتى يتوقف السكربت عند أول خطأ بدلًا
  من الاستمرار بشكل أعمى.
- يجد البرنامج **ShellCheck** الأخطاء الشائعة في سكربتات bash – ويمكنك تثبيته
  بمدير الحزم في كل التوزيعات الكبرى.
