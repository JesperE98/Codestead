# المهام المجدولة باستخدام cron

نسخة احتياطية كل ليلة، وتنظيف السجلات القديمة كل أسبوع، وجلب البيانات كل خمس
دقائق – يستطيع الحاسوب تشغيل الأوامر بنفسه في أوقات محدّدة. الأداة الكلاسيكية
لذلك هي **cron**، ولدى systemd **مؤقّتاته** الخاصة.

## cron وcrontab

تستيقظ الخدمة cron كل دقيقة وتشغّل المهام التي حان وقتها. ولكل مستخدم قائمته
الخاصة من المهام، وهي **crontab**:

```sh
crontab -l
```

تعني *no crontab for {{user}}* أنه ليست لديك مهام بعد.

## حقول الوقت الخمسة

في كل سطر من crontab خمسة حقول للوقت ثم الأمر:

```text
┌───────────── الدقيقة (0–59)
│ ┌─────────── الساعة (0–23)
│ │ ┌───────── يوم الشهر (1–31)
│ │ │ ┌─────── الشهر (1–12)
│ │ │ │ ┌───── يوم الأسبوع (0–7، الأحد هو 0 أو 7)
│ │ │ │ │
* * * * *  الأمر
```

| تكتب | المعنى |
|---|---|
| `*` | كل |
| `5` | 5 بالضبط |
| `1-5` | من 1 إلى 5 |
| `1,15` | 1 و15 |
| `*/10` | كل عاشر: 0، 10، 20 … |

| السطر | يعمل |
|---|---|
| `* * * * * command` | كل دقيقة |
| `*/5 * * * * command` | كل خمس دقائق |
| `30 2 * * * command` | في 02:30 كل ليلة |
| `0 7 * * 1-5 command` | في 07:00 من الاثنين إلى الجمعة |
| `0 0 1 * * command` | في منتصف الليل في اليوم الأول من كل شهر |
| `@reboot command` | مرة واحدة، عند بدء تشغيل الحاسوب |

و`@hourly` و`@daily` و`@weekly` و`@monthly` اختصارات أيضًا.

```quiz
متى تعمل المهمة `15 8 * * 6 ~/backup.sh`؟
- [ ] في 15:08 كل يوم
- [x] في 08:15 كل سبت
- [ ] في اليوم 15 من كل شهر في 08:00
---
الترتيب هو الدقيقة، ثم الساعة، ثم يوم الشهر، ثم الشهر، ثم يوم الأسبوع: الدقيقة
15، والساعة 8، وأي تاريخ، وأي شهر، واليوم 6 – السبت.
```

```quiz
كم مرة يعمل `0 */2 * * * command`؟
- [ ] كل دقيقتين
- [x] كل ساعتين، عند رأس الساعة
- [ ] مرتين في اليوم
---
الدقيقة 0 وكل ساعة ثانية: 00:00، 02:00، 04:00 …
```

## تثبيت المهام

يفتح `crontab -e` ملف crontab الخاص بك في محرّر نصوص ويثبّته عندما تحفظ. لا يوجد
في المحاكي محرّر بعد، لذا تعطي هنا `crontab` المهام عبر مدخله – وتعني `-` "اقرأ من
المدخل":

```sh
echo '* * * * * date >> ~/cron.log' | crontab -
crontab -l
```

انتبه: `crontab -` و`crontab FILE` **يستبدلان** ملف crontab كله. ولإضافة مهمة،
اجمع المهام القديمة مع المهمة الجديدة:

```sh
(crontab -l; echo '30 2 * * * ~/backup.sh') | crontab -
```

لحذف سطر واحد، استبعده باستخدام `grep -v` وثبّت الباقي – أو احذف كل شيء باستخدام
`crontab -r`:

```sh
crontab -l | grep -v backup.sh | crontab -
```

يفحص `crontab` الأسطر قبل أن يثبّت أي شيء:

```predict
$ echo '0 25 * * * date' | crontab -
"-":1: bad hour
errors in crontab file, can't install.
---
لا توجد ساعة 25 – فالساعات من 0 إلى 23. ولم يُثبَّت شيء.
```

## مشاهدتها وهي تعمل

بعد أن تثبّت المهمة التي تعمل كل دقيقة، انتظر دقيقة ثم انظر:

```sh
cat ~/cron.log
journalctl -u cron
```

كل تشغيل يُكتب في الـ journal، مثل
`CRON[4211]: ({{user}}) CMD (date >> ~/cron.log)`. في المحاكي لا يعمل cron إلا
والتطبيق مفتوح – وتمامًا مثل الحاسوب الحقيقي، لا يعوّض المهام التي فاتته وهو
مطفأ.

## فخّ cron: بيئة مختلفة

لا تعمل المهام في طرفيتك، وهذا يفاجئ الجميع تقريبًا:

- تعمل باستخدام `/bin/sh`، من دون الأسماء المستعارة الخاصة بك ومن دون `~/.bashrc`.
- `PATH` قصير (`/usr/bin:/bin`)، لذا تحتاج البرامج الموجودة في أماكن أخرى إلى
  مسارها الكامل.
- تبدأ في مجلد المنزل.
- المخرجات التي لا تُرسَل إلى ملف تضيع. أنهِ السطر دائمًا بشيء مثل
  `>> ~/job.log 2>&1`.

شغّل الأمر يدويًا أولًا. وعندما ينجح هناك، ضعه في crontab.

```quiz
المهمة `* * * * * echo hi` تعمل كل دقيقة، لكنك لا ترى `hi` في أي مكان. لماذا؟
- [ ] لا يسمح cron بـ `echo`
- [x] المخرجات ليس لها مكان تذهب إليه – أرسلها إلى ملف باستخدام `>>`
- [ ] المهام لا تعمل إلا بصلاحيات root
---
مخرجات مهام cron لا تُعرض في أي طرفية. يحاول cron الحقيقي إرسالها بالبريد
الإلكتروني، ومعظم الحواسيب ليس فيها بريد – لذا تضيع.
```

## مهام النظام نفسه

إلى جانب ملفات crontab الخاصة بالمستخدمين يوجد `/etc/crontab`، ومجلدات مثل
`/etc/cron.daily` و`/etc/cron.weekly`. والسكربتات الموجودة فيها تعمل مرة في اليوم
أو مرة في الأسبوع:

```sh
cat /etc/crontab
ls /etc/cron.daily
```

للأسطر في `/etc/crontab` حقل إضافي قبل الأمر: المستخدم الذي تعمل المهمة باسمه.

## مؤقّتات systemd

في التوزيعات الحديثة تتولّى **مؤقّتات** systemd كثيرًا من هذا بدلًا من cron: وحدة
`.timer` تبدأ وحدة `.service` في أوقات محدّدة. وهي تكتب سجلاتها في الـ journal
ويمكنها تعويض مرات التشغيل التي فاتتها، لكن كل مهمة تحتاج إلى ملفَّي وحدة. أما
لمهامك الصغيرة الخاصة، فإن cron هو الطريق الأسرع. اعرض المؤقّتات على الحاسوب،
مع مرة التشغيل التالية والسابقة:

```try
systemctl list-timers
```

## في التوزيعات الأخرى

| | Ubuntu وDebian | Fedora | Arch |
|---|---|---|---|
| الحزمة | `cron` | `cronie` | `cronie` |
| الخدمة | `cron` | `crond` | `cronie` |
| مثبّت منذ البداية | نعم | نعم | لا |

في Arch تبدأ بـ `sudo pacman -S cronie` و`sudo systemctl enable --now cronie`.
