# أصداف shell أخرى: zsh وfish

حتى الآن كتبت كل أمر في **bash**. لكن bash ليس إلا واحدًا من عدة أصداف (shells)
– وكثير من الناس يفضّلون شيئًا آخر. في هذا الفصل ستثبّت بديلين شائعين، **zsh**
و**fish**، وتجرّبهما وترى كيف يختلفان عن bash. وستتعلّم أيضًا لماذا لا تزال
السكربتات تُكتب لـ bash في كل الحالات تقريبًا.

## ما هو الـ shell، مرة أخرى؟

**الـ shell** هو البرنامج الذي يقرأ ما تكتبه ويفسّره ويبدأ برامج أخرى. فالـ
shell هو الذي يفهم `|` و`>` و`$VARIABLES` وأحرف البدل (wildcards) مثل `*.txt`
والحلقات. أما الطرفية فليست إلا النافذة التي يعمل فيها الـ shell.

البرامج مثل `ls` و`grep` و`cat` برامج مستقلة في `/usr/bin` – وهي تعمل بالطريقة
نفسها أيًّا كان الـ shell الذي تستخدمه. وما يختلف بين الأصداف هو **اللغة المحيطة
بها**: كيف تُعيَّن المتغيّرات، وكيف تُكتب الحلقات والشروط، وكيف يبدو المحث،
وما وسائل الراحة المتاحة.

```quiz
تنتقل من bash إلى shell آخر. أيّ هذه الأشياء يبقى كما هو تمامًا؟
- [ ] طريقة تعيين متغيّر
- [ ] طريقة كتابة حلقة
- [x] ما يفعله `grep` بخياراته
- [ ] شكل المحث
---
`grep` برنامج مستقل في `/usr/bin`. والـ shell يبدؤه فقط – أما اللغة المحيطة به
فهي ما يختلف بين الأصداف.
```

## شجرة العائلة: sh وbash وzsh وfish

| الـ shell | منذ | الخصائص |
|---|---|---|
| `sh` | 1979 | Bourne shell. يتبع `sh` اليوم المعيار **POSIX**، وهو القاسم المشترك الأدنى. |
| `bash` | 1989 | *Bourne Again SHell*. الافتراضي في كل توزيعات Linux تقريبًا. |
| `zsh` | 1990 | متوافق مع bash إلى حد كبير، لكن بميزات أكثر. الافتراضي في macOS. |
| `fish` | 2005 | *Friendly interactive shell*. سهل الاستخدام، لكن له **صياغته الخاصة**. |

**POSIX** معيار يصف كيف يجب أن يتصرّف shell من نوع `sh`. والسكربت الذي لا يستخدم
إلا ميزات POSIX يعمل في كل shell متوافق مع `sh`: bash وzsh و`dash` (وهو `/bin/sh`
على Debian وUbuntu) و`ash` (على الأنظمة الصغيرة مثل Alpine). أما fish فهو **غير**
متوافق مع POSIX عن قصد – وهذا ما يجعله أبسط، لكنه مختلف أيضًا.

## ما الأصداف المثبّتة؟

يسرد الملف `/etc/shells` الأصداف التي يجوز استخدامها بوصفها login shell (shell
تسجيل الدخول):

```sh
cat /etc/shells
```

أما الـ shell الذي تحصل عليه عند تسجيل الدخول فهو الحقل الأخير من سطرك في
`/etc/passwd`، وهو موجود أيضًا في المتغيّر `$SHELL`:

```sh
grep elev /etc/passwd
echo $SHELL
```

## zsh – bash مع إضافات

### ثبّت zsh

في طرفية Ubuntu تثبّت zsh باستخدام apt:

```sh
sudo apt update
sudo apt install zsh
```

أما التوزيعات الأخرى فتستخدم مدير الحزم الخاص بها، كما تعلّمت في الجزء الخاص
بالتوزيعات والحزم. واسم الحزمة هناك أيضًا `zsh`.

انظر إلى `/etc/shells` من جديد – لقد أضافت الحزمة `/usr/bin/zsh` (و`/bin/zsh`):

```sh
cat /etc/shells
```

### ابدأ zsh

الـ shell برنامج مثل أي برنامج آخر، لذا تبدأ zsh بكتابة اسمه:

```sh
zsh
```

في المرة الأولى يستقبلك **zsh-newuser-install**، لأنه ليس لديك ملف إعدادات لـ zsh
بعد. وهو قائمة تساعدك على البدء:

| المفتاح | ماذا يفعل |
|---|---|
| `q` | اخرج من دون فعل أي شيء (ستُسأل من جديد في المرة القادمة) |
| `0` | أنشئ ملف `~/.zshrc` شبه فارغ |
| `1` | القائمة الرئيسية بكل الإعدادات (غير متاحة في المحاكي) |
| `2` | أنشئ `~/.zshrc` بالإعدادات الموصى بها |

أجب بـ `2`. يتغيّر المحث إلى `elev@ubuntu ~ %` – ففي zsh تكون `%` العلامة
المعتادة للمستخدم العادي (ويحصل root على `#`، تمامًا كما في bash).

أيّ shell تشغّل الآن؟ يحمل المتغيّر `$0` اسم الـ shell:

```sh
echo $0
ps
```

يُظهر `ps` أن zsh يعمل **داخل** bash: فقد بدأ bash الـ zsh عمليةً جديدة. ولاحظ
أيضًا أن `$SHELL` لا يزال `/bin/bash` – فهذا المتغيّر يخبرك بالـ *login shell*
الخاص بك، لا بالـ shell الذي تصادف أنك تشغّله الآن.

```sh
echo $SHELL
```

### معظم الأشياء تعمل كما في bash

يفهم zsh كل صياغة bash تقريبًا. فالـ pipes وإعادة التوجيه والمتغيّرات و`if`
و`for` والدوال تعمل بالطريقة التي اعتدت عليها:

```sh
for f in ~/dokument/*.txt; do wc -l $f; done
```

### الميزة 1: `**` تبحث في كل المجلدات الفرعية

في zsh تعني `**/` "كل المجلدات، على كل المستويات". وهذا يسرد كل ملف `.txt` في
مجلد المنزل وكل ما تحته:

```sh
ls ~/**/*.txt
```

في bash تعمل `**` مثل `*` العادية – ما لم تفعّلها أولًا باستخدام
`shopt -s globstar`.

### الميزة 2: autocd

مع الخيار `autocd` (وهو جزء من الإعدادات الموصى بها) لا تحتاج إلا إلى كتابة اسم
المجلد لتنتقل إليه – من دون `cd`:

```sh
dokument
..
```

تُفعَّل الخيارات وتُعطَّل باستخدام `setopt` و`unsetopt`:

```sh
setopt
unsetopt autocd
setopt autocd
```

### فرق يجب الانتباه إليه: المتغيّرات لا تُقسَّم

في bash يُقسَّم المتغيّر غير المحاط بعلامات اقتباس عند المسافات. أما في zsh فلا:

```sh
filer="a.txt b.txt"
for f in $filer; do echo "[$f]"; done
```

يطبع bash `[a.txt]` و`[b.txt]` – بينما يطبع zsh `[a.txt b.txt]`. وطريقة zsh هي
عادةً ما تريده، لكنها تعني أن سكربت bash لا يفعل دائمًا الشيء نفسه في zsh. (ومع
`setopt shwordsplit` يتصرّف zsh مثل bash.)

لست مضطرًا إلى بدء shell لتجرّب فيه أمرًا واحدًا. مع `-c` يشغّل الـ shell الأمر
ثم يخرج فورًا – فيطبع `zsh -c 'echo $0'` الكلمة `zsh`، وتبقى في bash بعد ذلك.

السؤال التالي يبدأ في طرفية جديدة، لذا يثبّت zsh أولًا. ويرمي
`> /dev/null 2>&1` مخرجات ذلك السطر. ماذا يطبع الأمر الأخير؟

```predict
$ sudo apt update > /dev/null 2>&1 && sudo apt install -y zsh > /dev/null 2>&1
$ zsh -c 'filer="x.txt y.txt z.txt"; for f in $filer; do echo "<$f>"; done'
<x.txt y.txt z.txt>
---
لا يقسّم zsh المتغيّر عند المسافات، لذا تعمل الحلقة مرة واحدة بالقيمة كاملة. أما
في bash فكانت الحلقة نفسها ستطبع ثلاثة أسطر: `<x.txt>` و`<y.txt>` و`<z.txt>`.
```

### ~/.zshrc والمحث

يقرأ bash الملف `~/.bashrc` عندما يبدأ – ويقرأ zsh الملف `~/.zshrc`. انظر إلى
الملف الذي أنشأه zsh-newuser-install:

```sh
cat ~/.zshrc
```

يُضبط المحث بالمتغيّر `PROMPT` ويستخدم رموزًا تبدأ بـ `%`:

| الرمز | المعنى |
|---|---|
| `%n` | اسم المستخدم |
| `%m` | اسم الحاسوب |
| `%~` | المجلد كاملًا (مع `~` لمجلد المنزل) |
| `%1~` | الجزء الأخير فقط من المجلد |
| `%#` | `%` للمستخدمين العاديين، و`#` لـ root |
| `%F{green}` … `%f` | اللون (red، green، blue، yellow …) |

جرّب:

```sh
PROMPT='%F{green}%n%f:%~ %# '
```

لا يدوم التغيير إلا حتى تغادر zsh. وإذا أردته في كل مرة، فضع السطر في
`~/.zshrc`.

### Oh My Zsh

يثبّت كثير من مستخدمي zsh **Oh My Zsh**، وهي مجموعة من السمات (themes) والإضافات
(plugins) – مثل معلومات Git في المحث، وإكمال أفضل بمفتاح Tab، واقتراحات أثناء
الكتابة. وتُثبَّت بسكربت من موقع المشروع وتُضبط في `~/.zshrc`. وهي غير متاحة في
المحاكي، لكنك تعرف الآن ما يقصده الناس عندما يتحدّثون عنها.

### العودة إلى bash

zsh عملية تعمل داخل bash. اخرج منها باستخدام `exit` وستعود إلى bash – حيث تكون
المتغيّرات والأسماء المستعارة (aliases) وتغييرات المجلد التي أجريتها في zsh قد
اختفت:

```sh
exit
echo $0
```

## fish – الـ shell التفاعلي الودود

يريد fish أن يكون سهل الاستخدام فورًا، من دون إعدادات: ألوان، وإكمال بمفتاح Tab،
و**اقتراحات تلقائية** (autosuggestions) – إذ يقترح fish بقية الأمر بنص رمادي،
بناءً على سجل أوامرك، وتقبل الاقتراح بمفتاح السهم الأيمن. (لا يعرض المحاكي
اقتراحات، لكن الصياغة تعمل.)

### ثبّت fish وابدأه

يُثبَّت fish باستخدام apt بالطريقة نفسها – وعلى التوزيعات الأخرى بمدير الحزم
الخاص بها:

```sh
sudo apt update
sudo apt install fish
```

```sh
fish
```

يرحّب بك fish ويصبح المحث `elev@ubuntu ~>`. انزل بضعة مجلدات وانظر كيف
يختصر fish المسار في المحث:

```sh
mkdir -p ~/dokument/projekt
cd ~/dokument/projekt
cd ~
```

في المجلد `~/dokument/projekt` يعرض المحث `~/d/projekt>` – فكل مجلد ما عدا
الأخير يُختصر إلى حرف واحد.

### لـ fish صياغته الخاصة

هنا يختلف fish أكثر ما يختلف عن bash وzsh:

| هذا | bash وzsh | fish |
|---|---|---|
| تعيين متغيّر | `frukt=äpple` | `set frukt äpple` |
| متغيّر بيئة | `export EDITOR=nano` | `set -x EDITOR nano` |
| حذف متغيّر | `unset frukt` | `set -e frukt` |
| استبدال الأوامر | `$(pwd)` | `(pwd)` |
| حالة الخروج الأخيرة | `$?` | `$status` |
| وسائط السكربت | `$@`، `$1` | `$argv`، `$argv[1]` |
| الشرط | `if …; then …; fi` | `if …; …; end` |
| الحلقة | `for …; do …; done` | `for …; …; end` |
| الدالة | `hej() { …; }` | `function hej; …; end` |
| الحساب | `$((17 * 23))` | `math 17 x 23` |

### المتغيّرات مع set

جرّب تعيين متغيّر بطريقة bash (`frukt` تعني "فاكهة" بالسويدية، و`äpple` تعني
"تفاحة"):

```sh
frukt=äpple
```

يرفض fish ويخبرك بالطريقة الصحيحة لكتابته:

```text
fish: Unsupported use of '='. In fish, please use 'set frukt äpple'.
```

هكذا يتم الأمر في fish:

```sh
set frukt äpple
echo $frukt
set -x EDITOR nano
set -e frukt
```

يجعل `-x` (*export*) المتغيّر متغيّر بيئة تستطيع رؤيته البرامج التي تبدؤها،
ويحذفه `-e` (*erase*).

في fish كل متغيّر هو **قائمة**. وتُرقَّم العناصر بدءًا من 1:

```sh
set frukter äpple päron banan
echo $frukter[2]
count $frukter
```

يعمل `-c` في fish أيضًا. ماذا يطبع الأمر الأخير؟

```predict
$ sudo apt update > /dev/null 2>&1 && sudo apt install -y fish > /dev/null 2>&1
$ fish -c 'set frukter äpple päron banan; echo $frukter[3]'
banan
---
تُرقَّم عناصر القائمة في fish بدءًا من 1، لذا فإن `[3]` هو العنصر الثالث
والأخير.
```

### استبدال الأوامر و$status

في fish يُكتب استبدال الأوامر بأقواس عادية:

```sh
echo "I am in" (pwd)
```

داخل علامات الاقتباس تكون الأقواس نصًا عاديًا – ولهذا تقع `(pwd)` خارجها. أما
حالة الخروج لآخر أمر فتُسمّى `$status`:

```sh
false
echo $status
```

### and وor وnot

لدى fish أوامر خاصة به لربط الشروط:

```sh
test -f ~/.bashrc; and echo exists
test -f ~/missing.txt; or echo missing
```

تفهم الإصدارات الأحدث من fish (3.0 وما بعدها) أيضًا `&&` و`||`، ومنذ 3.4 يعمل
`$(...)` كذلك. لكن `X=1` و`$?` و`$((...))` لا تزال لا تعمل – فهي تعطي أخطاء
تخبرك بطريقة fish.

### الكتل تنتهي بـ end

في fish تنتهي كل كتلة – `if` و`for` و`while` و`switch` و`function` – بـ `end`.
فلا يوجد `then` ولا `do` ولا `done` ولا `fi`:

```sh
for i in 1 2 3; echo $i; end
if test -f ~/.bashrc; echo exists; else; echo missing; end
```

يمكنك أيضًا كتابة الكتلة على عدة أسطر. وينتظر الـ shell الكلمة `end` قبل أن
يشغّل الحلقة:

```sh
for f in ~/dokument/*.txt
echo (basename $f)
end
```

تحصل الدوال على وسائطها في القائمة `$argv`:

```sh
function hello; echo "Hello $argv!"; end
hello Kim
```

### الحساب مع math

ليس في fish `$((...))`. بل يوجد بدلًا منه الأمر `math`، الذي يتعامل مع الكسور
العشرية أيضًا:

```sh
math 17 x 23
math 10 / 4
```

اكتب `x` (أو `"17 * 23"` بين علامات اقتباس) للضرب – فالـ `*` وحدها حرف بدل في
fish، تمامًا كما في bash.

### إعدادات fish

يقرأ fish الملف `~/.config/fish/config.fish` عندما يبدأ. وإذا أردت التخلّص من
رسالة الترحيب، فأفرغ المتغيّر `fish_greeting`. ومع `-U` يصبح المتغيّر **عامًّا**
(universal): فيُحفظ في `~/.config/fish/fish_variables` ويسري في كل shell من نوع
fish، حتى بعد إعادة التشغيل.

```sh
cat ~/.config/fish/config.fish
set -U fish_greeting ""
```

اخرج من fish باستخدام `exit`:

```sh
exit
```

## لماذا لا تزال السكربتات تُكتب لـ bash

أيّ shell تستخدمه في الطرفية مسألة ذوق. لكن **السكربتات** تُكتب في كل الحالات
تقريبًا لـ bash (أو لـ `sh` وفق POSIX):

- bash مثبّت عمليًا على كل أنظمة Linux – أما zsh وfish فلا.
- صياغة fish لا تعمل في bash، والعكس صحيح.
- سطر `#!` في أعلى السكربت هو الذي يحدّد أيّ shell يشغّله – **بغض النظر** عن
  الـ shell الذي تجلس فيه.

جرّب كتابة سكربت bash وتشغيله من fish:

```sh
cat > ~/hej.sh << 'SLUT'
#!/bin/bash
name=Kim
echo "Hello $name, I am run by bash"
SLUT
chmod +x ~/hej.sh
fish
~/hej.sh
exit
```

يعمل السكربت في fish، رغم أن `name=Kim` ممنوعة هناك – لأن bash هو الذي يشغّله.
ولهذا فإن `#!/bin/bash` (أو `#!/usr/bin/env bash`) مهمّ جدًّا. والسكربت الذي يجب
أن يعمل في كل مكان، حتى حيث لا يوجد bash، يُكتب باستخدام `#!/bin/sh` وصياغة POSIX
فقط.

```quiz
أنت في fish وتشغّل سكربتًا يبدأ بـ `#!/bin/bash` ويحتوي على السطر `count=3`.
ماذا يحدث؟
- [ ] يرفض fish، لأن `count=3` غير مسموح بها في fish
- [x] يعمل – فـ bash هو من يشغّل السكربت، أيًّا كان الـ shell الذي أنت فيه
- [ ] لا يعمل إلا إذا غيّرت أولًا الـ login shell إلى bash باستخدام `chsh`
---
سطر `#!` هو الذي يحدّد أيّ shell يشغّل السكربت. وfish يبدؤه فقط.
```

## تغيير الـ shell الافتراضي باستخدام chsh

كتابة `zsh` في كل مرة تفتح فيها طرفية تصبح مملّة. مع `chsh` (*change shell*) تغيّر
الـ **login shell** الخاص بك – أي ذلك الموجود في `/etc/passwd`:

```sh
chsh -s /usr/bin/zsh
grep elev /etc/passwd
```

- يجب أن يُعطى الـ shell بمساره الكامل وأن يكون مسرودًا في `/etc/shells`.
- يطلب `chsh` كلمة مرورك (ويتخطّى المحاكي ذلك).
- يسري التغيير عند **تسجيل الدخول التالي**. فالطرفية المفتوحة لديك تحتفظ بالـ
  shell القديم، ولا يتغيّر `$SHELL` إلا بعد أن تسجّل الدخول من جديد.
- يستطيع root تغيير الـ shell للآخرين: `sudo chsh -s /usr/bin/fish kim`.

للعودة إلى bash، افعل الشيء نفسه:

```sh
chsh -s /bin/bash
```

من النصائح الشائعة بشأن fish أن تُبقي bash بوصفه الـ login shell وتدع برنامج
الطرفية يبدأ fish بدلًا من ذلك – عندها يستمر في العمل كل ما يتوقّع shell متوافقًا
مع POSIX عند تسجيل الدخول.

السؤال يبدأ في طرفية جديدة، ويثبّت zsh ويجعله الـ login shell. ماذا يطبع الأمر
الأخير؟

```predict
$ sudo apt update > /dev/null 2>&1 && sudo apt install -y zsh > /dev/null 2>&1
$ chsh -s /usr/bin/zsh > /dev/null 2>&1
$ echo $SHELL
/bin/bash
---
غيّر `chsh` سطرك في `/etc/passwd`، لكن التغيير يسري عند تسجيل الدخول التالي.
فالطرفية المفتوحة لديك تحتفظ بـ bash، وكذلك `$SHELL`.
```

## أيّ shell تختار؟

- **bash** – الافتراضي في كل مكان. ما تتعلّمه هنا يعمل على كل خادم ستسجّل الدخول
  إليه يومًا. اكتب سكربتاتك لـ bash.
- **zsh** – لمن يريد راحة أكبر مع الاحتفاظ بصياغة bash. ويمنحك Oh My Zsh سمات
  وإضافات.
- **fish** – أفضل تجربة جاهزة من البداية، لكن بصياغة مختلفة. فالأوامر التي تنسخها
  من الويب لا تعمل دائمًا.
- **sh/dash** – للسكربتات التي يجب أن تعمل في كل مكان، وعلى الأنظمة الصغيرة.

## ملخّص

| الأمر | ماذا يفعل |
|---|---|
| `cat /etc/shells` | يسرد الأصداف التي يجوز استخدامها |
| `echo $0` / `ps` | يُظهر الـ shell الذي تشغّله الآن |
| `echo $SHELL` | يُظهر الـ login shell الخاص بك |
| `zsh` / `fish` / `exit` | يبدأ shell آخر / يعود |
| `ls ~/**/*.txt` | يبحث في كل المجلدات الفرعية (zsh، fish) |
| `setopt autocd` | يفعّل خيارًا في zsh |
| `set frukt äpple` | يعيّن متغيّرًا في fish |
| `set -x NAME value` | يعيّن متغيّر بيئة في fish |
| `chsh -s /usr/bin/zsh` | يغيّر الـ login shell الخاص بك |

ملفات الإعدادات: `~/.bashrc` (bash)، و`~/.zshrc` (zsh)،
و`~/.config/fish/config.fish` (fish).
