# إدارة الحزم

في Windows وmacOS كثيرًا ما تنزّل البرامج من موقع ويب. أما في لينكس فتثبّت كل شيء
تقريبًا بواسطة **مدير الحزم** (package manager). وهذا هو أكبر فرق بين عائلات
التوزيعات – ويبدو هذا الفصل مختلفًا بحسب التوزيعة التي اخترتها. وهو الآن **{{pm}}**
على {{distro}}.

## الحزم والمستودعات والاعتماديات

- **الحزمة** (package) هي برنامج (أو مكتبة) معبّأ في ملف، مع معلومات عن إصداره
  وعمّا يحتاجه.
- **المستودع** (repository) هو خادم تنشر عليه التوزيعة كل حزمها. وهي مختبَرة
  وموقّعة، فتعرف أنه لم يُعبث بها.
- **الاعتمادية** (dependency) هي حزمة أخرى مطلوبة. ويثبّت مدير الحزم الاعتماديات
  تلقائيًا.

ويتتبّع مدير الحزم أيضًا ما هو مثبّت، ويستطيع تحديث *كل شيء* على الحاسوب بأمر
واحد.

## الشيء نفسه – بثلاث لهجات

| المهمة | apt (Debian) | pacman (Arch) | dnf (Red Hat) |
|---|---|---|---|
| تحديث قائمة الحزم | `apt update` | `pacman -Sy` | `dnf check-update` |
| ترقية كل شيء | `apt upgrade` | `pacman -Syu` | `dnf upgrade` |
| التثبيت | `apt install X` | `pacman -S X` | `dnf install X` |
| الإزالة | `apt remove X` | `pacman -R X` | `dnf remove X` |
| البحث | `apt search X` | `pacman -Ss X` | `dnf search X` |
| معلومات الحزمة | `apt show X` | `pacman -Si X` | `dnf info X` |
| عرض المثبّت | `apt list --installed` | `pacman -Q` | `dnf list --installed` |

الأوامر التي تغيّر النظام تتطلب صلاحيات root، لذا تُشغَّل باستخدام `sudo`.

## apt على {{distro}}

### update وupgrade شيئان مختلفان

هذا يربك الجميع تقريبًا في البداية:

- `apt update` ينزّل **قائمة** الحزم والإصدارات المتاحة. ولا يثبّت شيئًا.
- `apt upgrade` **يثبّت** الإصدارات الجديدة لما لديك أصلًا.

لذا شغّل `update` أولًا دائمًا. الطريقة الأكثر شيوعًا لتحديث النظام هي:

```sh
sudo apt update && sudo apt upgrade
```

قبل أن تشغّل `apt update` (على خادم مثبّت حديثًا مثلًا)، تكون قائمة الحزم فارغة
ولا يستطيع apt العثور على أي حزمة على الإطلاق.

### التثبيت والإزالة

```sh
sudo apt install htop
```

يزيل `apt remove` البرنامج لكنه يترك ملفات إعداداته. أما `apt purge` فيزيلها
أيضًا. وعندما يسأل apt `Do you want to continue? [Y/n]`، فإن الحرف الكبير `Y`
يدل على أن مجرد الضغط على Enter يعني الموافقة. ومع الخيار `-y` يجيب apt بنعم
تلقائيًا.

### apt أم apt-get؟

`apt` هو البديل الحديث سهل الاستخدام، مع شريط تقدّم وألوان. أما `apt-get`
و`apt-cache` فهما أقدم لكن مخرجاتهما أكثر ثباتًا، لذا ما زالا يُستخدمان في
السكربتات.

### خلف الكواليس: dpkg و‎.deb

الحزم عبارة عن ملفات `.deb`، والبرنامج `dpkg` هو في الحقيقة من يفكّ حزمها. أما
apt فيتولى كل ما يحيط بذلك: التنزيل، والاعتماديات، والتحديثات.

## pacman على {{distro}}

يستخدم pacman خيارات قصيرة يكون فيها **الحرف الكبير** هو العملية، والأحرف
الصغيرة معدِّلات:

| الخيار | المعنى |
|---|---|
| `-S` | Sync – التثبيت من المستودعات |
| `-R` | Remove – الإزالة |
| `-Q` | Query – الاستعلام عن الحزم المثبّتة |
| `y` | تحديث قاعدة بيانات الحزم |
| `u` | ترقية كل الحزم |
| `s` | البحث (مع ‎-S و‎-Q)، أو إزالة الاعتماديات (مع ‎-R) |
| `i` | المعلومات |

### تحديث النظام

```sh
sudo pacman -Syu
```

`-Syu` تعني: زامِن (`S`)، وحدّث قاعدة البيانات (`y`)، ورقِّ كل شيء (`u`). وArch
توزيعة *rolling release* (متجددة)، لذا ستشغّل هذا الأمر كثيرًا.

> **مهم!** لا تشغّل أبدًا `pacman -Sy` وحده ثم `pacman -S package`. فقد تحتاج
> الحزمة الجديدة عندئذ إلى مكتبات أحدث من التي لديك – وهذا ما يسمى *partial
> upgrade* (ترقية جزئية) وقد يعطّل نظامك. استخدم دائمًا `-Syu`.

### التثبيت والإزالة

```sh
sudo pacman -S htop
```

يزيل `pacman -R package` حزمة، ويزيل `pacman -Rs package` أيضًا الاعتماديات التي
لا يحتاجها أي شيء آخر.

### الـ AUR

إلى جانب المستودعات الرسمية هناك **AUR** (*Arch User Repository*)، حيث يتشارك
المستخدمون وصفات بناء لآلاف البرامج. وغالبًا ما يستخدم الناس أداة مساعدة مثل
`yay` أو `paru` للتثبيت منه. الحزم في AUR لا تراجعها Arch – لذا اقرأ دائمًا وصفة
البناء (ملف PKGBUILD) أولًا.

## dnf على {{distro}}

### بيانات وصفية تلقائية

يجلب dnf معلومات الحزم الجديدة بنفسه عندما يحتاج إليها، لذا لا توجد خطوة منفصلة
مثل `apt update`. وإذا أردت أن ترى التحديثات المتاحة، فشغّل:

```sh
dnf check-update
```

يكون رمز الخروج `100` إذا وُجدت تحديثات – وهذا مفيد في السكربتات.

### التثبيت والإزالة

```sh
sudo dnf install htop
```

لاحظ السؤال `Is this ok [y/N]`. الحرف الكبير `N` يعني أن **لا** (No) هي الإجابة
الافتراضية – فإذا ضغطت Enter فقط، أُلغي التثبيت. اكتب `y` ثم Enter، أو استخدم
`-y`.

### ترقية النظام

```sh
sudo dnf upgrade
```

### خلف الكواليس: rpm

الحزم عبارة عن ملفات `.rpm`، والأداة منخفضة المستوى اسمها `rpm`. حلّ dnf محل
`yum` الأقدم، وجاء Fedora 41 بالإصدار الجديد **dnf5** الأسرع بكثير. وعلى RHEL
وRocky وAlmaLinux يسمى الأمر أيضًا `dnf`.
:::

## البرنامج نفسه، بأسماء مختلفة

للحزم عادةً الاسم نفسه في كل مكان – لكن ليس دائمًا. بعض الأمثلة:

| البرنامج | Debian/Ubuntu | Arch | Fedora |
|---|---|---|---|
| Vim | `vim` | `vim` | `vim-enhanced` |
| Python 3 | `python3` | `python` | `python3` |
| عميل SSH | `openssh-client` | `openssh` | `openssh-clients` |

ابحث دائمًا بمدير الحزم إذا لم تكن متأكدًا من الاسم.

## صيغ الحزم العامة

هناك أيضًا صيغ تعمل على كل التوزيعات: **Flatpak** (شائعة لتطبيقات سطح المكتب، عبر
Flathub)، و**Snap** (من Canonical، وهي الافتراضية في Ubuntu)، و**AppImage** (ملف
تنفيذي واحد). ولكل منها أوامرها الخاصة، وهي تكمّل مدير الحزم الخاص بالتوزيعة.
